## 2. 评分模块化交付记录

原方案在局部拆文件与系统性收敛之间选择了后者：公共层只认识策略能力，不判断 V1/V2/V3 的算法差异；
档位差异集中在 `infra/scoring/profiles/`；训练与生产只共享纯特征计算、类型化合同、模型工件线格式和
内容 hash。该目标架构已经落地，当前主要边界为：

```text
domain/recommendation/model_scoring/         纯残差化、分位与档位身份
application/ports/model_scoring.py           类型化模型评分端口
application/recommendation/model_scoring_router.py
application/recommendation/tomorrow_model_scoring.py
infra/scoring/profile_factory.py             唯一 profile 组装入口
infra/scoring/profiles/{v1,v2,v3}/           各档位 codec、predictor 与证据
```

profile 只组装已经构造完成的能力；codec 只负责 JSON 到不可变类型对象及 schema/hash 校验；predictor
只接受类型化工件和输入并批量推理；locator 只定位工件；composition 只组合预风险模型信号。硬过滤、
DeepSeek、本地风险、固定融合、动作、TopK、冻结、持久化和 Web 投影不进入 profile 目录。

### 4.1 `baostock_daily_archive`

状态：`pending`。本节是 BaoStock 2000 日日线正式归档的唯一执行定义，不得在其他章节复制状态或完成条件。
目标是截至冻结交易日的最近 2000 个交易所开市日，每只股票最多 2000 个代码-日期逻辑记录；股票应有交易日

raw/qfq 必须在同一行 `(code, trade_date)` 保存；`--sessions` 接受 1–2000 且默认 2000，只有
`--sessions 2000` 能生成正式 manifest。归档身份为 `baostock_daily_core`，默认目录为

重算已有 horizon 并可能触发不可变冲突。现已建立领域唯一 `outcome_horizons()` 和纯
`CanonicalOutcomeEvaluator`，补入 T+4、20/50/100bp 参数化成本、D25 四 horizon 聚合与有类型等权基准人口；
`OutcomeTarget.pending_horizons` 使恢复只补缺失项。`make format-check`、`make lint`、`make type-check`、
`make test` 和 `make package` 及结算/持久化/架构专项回归均通过；Review 无已知未解决发现。历史 14:50 点时
人口、停牌/一字板和复权因子的真实数据资格仍归第 7.4 节，当前盘后等权记录只作运行监控，不冒充历史收益验证。

### 7.2 `feature_contract_unification`

建立 `FeatureSpecCatalog`、分组 `FeatureCalculators`、`FeatureComputationPlan` 和
`FeatureVectorManifest`，消除在线归一化、训练、模型 codec、历史回放和 Shadow 的字段名、顺序、单位、方向、
可见时间与缺失规则重复。内部动态集合只能是 `FeatureId -> FeatureValue` 的有类型映射；JSON 仅在配置、
持久化和报告投影边界出现。本章不得改变评分公式、已授权模型、固定融合或冻结行为。

### 7.3 `incremental_feature_computation`

按输入 revision 和 catalog 依赖只重算受影响特征组，复用同一轮 facts，并增加候选规模、各组计算耗时、
端到端决策年龄和 deadline 放弃原因。必须保持相同输入得到相同向量/hash，旧任务按现有 latest-wins 语义
完成或放弃；冻结后迟到结果不可发布。以固定全市场 fixture 比较改造前后 CPU、延迟和内存，不能用改变候选
或降低历史门槛换性能。

### 7.4 `point_in_time_data_qualification`

复用第 4 节 BaoStock 2000 日日线和历史行业事实，不建立重复归档。另对候选历史分钟来源做只读能力审计：
必须证明交易日、代码、时区、11:20/14:50 bar、成交量额、复权/公司行为身份、覆盖率和可复现 hash。若来源
不能证明真实点时数据，本章保持稳定 blocker；不得用 15:00 收盘价冒充 14:50，不得恢复未来日 collector，
不得把当前行业回填历史。

### 7.5 `candidate_recall_attribution`

实现隔离的 `CandidateRecallLedger`：为永久资格、动态硬过滤、字段资格、板内预选、每板上限、评分、风险、
动作和集中度记录首次拒绝边界；在未开启终端留出的历史数据上计算 20bp 成本后 oracle Top10/20/50 recall、
逐板召回、不可交易率和严重亏损率。只形成归因报告，不因召回不足自动降低 50 分、扩大每板 120 或改变 Top6。

### 7.6 `limited_factor_family_research`

参数族按 `01_评分逻辑.md` 第 11.2 节执行，一次只预注册一族，并固定现有六项 alpha 为对照。每族先过点时
可见、训练/在线一致、缺失率、覆盖率和计算预算，再用不重叠时间切分、Holm、多成本、换手、容量、严重亏损、
回撤和分市场状态判断。失败即记录 `historical_rejected` 并停止该族，不滚动搜索直到碰到正收益。

### 7.7 `risk_cost_uncertainty_deepseek`

分别形成 `AlphaScore`、`RiskDecision`、`ExecutionCost` 和研究态 `SelectionUtility`，禁止把成本统一清零分数或
让同一风险重复扣分。不确定性覆盖严重亏损概率、预测区间、Ridge/LightGBM 模型分歧、训练窗口分歧、OOD
距离和缺失诱发不确定性；至少报告 Brier、ECE、覆盖率和机会成本。DeepSeek 比较 local-only、结构化 facts
veto、固定 68/32 融合，失败/迟到/预算耗尽仍保留 local，不让 DeepSeek 自由文本直接扣分。

### 7.8 `shadow_and_manual_activation`

`ShadowMonitor` 只读消费生产输入身份与隔离研究结果，按候选和聚合层记录特征/分数漂移、召回、成本、风险、
不确定性、延迟和成熟 outcome；不写正式推荐、冻结或活动数据库。Shadow 通过也不自动生产化；只有完整点时
历史门禁、一次性终端留出、运行稳定性和人工 Review 均通过，并且用户明确授权新的完整批次，才允许修改生产
特征、阈值、权重、TopK、DeepSeek 用途或默认评分档位。

### 7.9 全路线固定禁止事项

- 不接入不可靠主力资金、社交热度、当前行业历史回填或无可靠归档的 L2；
- 不成组堆叠技术指标，不为补满推荐降低阈值，不把缺失填 0；
- 不恢复未来 collector，不使用已观察收益的窗口冒充盲测，不打开终端留出多次；
- 不自动训练、自动搜索、自动晋级、自动激活或自动回退；
- 不修改固定 68/32 融合、DeepSeek 168 物理请求上限和 11:20/14:50 冻结，除非后续证据通过且用户另行授权。

# 工程实施计划

本文件只维护尚未完成的工程任务；当前范围是已获授权的 V3 三头日线工程代理、依赖顺序和验收边界。候选、评分、风险、
融合与排名以[评分逻辑](01_评分逻辑.md)为准；产品、架构、配置、API、Web、运维和发布契约以
[工程设计](02_工程设计.md)为准；历史、训练与实时消费关系见[策略回溯](04_策略回溯.md)。批次、Review、
测试、提交和推送纪律以根目录 `AGENTS.md` 为准。

用户已明确授权复用当前 `data/history/baostock` 日线训练 Today、Tomorrow、D25 三个 V3 head，不新增分钟库、
不修改历史 archive schema、不重新下载历史，也不把日线代理写成历史点时验证。每次“继续”只执行顺序最前且
前置满足的一整节，完成 Review、单一提交和推送后停止。

配置与多头类型契约已经交付：唯一配置字段是 `scoring_profile`；`LoadedScoringProfile` 只保留档位 ID 和按
`Strategy` 键控的不可变 head，每个 head 自己拥有 predictor、combiner 与证据，profile 不再保存含义错误的
单一 model ID/hash。该完成事实以交付记录和 Git 为准，不在未完成任务表重复。
每个 head 的固定工件名都是 `model.json`、`report.json`、`training-input.json`、`active-bundle.json`；默认 V1 不变。

## 2. 共享多目标样本管线

任务身份：`v3_shared_multi_target_samples`

状态：`pending`

只读取当前 active BaoStock 日线、交易日历、股票总体和历史行业；不改历史库，不下载分钟数据。训练输入打开时
只完整验证一次 snapshot、月分片 hash 和来源 identity，然后按交易日顺序扫描一次。单一临时 SQLite 至少保存：

- `trade_date`、`code`、`board`、`industry`、20 日平均成交额；
- 1/3/5 日收益和 20/40/60 日 skip-5 残差动量；
- `target_t1`、`target_t2`、`target_t3`、`target_t4`、`target_t5`、`target_d25_aggregate`；
- `split_name`。

T+1 基准和现有 Tomorrow 标签数学不得改变。D25 只在四个未来 horizon 全部成熟时写样本，聚合值是四列扣
成本前相对超额的算术平均。扫描期只保留有界日期状态，不建立三份数据库、不恢复 `raw_samples`，SQLite cache
保持 32 MiB。完成条件是标签、缺失规则、稳定顺序、snapshot 绑定和 Tomorrow 等价性均由直接测试证明。

## 3. Today V3 模型头

任务身份：`v3_today_model_head`

状态：`blocked_by_shared_samples`

Today manifest 固定为 3/5 日收益和 20/40/60 日 skip-5 残差动量，不含 1 日收益；标签为 D 收盘到 T+1
收盘的扣成本前相对超额。按历史行业顺序拟合 StandardScaler、Ridge、浅层 LightGBM 50/50 集成和独立线性
校准，发布到 `data/train/today-v3/` 的四个固定文件。工件固定 `training_anchor=15:00_close_proxy`、
`runtime_anchor=11:20`、`point_in_time_parity=false`、`historical_data_insufficient`、
`production_authority=false`、`automatic_model_update=false`。

## 4. D25 V3 模型头

任务身份：`v3_d25_model_head`

状态：`blocked_by_shared_samples`

D25 使用与 Today 相同的五个趋势特征，仍只有一个生产 head。训练目标为 T+2 至 T+5 四列扣成本前相对超额
的算术平均，报告必须分别保留四个 horizon 的样本和验证指标；在线成本只扣一次，不按 horizon 重复。
发布到 `data/train/d25-v3/` 的四个固定文件，并固定 15:00 收盘代理 14:50 的无点时一致性证据。

## 5. train-v3 统一入口

任务身份：`v3_unified_training_entrypoint`

状态：`blocked_by_three_model_heads`

增加 `./run.sh train-v3`，保留 `train-tomorrow`。统一入口只做一次资源预检、snapshot 校验和历史扫描，随后严格
按 Today、Tomorrow、D25 顺序拟合到期 head；不同 head 的数组和 LightGBM dataset 在下一 head 前释放。
每个 head 独立按成熟标签截止和 20 日 cadence 判 due，失败不移动其成功基线。计算线程 2、单行业并发 1、
峰值 RSS 2048 MiB、历史维护锁和 Ctrl+C 清理合同保持不变。

## 6. V3 多头运行评分

任务身份：`v3_multihead_runtime_scoring`

状态：`blocked_by_three_model_heads`

V3 profile 同时加载 Today/Tomorrow/D25 三个策略 head；任一固定工件组失败则整个显式 V3 启动失败。router
改为有类型 `Strategy -> ScoringCapability`；Tomorrow 专用生产模型服务重构为策略感知服务，每个 head 有独立
锁、缓存、deadline 与统计。相同 facts identity 可复用特征计算，预测绝不跨策略复用。V1/V2 仍只声明
Tomorrow 模型能力，Today/D25 继续规则评分；Long 始终无模型。

## 7. 状态、API、SSE、Web 和冻结

任务身份：`v3_multihead_delivery_and_freeze`

状态：`blocked_by_runtime_scoring`

公开状态一次性切换为 `scoring_profile.profile_id` 与 `heads.today|tomorrow|d25`，不保留双 schema fallback。
每个 head 白名单公开身份、锚点、证据、候选/请求/缓存/预测批次、阶段耗时和 deadline 原因。Today/D25 决策
项目与 Tomorrow 一样携带本策略模型诊断和 `input_versions.score_model`，GET、完整 SSE 替换、冻结记录和 Web

冻结时间不变：Today 11:20 后不追补；Tomorrow/D25 14:50 first-wins；15:00 后允许的 `close_fallback` 只走

冷启动、正式记录命中、迟到结果和收盘恢复必须完整覆盖。

## 10. 每章统一退出条件

每章均按 `AGENTS.md` 和 `$trader-delivery` 执行：记录基线和用户已有变更；先改契约与失败回归，再实现；按
影响矩阵覆盖直接所有者及下游消费者；Review 完整 diff 至零已知发现；运行风险匹配的定向门禁，大任务最后
一章再统一运行一次完整门禁；更新 Changelog；只暂存本章文件；创建一个 Conventional Commit、推送并确认
`HEAD == @{upstream}`。未满足全部退出条件不得执行下一章。

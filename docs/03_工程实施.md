本文件只维护尚未完成的工程任务、依赖顺序、状态和验收边界。已经完成的交付只保留在 Git、
`CHANGELOG.md` 和必要的 `docs/reports/` 证据中，不在这里重复。

- 候选、过滤、评分、风险、融合、动作和排名规则以[评分逻辑](01_评分逻辑.md)为准。

`blocked_*` 表示前置证据或用户授权未满足。普通“继续”只执行表中顺序最前且可执行的一个完整同级章节。

## 2. 当前执行章节：候选资格先于板内限额

任务身份：`candidate_eligibility_before_board_cap`

回归身份：`candidate-eligibility-before-cap-single-owner`

状态：`in_progress`

### 2.1 已确认问题与目标架构

已确认的首个错误边界是：旧实时链在策略资格之前先用通用候选分按板截断，ST、停牌、历史不足、活动模型
字段缺失或过期股票会占用名额，合格后继股票不能补位。目标结构是由一个纯领域规划器统一拥有动态硬过滤、
策略历史/模型字段资格、核心缺失、候选最低分与稳定排序；应用层只维护按 `strategy + board` 隔离的有序储备，
对三策略活动窗口的去重并集执行共享行情 I/O，并在同一 deadline 内沿原策略同板储备补位。

局部地把一个过滤函数移到旧截断前不能解决三策略候选身份、模型字段资格、行情失效补位和双候选分所有权，
因此不采用。

### 2.2 剩余工作

1. 以本批原始基线和当前工作树为证据，拆开并保留其它批次的重叠修改，确认任务文件和暂存区只属于本章。
2. Review 候选规划、行情刷新、调度、状态/API 下游，修复零候选、重复代码、供应商返回未请求代码、
   stale/invalid 报价、储备耗尽、deadline 和跨策略隔离的所有已知问题。
3. 确认配置只剩板块策略候选权重一个生产真相源；正式评分复用同一规划规则，不新增字典 fallback、同步全市场
   历史下载或第二套候选公式。
4. 补齐 Changelog 的症状、确认根因、行为变化、验证和剩余风险；先运行定向门禁，再对完整候选批次执行一次
   高风险完整门禁和适用的真实性诊断。

## 4. BaoStock 父归档加增量归档

任务身份：`baostock_increment_archive`

状态：`blocked_by_task_1_worktree_closure`

只读 `history-plan` 已能证明父归档可复用范围和字段缺口；本章从其有类型计划继续，不重复扫描逻辑。目标是保持
旧 92 个 SQLite 分片和父 manifest 原字节不变，把新增或补齐事实写入独立增量分片，并用一个稳定 active manifest
绑定父 hash、增量 hash、活动数据 hash、截止日、交易日历、来源身份、字段覆盖和缺失原因。

实施顺序：

1. 先完成 active/increment manifest、字段族、checkpoint、冲突和防篡改契约；同一 key 同内容幂等，不同内容
   失败关闭，父归档绝不写入。
2. 实现增量 SQLite writer、整文件 hash、临时目录、flush/fsync 和原子 active 指针切换；失败保留上一份有效
   active manifest。
3. 让 `download_history` 显式消费只读计划，只请求缺失的新交易日和字段；raw 请求已返回 isST 时不得重复请求，
   失败不得写成成功。
4. 实现父加增量的有类型只读视图；旧 key 读父、新 key 读增量，同 key 内容冲突直接拒绝，不允许静默覆盖。
5. 运行持久化、恢复、损坏、重试、空间/并发上限和真实小批增量专项；不修改运行数据库或把研究归档接入 Web。

完成条件：父文件字节和 mtime 不变；重复执行无重复记录；active manifest 可完整校验和恢复；中断、损坏、冲突
均保留上一有效读取面；本章独立 Review、Changelog、完整高风险门禁、提交、推送和上游核对完成。

## 6. V3 训练工件重建与整组发布

状态：`blocked_by_dynamic_cutoff_and_missing_facts`

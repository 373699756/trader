# 工程实施计划

本文件只维护尚未完成的工程任务、依赖顺序、状态和验收边界。已经完成的交付只保留在 Git、
`CHANGELOG.md` 和必要的 `docs/reports/` 证据中，不在这里重复。

- 候选、过滤、评分、风险、融合、动作和排名规则以[评分逻辑](01_评分逻辑.md)为准。
- 产品、架构、生命周期、数据、API、Web、运维和发布契约以[工程设计](02_工程设计.md)为准。
- 历史下载、训练工件与实时评分的解释性链路见[策略回溯](04_策略回溯.md)。
- 评分权威文档与当前活动源码的逐节实现状态、已修复不一致及剩余缺口见
  [2026-09-10 评分链实现复核](reports/2026-09-10-scoring-chain-implementation-review.md)。
- 依赖、构建和入口以根目录 `pyproject.toml` 为准；批次、Review、测试、提交和推送纪律以
  根目录 `AGENTS.md` 为准。

状态只使用：`in_progress` 表示当前唯一执行章节；`pending` 表示前置已满足、等待执行；
`blocked_*` 表示前置证据或用户授权未满足。普通“继续”只执行表中顺序最前且可执行的一个完整同级章节。

## 4. V3 训练工件重建与整组发布

任务身份：`v3_training_artifact_rebuild`

状态：`pending`

当前 trainer 已输出扣成本前的基准超额，模型与报告合同固定 `label_target=pre_cost_excess_return`、
`training_cost_bps=0`，20/50/100bp 只由选择和评价层按场景扣除；当前 codec 也已要求
`tomorrow_scoring_model` 与 `tomorrow_training_report` 的来源、特征、训练合同和载荷 hash 配对。尚未闭合的是：
成本只由选择和评价层按场景扣一次，这项所有权已经闭合，不属于本章剩余整改。

1. 从父加增量活动归档读取确定性训练输入，不直接读取旧固定截止日目录身份；
2. 保持训练、校准和验证统一使用扣成本前标签；分批或流式构造训练样本，避免一次性保留全量 `_Sample`；
3. 在独立临时目录生成 `training-input.json`、`report.json` 和 `model.json`，三者全部通过 codec 与配对校验后
   一次原子切换；失败保留上一组有效工件；
4. 重新训练而不是给旧 schema 补字段或放宽 loader；结果继续如实标记日线工程代理、点时不足和无生产权限。

完成条件：新工件 schema、内容和父身份全部有效；重复训练确定性；峰值内存满足门禁；成本不重复扣除；旧工件
继续被明确拒绝；训练失败不破坏上一有效组；独立 Review、Changelog、完整高风险门禁、提交和推送完成。

## 6. 点时证据修复

任务身份：`point_in_time_evidence_remediation`

状态：`blocked_by_external_point_in_time_sources`

该 blocker 不是缺少数据类或失败关闭代码，而是缺少可信外部事实。进入实施前必须由用户提供或明确授权候选来源，
并先做小样本只读能力审计：历史行业要证明分类、生效/失效和查询时间；历史分钟要证明上海时区 11:20/14:50、

消融。不得用 15:00 收盘、当前行业、未来 collector、fixture 或日线工程代理冒充通过。完成条件是权威评分文档
规定的父证据和样本门全部满足，报告可复现且仍不开终端留出、不授予生产权限。

## 11. 每章统一退出条件

每章均按 `AGENTS.md` 和 `$trader-delivery` 执行：记录新基线和用户已有变更，先改契约与失败回归，再实现；按

运行一次完整门禁；更新 Changelog；只暂存本章文件；创建一个 Conventional Commit、推送并确认
`HEAD == @{upstream}`。未满足全部退出条件的章节不得删除或标记完成。

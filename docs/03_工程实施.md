# 工程实施计划

本文件只维护尚未完成的工程任务、依赖顺序、状态和验收边界。已经完成的交付只保留在 Git、
`CHANGELOG.md` 和必要的 `docs/reports/` 证据中，不在这里重复。

- 候选、过滤、评分、风险、融合、动作和排名规则以[评分逻辑](01_评分逻辑.md)为准。
- 产品、架构、生命周期、数据、API、Web、运维和发布契约以[工程设计](02_工程设计.md)为准。
- 历史下载、训练工件与实时评分的解释性链路见[策略回溯](04_策略回溯.md)。
- 依赖、构建和入口以根目录 `pyproject.toml` 为准；批次、Review、测试、提交和推送纪律以
  根目录 `AGENTS.md` 为准。

状态只使用：`in_progress` 表示当前唯一执行章节；`pending` 表示前置已满足、等待执行；
`blocked_*` 表示前置证据或用户授权未满足。普通“继续”只执行表中顺序最前且可执行的一个完整同级章节。

## 2. 当前执行章节：BaoStock 父归档加增量归档

任务身份：`baostock_increment_archive`

状态：`in_progress`

只读 `history-plan` 已能证明父归档可复用范围和字段缺口；本章从其有类型计划继续，不重复扫描逻辑。目标是保持
旧 92 个 SQLite 分片和父 manifest 原字节不变，把新增或补齐事实写入独立增量分片，并用一个稳定 active manifest
绑定父 hash、增量 hash、活动数据 hash、截止日、交易日历、来源身份、字段覆盖和缺失原因。

实施顺序：

1. 先完成 active/increment manifest、字段族、checkpoint、冲突和防篡改契约；同一 key 同内容幂等，不同内容
   失败关闭，父归档绝不写入。
2. 实现增量 SQLite writer、整文件 hash、临时目录、flush/fsync 和原子 active 指针切换；失败保留上一份有效
   active manifest。
3. 让 `download_history` 显式消费只读计划，只请求缺失的新交易日和字段；raw 请求已返回 isST 时不得重复请求，
   失败不得写成成功。
4. 实现父加增量的有类型只读视图；旧 key 读父、新 key 读增量，同 key 内容冲突直接拒绝，不允许静默覆盖。
5. 运行持久化、恢复、损坏、重试、空间/并发上限和真实小批增量专项；不修改运行数据库或把研究归档接入 Web。

完成条件：父文件字节和 mtime 不变；重复执行无重复记录；active manifest 可完整校验和恢复；中断、损坏、冲突
均保留上一有效读取面；本章独立 Review、Changelog、完整高风险门禁、提交、推送和上游核对完成。

## 3. 动态截止日与缺失事实补采

任务身份：`dynamic_cutoff_and_missing_fact_acquisition`

状态：`blocked_by_baostock_increment_archive`

新活动归档的 `source_cutoff` 取最近成功封存的完整交易日，并进入 active manifest 内容身份。新路径的日历、股票池、
训练输入和日期校验全部从该有类型上下文读取；既有固定截止日只允许在历史工件/父归档解码时原样只读兼容，
不得自动迁移、覆盖或产生新的项目版本名。

补采只覆盖计划明确标记的缺口：新交易日 raw/qfq、缺失 isST 和具备真实生效时间的行业/资格/硬过滤/风险事实。
无法提供 `effective_at`、`published_at` 或查询时间的来源继续记缺失，禁止用当前快照回填历史。完成条件是动态
截止日、滚动 2000 日窗口、逐字段覆盖与请求估算一致，父/增量 hash 可复现，旧工件兼容只读，新活动归档在
重启和重复执行后稳定；适用数据源、持久化、训练输入和完整高风险门禁通过并独立推送。

## 4. V3 训练工件重建与整组发布

任务身份：`v3_training_artifact_rebuild`

状态：`blocked_by_dynamic_cutoff_and_missing_facts`

当前 codec 已要求 `tomorrow_scoring_model` 与 `tomorrow_training_report` 的来源、特征、训练合同和载荷 hash
配对，但训练数据合同仍把 20/50/100bp 往返成本写进标签，训练样本也仍保存 `net_excess_returns`。选择和评价层
还会按成本场景再次扣除，因此单一成本所有权尚未实现。本章工作是：

1. 从父加增量活动归档读取确定性训练输入，不直接读取旧固定截止日目录身份；
2. 把训练目标改为扣成本前的基准超额，成本只由选择和评价层按场景扣一次；分批或流式构造训练样本，避免
   一次性保留全量 `_Sample`，并确保训练、校准和验证使用同一 label 口径；
3. 在独立临时目录生成 `training-input.json`、`report.json` 和 `model.json`，三者全部通过 codec 与配对校验后
   一次原子切换；失败保留上一组有效工件；
4. 重新训练而不是给旧 schema 补字段或放宽 loader；结果继续如实标记日线工程代理、点时不足和无生产权限。

完成条件：新工件 schema、内容和父身份全部有效；重复训练确定性；峰值内存满足门禁；成本不重复扣除；旧工件
继续被明确拒绝；训练失败不破坏上一有效组；独立 Review、Changelog、完整高风险门禁、提交和推送完成。

## 6. 点时证据修复

任务身份：`point_in_time_evidence_remediation`

状态：`blocked_by_external_point_in_time_sources`

该 blocker 不是缺少数据类或失败关闭代码，而是缺少可信外部事实。进入实施前必须由用户提供或明确授权候选来源，
并先做小样本只读能力审计：历史行业要证明分类、生效/失效和查询时间；历史分钟要证明上海时区 11:20/14:50、
量额、raw/qfq 与公司行动语义及至少 95% 分层覆盖；资格、硬过滤和风险事实要证明 `effective_at`/`published_at`。

只有资格报告真实通过，才允许构建实际 point-in-time 数据集、候选召回、有限参数确认、V3 开发/确认和风险成本
消融。不得用 15:00 收盘、当前行业、未来 collector、fixture 或日线工程代理冒充通过。完成条件是权威评分文档
规定的父证据和样本门全部满足，报告可复现且仍不开终端留出、不授予生产权限。

## 7. 一次性终端留出、Shadow 与人工生产授权

任务身份：`terminal_holdout_shadow_and_manual_activation`

状态：`blocked_by_point_in_time_evidence_and_user_authorization`

`point_in_time_evidence_remediation` 通过后，先冻结完整选择链、候选规范、模型及所有父 hash，再按评分权威文档
原子地打开一次至少 200 个
交易日的终端留出；任何二次或竞争打开必须拒绝。历史门通过最多形成 `historical_validated`，仍无生产权限。
随后执行 Shadow，比较 local-only、结构化 facts veto 与固定融合的成本后收益、尾部风险、漂移和机会成本。

只有 Shadow 门通过且用户在独立批次明确授权，才可切换默认生产档位；启用必须同步配置、决策输入身份、冻结、
状态/API/Web、两份权威文档和 Changelog，保持 V1/V2 可审计且禁止自动训练、晋级、激活或回退。

## 9. 每章统一退出条件

每章均按 `AGENTS.md` 和 `$trader-delivery` 执行：记录新基线和用户已有变更，先改契约与失败回归，再实现；按
影响矩阵覆盖直接所有者及下游消费者；Review 完整 diff 至零已知发现；运行风险匹配的定向门禁，大任务收尾只
运行一次完整门禁；更新 Changelog；只暂存本章文件；创建一个 Conventional Commit、推送并确认
`HEAD == @{upstream}`。未满足全部退出条件的章节不得删除或标记完成。

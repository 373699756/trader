# 工程实施计划

本文件只维护尚未完成的工程任务；当前队列是把 V2/V3 从共享工件迁移为独立训练目录。候选、评分、风险、
融合与排名以[评分逻辑](01_评分逻辑.md)为准；产品、架构、配置、API、Web、运维和发布契约以
[工程设计](02_工程设计.md)为准；历史、训练与实时消费关系见[策略回溯](04_策略回溯.md)。批次、Review、
测试、提交和推送纪律以根目录 `AGENTS.md` 为准。

用户已明确授权 V2 与 V3 改为独立三头训练目录和独立档位代码：V2 使用
`data/train/v2/{today,tomorrow,d25}`，V3 使用 `data/train/v3/{today,tomorrow,d25}`。当前已实现 `train-v2`
与 `train-v3` 两个独立入口、V2 的 120/250 日长期特征与 251 日有界输入、V3 的 61 日合同，以及不含档位判断的
公共训练引擎。两档只共享 `data/history/baostock`、样本/拟合机制和资源边界；各自拥有 feature manifest、模型 ID、
codec 身份、due 合同和输出根。当前批次不切换运行 loader、不修改历史 archive schema、不重新下载历史；为保持
默认 `run.sh` 可用，旧扁平目录暂时只读保留到后续原子 cutover。两档只读取当前 `data/history/baostock` 日线；本批不新增分钟库，不把日线代理写成历史点时验证。

配置与多头类型契约已经交付：唯一配置字段是 `scoring_profile`；`LoadedScoringProfile` 只保留档位 ID 和按
`Strategy` 键控的不可变 head，每个 head 自己拥有 predictor、combiner 与证据，profile 不再保存含义错误的
单一 model ID/hash。该完成事实以交付记录和 Git 为准，不在未完成任务表重复。
每个 head 的固定工件名都是 `model.json`、`report.json`、`training-input.json`、`active-bundle.json`；默认档位改为 V2，
显式 V1/V3 仍可用于对照，不会改写共享工件。
既有评分链 Review 见
[2026-09-10 scoring-chain implementation review](reports/2026-09-10-scoring-chain-implementation-review.md)。
当前 trainer 输出扣成本前的基准超额，成本只由在线选择与评价边界按场景扣一次；这项所有权已经闭合。

## 2. 共享多目标样本管线

任务身份：`v3_shared_multi_target_samples`

状态：`verified_ready_for_delivery`

只读取当前 active BaoStock 日线、交易日历、股票总体和历史行业；不改历史库，不下载分钟数据。训练输入打开时
只完整验证一次 snapshot、月分片 hash 和来源 identity，然后按交易日顺序扫描一次。单一临时 SQLite 至少保存：

- `trade_date`、`code`、`board`、`industry`、20 日平均成交额；
- 1/3/5 日收益和 20/40/60 日 skip-5 残差动量；
- `target_t1`、`target_t2`、`target_t3`、`target_t4`、`target_t5`、`target_d25_aggregate`；
- `split_name`。

T+1 基准和现有 Tomorrow 标签数学不得改变。D25 只在四个未来 horizon 全部成熟时写样本，聚合值是四列扣
成本前相对超额的算术平均。扫描期只保留有界日期状态，不建立三份数据库、不恢复 `raw_samples`，SQLite cache
保持 32 MiB。完成条件是标签、缺失规则、稳定顺序、snapshot 绑定和 Tomorrow 等价性均由直接测试证明。

## 3. Today V3 模型头

任务身份：`v3_today_model_head`

状态：`verified_ready_for_delivery`

Today manifest 固定为 3/5 日收益和 20/40/60 日 skip-5 残差动量，不含 1 日收益；标签为 D 收盘到 T+1
收盘的扣成本前相对超额。按历史行业顺序拟合 StandardScaler、Ridge、浅层 LightGBM 50/50 集成和独立线性
校准，发布到 `data/train/today-v3/` 的四个固定文件。工件固定 `training_anchor=15:00_close_proxy`、
`runtime_anchor=11:20`、`point_in_time_parity=false`、`historical_data_insufficient`、
`production_authority=false`、`automatic_model_update=false`。

## 5. train-v3 统一入口

任务身份：`v3_unified_training_entrypoint`

状态：`verified_ready_for_delivery`

增加 `./run.sh train-v3`。统一入口只做一次资源预检、snapshot 校验和历史扫描，随后严格
按 Today、Tomorrow、D25 顺序拟合到期 head；不同 head 的数组和 LightGBM dataset 在下一 head 前释放。
每个 head 独立按成熟标签截止和 20 日 cadence 判 due，失败不移动其成功基线。计算线程 2、单行业并发 1、

## 6. V3 多头运行评分

任务身份：`v3_multihead_runtime_scoring`

状态：`verified_ready_for_delivery`

V2/V3 profile 都同时加载 Today/Tomorrow/D25 三个共享策略 head；任一固定工件组失败则所选档位启动失败。router
改为有类型 `Strategy -> ScoringCapability`；Tomorrow 专用生产模型服务重构为策略感知服务，每个 head 有独立
锁、缓存、deadline 与统计。相同 facts identity 可复用特征计算，预测绝不跨策略复用。V1 仍只声明 Tomorrow 模型能力；
V2/V3 共用同一组三头工件与数值预测，只分离运行档位身份；Long 始终无模型。

## 10. 默认 V2 与现有三头工件启动

任务身份：`v2_default_existing_bundle_runtime`

状态：`verified_ready_for_delivery`

`config/strategy.json` 是默认评分档位的唯一真相源，固定为 `scoring_profile=v2`。`run.sh` 和 `run.ps1`
无参数时不再构造隐藏 `--profile v1` 覆盖，因此 server、`check` 和 performance 都由同一配置选中 V2。
显式 `--profile v1|v2|v3` 只作当前进程覆盖，不写配置。

任一文件、hash、manifest、训练输入或策略头身份错配都使启动失败，不回退 V1。真实工件验收必须证明三个 head
都能对完整 61 日现有特征向量生成有限预测、诊断分和成本后净超额。本章不读取或生成 120/250 日新特征，
不需要重训即可完成。

## 11. V2/V3 独立目录与训练切换

任务身份：`profile_owned_training_commands`

状态：`verified_ready_for_delivery`

当前批次已把 V2 与 V3 三头的四件固定工件提交到 `data/train/v2/{today,tomorrow,d25}` 和
`data/train/v3/{today,tomorrow,d25}`。V2 工件带有独立 V2 profile、特征 manifest、模型身份和 hash，未将 V3
工件复制到 V2 目录冒充 120/250 日模型；两档工件均保持可移植 JSON 和 `active-bundle.json` 配对。

本批已增加 V2 120/250 日残差动量与市场状态 manifest、251 日有界读取和动态宽度样本 SQLite；公共训练引擎
统一负责一次历史扫描、标签构造、行业拟合、codec 校验和原子发布，`profiles/v2` 与 `profiles/v3` 分别提供窗口、
特征、模型身份、输出根和命令 adapter，互不导入。`./run.sh train-v2` 与 `./run.sh train-v3` 分别训练三头，
训练入口统一按 profile 维护三头工件，不再提供 Tomorrow 专用命令。

完整 `train-v2` 实测扫描 8,058,342 行，产生 6,282,177 个有效样本，三头均扫描 81 个行业并得到
34 个有效行业模型；第二次同输入执行返回 `already_current`。紧凑窗口将峰值 RSS 从原始实测约
2.95 GiB 降至 507,764,736 字节，临时样本 SQLite 峰值 1,815,040,000 字节；V2/V3 revision 失效范围
分别为 250/60 个后续交易日。

本批不实施运行 loader cutover：V2/V3 工件仅作为可验证的离线产物提交，运行入口仍需在后续批次完成来源路径与
feature contract 的配套验证后才可加载。后续 cutover 必须让 loader、性能入口和状态显式选择分档目录，再删除旧目录
和所有临时兼容逻辑，恢复每档一个真相源。

## 12. 历史、训练与荐股应用边界

任务身份：`history_training_recommendation_application_boundaries`

状态：`本批闭合`

历史维护通过 `application/history/{download_history,update_history,history_status,history_ports}.py` 暴露
下载、缺口更新和只读状态用例；`HistoryArchiveGateway` 将两种请求路由到同一个原子同步 owner，避免下载和更新
形成两套 snapshot 发布语义。更新在没有 active snapshot 时失败关闭并返回稳定 `history_archive_missing`，不连接
供应商。训练通过 `application/training/{profile_training_primary,profile_training_secondary,training_due,training_ports}.py` 暴露 V2/V3 独立
运行器和 cadence 端口，entrypoint 只负责组合 profile-owned infra runner；不会自动 promotion、改配置或热加载。
荐股边界（候选、特征、本地评分、模型诊断、风险/融合、排名、冻结和只读 Web/SSE）沿用上一批已验证的独立端口，
本批仅补齐其与历史/训练应用层的单向依赖约束。

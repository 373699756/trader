# 工程实施计划

本文件只维护尚未完成的工程任务、依赖顺序、状态和验收边界。已经完成的交付只保留在 Git、
`CHANGELOG.md` 和必要的 `docs/reports/` 证据中，不在这里重复。

- 候选、过滤、评分、风险、融合、动作和排名规则以[评分逻辑](01_评分逻辑.md)为准。
- 产品、架构、生命周期、数据、API、Web、运维和发布契约以[工程设计](02_工程设计.md)为准。
- 历史下载、训练工件与实时评分的解释性链路见[策略回溯](04_策略回溯.md)。
- 评分权威文档与当前活动源码的逐节实现状态、已修复不一致及剩余缺口见
  [2026-09-10 评分链实现复核](reports/2026-09-10-scoring-chain-implementation-review.md)。
- 依赖、构建和入口以根目录 `pyproject.toml` 为准；批次、Review、测试、提交和推送纪律以
  根目录 `AGENTS.md` 为准。

状态只使用：`in_progress` 表示当前唯一执行章节；`pending` 表示前置已满足、等待执行；
`blocked_*` 表示前置证据或用户授权未满足。普通“继续”只执行表中顺序最前且可执行的一个完整同级章节。

## 2. 当前执行章节：V3 训练工件重建与整组发布

任务身份：`v3_training_artifact_rebuild`

状态：`in_progress`

当前 trainer 已输出扣成本前的基准超额，模型与报告合同固定 `label_target=pre_cost_excess_return`、
`training_cost_bps=0`，20/50/100bp 只由选择和评价层按场景扣除。工程实现现已闭合以下边界：
成本只由选择和评价层按场景扣一次，这项所有权已经闭合。

1. 训练输入只从父加增量 active archive 读取，绑定 active data、父 manifest、increment manifest、动态截止日、
   精确日历和完整代码总体；旧固定目录和 `--allow-partial-history` 不再是训练入口；
2. 训练、校准和验证统一使用扣成本前标签；按代码写入一次性 SQLite，按单日横截面和单行业拟合批次读取，不再
   一次性保留全量 `_Sample`；
3. `training-input.json`、`report.json`、`model.json` 在独立临时目录生成并完成 codec/配对校验，随后原子移动为
   内容寻址 generation，再原子替换
   `active-bundle.json`，由活动指针完成一次原子切换；失败保留上一活动组；
4. loader 继续拒绝旧 schema、partial checkpoint、缺件、篡改和父身份错配；结果继续固定日线工程代理、点时
   不足和无生产权限；重新训练而不是给旧 schema 补字段或放宽 loader。

repository codec、维护进程锁、磁盘预检、控制库旁路重建和故障注入；CLI 当前以
`history_maintenance_status/blocked/history_monthly_archive_pending` 防止重建旧目录；高效日更来源保持阻塞，

## 4. 点时证据修复

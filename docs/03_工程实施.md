## 2. 评分模块化交付记录

原方案在局部拆文件与系统性收敛之间选择了后者：公共层只认识策略能力，不判断 V1/V2/V3 的算法差异；
档位差异集中在 `infra/scoring/profiles/`；训练与生产只共享纯特征计算、类型化合同、模型工件线格式和
内容 hash。该目标架构已经落地，当前主要边界为：

```text
domain/recommendation/model_scoring/         纯残差化、分位与档位身份
application/ports/model_scoring.py           类型化模型评分端口
application/recommendation/model_scoring_router.py
application/recommendation/tomorrow_model_scoring.py
infra/scoring/profile_factory.py             唯一 profile 组装入口
infra/scoring/profiles/{v1,v2,v3}/           各档位 codec、predictor 与证据
```

profile 只组装已经构造完成的能力；codec 只负责 JSON 到不可变类型对象及 schema/hash 校验；predictor
只接受类型化工件和输入并批量推理；locator 只定位工件；composition 只组合预风险模型信号。硬过滤、
DeepSeek、本地风险、固定融合、动作、TopK、冻结、持久化和 Web 投影不进入 profile 目录。

### 3.4 BaoStock 2000 日归档（15.1.38）

目标是截至 `2026-08-31` 最近 2000 个交易所开市日，每只股票最多 2000 个代码-日期逻辑记录；新股、退市股、
停牌股和来源不足按真实有效区间保存，不补造数据。raw/qfq 必须在同一行 `(code, trade_date)` 保存，前复权、未复权
字段不能拆成两条记录。股票应有交易日从上市日起算，不能把新上市股票伪造成缺少 2000 日。`--sessions` 接受 1–2000 且默认 2000，
只有 `--sessions 2000` 可以生成正式 manifest。

归档身份为 `baostock_daily_core`，默认目录为
`data/history/baostock-daily/sessions-2000/`，分片文件位于 `shards/<board>-<code-prefix>.sqlite3`。分片按板块与股票代码前四位存储，每个分库最多 100 只股票，单个
分库损坏时只重新下载该分库（单个分库损坏，只重新下载该分库）；最终只登记 `catalog.sqlite3`、分片和
`manifest.json`，不生成合并总库。所有归档内容均带内容 hash，供恢复和审计复核。
日线分片完整性 hash 只覆盖日线上下文、日线记录、批次和成功 checkpoint；追加行业和训练事实不得改变日线 manifest，
但日线载荷、批次或成功 checkpoint 的任何漂移仍失败关闭。这样第二批只能补齐行业所有权数据，不能隐式重写第一批日线身份。
正式封存先从轻量 checkpoint 索引确认代码终态，再按稳定路径一次只解码一个 SQLite 分片并顺序完成覆盖审计、
日线 hash 和 catalog 组装；不得在收尾前把全部分片日线载荷同时载入内存。单分片完成消费后即可释放，
行业/训练事实仍不进入日线封存内存集合或完整性 hash。
供应商物理坏行数只保留为质量证据；坏行必须被丢弃并落实为对应日期的显式缺失单元，不得伪造 OHLCV，
也不得越过逻辑覆盖率门禁。最终资格由全体、逐板和全窗口老股的逻辑代码-日期覆盖率及其它完整性异常裁决，
不能仅因已被隔离的供应商坏行计数否定达到门槛的归档。

覆盖门禁要求全体和逐板应有代码-日期单元覆盖率均不低于 95%，至少 95% 的全窗口老股各自达到 95% 完整率，
并保留最新 200 日、失败代码、停牌证据和全部 hash。BaoStock 不能证明历史 11:20/14:50 点时、行业或资格
`effective_at`，所以日线合格不能直接打开 Today/Tomorrow/D25 留出或生产权限。

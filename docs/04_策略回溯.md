# 策略回溯：从历史数据到实时荐股

本文回答一个具体问题：历史数据下载了什么，怎样变成训练样本，训练结果怎样参与实时评分，以及哪些因素最终
影响荐股。它是解释性导航，不另立产品或评分契约：评分公式和 D25 定义以[评分逻辑](01_评分逻辑.md)为准，
软件运行和命令边界以[工程设计](02_工程设计.md)为准，尚未完成的历史归档、训练和授权状态以
[工程实施](03_工程实施.md)为准。

本文同时解释已经交付的能力和已确认的目标链路。零参数重构的阶段 A/B/C/D/E 已完成：公开
`download_history` 已删除旧参数，新的不可变控制状态、SQLite repository、维护锁、磁盘预检和损坏重建已交付；
按日期聚簇的月分片、revision、双索引、snapshot 路由、61 日滚动扫描与训练日期缓存也已交付；同步使用
单个受控 BaoStock 子进程完成初次 2000 日、日更缺口、最近 5 日回读、qfq 修订、checkpoint 续传和原子发布；
只读 `history-daily-capability` 已固化来源能力审计。训练入口已经固定为零参数并只读新 active snapshot，
节奏以最后成功 bundle 的 `label_cutoff` 为唯一基线，且三件训练工件和活动指针整组绑定该截止日。旧活动归档实现
和专属测试已在阶段 G 的代码切换中物理删除；用户要求保留的一次性转换脚本已与退役下载链解耦。阶段 G 的完整
门禁与仓库外 wheel 验证已通过；用户明确本批不再处理真实下载，因此本机仍没有可训练 snapshot，真实下载和
重训总验收未闭合，必须以 `03_工程实施.md` 的状态为准。

## 1. 文档边界与结论

先固定九个容易混淆的结论：

1. 用户可执行的离线主链只有一个零参数下载入口和一个训练入口。`download_history` 不接受路径、日数、模式或
   评分档位；当前只维护稳定年月月分片，不会回退到已退役下载链。
2. 历史数据不直接进入每日实时打分。它先离线形成样本，再训练成有 hash 的模型工件；服务启动时加载所选
   Tomorrow 档位的模型，盘中把实时特征送给模型推理。
3. 当前只有 Tomorrow 的 V1/V2/V3 评分档位使用模型。Today 当前是独立规则评分；D25 当前是独立规则评分，
   不读取 Tomorrow 模型；Long 不评分。
4. V1/V2 使用已封存模型，不需要用户下载 2000 日历史或重新训练；三档盘中推理都使用最近至少 61 根 qfq
   日线。最多 2000 日、至少 1250 个共同完整交易日是 V3 离线完整训练边界，不是 V1 的训练要求或盘中窗口。
5. D25 的目标是筛选未来第 2 至第 5 个交易日区间内具备上涨能力的股票。它只输出一个 D25 信号，不拆成
   四个荐股头；T+2、T+3、T+4、T+5 是收益观察点。区间信号不是逐日上涨保证。
6. 下载完成、训练完成、历史验证通过和生产启用是四件不同的事。研究工件保持
   `production_authority=false`、`automatic_model_update=false`，不会自行替换当前档位。
7. 当前 V3 工程试跑仍以 `15:00_close` 作为日线训练代理，而生产锚点是 14:50，所以固定
   `point_in_time_parity=false`。BaoStock 日线不能单独证明 14:50；只有真实分钟来源资格和完整点时数据集
   闭合后，才允许评价生产锚点收益。
8. 点时数据集的构建与逐日封存代码已经具备，但当前三门资格不足时会在读取历史来源前失败关闭，不会生成
   部分数据集。训练、早停、校准、确认可在合格后按日构建；终端留出在这一阶段只封存日期/hash，固定不读收益。
9. 候选召回账本代码已经具备：oracle 每日由全部点时行的成熟 20bp 成本后净超额稳定排序，逐层报告
   Top10/20/50、逐板召回、不可交易、严重亏损、规模和累计延迟。父数据或后续 trace 不完整时整份报告失败
   关闭；当前没有真实点时数据集，所以没有真实召回或收益结论。

## 3. 历史数据下载：下载什么、为什么需要

### 3.1 唯一下载入口与落盘方式

```bash
./run.sh download_history
```

命令不接受任何尾随参数；最多 2000 个交易所开市日、`data/history/baostock` 路径和运行资源都属于有类型配置，
不是用户输入。新股从上市日开始，退市股票到退市生效日前结束，停牌日保留明确状态。阶段 D 已把唯一命令
接到新控制面与月分片：同一命令自动区分初次下载、缺口续传、最近 5 日回读与 `already_current`；供应商失败、
迟到数据和取消只留下 checkpoint，不改变上一 active snapshot；Web 永不触发它。

旧目录、generation manifest 和兼容读取均不进入活动产品。若工作机仍有唯一旧归档，可由用户显式执行
`.venv/bin/python scripts/convert_baostock_history.py`，一次性生成当前控制库和稳定年月月分片；该脚本不会被
零参数同步、服务或训练隐式调用。缺少历史生效/发布时间的行业、资格、硬过滤和风险事实继续保持缺失。

### 3.2 数据项及其用途

| 数据项 | 保存内容 | 在训练/回溯中的作用 | 缺失或用错的后果 |
| --- | --- | --- | --- |
| 交易日历 | 有序、唯一的开市日期 | 定义 D、D+1 和 T+2 至 T+5，建立时间切分与 embargo；防止把停牌后的“下一条记录”误当下一交易日 | 标签错位、跨停牌或上市前穿越 |
| 证券身份与上市/退市日期 | 代码、名称、板块、上市日、退市日、来源版本 | 确定每只股票实际应有的日期范围和主板/创业板/科创板分层 | 新股被补造历史、退市后仍进入总体、板块口径错误 |
| 未复权 OHLCV | 开盘、最高、最低、收盘、成交量、成交额 | 还原当时可交易价格、涨跌停、成交能力、换手和风险；OHLC 用于波动与最大不利变动 | 交易约束、成本、风险和标签无法核验 |
| `preclose`、`pct_change`、`turnover` | 昨收、当日涨跌幅、换手率，仅属于未复权侧 | 校验收益与涨跌状态，构造流动性/拥挤度证据和规则特征 | 动态过滤或流动性判断失真 |
| 前复权 OHLCV | 前复权开高低收、成交量、成交额 | 构造跨日收益、均线、动量、回撤和可比历史序列，避免分红送转形成假跳变 | 模型把除权缺口误学成价格信号 |
| 成交额 | raw/qfq 日线中的 amount | 计算 20 日平均成交额、流动性暴露、容量和 Amihud 成本代理 | 小盘低流动股票可能得到虚高信号 |
| 停牌状态 | `trading` 或 `suspended` | 区分供应商明确停牌与未知缺行；停牌不能当 0 收益或普通缺失 | 覆盖率和下一日标签被伪造 |
| 逐日 ST | 每只股票每个交易日的 `is_st` | 在当日点时资格过滤中剔除 ST，而不是拿今天的名称反推过去 | 产生幸存者偏差和资格时间穿越 |
| 历史行业生效区间 | 行业、分类体系、`effective_from`、`effective_to` | 在当日只使用已经生效的行业；用于横截面暴露处理、分行业模型和集中度评价 | 用当前行业覆盖过去，形成时间穿越；V3 必须失败关闭 |
| 来源版本与查询边界 | SDK/供应商版本、活动 snapshot 的 `source_cutoff` 与发布时间 | 让相同归档可重放，禁止以后悄悄混入更新数据 | 两次训练输入看似相同、实际不同 |
| `coverage` 与异常计数 | 期望/获得单元格、逐板/逐股覆盖、重复、空值、越界、未来行、失败原因 | 决定数据是否有资格形成训练总体 | 不完整数据被误当完整训练集 |
| manifest 与 `content hash` | 日历、股票池、逻辑记录、来源版本、月分片 SHA-256 和 snapshot hash | 把训练、报告和模型绑定到唯一输入；同内容幂等、不同内容冲突 | 无法证明模型到底由哪批数据训练 |

一个逻辑日线单元是“股票代码 × 交易日”，必须同时说明未复权侧、前复权侧以及状态。供应商明确停牌可以
作为已获得单元保存；只有一侧缺失、两侧都未知、数值非有限、日期越界或 raw/qfq 状态不一致都不能伪装成
完整交易记录。

### 3.3 月分片、revision 与 active snapshot

目标读取面由 `control.sqlite3` 和 `partitions/YYYY/MM.sqlite3` 组成。日线按日期主键聚簇，单股索引服务 61 日
查询；每行绑定 revision 与内容 hash。同一 key 同内容重复执行幂等，不同内容写新 revision，不能静默覆盖旧
snapshot。每个月先在旁路构建、校验并通过 rollback sidecar 替换，全部目标月完整后才由控制库原子发布 active snapshot；损坏、中断、
磁盘不足或内容冲突继续保留上一读取面。

阶段 C 已由 `SQLiteHistoryMonthPartitionRepository` 固化月库主键、单股与日期/板块双索引、revision 幂等/冲突、
同步序号到 revision 的不可变观察映射、WAL checkpoint、quick check、行数和整文件 hash；同一内容重新出现时
仍按当次观察序号还原 A→B→A。`SQLiteHistoryMonthlyArchive` 只按 snapshot 引用逐月打开，
提供单日截面、最多 61 个实际交易日的单股窗口和按日期/代码顺序的全量流式读取，每次只持有一个月库连接、
每股最多保留 61 行连续滚动状态。`SQLiteHistoryTrainingCache` 绑定 snapshot hash 并以 `(trade_date, code)`
聚簇临时训练行。阶段 C 没有接入供应商或创建生产归档，阶段 D 才拥有旁路月库写入与 active 发布编排。

更新请求按缺口最小化：已验证 raw/qfq 不重复下载，最近 5 个交易日按行 hash 回读，公司行动只重拉受影响股票
的活动窗口 qfq。行业、历史资格、硬过滤和风险事实只有在供应商能提供真实 `effective_at`、`published_at` 或
可证明查询时间时才写入；无法提供时继续标记缺失，禁止用当前快照回填历史。

### 3.4 覆盖率不是训练资格的同义词

日线下载成功只证明价格记录存在。训练还要求对应日期的逐日 ST、历史行业和其它资格事实具有可验证的
`effective_at`。当前行业名称不能冒充过去行业。归档会分别审计总体、三个板块、每只股票和老股完整窗口；
逐股低于既定 coverage 门槛会被排除，最近交易日还需为点时留出保留。任何必需事实不完整，都返回稳定失败原因，
不补值、不猜测、不打开留出。

资格检查固定拆成日线、历史行业和历史分钟三门，并由一个失败关闭报告汇总。日线门要求 2000 日正式 manifest、
全部代码完成且零失败；行业门要求至少 300 只分层样本及生效/失效/查询时点；分钟门要求至少 95% 分层覆盖、
Asia/Shanghai 的 11:20/14:50 精确 bar、量额、raw/qfq 和公司行动语义。单股下载或连通性测试只验证工程接缝，
不会打开点时数据集、终端留出、训练或生产权限。

## 4. 从归档到可训练样本

### 4.1 点时拼接

对每个历史日期 D，样本只拼接 D 当时已经可见的事实：股票当日身份和板块、D 日或更早的 raw/qfq 日线、
D 日 ST 状态、D 日生效的行业，以及当时可复现的硬过滤证据。历史数据按交易所日历对齐；某股在必需日期
没有实际记录就跳过该样本，不能按数组“下一行”跨过缺失交易日。

样本进入模型前必须同时满足：硬过滤证据完整、该股在 D 日通过硬过滤、特征窗口完整、标签已经成熟且基准
总体可计算。被拒绝的行仍计入 manifest 的拒绝统计，以便区分“源数据不存在”“资格证据不完整”和“明确未
通过过滤”。

工程构建器以生产纯领域 `select_scored` 重建上述每日漏斗，并只保存第一个拒绝边界；候选阈值和每板 120 只
上限发生在基准人口固定之后，所以这两类淘汰行仍参与同点时等权基准。每行绑定统一特征向量、日线/14:50
分钟路径、证券身份、行业和事件事实 hash；`published_at` 晚于锚点的事件直接拒绝。工件按交易日分片并由
根 manifest 绑定父资格、日线归档、特征、日历、证券主数据、选择策略和日期切分 hash，同内容重放幂等，
不同内容或篡改失败关闭。当前资格不足，所以该能力没有生成真实历史数据集或任何收益结论。

`CandidateRecallLedger` 延续同一行身份：永久资格、动态硬过滤、字段资格、候选阈值和每板上限直接使用数据集
边界；只有通过每板上限的行才接收绑定行 hash 的评分、风险、动作、集中度追踪。oracle 从每日全部行按 20bp
净超额降序、代码升序固定 Top10/20/50，逐板指标只是该全市场 oracle 的拆分，跨日以分子/分母微汇总。
阶段尾部率以当层剩余行计算，累计延迟由一致的测量证据 hash 绑定并汇总 p50/p95。未来 outcome 仅用于离线
归因，不能送回候选输入、改变阈值或开启终端留出。

### 4.2 Tomorrow 六个训练特征

当前 Tomorrow 日线训练合同固定为六个 `decimal_return` 特征：

| 特征 | 含义 | 希望捕捉的影响 |
| --- | --- | --- |
| `qfq_return_1d` | 前复权 1 日收益 | 最近一天的延续或反转 |
| `qfq_return_3d` | 前复权 3 日收益 | 极短周期方向与加速 |
| `qfq_return_5d` | 前复权 5 日收益 | 一周尺度强弱 |
| `qfq_residual_momentum_20d_skip5` | 跳过最近 5 日的 20 日动量，经横截面残差化 | 较短趋势，减少市场、板块和流动性共振 |
| `qfq_residual_momentum_40d_skip5` | 跳过最近 5 日的 40 日残差动量 | 中短趋势稳定性 |
| `qfq_residual_momentum_60d_skip5` | 跳过最近 5 日的 60 日残差动量 | 较长趋势背景 |

“跳过最近 5 日”把慢动量与 1/3/5 日短线收益分开，减少同一波动被重复计权。残差化先扣除市场均值，再在
板块内扣除板块均值和 20 日平均成交额暴露；V3 还要求历史行业可用并使用固定行业暴露合同。行业不是一个
可随意正向加分的标签，而是用来控制共同风险及训练分组。

六项公式、依赖和单位由一个 `FeatureSpecCatalog` 声明，训练、在线、codec、回放和 Shadow 按同一个
`FeatureVectorManifest` 绑定向量。慢动量口径固定为 `D-5 / D-{20,40,60} - 1`；缺失就是缺失，不能填 0。
新参数先进入隔离 catalog 和有限参数族研究，只有样本外确认通过后才可成为新的 V3 alpha 输入。

### 4.3 标签：模型究竟学什么

Tomorrow alpha 的日线代理训练标签是：

```text
(股票 close[D+1] / close[D] - 1)
- D 日合格股票总体在 D+1 的等权收益
```

因此模型学习的是“下一交易日相对可投资总体的扣成本前超额”，不是预测绝对股价。ExecutionCost 在验证和
在线选择中再从该预测扣除一次完整往返成本；训练目标不得先扣 20bp 后又由在线门重复扣除。验证同时保存
20bp、50bp、100bp 三档净超额用于准入与压力评价。D+1 必须是交易日历中的下一开市日；标签未成熟或基准
总体为空不生成样本。次日停牌或不可卖不能删除样本：使用同一前复权基准的 mark-to-market，价格缺失时按
第 4.4 节 carry-forward，并保留 `exit_untradable`。

当前工程试跑的标签锚点身份是 `15:00_close` 日收盘代理，而生产 Tomorrow 决策锚点是 14:50，因而工件保持
`point_in_time_parity=false`。日线代理可以验证工程接缝和筛除明显无效方案，但在真正的 14:50
point-in-time 特征、可交易总体与一次性终端留出证据闭合前，不能声称训练/在线完全一致。

### 4.4 可复现的价格、成本、MAE 与留出口径

本节仅解释并复述 `01_评分逻辑.md` 第 12.1 节的权威定义。回溯的进场价是决策时点的
`anchor_price`：Today 为 D 日 11:20，Tomorrow 和 D25 为 D 日 14:50。Today/Tomorrow 的退出价是 T+1
前复权收盘；D25 的退出价分别是 T+2、T+3、T+4、T+5 前复权收盘。进场价与退出价必须转换到
同一前复权基准；raw 价只用于当时的停牌、涨停、跌停和成交可执行性证据。

进场时停牌或一字涨停不进入可执行样本。计划退出日停牌或一字跌停不得删除样本或伪造成交：
主标签用该日有效前复权收盘 mark-to-market，缺失时 carry-forward 上一有效前复权收盘并记录
`exit_untradable`，另报告首次恢复可交易日的延迟退出压力结果。

工程实现以 `OutcomePrice(qfq/raw) + OutcomeTradingStatus` 明确表达价格基准和退出事实；raw 锚点先按推荐日
同一来源、同一交易日的 qfq/raw 收盘比例转换，不能直接除以前复权退出价。供应商两侧窗口不齐时只保留
完整日期交集，缺少任一侧的预期交易日形成 `missing_carried_forward`；禁止跨日、跨源拼接，未知交易状态
或无法完成同源换算则保持 `insufficient_data`。

```text
gross_return_h = (exit_price_h / entry_price) - 1
net_excess_h = gross_return_h - benchmark_return_h - round_trip_cost
d25_aggregate = (net_excess_T2 + net_excess_T3 + net_excess_T4 + net_excess_T5) / 4
```

D25 必须同时报告四个 horizon 和算术平均。基准身份为
`point_in_time_local_only_equal_weight`：只使用同一历史时点资格、硬过滤、必需字段和进场可执行性都完整的股票，
按股票等权。成本是每个 horizon 只扣一次的完整往返成本：20bp 是主评价成本；50bp 是准入稳健性门；
100bp 只用于压力测试，不是优化目标。

不利波动在进场至目标退出区间按同一前复权基准计算：

```text
MAE = min((low[t] / entry_price) - 1)
MAE/ATR20 = MAE / (ATR20_at_entry / entry_price)
```

MAE 与 `MAE/ATR20` 必须不大于 0；Today/Tomorrow 统计进场至 T+1，D25 统计进场至 T+5 并可分 horizon 报告。
终端留出在点时一致性、训练/确认门禁、增量同源等价、完整风险/成本/不确定性/DeepSeek/融合/动作/TopK
选择链、日期身份与“候选规范与父 hash 已冻结”都成立前，
必须保持 `terminal_holdout_not_opened`。满足条件后只允许原子地打开一次；竞争或第二次打开返回
`terminal_holdout_already_opened`，不得更换候选或覆盖报告。

## 5. Tomorrow 如何训练与验证

### 5.1 唯一训练入口

```bash
./run.sh train-tomorrow
```

目标训练只接受完整、hash 校验通过的 active snapshot；不会隐式下载数据，也不接受 partial checkpoint 参数。
阶段 C 已提供月分片读取面；阶段 D/E 将依次发布 active snapshot 并把训练入口接入。当前没有 snapshot，所以训练失败关闭。
训练和下载仍是两个显式离线动作：训练不会补采数据，下载也不会自动启动训练。

### 5.2 时间切分与防穿越

数据始终按交易日排序，禁止随机拆分。完整链最多消费 2000 个交易所开市日，至少需要 1250 个共同完整交易日，
并按顺序形成训练、早停、校准、确认和留出：开发段内部最后 20 日用于早停、再后 20 日用于校准；开发与确认、
确认与终端留出之间各保留 5 个交易日 embargo；确认段至少 200 日，最新至少 200 日只预留给 point-in-time
终端留出。训练/确认后还必须固定增量计算等价性及完整风险、成本、不确定性、DeepSeek、融合、动作与 TopK
选择链，才允许原子开启终端留出一次。

模型、阈值或特征必须在读取对应评价收益前固定。留出打开后不能因为结果不好更换候选再重看同一窗口。
评价包括 Rank IC、分位单调性、Top10/20/50 与 Top6 净超额、20bp/50bp 成本、严重亏损率、最大回撤、
换手、容量和板块/行业集中度；合法空仓按现金组合结算。

### 5.3 模型与产物

V3 的 Tomorrow 训练按历史行业形成模型，使用 Ridge 与浅层 LightGBM 的 50/50 集成。Ridge 提供稳定线性
基线，LightGBM 捕捉有限非线性和特征交互；早停、校准和确认防止只记住训练期。模型文件还封存特征名称、
顺序、单位、预处理参数、行业覆盖、依赖版本、snapshot hash、训练日期范围和模型 hash。

训练目标、早停、校准和验证统一使用 `training_alpha_target()` 生成的扣成本前超额收益；raw `next_return`
只保留为 outcome/benchmark 诊断，不得混回模型标签，也不得预扣成本后再由在线成本门重复扣除。样本按股票或
日期分批/流式构造，保持特征顺序、单位、残差化规则和稳定排序不变，避免把全量 `_Sample` 长期驻留内存。

训练器只消费已经通过数据资格、候选召回和有限参数族确认门的 alpha manifest。每个训练日期必须先按当日
可见事实重建生产同源人口：一级资格、动态硬过滤、评分字段资格、板内总体、候选阈值和每板上限都必须留证；
不能只用 `非 ST + 当日有交易` 代替完整生产漏斗。字段年龄、来源一致性和
缺失率只决定数据资格；行业/板块/成交额默认只用于暴露处理；风险、不确定性和成本分别留给风险与执行模块；
未来 outcome、oracle 排名和留出结果绝不能成为特征。这样“增加股票参数”不会退化成盲目堆字段。

一次训练以 active snapshot 和训练输入 hash 派生审计身份。训练器在独立临时目录生成：

- `model.json`：实时推理真正加载的参数和特征合同；
- `report.json`：训练/验证状态、指标和失败原因；
- `training-input.json`：可复核的 snapshot、训练股票集合和输入身份。

三个文件的 active data、snapshot、来源、特征、切分、训练合同和模型载荷身份全部通过
codec/hash 配对后，临时目录才原子移动到 `data/train/tomorrow-v3/generations/<bundle-hash>/`，随后仅原子替换
`active-bundle.json`。任一生成、校验或切换步骤失败时保留上一活动组；已经移动但尚未切换的 generation 不会被
运行时消费。不得给旧 schema 直接补字段，也不得放宽 loader 伪造兼容。显式选择 V3 后，实时评分只读取活动组
中的 `model.json`；
另外两个 JSON 不直接参与算分，但必须作为加载前的配对证据存在。

`historical_validated` 只能由一次性终端留出完整报告产生，不能因模型文件存在、验证行数非零或 codec 可加载
就设置；工件必须保留点时一致性、完整选择链身份、评价指标、失败原因和生产权限字段。研究状态即使达到历史验证，
也固定 `production_authority=false` 和 `automatic_model_update=false`。训练命令
不会改默认配置，不会自动切换 V1/V2/V3，不会向正在运行的服务热注入模型。

## 6. 训练结果如何参与实时荐股

### 6.1 参与的是模型工件，不是历史数据库

服务启动时根据用户选择的 Tomorrow V1/V2/V3 profile 加载相应 `model.json`。当前 `train-tomorrow` 只生成
V3 训练工件，不重训或覆盖 V1/V2；V1/V2 使用各自封存的模型，因此不要求用户为 V1/V2 下载训练历史。
V3 只有在用户显式选择且训练工件存在时才
加载。codec 会校验模型身份、content hash、特征顺序/单位、暴露
合同、行业模型和输入覆盖；缺少或篡改时失败关闭，不暗中换回其它模型。

可加载只表示该模型能够参与显式 V3 的 Tomorrow 工程评分，不等于取得生产权威。在真实点时资格、风险事实、
终端留出、Shadow 和用户授权未闭合时，模型与报告必须保持 `historical_data_insufficient`、
`point_in_time_parity=false`、`production_authority=false`；默认 V1 不变。

盘中服务不读取 BaoStock 训练分片、不执行拟合，也不在评分线程同步下载历史。它从生产行情链取得当前报价和
已经预热或持久化的最近至少 61 根历史日线，构造与
profile 相符的实时特征。这样既避免把慢速研究 I/O 带入荐股时延，也避免服务在用户不知情时改变模型。

### 6.2 单次实时评分顺序

1. 合并全市场快照、定向报价、证券身份、交易日历和历史特征，拒绝过期、未来或来源身份不一致的数据。
2. 先执行一级资格和二级动态硬过滤；只有合格候选进入板内横截面和每板最多 120 只预选。
3. 检查模型输入完整性。Tomorrow 至少需要所选 profile 的特征，V3 还要求行业落在训练工件覆盖中；缺失者
   记录原因，不以中性分冒充模型预测。
4. 对同一批候选执行与训练一致的市场/板块/成交额残差化；V3 同时执行固定行业暴露处理。
5. Tomorrow 与 Today/D25 一样，先按板块证据质量权重合成具有固定 0/50/100 锚点的 `base_score`；所选
   profile 的 predictor 另行产生预期超额和诊断，其中 V3 对每个行业执行 Ridge/LightGBM 集成，并用两者
   差异表示模型分歧。预测横截面分位只作为模型相对信号诊断，不覆盖 `base_score`，也不单独决定动作门槛。
6. 根据 20 日 Amihud 流动性分位估算交易成本，执行“预测超额收益 - 估算交易成本”门。净效用不为正时
   可以形成合法成本空仓；成本门不能反向篡改模型信号分。
7. 本地已知风险从 base score 扣一次，得到 `local_score`。之后可选 DeepSeek 只复核结构化候选事实；本地
   规则映射经 schema/证据验证的模型风险事实，自由文本不能直接扣分。
8. hybrid 固定为：

   ```text
   clamp(local_score * 0.68
         + deepseek_score * 0.32
         - deepseek_risk_penalty, 0, 100)
   ```

   最终按 `ROUND_HALF_UP` 保留两位小数；`local_score` 已扣本地风险，融合时不得再扣一次。
9. 分数经过正式/观察动作门槛、5 分升级余量、稳定排序、Top6、单板最多 60% 和同一行业最多 2 只约束。
10. Tomorrow 在 14:50 冻结正式结果。冻结后模型迟到结果不能覆盖同日正式记录；Web 只读展示已经发布的
    current/history，不在 HTTP 请求里抓行情、训练、评分或调用 DeepSeek。

### 6.3 为什么训练好不等于实时一定推荐

模型只负责 Tomorrow 的预测超额、相对信号诊断和成本净效用门，不负责生成统一 `base_score`。股票仍可能因
退市/ST、上市期、停牌、价格、涨停不可执行、成交额、换手、历史完整性、模型输入缺失、成本净效用不正、
本地风险、动作门槛或集中度限制而不进入 Top6。
外部行情或 DeepSeek 失败时，本地推荐仍可发布并标记降级；没有任何候选满足门槛是合法业务空集。

## 7. Today、Tomorrow、D25 的关系

| 策略 | 目标与冻结 | 当前 base score 来源 | 历史训练数据当前怎样参与 |
| --- | --- | --- | --- |
| Today | 面向 T+1，11:20 冻结 | 板块规则权重 | 不加载 Tomorrow 模型；历史短窗只用于规则特征和风险 |
| Tomorrow | 14:50 到下一交易日收盘的成本后净超额，14:50 冻结 | 板块证据质量权重；模型另作预测诊断和成本门 | 通过离线训练形成模型工件，盘中用实时输入推理 |
| D25 | 未来 T+2 至 T+5 区间的上涨能力，14:50 冻结 | 独立 D25 规则权重与入场质量 | 当前不读取 Tomorrow 模型；历史序列只用于 D25 规则、风险及回溯评价 |
| Long | 固定长期池当前行情 | Long 不评分 | 不训练、不冻结、不写推荐历史 |

Today、Tomorrow 和 D25 的模型所有权不同，但盘中必须消费同一个最新完整交易日、`DailyFeaturePack`、
`MarketEpoch` 和 data revision；mixed-epoch 或 stale-data 必须失败关闭，不能让三个策略混用不同批次行情。
Long 只读取同批最新报价展示，不参与评分或历史冻结。统一数据快照不代表 Today/D25 复用 Tomorrow V3 模型。

D25 当前是独立规则评分：趋势关注均线结构、斜率和突破，质量价值综合质量/价值/成长，量价流动综合 20 日
成交额分位、换手和成交额，入场质量取缩量回踩与放量突破较高值；过热只进入审计和风险，不作为正向加分。
随后与 Today/Tomorrow 一样经过本地风险、可选 DeepSeek、固定融合、动作、TopK 和冻结。

D25 的历史评价分别结算 T+2、T+3、T+4、T+5 收益，并可用四点算术均值描述区间综合表现，同时检查
T+1 至 T+5 最低价、MAE、严重亏损、换手、容量和集中度。未来若训练独立 D25 模型，必须另立数据、标签、
验证和人工授权批次；不能把 Tomorrow 模型改名后直接复用。

## 8. 影响最终荐股的因素

| 因素 | 影响链条 | 为什么重要 | 约束 |
| --- | --- | --- | --- |
| 数据时效与完整性 | 来源 → 特征资格 | 过期报价或缺历史会让分数与当前市场脱节 | 缺失显式降级，不能伪造 |
| 证券资格与可执行性 | 两级硬过滤 | ST、停牌、涨停不可买等股票即使信号高也不能执行 | 硬过滤先于评分 |
| 1/3/5 日收益 | Tomorrow 模型 | 反映极短周期方向、加速与反转 | 使用前复权并与训练单位一致 |
| 20/40/60 日残差动量 | Tomorrow 模型 | 反映不同趋势尺度，同时减少市场/板块/流动性共振 | 必须按同批横截面处理 |
| 行业、板块和成交额暴露 | 训练与在线标准化 | 防止模型只偏好某轮行情、某板块或高流动性股票 | 历史行业必须有生效时间 |
| Ridge/LightGBM 分歧 | 模型置信信息 | 两类模型意见分散时，置信度较低 | 不得把分歧隐藏成高确定性 |
| 流动性与交易成本 | 执行门 | 毛预测可能不足以覆盖冲击和往返成本 | 净效用不正允许空仓 |
| 本地风险 | local score | 回撤、波动、过热、缺失或其它已知风险降低可执行吸引力 | 只扣一次，最高有界 |
| DeepSeek 结构化复核 | hybrid 升级 | 补充五维语义复核，但依赖外部服务和证据质量 | 不能由自由文本直接扣分 |
| 动作门槛与升级余量 | 推荐/观察 | 控制弱信号进入正式池及异步升级抖动 | 不是收益已最优证明 |
| Top6 与集中度 | 最终组合 | 限制单板、行业过度暴露，改善组合分散 | 可能牺牲部分原始高分，需回溯衡量 |
| 冻结时点 | 正式历史 | 决定当日哪一个点时结果可被验证 | 冻结后 first-wins，不接受迟到覆盖 |
| 市场状态漂移 | 训练 → 实时 | 历史关系在新市场环境可能减弱或反转 | 监控漂移，禁止在线自动重训 |

这些因素相互串联，不应只看一个模型分数。例如“高预测分位 + 高成本 + 高风险”可能仍不推荐；“中等模型
分位 + 低成本 + 低风险”也不保证越过正式动作门槛。正确回溯对象是完整决策链及其成本后组合结果。

## 9. 失败、降级与不会发生的行为

- 下载失败：active snapshot 不变，只保留耐久 checkpoint，下次仅重试未成功缺口；供应商错误、日线
  缺失和事实未就绪分别报告，失败请求不得写成成功。
- 月分片或控制库不完整、损坏或同一 key 内容冲突：保留上一有效读取面并失败关闭，不把部分覆盖伪装成
  正式输入；训练不存在部分历史工程试跑例外。
- 训练或验证失败：保留上一组有效的 model/report/input，另报告稳定失败原因，不生成自动晋级，不修改默认档位。
- 模型工件缺失、hash 不匹配或特征合同不符：所选 profile 启动失败关闭，不静默切换另一模型。
- 实时行情失败：保留最近有效快照并标记降级；Web 请求本身不会触发补抓、训练或评分。
- DeepSeek 失败或预算耗尽：本地推荐继续，不阻塞冻结；风险自由文本不生效。
- 冻结后迟到：today 11:20、tomorrow/d25 14:50 的正式记录不可覆盖，避免用事后信息改写历史。
- 不会在线自动训练、自动调参、自动 promotion、自动切换 profile，也不会让线上 T+1 结算回灌训练。

## 10. 操作顺序与结果判读

先运行不写归档的来源能力门：

```bash
.venv/bin/python -m scripts.diagnose_runtime --profile history-daily-capability --output -
```

当前可以执行零参数同步；全新根下载最近 2000 个完整交易日，已有 active snapshot 时补缺口并回读最近 5 日，
相同 cutoff 和身份返回 `already_current`。训练命令仍只消费完整活动读取面并整组发布，随后性能检查和显式 V3
启动属于后续独立运行验收章节：

```bash
./run.sh download_history
./run.sh train-tomorrow
.venv/bin/trader-cli --config "$PWD/config/runtime.json" --profile v3 performance-check
TRADER_PORT=5051 ./run.sh --profile v3
```

仍只有一个下载入口和一个训练入口：第一条只读诊断不落盘；下载以 `history_maintenance_status` 投影
`completed/already_current/already_running/cancelled/failed/blocked` 及稳定原因。本机没有活动 snapshot 时训练会
返回 `history_manifest_unavailable`，不会改写现有工件或冒充已使用新增数据。下载结束看复用/新增请求数、
失败原因、字段覆盖、cutoff 与 snapshot hash；训练结束看三件工件的 schema、配对 hash、数据范围和失败
原因。全局健康检查仍使用 `./run.sh check`，其内部只读研究状态，不会增加下载或训练动作。

工程人员可运行只读能力门：`.venv/bin/python -m scripts.diagnose_runtime --profile
history-daily-capability`。2026-09-10 实证为：Tushare 120 积分的 3 只样本 raw 3/3 成功，但 qfq/复权因子不可用，
且停牌不返回行；腾讯 raw/qfq 3/3 成功但只能逐股调用，没有全市场单日、停牌、代码变更与完整 cutoff 合同；
东财 0/3；BaoStock 登录在 8 秒硬超时内未完成。按 5453 只、2 秒最短间隔，单面至少 5453 次、
10,904 秒，raw+qfq 至少 10,906 次、21,810 秒，尚未计日历、总体、行业、重试和传输。故阶段 A 选择 BaoStock
作为正确性基线与慢速兜底，但没有候选通过高效日更门，高效日更来源保持阻塞，不能把腾讯小样本或 Tushare raw
冒充训练完备来源。供应商合同依据为 [Tushare A 股日线](https://tushare.pro/document/1?doc_id=27)、
[Tushare 复权因子](https://tushare.pro/document/2?doc_id=28) 和
[BaoStock 下载接口说明](https://github.com/zxygithub/baostock/blob/master/docs/data_download_plan.md)；历史行业、
分钟锚点和完整 point-in-time 资格仍是独立 blocker。

阶段 B 至 D 完成后，日常 `check` 只对控制库、命中月分片、WAL 和内容摘要做有界只读检查并投影 checkpoint，
不重复 SHA-256 全部历史库；训练输入打开仍完整验证 snapshot 引用的整文件 hash，不迁移旧数据。

结果判读顺序应为：

1. 控制库与命中月分片是否完整，是否形成 hash 有效且不倒退的 active snapshot；
2. 逐日 ST 与历史行业是否在各自日期有效，训练总体是否就绪；
3. 特征、标签、切分和成本口径是否与预注册合同一致；
4. 确认与留出收益、严重亏损、回撤、换手、容量和集中度是否一起过门；
5. `model.json`、`report.json`、`training-input.json` 与 active snapshot 是否整组配对；
6. 工件是否仍为研究状态，是否获得单独的用户生产授权；
7. 启动时所选 profile、加载的模型 ID/hash 和在线特征合同是否一致，Tomorrow 是否确实使用 V3 且没有回退；
8. 当日从过滤、模型分、成本门、风险、DeepSeek、动作到 Top6 的每个拒绝原因是否可解释；
9. 冻结记录是否保持点时不可变，后续结果只做收益结算而不反写模型。

因此，“下载完成”不能简写成“模型已经可用”，“训练完成”不能简写成“模型已经能赚钱”，“模型分高”也不能
简写成“最终必然推荐”。只有把数据身份、点时样本、样本外收益、生产授权、实时输入和完整决策漏斗逐环节
对齐，才形成可审计的策略回溯闭环。

## 11. 新优化路线如何形成证据闭环

唯一顺序是：统一 outcome → 统一特征合同 → 点时数据资格 → 点时数据集 → `CandidateRecallLedger` → 有限
参数族研究 → V3 训练与开发/确认 → 增量同源计算 → 风险/成本/不确定性与 DeepSeek 消融 → 完整选择链冻结 →
一次性终端留出 → Shadow。
统一 outcome 回答“历史上实际发生了什么”，统一特征合同回答“当时真正看到了什么”；点时资格和数据集阻止
15:00 收盘价冒充 14:50，也不得恢复未来日 collector。之后召回账本才回答“好股票第一次在哪一层被丢掉”，
有限参数族研究回答“哪个新增信息在样本外真正贡献成本后收益”，通过确认的 alpha 才进入 V3。增量计算只
改善相同输入的时效，不改变向量；不确定性和 DeepSeek 消融回答“减少尾部损失的代价是什么”。

最后的 Shadow 仍不改变正式推荐，只把候选、特征、alpha、风险、成本、不确定性、延迟与成熟 outcome 连成
可审计证据。不会使用不可靠主力资金、社交热度、DeepSeek 自由文本直接扣分，也不会自动训练或自动晋级；
任何生产变化必须由用户明确授权。因此该路线提高的是结论可信度和发现有效改进的概率，而不是提前承诺收益。

`Regression-Key: zero-argument-history-snapshot-training-alignment`。

### 12.1 Review 结论与被拒绝方案

二次 Review 后，以下约束必须同时成立：

1. 拒绝 `单个巨型 SQLite` 和按板块拆成三个大库。训练的主要访问维度是交易日，板块数据量也不均衡；两种
   方案都会放大单文件损坏范围、维护锁竞争和重建成本。目录精简不等于把所有责任塞进少数大文件。
2. 2000 日只定义活动研究窗口，不等于模型必须拟合全部 2000 日，也不应让活动窗口无限增长。物理旧行和旧
   snapshot 可保留用于复现，最新训练读取面始终是滚动 2000 个完整交易日。
3. BaoStock 日线按股票请求且必须限速，逐日执行与累计约 20 日再执行的股票请求数量接近；允许日更，但不能
   宣称日更天然高效，更不能把每日完整训练设为默认行为。
4. 下载不得隐式触发一至两小时训练，训练也不得热替换运行中模型。数据发布、训练发布和服务启用继续是三个
   独立原子边界。
5. 以当前 5453 只总体和最短 2 秒逐股间隔计算，单轮至少 `5453 × 2 秒约为 3 小时`，还未包含登录、重试和
   raw/qfq 多次查询；因此每天触发不等于每天全市场逐股重拉，日更前必须先过批量来源能力与同源门。
6. “20 日”只能数活动模型之后新增且标签已经成熟的交易日，不能数自然日、下载次数或日线 cutoff；失败训练
   不能清零。生产合同仍固定禁止自动训练和自动切换模型，所以本计划默认自动日更、到期提醒、人工零参数训练。
7. 自动化不能塞进盘中生产调度器或 HTTP；它必须由操作系统在独立进程触发，并处理休眠补跑、重复触发、
   上海时区、资源上限和可撤销安装。
8. 月分片之外还必须处理控制库单点损坏、磁盘写满、旁路空间、SIGTERM、通知失败和供应商迟到发布；这些都要
   有稳定状态，不能被笼统记为下载失败。

时间有序训练、验证和真正样本外测试用于防止未来数据进入过去；候选窗口与重训频率必须用 walk-forward 证据
选择，不能以单次回测最佳值拍板。参考 [Empirical Asset Pricing via Machine Learning](https://academic.oup.com/rfs/article/33/5/2223/5758276)
的时间分割与周期性重估方法，以及 [TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)
对时间顺序和 gap 的约束。

### 12.2 唯一命令和稳定目录

`./run.sh download_history` 是唯一历史维护入口；它不接受 `--runtime-dir`、`--sessions`、`--mode` 或 `--profile`，
任何尾随参数都必须在创建环境、联网和写文件前失败。路径、2000 日活动窗口、单 worker、调用
超时、重试和限速由一个有类型的离线研究配置所有，测试通过依赖注入替换路径，不再把生产参数暴露给用户。
运行期间 stderr 持续输出紧凑单行：阶段与状态标明当前登录、日历、证券总体、行业、raw、qfq、股票或月份；
真实股票/月分片进度用 `n/m (百分比)`，重试用“尝试 n/m”，累计与调用耗时用 `HH:MM:SS`。行业子阶段显示的是
当前快照日期，不把内部 `0/1` 占位冒充整体下载进度；失败摘要保留具体阶段、当前项和稳定错误码。供应商等待每 5 秒
产生内部心跳，但交互终端只在一只股票完成、重试或失败时打印。最终 `history_maintenance_status` 仍单独输出到
stdout，便于脚本消费。
在上下文加载或逐股下载时按 Ctrl+C 都返回受控 `cancelled`，不会打印 Python traceback 或移动活动指针。

目标目录固定且有界：

```text
data/history/baostock/
├── control.sqlite3
└── partitions/
    ├── 2018/
    │   └── 01.sqlite3
    └── YYYY/
        └── MM.sqlite3
```

`control.sqlite3` 只拥有交易日历、证券总体、来源身份、同步 checkpoint、活动 snapshot 与逻辑内容 hash；行情与
有生效时间的事实按自然年目录、自然月分片，路径合同为 `YYYY/MM.sqlite3`；SHA-256 保存在控制库引用中，不进入文件名。运行时允许 SQLite 自身 WAL/SHM 和
一个进程锁；替换已有稳定月文件前临时保存固定名 `.MM.rollback.sqlite3`，发布失败立即恢复，异常退出由下次维护
按 active hash 恢复或清理，成功发布后删除。该 sidecar 不是归档读取面或 generation。正常结束必须完成
checkpoint，不能再产生业务 generation 目录。目标实现只保留控制库与稳定年月
月分片；旧目录、旧活动指针、legacy、迁移、subset workaround 和对应测试均已删除。
保留的一次性转换脚本可把其自身已完成的 hash 子目录结果原地归一化为稳定年月文件：先核对旧控制身份、来源、
分片 hash 和行数，再准备并验证新控制库，移动月文件，最后原子切换控制库；中断后重复同一命令继续。该能力不进入
活动训练或同步读取链，不保留两种布局，也不重新下载已经验证的数据。若已发布归档仅剩 qfq 缺口，联网重跑
转换器会逐项请求 BaoStock：能返回 qfq 的代码（包括按确认生效日查询历史代码的更名证券）直接采用供应商结果；
仍明确标记 `supplier_adjustment_unavailable` 的上市初期记录，以同源 raw、随后首个有效 qfq 锚点和
BaoStock 官方涨跌幅复权算法按六位因子反向递推。修订只写受影响月份的新 revision，利用 rollback sidecar
恢复失败发布，并在全部封存校验后原子发布新 snapshot；禁止直接 SQL 覆盖、混入其它来源因子或修改旧 revision。

月库的规范行情表以 `PRIMARY KEY (trade_date, code, revision_id) WITHOUT ROWID` 聚簇存储，revision 只作为末位
身份，不改变日期主顺序；另建立 `(code, trade_date)` 单股索引和 `(trade_date, board, code)` 截面覆盖索引。
BaoStock 虽逐股返回数据，但下载顺序不决定物理布局；旁路构建
月库时先批量写入再校验索引。查询路由用交易日起止范围计算月份，只打开命中的月库：单日截面只读一个库，单股
61 个实际交易日窗口通常只跨少数连续月库，完整训练则按月份、日期、代码顺序流式扫描，不做全目录盲扫，也不做
“全部股票 × 全部月份”的逐股小查询。扫描时为每只股票仅保留最长 61 日滚动状态，每日结束即构造当日横截面；
训练样本缓存同样按 `(trade_date, code)` 存储，直接服务残差化、时间切分和顺序拟合。进程只维持有上限的只读连接，
跨月结果使用相同字段顺序；月分片只是物理故障边界，业务唯一键仍是无顺序含义的 `(code, trade_date)`。

每条数据绑定同步序号与行 hash。下载可以逐月提交耐久 checkpoint，但训练只读取 `control.sqlite3` 已原子发布
的活动 snapshot；任一目标月未完成、供应商失败、内容冲突或进程中断都不能切换活动指针。未发布 revision 即使
已经落入月库也不可见，后续修订同样写新 revision，旧 snapshot 仍按自身同步序号复现，禁止原地静默覆盖。
每个月库单独保存内容 hash 并执行完整性检查；常规更新在旁路构造完整替换库，验证后才切换，失败时活动
snapshot 继续读取原文件；未变化月份直接复用旧不可变引用，不每天复制并重封全部窗口。若活动月库本身损坏，归档查询和新训练必须显式失败，线上运行继续使用既有模型 bundle；
该月旁路重建并验证完成后才能恢复归档，不得用不完整数据降级训练。月分片缩小的是故障和校验范围；由于 BaoStock
仍需逐股票请求，重拉全市场某个月的耗时下限主要由请求次数和限速决定，不能按文件体积推断会同比缩短。

写入前必须校验磁盘余量至少覆盖目标月完整旁路副本、SQLite 临时空间和训练工作库；不足时不改活动指针。
月库保存可独立校验的来源、日期、revision 与内容摘要，控制库损坏时只能由已验证月库重建索引和最近完整
snapshot，重建完成前禁止下载发布和训练。进程锁覆盖手工与定时任务；竞争者返回 `already_running`，不删除锁。
收到 Ctrl+C 或 SIGTERM 后停止发起新请求、在 10 秒宽限内回收 SDK 子进程并落耐久 checkpoint，超时则退出并由
下一次触发续传，不能把未尝试股票写成失败。

### 12.3 初次下载、日更和复权修订

命令根据状态自动选择且不再要求用户选择模式：无归档时建立最近 2000 个已完整发布交易日；有归档时补齐到
供应商已经完整发布的最新收盘交易日；数据和身份均未变化时返回 `already_current`。同日重复执行保持幂等，
未完整发布的当日数据不能成为新 cutoff。每次同步同时重读最近 5 个交易日并比较行 hash，捕获供应商迟到修订；
证券总体变化时，新上市证券从上市日补齐，退市证券保留既有历史并停止生成退市生效日后的预期记录。

活动 snapshot 始终选择最近滚动 2000 日；为了复现已发布模型，旧 snapshot 引用的物理行不随窗口前移立即
删除。将来只有在没有活动模型、研究报告或留出引用时，才能由独立 Review 的回收策略删除旧 revision，本计划
不增加隐藏自动清理。

归档继续保存供应商明确返回的 raw 与 qfq；仅上述一次性已发布归档补缺允许使用已由 BaoStock 官方文档证明、
且由同源 raw 与 qfq 锚点闭合的公式，不得扩展为一般自行推导。同步先读取每日复权因子识别发生公司
行动的代码：普通代码只补缺口，受影响代码重新拉取活动窗口 qfq 并写新 revision；固定除权样本必须证明更新后
收益连续、raw 交易约束不变且训练读取与供应商 qfq 一致。行业、ST、上市/退市和停牌事实同样按生效时间更新，
不能用当前快照回填过去。

日更来源能力门必须先用真实数据证明候选来源能在有界批次中返回全市场当日 raw，以及可信 qfq 或可验证复权
因子，并在普通日、停牌、除权和代码变更样本上与训练源同单位同语义。通过后，日常只写当日/月内 delta，
每 20 个成熟标签日再用 BaoStock 批量复核活动窗口；没有来源通过时只能使用 BaoStock 逐股夜间同步并如实显示
预计耗时，不能用未经证明的数据换取“日更”速度，也不能宣称已经实现高效日更。

操作系统每天在 `Asia/Shanghai 15:10` 调用零参数下载，`Asia/Shanghai 20:30` 无条件再触发一次幂等检查；命令
先确认交易所开市日、供应商完整 cutoff、活动 snapshot 和 checkpoint。首轮已完整发布则返回 `already_current`
且不再逐股联网，首轮仍运行则返回 `already_running`；失败、未执行、未完整发布或中断则只补缺口，绝不重下
已经验证的内容。休市且无历史缺口时返回稳定 no-op。
Web、HTTP 和盘中生产调度器永不触发这条离线链；日常盘中评分继续使用生产行情与历史预热，不等待离线归档。

### 12.4 2000 日怎样进入训练

2000 日是为 60 日特征预热、开发、确认、embargo 和终端留出共同准备的归档窗口，不是一个需要全部拟合的魔法
数字。开发区内预注册 750、1000、1250 三种最近窗口，用滚动前推比较成本后净超额、严重亏损、回撤、换手、
容量、板块/行业稳定性和模型漂移；约 250 日确认区与约 250 日终端留出不得参与窗口选择，窗口之间继续保留
至少 5 日 embargo。只有多个连续前推窗口稳定通过的训练跨度才能写入最终训练合同。

全市场交易日历是唯一日期主轴，2000 日是全局日期集合，不要求每只股票都有 2000 行。证券的预期日期只能是
交易日历与其 `[上市日, 退市生效日)` 的交集；上市前日期不造空行、不补零、不前向填充。退市股票在退市生效日前的历史继续保留。
停牌日按点时交易状态表达，不能当作未上市或凭空合成可交易行情。特征和标签一律按
`(code, trade_date)` 连接，并用交易日历寻找前后交易日，不允许按某只股票的第 N 行做位置对齐。

新股先进入覆盖统计，达到至少 61 个实际有效交易日且点时资格、字段和标签齐全后才产生训练样本；缺少必要观测
时丢弃该样本并记录原因，不能借用别的股票日期或跨越停牌补值。横截面计算只纳入该日已经上市、尚未退市且符合
点时资格的股票。同一交易日的全部股票必须进入同一切分，不能让同日截面一部分进入训练、一部分进入确认或留出；
因此新股自然只在较晚日期贡献样本，不需要把每只股票强行拉齐到相同行数，也不会产生当前成分股回填历史的幸存者
偏差。

20 日计数的唯一基线是活动模型成功训练所绑定的 `label_cutoff`；归档用全市场交易日历找到已有完整 T+1 outcome
的最新日期，计算两者之间不同交易日数 `matured_label_days_since_training`。无活动模型为
`initial_training_required`，每新增 20 个标签成熟交易日即记为 `cadence_due`，影响活动输入的旧日修订为 `input_revision_due`，
归档/标签/点时资格不完整为 `data_incomplete`。只有成功发布新训练 bundle 才能清零；下载失败、提醒已发、训练
开始或训练失败都不改基线；前三种可训练到期原因统一投影 `training_due=true`。5、20、60 日节奏仍用
walk-forward 比较，未有新证据前固定 20。

`download_history` 只投影数据 hash、两个 cutoff、成熟日计数、due 状态和原因，不会自动启动训练。

`./run.sh train-tomorrow` 是独立零参数入口，不接受路径、profile 或阶段参数。它只在
initial/cadence/revision due 且输入完整时固定一个活动 snapshot；未到期返回 `not_due`，相同身份已有完整 bundle
时返回 `already_current`。训练样本按交易日缓存，新增数据只构造新日期；历史 revision 只失效受影响日期前一日的
T+1 标签、受影响日期及其最长 60 日特征依赖范围。模型拟合仍完整、确定性重建，不保留不可复现的在线增量模型状态。
训练应在盘后或非交易日手工启动，固定两个计算线程、2048 MiB 峰值 RSS 门和独占训练/下载互斥；内存、训练
旁路磁盘或活动 snapshot 不满足时写明 blocked 原因，不与盘中服务争抢资源，也不从半成品续接模型拟合。

训练命令启动后立即在 stderr 显示固定资源策略；随后按输入分片、历史行、横截面样本、行业模型和工件发布持续
显示真实 `n/m`、两位百分比及累计 `HH:MM:SS`。历史行同时显示已生成有效样本数，日志不显示 RSS；阶段推进
按 30 秒节流，60 秒无推进仍重复当前计数，因而相同 `n/m` 表示进程存活但当前工作单位尚未完成。训练读取器先对
活动 snapshot 的每个月分片完成且只完成一次 hash、`quick_check` 和行数验证，再复用该信任结果计数及逐股读取；
不得为每只股票重新校验全部 25 GB 分片。Ctrl+C 清理一次性样本库和未发布 staging，旧活动 bundle 保持不变。

### 12.5 从训练到实际使用

训练输出继续整组绑定 input/report/model、数据 snapshot hash、特征 manifest、切分、源码和模型 hash。全部
验证通过后才原子切换磁盘活动 bundle；任一步失败时继续使用上一活动模型，不生成部分工件、不回退其它评分
档位。运行中的服务不热加载文件，用户显式选择 V3 并正常重启后才读取新 bundle。

训练和盘中推理必须调用同一个纯特征公式并绑定相同字段顺序、单位、缺失语义和 manifest hash；固定股票、固定
日期的归档输入与生产标准化输入必须形成黄金向量等价证据。BaoStock 与生产 Tencent/Eastmoney qfq 在公司行动、
停牌和普通交易日样本上不能通过容差门时，V3 保持 `production_authority=false`，不得用“训练成功”替代输入同源
证明。

### 12.6 自动化与提醒的选择

当前执行策略固定为“每日自动同步、到期只提醒”。`automatic_model_update=false` 仍是评分权威边界，操作系统
任务不得自动调用 `train-tomorrow`，更不得自动切换 profile、重启服务或启用模型。每次下载结束、due 首次出现
以及 due 尚未解除的后续日期，分别输出控制台摘要、任务日志和桌面通知；同一 due 身份每天最多提醒一次，通知
失败只记录 `notification_degraded`，不把已成功下载改成失败。`./run.sh check` 只读展示相同 due 状态，不另算计数。

平台适配器只负责唤起同一零参数命令：Linux 用户 timer 使用 `Persistent=true`，Windows Task Scheduler 使用
`StartWhenAvailable`，macOS LaunchAgent 使用日历触发和登录后补跑；业务时间和幂等性仍由控制库按上海时区判断。
一键安装脚本必须显示将写入的用户级任务并由用户确认，卸载可逆，不要求管理员权限。休眠补跑与 20:30 补偿若
和手工运行重叠，由同一进程锁返回 `already_running`。以后若用户明确授权无人值守挑战者训练，必须另立批次同步
修改 `01_评分逻辑.md`、`02_工程设计.md`、测试和 Changelog；即使获准也只能产出候选 bundle，不能自动生产启用。
任务模板固定绝对工作目录、配置和虚拟环境，只传最小非敏感环境；安装时先验证依赖，定时运行不得静默联网安装
或升级包。日志按大小轮转且不记录 token、完整供应商载荷或股票明细。

不重复跑全量，阶段 G 再对完整合并 diff 运行一次高风险总门禁：

| --- | --- | --- |
| 阶段 A（已完成）：合同与来源实证 | 已改 `01/02/04`、CLI/状态契约；实测 BaoStock 调用下限，并审计 Tushare、腾讯、东财的 raw/qfq、复权、停牌、代码变更和截止时间能力 | BaoStock 选为正确性基线；没有来源通过高效日更门，已明确阻塞且未伪造高效日更 |

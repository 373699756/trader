# V4：A股收益预测与选股方案

本文提出用已下载的A股数据训练自己的收益预测模型：输入当时可知的股票和市场数据，输出未来收益估计，扣除交易成本后选股、排序，并检验实际结果。产品目标是预测荐股收益，不是问答、生成研究报告或解释新闻。

**本文是待验证的设计方案。** V4是本文的方案名称，不表示已经存在可运行的V4档位、训练命令或生产模型。本次文档交付不修改现行算法。当前评分与收益准入仍以[评分逻辑](1_评分逻辑.md)为准，数据与训练工程以[下载训练](4_下载训练.md)为准；实施时先把获准变更写入对应权威合同，实际进度只记入[工程实施](3_工程实施.md)。

## 1. 要解决什么问题

希望系统直接回答三个可检验的问题：这只股票未来预计赚多少、成本后是否值得推荐、同一天哪些股票的预期收益更高。所谓“通用”，首先指跨股票、跨行业共享训练和预测方法，不是保证适用于任意市场、任意期限。

| 方案 | 模型主要学习什么 | 推荐排序依据 |
| --- | --- | --- |
| 当前V2/V3 | 按行业预测收益，提供诊断和成本净效用门 | 已扣本地风险的规则分`local_score` |
| 当前新V1工程Shadow | 全市场LambdaRank学习相对次序，另有Ridge收益估计 | 排序模型产生的相对分位；不是预计收益率 |
| 本文方案 | 全市场共享模型直接学习未来毛收益，再估计成本后净收益 | 通过资格与风险约束后，按预计净收益率排序 |

第一版采用全市场共享的LightGBM收益回归，另用Ridge作基线。先证明这种改变在未参与开发的数据上有价值，再研究更复杂的时序神经网络。没有“参数越多、收益越好”的前提，也不把训练出一个模型等同于具备荐股能力。

## 2. 预测目标与计算口径

### 2.1 两个预测期限

保留Tomorrow和D25两个业务期限，分别训练一个收益预测头。Long仍是观察名单，不参与训练选股、排名或推荐历史。

设D为信号交易日，`P_entry`为该次研究约定的入场参考价，`P_exit(h)`为第h个后续交易日的退出参考价。价格须采用一致的复权与收益口径，不能混用raw和qfq价格。

```text
第h日毛收益 r(h) = P_exit(h) / P_entry - 1
Tomorrow标签   = r(1)
D25标签        = [r(2) + r(3) + r(4) + r(5)] / 4
预计净收益     = 校准后的预计毛收益 - 预计完整往返成本
```

D25预测的是四个期限收益的平均值，不是“未来四天最高能赚多少”，也不代表已经定义了在哪一天卖出。评价时仍逐一报告T+2、T+3、T+4、T+5的实际结果；没有退出、重叠持仓和资金占用规则前，不据此宣称资金年化收益。

内部收益统一用小数：`0.012`表示`1.20%`；`20bp = 0.002 = 0.20%`。模型训练毛收益标签，推断后只扣一次完整往返成本，避免训练标签已扣费、推断又重复扣费。

### 2.2 绝对收益与超额收益分开

本方案主要预测股票本身的收益，不把“跑赢市场”当成“赚钱”。例如股票跌1%、基准跌2%，超额收益为正1个百分点，但股票绝对收益仍为负。

在线选股使用预计绝对净收益；离线评价同时计算绝对净收益和相对基准的净收益。基准沿用评分合同：同日同策略、当时已合格可交易总体的等权收益，总体在模型选择前固定。未来已经实现的基准收益只能用于事后评价，不能作为当天预测输入。第一版不增加市场收益预测头，也不把现有的超额收益预测值直接改名为绝对收益。

### 2.3 信号时间、标签价格与成交可行性

第一版历史研究沿用现有D日15:00入场锚点，日线特征只读取D日前已完成的数据。用D日完整收盘价构造标签，不等于D日15:00前已能取得全部收盘字段，更不等于用户实际能按该价买到。

| 研究层次 | 可用输入及结论 |
| --- | --- |
| 日线工程原型 | 先用截至D−1的完整日线预测，以D日收盘入场代理检验拟合、校准和排序流程；只证明工程及研究假设 |
| 点时一致回放 | 重建决策截止时真正已到达的行情、资格和风险证据，保留接收时间及来源身份；检验完整选择链 |
| 成交可行性验证 | 另报决策后可交易价格、滑点、涨跌停、停牌、无法买入及无法按计划退出的结果；不删除不利样本来美化收益 |

首批特征不使用D日最终成交额、最高最低价或收盘后才发布的财务/公告。若后续增加盘中数据，必须有与在线采集一致的历史时间戳和可得性证据，另做增量研究。若改成收盘后预测、次日开盘入场，则是另一套入场与标签合同，不能和本方案现有锚点的结果混报。

## 3. 下载数据能支持什么

仓库已有完整历史下载、独立qfq、训练、模型工件与研究报告框架，可复用工程基础。现有历史下载目标为最近2000个市场交易日，但这不意味着本机每只股票已有2000日完整数据；本方案没有对实际磁盘数据做覆盖验收。

| 数据 | 第一版用途 | 必须先核实的问题 |
| --- | --- | --- |
| 交易日历、raw与独立qfq日线 | 收益标签、趋势、波动、成交额及流动性特征 | 完整性、复权一致性、异常价格、缺日原因、历史修订身份 |
| 股票上市与退市、ST、停牌等历史资格 | 恢复每一天真实可选总体和不可交易状态 | 不能用今天仍上市、今天非ST的股票倒推全部历史 |
| 历史行业、板块归属 | 分组诊断和可选的类别特征 | 当前行业快照不能冒充历史归属 |
| 财务与公告证据 | 后续增量特征及风险资格 | 需要公告生效时间及修订版本；现有公司资料窗口不等于2000日点时财务历史 |
| 分钟数据、当时行情及接收时间 | 后续盘中增强与完整回放 | 当前快照不能还原过去每次决策时可知的信息 |

第一版先采用日线量价特征：多期限历史收益、波动、回撤、成交额及流动性变化。优先复用新V1的251日输入和已有纯特征计算，以减少训练/在线口径差异。市场状态、行业及财务特征只有在历史时点可核实后才能加入；缺少时点证据的字段不进入正式研究。

每条样本至少绑定股票、信号日期、特征截止时间、数据身份、标签成熟日期和资格状态。新股不补造上市前历史，缺失标签不能填0；停牌或退市造成的标签缺失必须单独统计并给出处理依据。只有当前存续股票的数据时，可以先做有偏工程原型，但不能通过全市场收益准入。

即使约5000只股票乘2000日形成名义上的千万行，同一天股票仍高度相关。有效证据来自足够长、不同市场状态的独立时间区间，不能按千万个独立样本计算置信度。

## 4. 模型如何学习收益

### 4.1 第一版模型

每个期限使用一套全市场共享LightGBM回归模型，目标为毛收益的平方误差。它学习历史特征组合与后续收益之间的统计关系，例如同样的上涨幅度在不同波动和流动性条件下，对应的后续收益是否不同。平方误差回归针对条件均值，符合“预计收益”的目标；能否捕捉到稳定关系必须通过时间外检验。

LightGBM官方把L2回归、分位数回归和LambdaRank列为不同目标；本方案主模型选择`regression_l2`，不把排序分或分位数当成平均收益。[目标函数定义](https://lightgbm.readthedocs.io/en/stable/Parameters.html#objective)

| 模型/处理 | 职责 | 第一版安排 |
| --- | --- | --- |
| 历史均值预测 | 判断复杂模型是否只是重复市场平均表现 | 必须保留；均值只从训练区计算 |
| 全市场Ridge | 简单线性收益预测基线 | 与主模型使用相同标签、特征和时间切分 |
| 全市场LightGBM回归 | 学习非线性关系，直接输出毛收益估计 | 主模型；Tomorrow/D25独立拟合 |
| 收益校准 | 检查并修正预测幅度过大、过小或整体偏移 | 独立历史校准区拟合；原始值和校准值均保存 |
| 分位数或亏损概率模型 | 估计下行风险或事件概率 | 后续独立研究，不作为第一版必需项 |

同一天样本总权重相同，防止股票数量较多的日期主导拟合。行业、板块和不同上市年限分别评价，避免全市场均值掩盖局部失效。第一版不以股票代码作为可记忆的数值特征，不依赖为每只股票单独训练一个模型。

### 4.2 校准不是把分数变成收益

例如原模型报出的2%经常只实现0.5%，应在独立校准区学习这种偏差，随后在未见区验证。第一版比较“不校准”和简单仿射校准两个预先登记的候选，确认区选定后固定；校准方向反转或样本不足时判定模型不合格，不临时启用未经验证的替代方案。

“预测收益1.2%”表示模型对这一条件下平均收益的估计，不是这只股票必然上涨1.2%，也不是上涨概率。只有经过单独概率建模和校准，才能展示上涨概率；第一版不展示伪造的置信百分比。

### 4.3 什么时候研究更大的模型

先完成简单基线、LightGBM、真实数据覆盖和样本外评价。只有证明数据规模、时点质量及当前模型能力存在明确瓶颈，再以相同数据和验收口径比较时序神经网络。新增模型必须带来未见区的净收益或风险改善，并满足个人PC资源约束；不能只凭训练损失更低或参数更多替换已有模型。

## 5. 训练与防止未来信息泄漏

按日期依次划分拟合、早停、校准、独立确认和最终留出区。同一天的所有股票进入同一区间；不随机打散股票日期行。标准化、缺失处理参数、特征选择及校准均只能从其获准的历史区学习。

研究开始前固定特征集合、模型候选数、参数范围、成本、基准、停止条件和留出身份。第一轮限制为上述简单基线、Ridge、LightGBM及有限校准候选，不开展无上限调参。

1. 先按可用交易日做覆盖审计，再决定训练窗口；不因为日历目标是2000日就把所有日期用来拟合。
2. 对每个分区边界清除标签区间跨界的样本，并至少隔离5个交易日；如果入场或退出合同延长，按最长标签跨度扩大隔离。Tomorrow标签等待1日、D25完整标签等待5日成熟。
3. 开发区按时间向前滚动训练和评价，覆盖上涨、下跌及震荡区间。每次预测只能用当时已成熟的标签训练；近期重训不能接触尚未开放的确认或留出数据。
4. 独立确认用于一次性固定完整预测与选股链；最终至少200交易日留出按现有研究协议只开启一次。以前已经看过结果的区间不能改名为“全新留出”。
5. 每个工件记录数据、样本、特征、标签、成本、参数、校准及切分身份，能够复现某天为什么产生这一预测。

2000日下载窗口还要容纳特征前置期、标签尾部、隔离期和所有评价分区。如果有效日期不足，应补数据或缩小开发训练窗口；不能通过压缩最终留出或挪用未来数据凑齐训练。

## 6. 如何据此荐股

拟议链路为：**恢复当时可选总体 → 校验资格与输入 → 预测毛收益 → 校准 → 扣一次成本 → 风险及容量约束 → 按预计净收益选取最多6只 → 输出解释与身份。**

成本估计复用现有执行成本所有者，流动性参考总体在筛选前固定，避免只对最后几只股票重新计算分位。费用、滑点与冲击应由同一个明确口径处理；具体费率与成本敏感性通过既有研究协议固定。

第一版只纳入预计净收益严格大于0、输入合格且通过风险/容量约束的对象；允许不足6只或全部空缺，不为凑名额推荐预测亏损股票。按未经过展示舍入的预计净收益降序排序，完全相同时按股票代码稳定排序。排序字段与现有规则分分开，UI百分比展示不得反过来决定名次。

| 示例股票 | 校准后预计毛收益 | 预计往返成本 | 预计净收益 | 处理 |
| --- | --- | --- | --- | --- |
| 甲 | 1.20% | 0.25% | 0.95% | 通过其余约束后排名在乙前 |
| 乙 | 0.90% | 0.20% | 0.70% | 通过其余约束后可入选 |
| 丙 | 0.15% | 0.20% | −0.05% | 不入选 |
| 丁 | 2.00% | 0.30% | 1.70% | 若存在已核实的风险veto，仍不入选 |

这些数字仅解释算法，不是训练或回测结果。上线候选应保留既有硬资格、集中度、流动性及可交易性约束；第一轮不同时放宽这些限制。现有`local_score`可用于对照诊断，但不能继续决定本文方案的最终排序，也不能把“扣10分”换算成“扣10%收益”。下行风险若需要数值调整，必须另建可验证的收益单位模型，不能混用量纲。

DeepSeek如沿用，只承担证据核验后的结构化风险veto；它不预测收益、不改收益数值、不参与训练目标。模型也不能绕过停牌、资格失效或证据缺失。

预测缺失、模型过期或输入不合格时，明确给出原因，不用0收益冒充预测。保留同一运行身份最近的有效快照并标注年龄；不借V2/V3规则分伪装成本文方案的新预测。

## 7. 怎么证明比现有方案更好

所有方法使用相同日期、可选总体、入场/退出口径、约束和成本做配对比较。除历史均值、Ridge外，保留现行V2/V3作为产品基线；另外比较“同一收益模型只做准入、仍按规则分排序”和“同一收益模型直接按净收益排序”，区分模型预测与排名改变各自的贡献。

| 评价层次 | 需要报告什么 | 不能据此直接声称什么 |
| --- | --- | --- |
| 预测误差 | 毛收益平均绝对误差、均方根误差、分桶预测与实现均值、分期偏差 | 误差较小不一定选股更赚钱 |
| 排序能力 | 日截面RankIC、收益分组单调性、前6名效果 | 排序相关为正不代表覆盖成本 |
| 推荐收益 | 绝对净收益、相对基准净收益、入选率、空缺比例、逐期限结果 | 只报告入选股票均值不能解释低覆盖率 |
| 风险与交易 | 严重亏损、回撤、换手、容量、滑点及不可成交情景 | 理想价格下的回测不能证明可成交 |
| 稳定性 | 行业、板块、市场状态、年份和最近窗口的差异 | 某一段牛市有效不代表长期有效 |

预测的“平均绝对误差”与评分合同风险项中的`MAE`不同：后者指持有期最大不利变动，不能共用字段或混成一个指标。报告分别标注全称和单位。

固定六槽指标按现有合同计算，空缺槽记0，同时报告实际入选股票均值；这两种指标分别解释，不把空缺造成的稀释当成模型能力提升。D25四期限均值与六槽结果均不是完整资金组合收益，不能直接年化。

正式收益准入沿用[评分逻辑第12节](1_评分逻辑.md#12-收益验证与变更门禁)，不因新模型而降低标准：20bp主评价和50bp稳健性评价相对基准净收益置信下界均须为正，风险、换手与容量不得劣化；100bp只作压力报告。按该节使用移动区块、10000次bootstrap、Holm 0.05校正及95%置信区间，避免把相邻日期或同日股票当成独立证据。

资格证据不完整时，先完成工程诊断并明确缺口，不跳过研究准入去打开封存收益结果。终端留出通过后，仍需至少60个合格交易日Shadow、资源验收及明确生产授权；普通日线代理结果不能累计成正式Shadow证据。

| `training/domain/` | 纯特征、毛收益标签、校准及预测对象的合同 | 离线样本和在线特征使用同一含义、单位与顺序 |
| `training/application/`、`training/infra/` | 编排拟合/校准/评价，扩展现有模型工件读写 | Tomorrow/D25完整工件成套发布；绑定特征schema与训练身份 |
| `recommendation/domain/` | 以收益为单位的预测、成本、准入与排名规则 | 保留风险/容量约束；规则分与收益不混用 |
| `recommendation/application/` | 接入预测、发布只读结果并处理失败 | 模型、输入和快照身份贯穿选择与发布；不隐藏降级 |
| `bootstrap.py` | 注入模型、时钟、配置及适配器 | 启动校验完整工件；不在适配器内偷偷创建第二套资源 |
| `http_api/`、`web/` | 展示预计毛收益、成本、净收益、期限、数据年龄与失败原因 | 只投影已生成结果，不训练、不评分、不抓行情 |

建议预测对象至少包含`predicted_gross_return`、`estimated_round_trip_cost`、`predicted_net_return`、`forecast_horizon`、特征截止时间及模型身份，内部使用不可变类型，输出边界按白名单投影。百分比只在展示边界转换；校准前预测保留在诊断中。

已有工件和冻结历史保持原身份。正式接入时需要一并检查预测对象、选择链、动作解释、API/SSE、Web、冻结与历史消费者，防止某处仍把数值当0–100规则分。新增试验算法在隔离研究身份运行；替换既有职责时完成新owner、全部消费者和旧活动路径的原子切换，不留兼容转发。

训练继续离线手动执行，模型加载服从明确的工件校验和启动流程。在线行情与分钟输入沿用10秒采集配置，这表示获取输入的调度间隔，不是每10秒训练一次，也不是整条荐股链必定10秒完成。共享日线特征尽量预计算，推断在输入变化时运行；资源和调度约束见[工程设计](2_工程设计.md)。

第一轮按个人PC的CPU与受控内存设计，离线历史按分区处理，在线只持有所需窗口与模型。训练耗时、峰值内存、全市场推断延迟和工件大小必须实测，当前不承诺具体耗时或硬件足够。15:00冻结、迟到结果和恢复流程仍遵守原合同；新模型不可用时不能以未经授权的规则结果冒充该模型正式推荐。

## 9. 实施顺序与每步产物

下表是依赖顺序，不是活动进度台账；启动开发后，阶段号、状态和证据只登记到工程实施。

| 顺序 | 工作 | 产物及进入下一步的条件 |
| --- | --- | --- |
| 1 | 审计本机历史覆盖、历史总体和时点资格 | 覆盖报告、缺口原因、可用日期及样本规模；区分工程可训练与正式研究合格范围 |
| 2 | 固定目标、入场代理、成本、基准和时间分区 | 样本合同及预先登记的有限实验方案；隔离终端留出，不读取其收益调参 |
| 3 | 接通毛收益样本、均值/Ridge/LightGBM及校准 | 可复现的双头工件、时间外预测及预测误差报告；不新增生产入口 |
| 4 | 接通完整约束下的净收益排序与配对研究 | 模型与规则排序贡献分解、成本敏感性、风险/容量报告；合格后才能进入终端留出 |
| 5 | 完成点时回放、终端留出与独立Shadow | 合格研究身份、未见区结论、至少60交易日Shadow证据及资源实测 |
| 6 | 获准后接入正式展示与发布 | 更新权威合同，完成所有消费者、冻结/恢复和失败路径验证；保留完整旧release回退能力 |

如果第1步发现关键历史资格缺失，先报告和补齐，不把后续模型调参当成替代；工程原型可使用明确标记的受限样本，但不得据此进入正式研究准入。如果第4或第5步失败，保留失败结论和工件身份，继续使用现有生产方案；不能反复查看留出并调到通过。

本方案的第一个可验收成果是“数据覆盖报告 + 明确的毛收益标签 + 简单基线与LightGBM的时间外预测比较”。只有该成果证明存在值得继续的收益信号，才投入更复杂模型和生产接入。

# 荐股评分逻辑

本文是候选、过滤、因子、评分、风险、DeepSeek、融合、动作、排名和冻结策略的唯一权威。产品架构、
调度、持久化、API、SSE、Web 生命周期和运维见[工程设计](02_工程设计.md)；研究任务、依赖、状态、
历史工件与交付证据见[工程实施](03_工程实施.md)和 `CHANGELOG.md`；历史下载、训练以及训练结果进入实时
荐股的解释性链路见[策略回溯](04_策略回溯.md)。

V1、V2、V3 只表示用户确认的 Tomorrow 评分生产档位。本文不维护软件发布版本、迁移过程、模块 owner、
命令实施状态或历史事故复盘。策略仅用于本地 A 股研究，不构成投资建议，不保证收益，也不触发真实交易。

## 1. 目标、范围与当前结论

唯一优化目标是：在对应持有期内，提高相对同日可投资 A 股基准、扣除交易成本后的可重复净超额收益，
同时约束严重亏损、最大不利变动、换手、容量和集中度。推荐数量、页面非空、原始涨幅、命中率或模型分数
本身都不是最终目标；允许 0 只推荐，禁止为了凑数降低风险或质量门槛。

| 策略 | 决策目标 | 生产锚点 | 正式结果 |
| --- | --- | --- | --- |
| `today` | 当日盘中选择，面向 T+1 | 11:20 冻结 | 0–6 只正式推荐，盘中另有最多 6 只观察项 |
| `tomorrow` | 14:50 至下一交易日收盘的净超额 | 14:50 冻结 | 0–6 只正式推荐，盘中另有最多 6 只观察项 |
| `d25` | 筛选未来第 2 至第 5 个交易日区间内具备上涨能力的股票 | 14:50 冻结 | 一个 D25 决策，0–6 只正式推荐，盘中另有最多 6 只观察项 |
| `long` | 固定长期研究池的当前行情观察 | 不冻结 | 无评分、无动作、无推荐历史 |

D25 是一个完整且唯一的 2–5 日生产策略头，不得拆成 T+2、T+3、T+4、T+5 四个生产头；
四个观察点只用于 D25 的标签、终端留出、风险和稳定性评价。“具备上涨能力”是对该区间综合收益信号的
研究判断，不表示四天必须逐日上涨，也不构成收益保证。当前 D25 使用规则评分，不读取 Tomorrow 训练模型。

所有计算只使用评估时刻已经生效的数据。实时价格、涨跌停和冻结锚点使用未复权价格；历史收益、均线、
波动和回撤使用点时可得的前复权序列。行业、证券状态、财务、公告和规则只能在各自生效或披露时间之后
进入决策。无时区时间、未来数据、非有限值、过期数据和无法核验的状态不能形成可执行推荐。

缺失原始值保持 `null`，同时记录字段和原因。确定性评分可以按明确规则使用中性占位 50，但该占位不得
序列化成真实观测，也不得让缺失字段获得优势。

当前收益结论是“仍有优化空间，但尚未证明任何新方案能稳定提高未来收益”：V1 结构简单但既有留出净增量
为负；V2 平均成本后净增量证据强于 V1，但严重亏损、换手和排序门禁失败；V3 的完整点时数据、收益验证和
生产授权尚未闭合。因此当前规则必须保持，所有优化先走第 12 节历史验证。

## 2. 端到端荐股链路

```text
来源采集与点时校验
  -> 统一字段、单位、时区、来源与稳定内容身份
  -> 一级永久资格过滤
  -> 二级动态硬过滤
  -> 分板横截面总体
  -> 逐股评分输入资格
  -> 每板候选分与每板最多 120 只预选
  -> Today/D25 规则评分或 Tomorrow V1/V2/V3 模型评分
  -> local_score（本地风险只扣一次）
  -> 可选 DeepSeek 结构化复核
  -> 固定 68/32 融合
  -> 下行保护与动作门
  -> 正式池/观察池稳定 TopK 与集中度约束
  -> local 先发布，合法 hybrid 可升级
  -> today 11:20、tomorrow/d25 14:50 冻结
  -> 当前、冻结、最高分、降级与空结果的只读展示
```

各环节的输入输出必须可追踪：

| 环节 | 输入 | 输出/拒绝原因 |
| --- | --- | --- |
| 数据采集 | 实时行情、前复权历史、证券主数据、财务/公告/风险事实 | 带来源时间、接收时间、单位、时区、质量和稳定身份的不可变输入 |
| 一级资格 | 已生效的永久事实 | `permanently_excluded`、`eligible_unverified` 或 `qualification_pending` |
| 二级过滤 | 当前行情、交易状态、上市年龄、流动性和结构化风险 | `reject`、`observe_only` 或 `pass`，并保留具体原因 |
| 板内总体 | 同板、同阶段、同数据版本的完整有效人口 | 截尾参数、分位和可靠度基准 |
| 评分资格 | 硬过滤后股票、策略必需历史与模型字段 | 可评分股票，或稳定的缺失/过期原因；资格检查先于板内限额 |
| 候选预选 | 已具备评分输入资格的股票及策略候选因子 | `candidate_score`、每板稳定排序及预选原因 |
| 本地/模型评分 | 策略组件或模型预测 | `base_score`、组件、模型诊断 |
| 风险与复核 | 本地风险事实、证据 manifest、合法 DeepSeek facts | `local_score`、模型分、penalty、veto、复核终态 |
| 动作与 TopK | 最终分、过滤状态、下行保护、集中度 | `executable`、`observe` 或 `unavailable` 及正式/观察排名 |
| 冻结 | 截止前最新合法完整决策 | 不可变正式记录或明确 `not_ready` |
| 展示 | 当前或冻结决策、报价 overlay、诊断 | 正式推荐、观察池、最高分、时间、来源、降级和空结果原因 |

必须区分三种“没有股票”：输入未就绪时为 `not_ready`，保留最近有效结果且不能冻结伪空集；输入完整但
全部被业务规则淘汰时为合法空结果；数据源或 DeepSeek 局部失败时为降级结果，继续发布可证明的本地结论。

## 3. 数据采集、点时归一化与数据就绪

### 3.1 输入与时间口径

活动短线链至少消费以下数据：

- 全市场未复权当前行情：代码、名称、板块、价格、开高低收、涨跌幅、成交额、成交量、换手率、来源时间；
- 候选定向行情与分钟尾盘：当前价格、30 分钟收益、尾盘量比、收盘位置、5 分钟涨幅和涨速；
- 前复权日线：至少覆盖各策略要求的流动性、波动、回撤、均线、ATR 和 Tomorrow 模型窗口；
- 证券主数据：交易所、板块、上市日、上市交易日龄、价格限制和交易状态；
- 点时财务、公告和公司风险：披露/生效时间、来源与稳定证据 ID；跨进程保存原文或规范载荷时才附内容 hash；
- DeepSeek 证据 manifest：只包含不晚于评估时刻的结构化行情、财务、公告、监管和新闻证据。

所有业务时间先转换为 `Asia/Shanghai`，再比较新鲜度与截止时间。来源时间用于判断数据是否可用于动作，
接收时间用于解决同来源先后；不得用处理完成时间伪造行情更“新”。历史因子与标签按交易所实际开市日对齐，
新股、停牌和退市证券不补造不存在的交易日。

### 3.2 板块身份与交易规则

板块固定为 `main`、`chinext`、`star` 和 `unsupported`。识别顺序为带生效时间的证券主数据、交易所清单、
行情源市场字段、六位代码前缀降级。前缀降级记录 `board_source=code_prefix_fallback` 和
`board_reliability=degraded`；来源冲突记录 `board_classification_conflict`，只能观察。

首次上市第 0–5 个交易日、重新上市首日和退市整理首日直接排除，第 6 个交易日起使用普通规则。上市日期
或交易日龄无法验证时只能观察。普通热度边界为：主板 8.00% 通过、8.01% 剔除；创业板和科创板 16.00%
通过、16.01% 剔除。无价格限制状态不计算普通 `limit_proximity`。

### 3.3 统一行情与跨源合并

策略只消费不可变统一行情，不直接消费供应商对象；应用链只通过应用层 `DataPlaneReadPort` 读取。
相同有效输入无论完成顺序如何，都必须产生相同字段归属、冲突集合、缺失集合和数据身份。跨进程持久化、
冻结或缓存键需要内容寻址时才计算规范内容 hash；进程内下游复用已接纳身份，不重复序列化和校验同一对象。

- 同来源按来源时间、接收时间选较新字段；跨来源同时点按已登记的稳定优先级；
- 慢结果不得覆盖更新价格，未来值和无时区值直接拒绝；
- 新鲜腾讯候选价只有在与东方财富或新浪至少一个全市场观测偏差不超过 0.50% 时才完成跨源复核；
- 未准入影子来源不得写入统一行情或参与过滤、评分、冻结和收益结算；
- 全源失败时保留最近有效统一快照并显式降级，不能用空快照清除推荐。

前复权历史默认使用已证明的 qfq 数据。腾讯显式 qfq 响应若返回 `day`，只有窗口内
逐行公司行动元数据为空且两个调整标志均为零，才构成 qfq 等价证明；证明不完整时
不得把一般未复权 `day` 标记为 qfq。成交量和
成交额必须先统一为股和元，再计算因子。

### 3.4 数据就绪、实时触发与失败降级

证券主数据覆盖为 100% 是潜在可执行代码的必需条件；候选历史覆盖率是加法健康指标，不是整批否决门。逐股按照
策略真实需要判定：Today 和规则 D25 至少需要 20 个有效交易日的流动性/风险摘要；Tomorrow V1/V2/V3
按所选模型需要至少 61 个有效 qfq 交易日及全部模型字段。单股不足只淘汰该股；所有股票都不合格时才是
`not_ready`。

全市场人口和候选定向行情分别使用自身点时水位与年龄上限。候选历史、分钟或研究增强较慢，不能把已经
完整接纳的总体倒算为过期；候选原始来源时间过期仍必须拒绝，不能借总体水位恢复执行资格。

离线 V3 在构造任何点时样本前还必须分别通过三道资格门，不能用一个总进度互相替代：2000 个交易所开市日
日线归档必须形成完整 manifest 且所有代码完成、无失败；历史行业必须对至少 300 只分层样本证明分类体系、
生效/失效日期、查询时间和来源身份；历史分钟必须在分层股票与交易日样本上证明 Asia/Shanghai 的 11:20、
14:50 精确锚点、量额、raw/qfq 配对、公司行动语义且覆盖率不低于 95%。资格报告是不可变、失败关闭的研究
证据，只决定后续数据集能否开始，不产生 alpha、不开启终端留出也不授予生产权限。任一门不足统一返回
`historical_data_insufficient`；单股连通性或日线可用性只能作为工程 smoke，不能代替总体资格。

点时数据集只能在三门资格同时为 `qualified` 后读取历史日分区。每个 Tomorrow 14:50 日期直接复用生产纯
领域 `select_scored` 重建一级永久资格、动态硬过滤、字段资格、板内总体、候选阈值和每板最多 120 只；每行
只记录第一个拒绝边界，但拒绝行也必须保留在覆盖统计和数据分片中。基准人口在候选阈值和每板上限之前固定，
因此候选模型不能改变 `point_in_time_local_only_equal_weight` 的成分。统一 `FeatureVectorManifest` 绑定特征
顺序、单位和缺失掩码，`CanonicalOutcomeEvaluator` 对全部保留行生成 20/50/100bp、T+1、MAE/ATR20 和
退出不可交易标签。训练、早停、校准、确认分片及开发/确认、确认/留出之间的 embargo 可以封存；构建器只
读取四个开发分片，终端留出只封存日期与父 hash，数据集构建
阶段固定读取 0 行、`terminal_holdout_opened=false`、`production_authority=false`。任一父资格不足或合格
基准人口标签不完整，整个数据集返回 `historical_data_insufficient`，不得产出可供下游消费的部分 manifest。

评分由真实输入版本变化触发，不因定时器空转而重复计算。同一不可变输入只评分一次；新输入可以替换尚未
开始的旧任务，但已经开始的评分允许完成并发布 local。不同策略隔离，Tomorrow 优先但不得饿死 D25/Today。
上午 Today、Tomorrow、D25 可共享相同原始 facts；午后 Tomorrow/D25 再使用受截止约束的尾盘增量。

任何来源失败都不能把未知写成 0 或“无风险”。最近有效数据可以用于展示，但超过动作年龄后只能观察，
不能形成新可执行动作。已确认公司风险不能因本轮来源失败消失。

## 4. 两级硬过滤

硬过滤只能由确定性结构化规则执行。DeepSeek 不能新增候选、放宽资格、删除阻断，也不能用自由文本直接
改变过滤结果。

### 4.1 一级永久资格过滤

任一不晚于评估时刻的下列事实命中后，股票进入 `permanently_excluded`：

- 正式年度财报已披露归母净利润或扣非/核心净利润小于 0，原因 `historical_audited_loss`；
- 任一历史点时已确认 ST、`*ST` 或正式退市风险警示，原因 `historical_st` 或对应退市原因；
- 监管、交易所、发行人或司法结构化证据正式确认财务造假、重大违法、资金占用、违规担保或强制退市；
- 配置中经人工授权的永久黑名单。

一级事实必须绑定代码、原因、事实生效时间、稳定证据 ID 和来源；只有保存外部原文或跨进程规范载荷时才绑定
其 SHA-256，不能为已经类型化且未越过信任边界的同一事实逐层重复计算。普通新闻、DeepSeek 自由文本、
问询函、一般诉讼、亏损预告或未形成正式结论的调查不得创建一级永久事实。覆盖不完整时保持
`eligible_unverified` 或 `qualification_pending`，不能假定安全。

一级资格在所有逐股历史、候选、公司研究、参考资料和分钟行情请求之前执行。全市场批量接口可能物理返回
已排除股票，但下游人口和逐股请求必须立即剔除。历史回放按事实生效时间重建资格，
不得用当前一级名单反向删除事实生效前的股票。冻结记录不因后来出现的一级事实而追溯改写。

### 4.2 二级动态硬过滤

一级通过后，下列任一必需条件失败即 `reject`：

- 不是受支持六位 A 股代码、板块为 `unsupported`、当前 ST/`*ST`/名称含“退”或停牌；
- 价格、成交额、涨跌幅或 OHLC 结构非法，时间无时区、来自未来或超过动作年龄；
- 上市第 0–5 个交易日、重新上市首日或退市整理首日；
- 20 日成交额中位数缺失、非有限或低于 5000 万元；
- 一字涨跌停、重大监管风险或超过板块热度上限；
- 经点时 schema 和官方证据确认的减持、造假、正式调查、重大违法、资金占用、违规担保或强退风险；
- `unlock_risk > 0`、`pledge_risk > 0` 或 `financial_deterioration > 0.5`。

跨源价格偏差未复核、板块冲突/降级、上市日期或交易日龄缺失、结构化风险覆盖不足属于 `observe_only`，
不是硬拒绝。候选核心字段缺失超过 30% 属于预选剔除；板块可靠度低于 0.85 属于动作和复核限制。三者必须
保留各自原因，不能合并成模糊的“无候选”。

公司风险只接受带生效时间的官方结构化证据：控股股东、实际控制人或持股不低于 5% 的股东减持，从公告
起至正式完成/终止后 90 天阻断；正式立案调查和强制退市程序在存续期及官方结束后三个自然年阻断；正式
决定确认的造假、重大违法、资金占用和违规担保永久阻断。来源失败时保留旧命中，其余候选降为观察。

## 5. 板内总体、候选预选与评分资格

### 5.1 板内总体

横截面身份固定为 `trade_date + phase + board + data_version`。流动性、换手、波动、回撤、趋势和相对强度
在板内执行 2.5%/97.5% 截尾、归一化和稳定排序。每板至少 100 个有效样本；不足时最多回退最近 5 个有效
交易日的同板同阶段总体，不能借用其他板块。

总体与候选是两个集合：全市场只生成参考分布；候选定向报价后的股票先完成硬过滤、策略历史和模型字段
资格，再把每板最多 120 只合格预选投影到同一分布。候选预选和正式评分必须沿用相同总体身份；候选更新
只失效相应候选分，不得让未变化的板内总体重复构建。

行业直接评分权重为 0：它不进入候选分、Today/D25 规则分、DeepSeek 总分或下行保护；行业名称可用于证据
标签、展示和最终集中度。V3 可以将行业用于风险中性化/残差化，并要求行业身份在训练和在线均有效；这种
暴露控制不作为正向行业加分。`industry_policy` 权重固定为 0，`peer_gap` 和 `leader_gap` 不属于活动评分输入。

换手与成交代理：

```text
turnover_shock_20 = current_turnover / median(turnover, 20)
amount_shock_20 = current_amount / median(amount, 20)
volume_price_confirmation = sign(return) * normalized_amount_shock
```

分母缺失、非正或非有限时保持缺失。换手带通为 `B(x;0.8,1.1,2.0,4.0)`，成交额带通为
`B(x;0.8,1.2,3.0,6.0)`。这些指标统称 `flow_proxy`，不得解释为主力或机构资金。

## 6. 本地与模型评分

### 6.1 统一计算边界

`P(x)` 是 0–100 横截面平均秩，反向因子使用 `100-P(x)`。带通函数 `B(x;l,o1,o2,u)` 在区间
`[o1,o2]` 得 100，在 `x <= l` 或 `x >= u` 得 0，中间线性变化。

```text
base_score = sum(component_score * component_weight)
local_score = clamp(base_score - local_risk_penalty, 0, 100)
```

## 7. 本地风险与 DeepSeek 结构化复核

### 7.1 本地风险

风险事实按代码、风险类型、实际值、来源、交易日和证据去重，同一事实不因多来源重复扣分。本地风险上限
固定 25 分：

| 风险 | 含义 | 扣分 |
| --- | --- | ---: |
| `near_limit_crowding` | 接近板块涨停限制的追高拥挤 | 5 |
| `price_volume_divergence` | 价格与量价确认背离 | 4 |
| `high_volatility` | 20 日波动率处于极端区间 | 3 |
| `short_term_overheat` | 5/10 日收益或 MA20 偏离极端 | 3 |
| `intraday_reversal` | 冲高回落且收盘位置低 | 4 |
| `liquidity_contraction` | 绝对流动性合格但相对流动性骤降 | 3 |
| `trend_breakdown` | 价格、均线和短期收益共同破位 | 3 |

缺失、非有限或样本不足不触发扣分，只记录缺失。已确认结构化监管/财务事实可以形成 veto。模型自由文本、
评级、置信度和情绪词不能直接决定 penalty、veto、动作或排名。

### 7.2 活动下行保护

下行保护在融合后、动作和 TopK 前执行；命中只把原本可执行的股票降为观察，不修改分数：

- 从当日最高价回落至少 1 个 ATR20，且收盘位置不高于 35；
- `trend_breakdown` 命中；
- `low_volatility_score <= 20` 且 `low_drawdown_score <= 20`；
- `market_regime=risk_off`、市场上涨宽度不高于 30，且短线收益为负或收盘位置不高于 50；
- ATR20、20 日波动、20 日最大回撤、低波动分或低回撤分缺失、非法或过期。

单独的短期过热、高波动或临近涨停仍只执行表内软扣分；结构化 veto 保持 `unavailable`。保护器不得把低于
观察线、硬拒绝或 veto 股票提升为观察。

### 7.3 DeepSeek 结构化复核

DeepSeek 是可选事实复核器，不是候选生成器。只有 `pass`、无 veto、已有本地分、可靠度合格且位于高风险、
动作门槛附近、TopK 边界或证据冲突范围的候选才进入待审集合；每策略每次最多 28 只。

每只候选最多 12 条点时证据。事实必须引用本地 manifest 中的证据 ID、来源等级、发布时间和摘要 hash；
无法通过 schema、代码、时点和证据核验的结果拒绝或 `abstain`。正向事实要求官方来源或至少两个独立可信
来源；相反证据必须保留。

模型只返回催化、价格反映、基本面、行业政策、监管/减持/解禁/质押/诉讼/业绩风险、冲突、覆盖和
`abstain` 等结构化事实。行业政策只作零权重标签。有效维度从 50 出发并按证据置信度向 50 收缩：

```text
effective_i = 50 + (score_i - 50) * raw_confidence_i
deepseek_score = sum(effective_i * weight_i)
confidence_coverage = sum(raw_confidence_i * weight_i)
```

| 策略 | 价值质量 | 财务健康 | 资金量价 | 行业政策 | 风险质量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Today | 11.7647% | 11.7647% | 47.0588% | 0% | 29.4118% |
| Tomorrow | 18.75% | 25% | 31.25% | 0% | 25% |
| D25 | 25% | 31.25% | 25% | 0% | 18.75% |

至少两个计分维度已知且 `confidence_coverage >= 0.50` 才应用模型分。风险事实必须经本地稳定映射后才能
形成 `deepseek_risk_penalty` 或 veto；模型不能自定扣分。供应商不可用、密钥缺失、超时、预算耗尽、
schema 失败、结果迟到或全部 abstain 时保留 local 决策。单次网络 timeout 为 20 秒。

### 7.4 Tomorrow 保守 challenger

仅 Tomorrow 使用 challenger，Today 和 D25 的 challenger 请求上限均为 0。它不是第二套评分器，也不对所有
primary 结果普遍复审；只有 primary 已成功应用，且至少命中以下一项时才进入稳定优先队列：

1. 出现置信度不低于 0.7 的新高风险；
2. local score 位于动作门槛上下 5 分；
3. local 与 primary 的方向冲突；
4. primary 维度证据含冲突或矛盾标记；
5. 候选位于下行保护集合。

队列按新高风险、门槛附近、方向冲突、证据冲突、下行保护、local 名次和代码稳定排序。每批最多 4 只，
每日最多 2 次 challenger 物理 HTTP 请求；缓存命中不消耗物理请求，共享预热不运行 challenger。其请求、
失败、超时、重试和 schema 修复都计入每日 168 次全局物理请求上限，且不能突破 Tomorrow 自身预算和截止时间。

challenger 只能保守确认或中和 primary：`confirm` 只能保持或降低 primary 置信度；带合法证据的
`contradict` 把冲突维度改为 50 分、0 置信度和未知。它不能提高原始分数、置信度或结论，不能生成目标价、
penalty、veto、排名或动作。失败时保留 primary；primary 不可用时保留 local；迟到、缺失或 schema 无效也执行同一降级，
不新增补偿请求链。中和后的维度会重新计算 `deepseek_score`，因此只能保持或降低可用证据强度。

### 7.5 全局预算、健康门与缓存

每日物理 HTTP 请求全局上限为 168，失败、超时、重试和 schema 修复均计数。正常计划内硬上限为 Today 8、
Tomorrow 38、D25 16、共享预热 4、独立 emergency 5；普通阶段目标 36、硬上限 66；
tomorrow 独占目标 21、硬上限 38。emergency 只用于新高风险或冻结边界变化，不能用于普通利好或补满 TopK。

Today 11:18 停止提交，Tomorrow/D25 14:46 停止提交，14:48 后拒绝所有新请求。预算通过原子总账预留，
重启和并发不能突破上限；预留后无论结果如何都不退回。

连续传输/schema 失败或应用率过低触发 15 分钟熔断；熔断只停止物理请求，不阻塞 local、缓存和只读展示。
缓存身份绑定股票、交易日、阶段、证据 manifest、模型、prompt、schema 和配置，不绑定普通报价版本；仅报价
变化时复用原始 facts 并重新本地投影，不增加 HTTP 请求。

## 8. 融合、动作、稳定排名与 TopK

### 8.1 固定融合

```text
final_score = clamp(
    local_score * 0.68
    + deepseek_score * 0.32
    - deepseek_risk_penalty,
    0,
    100,
)
```

`local_score` 已扣本地风险，融合时禁止再次扣 `local_risk_penalty`。所有计算使用十进制确定性规则，最终以
`ROUND_HALF_UP` 保留两位小数；固定验收向量必须为 `83.40`。没有合法 hybrid 时
`final_score = local_score`，但已验证的本地或结构化 veto 仍保持更保守动作。
单行等价式为 `local_score * 0.68 + deepseek_score * 0.32 - deepseek_risk_penalty`。

生产排序固定为 `final_score` 降序、`local_score` 降序、代码升序。评级、置信度、挑战者状态和自由文本
不得改变排序。

### 8.2 动作门

| 策略/时段 | 可执行线 | 观察线 |
| --- | ---: | ---: |
| Today 09:36–10:30 | 70 | 65 |
| Today 10:30–11:20 | 76 | 71 |
| Tomorrow | 78 | 73 |
| D25 | 76 | 71 |

可执行项还必须通过硬过滤、新鲜度、周期、成本净效用、下行保护且无 veto。距可执行线 5 分以内为观察，
其余为 `unavailable`。73/78 等阈值是当前固定策略参数，不是已证明的全局收益最优值。

本地评分完成后立即发布 local `ScoredDecision`；合法复核只能引用仍为 current、未冻结的同日 local 父版本
生成 hybrid `ScoredDecision`。两者具有不同身份；失败或迟到结果保留 local，不能回写旧决策。

### 8.3 TopK 与集中度

三板草稿合并后按全局稳定顺序选择，不能先按板填满再拼接。正式池最多 6 只，观察池最多 6 只，两池独立
选择并分别应用集中度约束：单一板块最多 `ceil(top_n * 60%)`，同一行业最多 2 只，缺失行业统一归入
`unknown` 且同样最多 2 只。观察项不占正式名额，被集中度跳过的股票保留原排名和原因，不从池外补数。

成本后净效用不大于 0、硬拒绝、低于观察线或任一 veto 均不能进入两池。合法空仓日保留现金组合，不降低
门槛。Tomorrow 逐层保存请求候选、特征、主数据、历史、过滤、评分、复核、动作和两池数量，使空结果可以
区分数据不足、`no_positive_net_utility`、分数不足、风险 veto 或集中度限制。

## 9. 冻结、恢复与不可变历史

today 11:20、tomorrow/d25 14:50 后，迟到行情、模型、风险和复核结果不得改变已有正式记录。

- Today：11:20 前存在 current 才冻结正式投影；错过后同日保持 `not_ready`，同日也不允许
  `close_fallback`。已有记录只更新报价 overlay；
- Tomorrow/D25：14:50 冻结截止前最新完整正式投影。若同日正式记录缺失，15:00 后可优先固化本次运行
  current，或在冷启动时按完整同日收盘输入执行一次 local-only `close_fallback`；
- Long：不冻结、不写推荐历史。

冻结前先删除观察池，只保存 `selected=true` 且 `action=executable` 的正式条目。正常冻结沿用决策内点时
锚点；`close_fallback` 使用正式同日收盘锚点，但不能改变分数、动作、排名或风险，也不能新增 DeepSeek。

冻结记录绑定输入摘要、正式股票、本地/模型分、风险、动作、排名、锚点、数据/规则/配置/因子/模型/融合
身份和规范 SHA-256。相同身份同内容重试幂等，不同内容冲突。持久化暂时失败只能重试已经固定的同一对象，
不得重新评分。Tomorrow 在封口时只接受已通过 `UnifiedDecisionIndex` CAS 的最新完整 `ScoredDecision`；
若合法 hybrid 已接纳则冻结 hybrid，否则冻结 local，不等待模型。

冻结后只允许正式股票的报价 overlay 变化。旧策略、旧引擎或旧 schema 不参与当前链重新评分；冻结历史
只按其原始身份只读保存。

## 10. 展示与可解释性

展示是决策的只读投影，不触发抓行情、评分、DeepSeek、冻结或写库。短线页面必须同时呈现：

- 正式推荐：只含当前或冻结的 `executable` 股票，展示代码、名称、板块、最终分、本地分、动作和排名；
- 观察池：仅盘中 current 展示，独立于正式池；冻结、盘后和历史页面不展示观察项；
- 评分最高：从本轮全部已评分候选稳定显示最多 3 只，即使没有股票达到观察线，也不得与正式推荐混淆；
- 决策身份：策略、交易日、local/hybrid、评分档位与真实模型 ID/hash、计算/冻结时间和数据来源时间；
- 解释：过滤漏斗、模型/成本门、本地与模型风险、DeepSeek outcome、集中度跳过和首要空结果原因；
- 数据状态：ready、not_ready、degraded、stale，以及当前结果是否为冻结或 `close_fallback`。

页面必须区分“未评分”“已评分但分数不足”“预测成本后净效用均不大于 0”“全部风险受限”和“合法空仓”。
模型信号分、预测超额、估算成本和成本后净效用分别展示，成本不得把评分统一清零。数据陈旧时可以展示最近
有效结论，但必须标记陈旧/降级，不能把它显示为新推荐。

最终 V2 评分口径只产生 `ScoredDecision`；Long 只产生 `LongProjection`，`score_status=not_applicable`。
long 原生当前投影按配置保留完整固定名单，报价缺失时保留占位或同交易日最近有效报价，不得自动换股；
long 不借用评分字段伪造荐股决策形状，DeepSeek 物理 HTTP 请求始终为 0。

## 11. 逐环节优化空间与优先级

所有优化项当前均为研究建议，不是已生效规则。没有通过第 12 节历史 point-in-time 样本外验证前，只能说明
“可能改善”或“需要验证”，不能宣称提高收益，也不能据此修改生产阈值。

优先级：“最高”是先补齐可验证数据和收益闭环；“高”是直接影响净收益与尾部风险的候选；“中”是在前两类证据完备
后再做的精细优化；“保持”表示当前无需为了收益主动改动。优先级不用 `Pn` 编号，避免与评分档位混淆。

及成本感知选择，最后才研究 DeepSeek 权重、动作门槛和 TopK 集中度。这个顺序避免在数据和标签不可靠时
反复调参，也避免把推荐数量增加误当成收益提高。

### 11.1 模块化目标边界

优化链保持“事实、信号、风险、成本、选择”分离，不能再由一个总分同时承担预测、风控和可交易性语义：

- `CanonicalOutcomeEvaluator` 唯一解释进场、退出、复权、停牌、涨跌停、基准、成本和 D25 四个 horizon，
  其产物是验证真值，不修改正式决策或冻结记录；
- `FeatureSpecCatalog`、`FeatureCalculators`、`FeatureComputationPlan` 与 `FeatureVectorManifest` 共同约束
  特征身份、单位、方向、可见时间、依赖、缺失规则、训练/在线顺序和内容 hash；
- `CandidateRecallLedger` 记录每只股票第一次失去资格的边界，并用历史 oracle TopK recall 衡量候选预选是否
  在评分前错失了事后高净收益股票；它只归因，不能为了提高召回自动放宽硬过滤或候选阈值；
- `AlphaScore` 只表达预测信号，`RiskDecision` 只表达 penalty/veto，`ExecutionCost` 只表达交易成本与容量；
  `SelectionUtility` 首先只用于隔离研究和 Shadow，不得替换当前生产固定融合、动作门和 TopK；
- `ShadowMonitor` 在不改变正式推荐的前提下，对全候选特征、分数、风险、成本、不确定性、延迟和成熟 outcome
  做漂移与增量收益归因；任何生产变更仍须通过第 12 节并由用户明确授权。

训练/在线同口径、缺失可解释，再比较样本外成本后收益。数据质量字段只能做资格、风险或诊断，不能因“更新”

| 市场、板块、行业与流动性暴露 | 横截面残差化、稳定性分层 | 默认否 | 用于去共同暴露；若要作为 alpha，必须另立候选，不能重复表达同一信息 |

| 成本、容量与可执行性 | `ExecutionCost` 和成本执行门 | 否 | 只决定预测是否覆盖交易成本，不改写模型原始信号分 |

### 11.3 召回、不确定性与机会成本

候选召回必须按实际链路逐层计算：历史总体中的 oracle TopK，经过永久资格、动态硬过滤、字段资格、板内
预选和每板上限后分别剩余多少；每只丢失股票只归到第一个拒绝边界。oracle 只能由冻结研究集中的未来
20bp 成本后净超额定义，不能进入生产输入。报告同时给出 Top10/20/50 recall、逐板 recall、不可交易率、
严重亏损率和候选规模/延迟，避免用扩大候选池虚增事后召回。

`CandidateRecallLedger` 的 oracle 每日从点时数据集全部股票按“20bp 成本后净超额降序、股票代码升序”固定
排序，TopK 分母为 `min(K, 当日总体数)`，不因收益为负、后来被过滤或候选模型未评分而删除；逐板 recall
是同一个全市场 oracle TopK 按板块拆分，不另建事后板内 oracle。召回按每日分子/分母跨日微汇总，不对
日 recall 做简单平均。阶段顺序固定为总体、永久资格、动态硬过滤、字段资格、候选阈值、每板上限、评分、
风险、动作、集中度；到达集中度后仍保留的行记为 `selected`。每行只允许一个最早拒绝边界，已经在数据集
边界被拒绝的行不得伪造后续追踪，通过每板上限的行则必须具有绑定数据行 hash 的完整后续追踪。

每个阶段的不可交易率和严重亏损率都以该阶段实际剩余行作为分母；严重亏损继续使用 Tomorrow
`MAE/ATR20 <= -1.5` 的统一 outcome 标签。候选规模记录剩余行数，延迟记录从总体开始到该阶段结束的累计
毫秒，并由所有日期一致的延迟证据 hash 绑定测量方法与环境；跨日给出候选总数/均值及累计延迟 p50/p95。
点时数据集、任一日后续追踪、行 hash 或延迟证据身份不足时，整个归因报告返回
`historical_data_insufficient` 且不保留部分日结果。账本固定不读取终端留出、不接生产评分、不放宽阈值，
也不能把 fixture 指标解释为真实收益或生产准入。

不确定性必须独立校准：严重亏损概率至少报告 Brier score 与 ECE，预测区间报告覆盖率，模型分歧和 OOD
距离报告分桶后的净收益与尾部风险。任何不确定性动作只能是风险收缩、观察、veto 或同分稳定排序；其收益
价值必须与放弃高 alpha 股票的机会成本一起报告。

风险、成本与不确定性研究使用四个互不替代的有类型对象：`AlphaScore` 保存未扣风险的信号分、扣成本前预测
超额和模型/特征向量身份；`RiskDecision` 独占一次性 penalty、veto、结构化风险事实、严重亏损概率、预测区间、
模型分歧、训练窗口分歧、OOD 与缺失不确定性；`ExecutionCost` 独占完整往返成本、容量、参与率和成本场景；
`SelectionUtility` 只在隔离研究中计算“alpha 预测超额减完整往返成本”的净效用，并把风险后本地分、严重亏损
概率和不确定性作为约束或稳定同分依据。不得把成本换算成分数重复扣除，也不得让风险或数据质量成为正向 alpha。

DeepSeek 增量必须在同一父样本、同一逐日 Top6 与板块/行业集中度约束下比较 local-only、结构化 facts veto、
固定 68/32 三组。固定组仍严格使用既有融合公式，本地风险已在 `local_score` 扣除，融合时只允许再扣经 schema、
证据和事实身份验证的 `deepseek_risk_penalty`。失败、迟到、预算耗尽或 abstain 全部保留 local；自由文本不能直接扣分，
也不能改变 veto、排名或报告身份。每组至少报告选中样本成本后净超额、严重亏损率、应用/回退数量，以及相对
同一日、同一集中度约束 oracle 的机会成本；缺少真实点时父证据时必须零读取评价收益并返回
`historical_data_insufficient`，不得用 fixture 或 15:00 收盘代理填造校准结果。

## 12. 收益验证与变更门禁

### 12.1 评价口径

所有评分策略验证只使用历史 point-in-time 数据。线上 T+1 结算只用于正式推荐历史与运行监控，
不进入评分训练、校准、历史门禁、自动调参或生产切换。研究路线不改变安全规则、冻结记录或 DeepSeek 预算。

#### 12.1.1 进场、退出、可交易性与复权

历史回溯的进场价固定为该策略决策锚点的点时 `anchor_price`：Today 为交易日 D 的 11:20，Tomorrow 和
D25 为 D 的 14:50。锚点必须属于 `Asia/Shanghai`、价格有限且大于 0，并具有当时已生效的证券资格、交易
状态和复权因子。收益计算把进场价与未来价格转换到同一前复权基准；未复权价格只用于判断当时真实涨跌停、
停牌和可执行性，禁止混用 raw 进场价与 qfq 退出价。

Today 和 Tomorrow 的退出价为 T+1 交易日的前复权收盘价。D25 分别以 T+2、T+3、T+4、T+5 的前复权
收盘价形成四个 horizon。进场时停牌或一字涨停不可买的股票不进入可执行样本；普通涨停但存在合法成交证据
仍须保留该证据。计划退出日停牌或一字跌停不可卖时不得伪造成正常成交或删除样本：主标签使用该日可验证的
前复权收盘 mark-to-market；供应商没有有效收盘时以前一有效前复权收盘 carry-forward，并记录
`exit_untradable`，另以首次恢复可交易日收盘报告延迟退出压力结果。其它涨停、跌停都按相同规则保存价格和
可交易标记，不因事后收益好坏改变样本。

#### 12.1.2 收益、D25 聚合、基准与成本

每个 horizon 的净超额固定为：

```text
gross_return_h = (exit_price_h / entry_price) - 1
net_excess_h = gross_return_h - benchmark_return_h - round_trip_cost
d25_aggregate = (net_excess_T2 + net_excess_T3 + net_excess_T4 + net_excess_T5) / 4
```

D25 当前聚合标签是四个 horizon 的算术平均，同时必须逐项报告 T+2、T+3、T+4、T+5，不能用均值掩盖
任一 horizon。基准身份固定为 `point_in_time_local_only_equal_weight`：在同一交易日、同一策略锚点，使用
当时已生效资格、硬过滤、必需字段与进场可执行性均完整的股票组成基准股票池，按股票等权计算各 horizon
收益；不得使用今天的成分股反推历史，也不得让候选模型结果改变基准人口。策略与基准必须使用同一人口定义，
合法空仓日仍进入分母并按现金组合结算。

成本是一次完整买入加卖出的 round-trip cost，并从每个 horizon 扣一次。20bp 是主评价成本；50bp 是准入稳健性门，
用于证明收益不依赖过低成本假设；100bp 只用于压力测试和尾部报告，不作为主优化目标，也不能
单独授权生产。必须同时报告三档结果；20bp 与 50bp 门禁不通过时，即使 0bp 或毛收益为正也不能晋级。

#### 12.1.3 MAE、严重亏损与终端留出

对进场日至目标退出日内所有实际交易日，使用同一前复权基准计算带符号最大不利变动：

```text
MAE = min((low[t] / entry_price) - 1)
MAE/ATR20 = MAE / (ATR20_at_entry / entry_price)
```

所以 MAE 与 `MAE/ATR20` 均不大于 0，越负表示盘中不利波动越大。Today/Tomorrow 使用进场至 T+1 的
最低价；D25 使用进场至 T+5 的最差值，并可同时报告各 horizon 的区间最差值。ATR20 只能由进场锚点前
已经可见的前复权日线计算；缺失、非正或穿越使样本不具备风险标签资格。严重亏损阈值为 Today/Tomorrow
`MAE/ATR20 <= -1.5`，D25 `<= -2.5`。

终端留出至少 200 个交易日。开启前必须满足：点时字段/单位/复权/资格完全一致，训练和确认已结束，增量计算
只改变效率且已证明同源，完整的 alpha、风险、成本、不确定性、DeepSeek、融合、动作与 TopK 选择链已经固定并
通过确认门；候选规范与父 hash 已冻结，留出日期和 date-set hash 已封存，状态仍为 `terminal_holdout_not_opened`，
且任何候选选择都没有读取留出收益。满足后只允许原子地打开一次，同时写入准确日期、父 hash 和打开证据；
第二次或竞争打开必须返回 `terminal_holdout_already_opened`，不得再次读取、换候选或覆盖原报告。完整
point-in-time parity、各市场/波动/流动性状态样本和一次性打开证据缺一项，均保持留出关闭。

至少报告 Rank IC、Q1–Q5 单调性与 Q5-Q1、Top10/20/50 和正式 Top6 净超额、20bp 与 50bp 成本敏感性、
严重亏损率、最大回撤、胜率、换手、容量、板块/行业/单股集中度以及不同年份和市场状态稳定性。
严重亏损率不得高于同口径生产基准；合法空仓日必须结算为现金组合。固定 68/32 融合在任何挑战者验证中
都作为当前生产边界保留。

### 12.2 待验证收益路线

数据按交易日排序，训练、校准、确认和终端留出不重叠；禁止随机拆分、未来标签、同日穿越和看完结果后换
候选。边界保留明确 embargo，最终留出至少 200 个交易日且只开启一次。状态只允许：

- `historical_point_in_time_parity`：训练/在线点时口径已证明一致；
- `historical_data_insufficient`：字段、日期、身份或样本不足；
- `historical_rejected`：证据完整但收益、风险、成本、排序或校准门禁失败；
- `historical_validated`：单次历史终端留出通过，但仍为 `production_authority=false`；
- `terminal_holdout_not_opened`：前置门禁尚未满足，终端留出不得查看。

每个候选在读取评价收益前固定策略、持有期、进场价、退出价、停牌/涨跌停处置、复权、训练代理与生产锚点、特征、窗口、切分、成本、指标、统计功效、
停止条件和生产权限。报告必须绑定规范、父归档、manifest、模型/候选和证据 hash；同内容重放幂等，不同内容
冲突。历史通过本身不生成晋级档案，也不授权后台自动更新；生产变化必须另立用户授权批次。

研究顺序固定为：收益真值与结算契约、统一特征合同、点时数据资格、点时数据集、候选召回归因、有限参数族
研究、V3 训练与开发/确认、增量特征计算、风险/成本/不确定性与 DeepSeek 消融、完整链冻结后一次性终端留出、Shadow 与人工生产
授权。前一阶段的口径、输入 hash 和门禁未闭合时不得读取后一阶段评价收益。BaoStock 日线不能单独证明
Tomorrow 14:50 的点时收益；历史 11:20/14:50 分钟来源必须先做能力审计。若不能证明真实点时数据，对应
研究保持 `historical_data_insufficient`，不得用 15:00 收盘价冒充 14:50，也不得恢复未来日 collector。

当前资格审计已验证这条失败关闭边界：2000 日日线归档已经封存正式 manifest，日线和训练事实 checkpoint
均覆盖 5453/5453 只，全体日线单元覆盖率为 99.9976%。历史行业进一步审计了 5453 只和 9,085,235 个实际
交易日期，既有区间覆盖 8,931,889 日，3521 只完整、1932 只缺 153,346 日；虽然 6326 条事实没有分类冲突
或时间穿越，但封存的 BaoStock 证据没有可证明的 `queried_at`，合格股票仍为 0。Tushare 候选接口当前权限
不足且没有取得样本，既有免费分钟来源也不能提供 2022-01-04 的 11:20/14:50 锚点。因此下一阶段仍被阻塞，
不能读取收益、训练 V3 或修改生产档位；完整日线和既有工程训练 checkpoint 都不得被误解为点时数据资格通过。

有限参数族研究每次只改变一个参数族并保留现有六项 alpha 对照，采用 Holm 控制多重检验，同时报告成本、
风险、容量、换手和不同市场状态。DeepSeek 必须比较 local-only、结构化 facts veto、当前固定融合三组增量；
不能稳定改善成本后净收益和尾部风险时，应缩小用途而不是增加权重。`SelectionUtility` 即使历史通过也先停留在
Shadow，只有生产门禁全部通过且用户明确授权，才允许另立生产变更批次。

每个有限参数族在开发/确认收益读取前固定 14:50 锚点、父数据/召回 hash、候选公式与单位、唯一预选候选、
日期集合、5 日移动区块、10000 次 bootstrap、Holm 0.05 和 95% 全体/逐板覆盖。20bp 与 50bp 相对六项
alpha 对照的置信下界必须为正；Rank IC、Top10/20/50 和 Q5-Q1 必须改善，严重亏损、最大回撤、换手和容量
短缺不得劣化，任一市场状态不得反向。100bp 只报告压力结果。父点时数据或候选召回不足时零读取评价收益并
返回 `historical_data_insufficient`；证据完整但任一门失败时返回 `historical_rejected`，不得滚动搜索其它因子。

### 12.3 当前证据与可复用研究候选

这里只保留影响当前策略选择的结论。详细工件身份、hash 与交付证据统一见 `03_工程实施.md` 和 `CHANGELOG.md`：

- 旧历史候选路线已经终止，当前没有可继续晋级的候选；新的候选必须另立未读取新收益的研究身份。
- V2 的平均成本后净增量证据强于 V1，但不能据此断言 V2 未来更能挣钱；其严重亏损、换手和 Q5-Q1 门禁
  已失败。V1 同口径平均净增量为负。不设跨年配对采集任务。
- V2 人工越权生产切换只表示 `manual_user_override`，不表示 `historical_validated`；自动更新仍关闭，严重
  亏损概率仍未建模。历史身份与完整性 hash 不在评分权威文档复制。
- 已知强制本地风险在候选收益上界中仍记为 `mandatory_known_local_risk_penalty`，不得假定已确认风险消失。
- 候选研究必须保持财务/公告 `published_at` 与行业 `industry_effective_at` 的点时边界；成本只能形成执行
  效用，不能改写模型信号分。
- 严重亏损概率通过独立校准和检验前保持 `loss_probability_status=not_modeled`。

这些候选都不得自动训练、调权、晋级、激活或回退。`automatic_model_update=false` 是固定生产边界。

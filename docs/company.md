# company全量初始化、增量更新与断点续传重建设计

本文保存用户确认方向下的可执行设计方案，不表示代码已经实现或验收通过。业务字段以《下载训练》DB01、DB02及枚举协议为准，评分语义以《评分逻辑》为准；实施时同步更新《工程设计》和《下载训练》的相关运行合同。实施进度和验证证据只记入《工程实施》阶段318，不在本文维护第二份进度台账。

## 1. 用户目标与重建边界

- 用户自行清理`data/company`，新实现不迁移、不导入、不兼容旧公司数据或旧断点。
- 删除和重建范围仅限公司资料。行情历史、训练样本、模型、推荐冻结记录不受影响。
- 先完成ST资格过滤，再创建公司资料任务。当前ST、*ST及已确认曾经ST的股票不进入目标总体；资格未知或过期未核实的股票暂缓，不按非ST处理。
- 第一次执行`./run.sh sync company`初始化全部目标股票最近365天内的所需公司资料；可中断，但不能因分批而要求用户逐项执行命令。全量仅指一年窗口内的全量，不指上市以来历史。
- 初始化途中再次运行，从已提交步骤继续；初始化完成后再次运行，只获取上次采集断点至本次执行截止时间内的新资料和修订，并恢复旧失败任务。
- `./run.sh sync company --fill`使用同一账本，优先补已有缺项和到期失败；不创建第二份完成状态，不强制重下成功内容。
- 每股在`company_facts`保存一条当前主快照。独立风险、利好、减持、解禁和证据仍使用字典中的关联表，共同组成一份完整、有类型的公司快照。
- 程序启动统一预读正式快照参与荐股。评分热路径不抓公告、不解析PDF、不读取raw、不查询公司数据库。

“首次全量”是一次初始化作业，可能跨多次进程运行完成；不能把每次进程启动当成一次新的全量初始化。

## 2. 必须成立的续传约束

1. 同版本、同处理规则已经发布成功，重复执行命令的正文下载次数为0。
2. 完整PDF已在本地，失败恢复只能从分析开始，不能重新下载。
3. 分析结果完整且身份有效，失败恢复只能从发布开始，不能重复下载、重复分析。
4. OCR成功页跨进程保留；恢复从第一张未完成页开始。
5. 原文已按规则清理，但正式成功凭证存在，仍视为完成，不能重新入队。
6. 重复返回的目录记录只做幂等登记，不重置文件、分析或发布状态。
7. 并发、缓存、日志、调度间隔、超时参数调整，不使成功结果失效。失败任务的重试策略可以变化，但不得因此重开成功任务。
8. 来源真实修订、文件损坏、输入丢失或结果规则变化导致的重新处理，必须有明确原因和数量，禁止全表重置。
9. 下载完成、分析完成、正式发布完成、业务资料完整是四个不同概念，不能共用一个布尔字段。

## 3. 首次全量的范围和固定截止时间

每次作业开始获取带时区的`Asia/Shanghai`时刻`T0`，作为该次新发现资料的固定上界；耗时、deadline和等待使用单调时钟。执行期间不把上界不断追到当前时间，否则全量永远无法收尾。

历史查询下界固定为`L0=T0-365天`，公告、风险、财务等资料仅采集`[L0,T0]`内披露或正式修订的信息。上市日期晚于L0的股票以其上市日期作为更晚下界。禁止为初始风险、原事件、合同参考年度或字段补缺向L0之前额外回溯；`--fill`同样受此边界约束。只有来源存在可识别的正式修订证据时，才可按窗口内修订时间纳入旧报告，不能把重新抓取时间当成修订时间。

首次初始化按以下范围创建持久分区：

| 资料 | 初始化范围 |
| --- | --- |
| 股票总体和上市日期 | 当前官方名单先按公共参考ST资格过滤，仅纳入已核实合格股票；缺官方身份的股票明确失败，不伪造上市日 |
| 财务 | 最近365天内披露或正式更正的财报，选择最新有效结果；不向窗口外补取旧财报或合同营收依据 |
| 质押 | 截至T0的最新完整来源快照 |
| 解禁 | T0起未来180日的完整范围 |
| 公告和风险 | 最近365天内披露或正式修订的信息，仅下载风险/利好合同及字段核验所需正文，不查询上市以来历史 |
| 合同、回购、增持等 | 一年窗口内仍有效的事件及窗口内可取得的前置、修订和关联材料 |

采集范围最多向前365天，不安排更早的初始风险覆盖。资料完整性只评价该窗口，不能因缺少上市以来证明而让全部股票永久不完整，也不能宣称已核验更早历史。窗口内公告引用了窗口外原事件或财报、且缺少现有证据时，明确记录对应关联或字段未知，不自动扩大下载范围。未来180日解禁属于前视日程，不是向过去回溯；仍保留该既有前视范围。

目录全量不等于PDF全量：目录用于证明覆盖，只有字段填充、风险核验和证据关联需要的文件才进入正文下载队列。

初始化范围、目标总体、原始截止T0、每个分区游标和任务均持久保存。中断后先恢复未完成分区，不重新创建已经覆盖的日期片或已经拆分的父片。

### 3.1 ST预过滤与公告目录的关系

ST资格复用《下载训练》2.2节的唯一公共参考来源`market/reference/company_st.sqlite3`，不在company库另建ST名单。当前官方名称命中ST、*ST或可信证据确认曾经ST时排除；沿用既有ever-ST规则，摘帽不自动恢复。当天有效clear证据且官方名称未命中ST才进入目标总体，资格查询失败或证据未知单列暂缓。

- 首次初始化、普通增量及`--fill`均先准备资格，再登记或恢复公司业务任务。ST资格核验本身属于公共准备，不受“最多一年公告资料”限制；不能因公告窗口变化丢弃已确认ever-ST事实。
- 公告目录仍主要按市场和日期查询。来源返回全市场记录时，保留分页计数、成员及覆盖证明所需的最小元数据；不能先删ST条目再用剩余条数核对来源总数，否则会制造目录缺口。
- 创建正文下载、文本分析、OCR、字段补采和当前快照发布任务前，将关联股票与合格总体取交集。仅关联被排除股票的公告不派发；同时关联合格股票与ST股票的公告只下载、分析一次，结果仅为合格股票更新。财务、质押、解禁批量来源同样按合格总体筛选业务结果，不为ST股票单独补采。
- 每次续传先复核本轮资格。新确认ST的股票退出当前任务总体，其独占的未完成任务记录资格排除原因并停止派发，不能计为成功或持续拉低合格总体完整率。已有事实、成功凭证和必要证据保留；共享文件有合格股票引用时不能删除。资格未知的任务暂缓，恢复资格后沿原断点继续，不能重下已有有效PDF。
- 不因股票退出总体重置其他股票的日期分区、水位、成功回执或正文。运行中若收到新的可信ST证据，停止该股后续派发及当前快照发布；已在途文件按共享引用及缓存生命周期收尾。

## 4. 后续增量从什么时间开始

### 4.1 不以任意一条最新记录充当断点

禁止使用以下值作为全局增量起点：

- 某篇公告的最大发布时间；
- 某股的最后更新时间；
- 全表最大`published_at`或`checked_at`；
- 本轮进程退出时间；
- 最新一次成功HTTP请求的时间。

这些值不能证明更早的分区和其他股票已经完成，直接使用会漏数据。

### 4.2 两类进度，各有明确含义

采集库按“资料组件、来源、市场或真实查询范围”保存连续区间证明：

- **发现水位D**：截至该时刻，来源页已经完整核对，所有发现的任务已可靠登记。只有页数据、任务登记及游标提交成功才能前进。
- **处理覆盖P**：截至该时刻，已发现输入均已发布有效结果，或已发布明确的来源未披露/确定性未知状态；可重试失败不能使该范围闭合。P从区间和任务账本推导，不维护第二套独立完成真相。

D用于决定下次向网络查询什么区间，P用于解释数据库处理到哪里。某篇OCR失败可以使P落后，但不能让下次从P重新下载D之前所有资料。

### 4.3 有效新资料覆盖旧任务

发现顺序优先近期资料，但“时间更晚”本身不能作为跳过旧资料的依据。协调器在新结果正式提交后判断是否足以覆盖旧任务：

- 财务、质押等当前快照字段：同一股票、同一业务口径的新资料已核验，且覆盖旧任务负责的全部所需字段时，旧任务不再下载或分析。新资料缺项、待核实或失败时不能触发替代；旧资料仍可能作为带日期的最近有效依据。
- 同一报告或公告的正式更正、完整替代：必须有来源记录的明确版本关系，不能仅按标题相似或发布时间推断。新版本有效且不依赖旧正文后，旧任务转为已替代。
- 独立风险、减持、回购等事件不能按股票整体覆盖。只有同一事件身份、主体及关联证据成立，且新资料足以承担旧任务的全部核验用途时才能替代；新公告未提及旧风险不等于旧风险解除。关联核验或字段时点判断仍需旧资料时继续保留任务。
- 替代发生在有效结果提交之后。采集账本记录旧任务、新版本或正式结果凭证、覆盖字段/用途及替代原因；已替代不等于已下载或已核验。仍被其它任务引用的文件不能删除；新任务自身失败时不允许提前关闭旧任务。
- D仍要求来源目录分页完整，避免漏掉另一项风险；只跳过已证明多余的正文与分析。P把有有效替代凭证且全部用途均被覆盖的任务视为已满足，不被这类旧任务阻塞。若后续正式更正使替代依据失效，按依赖重新开放受影响任务，优先复用本地文件和分析结果。

终端分别统计实际下载、缓存复用、有效新资料替代三类数量，并可定位替代证据；不能把跳过数量算作提取成功数。

### 4.4 增量执行步骤

1. 固定本轮截止时间T1，完成公共参考及ST资格准备，确定本轮合格总体。
2. 先按资格更新已有任务的派发范围，再恢复仍适用的未完成任务；被排除或资格未知股票按第3.1节处理。
3. 本轮历史下界为`L1=T1-365天`；对各来源查询`max(D,L1)`至T1之间的资料，边界取包含端点并依靠稳定身份去重。D早于L1的未处理前缀标记为超出当前范围，不能伪造为已核验，也不再下载。
4. 对只支持按日期查询的来源，查询水位所在自然日到T1所在日；最后一天标记为截至T1核对，不能声称当天未来时间也已覆盖。
5. 公告额外回看最近7天的目录元数据以发现近期迟到和修订，所有回看和补缺均裁剪到L1；同版本记录不触发PDF下载。
6. 财务按披露/正式修订时间增量，不以报告期过滤掉窗口内正式披露的旧期更正；不为补字段查询窗口外财报。
7. 质押核对新的来源快照日期；日期及内容未变化则复用。
8. 解禁补齐随时间推移新增的前视尾部，并复核尚未发生区间的来源变更。
9. 全部分页和任务可靠登记后推进相应D；结果发布后推进相应P。

不重新下载整个一年窗口，更不查询一年之前的历史。来源提供修订更新时间或索引时，在当前窗口内按它增量处理；来源未提供可靠修订索引时，7天回看不能证明发现窗口内更早日期的所有追溯修改，这一来源限制必须公开记录。已知缺项通过同一任务账本在一年窗口内定向补采。

新上市或新增进入总体的股票只初始化其所需范围，不重置原有股票。退出总体后保留必要事实与证据，取消不再需要的新派发，不能影响其他股票断点。

### 4.5 示例

11月1日初始化截止到10:00，之后再次执行的截止为11月2日09:00：新增发现主要查询各来源已完成发现水位至11月2日09:00，另做近期目录元数据回看，历史下界始终不早于本轮截止减365天。11月1日留下且仍在当前窗口内的OCR任务从本地PDF和成功页面恢复，不重新下载整个一年窗口正文。

若初始化只完成一半，下一次继续原初始化分区与当前一年窗口的交集，超出当前下界的未完成任务标记范围过期；已经完成发现的范围可以追加10:00后的增量，不能把原作业丢弃并改为新的全量。范围过期不等于核验成功，不能用于填造连续覆盖。

## 5. 数据来源、字段与最新值规则

直接按《下载训练》的业务字段落实“来源→获取→提取→校验→发布→消费者”，不另建字段规范。财务、质押、解禁沿明确的结构化来源采集；公告、风险、减持、回购、增持和合同必须保留正式披露依据。结构化来源缺字段时，只登记一年窗口内可取得的官方材料补采任务；依据在窗口外则明确未知，不突破范围。

重点完成财务八指标、合同金额/税口径/年度营收及占比、减持日期/比例/完成披露、股份实际实施比例、风险主体/案件/解除关系。合同营收必须采用该公告时点已经可知且在采集窗口内有依据的对应年度数据，不能用未来披露数据回填过去判断；缺少窗口内依据时保留未知。

- 同一事实按业务日期、正式修订和披露时间更新，不能按下载完成顺序更新。
- 同报告期更正覆盖原财报；不同期不能拼成一份财报。
- 同一事件的新进展更新原事件，独立事件各自保存；解除必须关联原事件。
- 一年限制约束网络采集范围，不授权自动抹除已经确认且尚未解除的风险或必要证据；已有有效事实按现有业务规则维护，不能仅因原公告移出窗口就当作风险解除。该保留不触发窗口外重新下载。
- 最新资料缺项时保留原有效事实和日期，同时标记最新资料尚不完整，不能把旧值冒充最新值。
- 字段分为有效、不适用、来源未披露、待获取、提取失败、核验失败。字典允许的NULL保留NULL并带原因，禁止默认零、捏造金额或日期。
- 完成队列不等于所有字段有值；确定性未知可以结束无效自动重试，但继续影响资料完整性与现有荐股准入。

## 6. 稳定身份和唯一任务账本

| 身份 | 组成 | 作用 |
| --- | --- | --- |
| 来源记录 | 来源＋稳定记录标识 | 重复发现时定位同一条记录 |
| 来源版本 | 来源正式修订信息及稳定业务元数据 | 判断是否真实发生变化 |
| 文件内容 | 完整文件SHA-256 | 校验和物理文件去重 |
| 文本处理 | 影响输出的文本/OCR算法、工具及语义配置 | 判断文本检查点能否复用 |
| 结构化处理 | 字段、主体、事件核验规则身份 | 判断分析结果能否复用 |
| 发布输入 | 股票＋来源版本＋分析结果摘要 | 证明该输入已进入正式快照 |

来源版本不得混入抓取时间、分页位置、临时URL参数、重试次数等易变信息。来源版本改变但内容摘要相同，复用已有内容和适用分析结果，不重复OCR；各公告的主体和证据归属仍须分别校验。

采集SQLite为唯一任务账本，保存资料类型、来源版本、关联股票、步骤、文件路径/大小/摘要、分析和OCR检查点、规则身份、发布凭证引用、失败步骤/原因/次数/重试时间及运行占用信息。

主步骤：

```text
待下载 → 下载中 → 已下载 → 分析中 → 已分析 → 已发布 → 已清理
```

冷却、来源暂停、确定性未知作为明确状态附着在失败步骤上。OCR超时恢复分析，发布失败恢复发布，不能一律回到待下载。取得company独占维护锁并确认旧进程不再持有后，才回收其未完成执行占用。

## 7. 启动恢复算法

每次启动先检查持久状态，再发起网络请求：

1. 正式库已有匹配成功凭证：补齐调度状态，必要时清理文件；不下载、不分析、不重复发布。
2. 完整分析结果及身份有效：直接排入发布。
3. 完整PDF有效：直接排入本地分析；OCR成功页有效则继续剩余页。
4. 完整文件已落盘但任务未登记：按任务标识、大小和摘要重新认领，禁止立即重新联网。
5. 未完成下载：支持Range且版本验证一致时续传，否则仅重下该不完整文件。
6. 无凭证、无结果、无完整原始文件：才进入待下载。
7. 恢复完执行状态后，继续原初始化分区或D至本轮截止时间的增量发现；所有网络派发先裁剪到本轮一年窗口，过期未完成任务退出下载队列并保留范围过期原因。

首次空目录才创建初始化作业。发现只有部分库或文件损坏时报告明确故障，不偷偷把整个公司库当空库重建。

## 8. 异步调度与资源所有权

```text
来源发现 → 持久任务 → 下载 → raw文件 → 文本/OCR → 分析结果 → 正式发布 → 缓存清理
                 ↑                    状态和诊断均回到唯一协调器                    ↓
                 └──────────────────── 正式成功凭证确认 ─────────────────────────┘
```

| 角色 | 默认并发 | 职责 |
| --- | ---: | --- |
| 协调器 | 1 | 状态提交、执行占用、容量预留、派发、恢复与清理 |
| 来源发现 | 1 | 有界分页及结构化来源请求，返回有类型结果 |
| 文件下载 | 2 | 校验、分块落盘、摘要和完成结果 |
| 普通文本提取 | 2 | 从本地文件提取文字 |
| OCR | 1 | 默认一个文档，每个文档逐页识别和保存检查点 |
| 正式发布 | 1 | 结构化校验、事实合并和正式事务 |

执行器、客户端和子进程生命周期统一由组合根显式创建和注入。工作线程不自行写业务数据库，向协调器返回有类型的结果；领域层不访问配置、时钟、网络、文件或数据库。

所有可调运行参数统一在`config/download.json`的`company`段维护：`document_workers`、`text_workers`、`ocr_workers`分别控制下载、普通解析、OCR并发；`document_queue_limit`限制一次读取的任务数；`directory_batch_pages`、`document_batch_size`控制批次；`publication_batch_size`、`publication_interval_seconds`控制发布触发；`raw_capacity_bytes`、`raw_analysis_reserve_bytes`、`text_task_reserve_bytes`、`ocr_task_reserve_bytes`和`temporary_disk_reserve_bytes`控制容量。已有请求间隔、下载/解析/OCR总时限和单页时限、重试冷却及文件/页数上限也保留在同一配置段。协调器与正式写入保持一个所有者，不提供多写入线程开关。配置启动时校验范围及并发乘以任务预留的总额；资源不足拒绝启动，不静默降低并发或突破容量。上表为默认值，OCR允许按资源校验后的配置调节并发，每个文档仍逐页识别。

| 配置键 | 默认值 | 用途及约束 |
| --- | ---: | --- |
| `document_workers` / `text_workers` / `ocr_workers` | 2 / 2 / 1 | 下载 / 文本 / OCR执行位；范围分别1–8、1–8、1–4 |
| `document_queue_limit` / `document_batch_size` | 128 / 50 | 队列上限与批次；批次不能超过队列 |
| `directory_batch_pages` | 20 | 每轮来源分页预算 |
| `publication_batch_size` / `publication_interval_seconds` | 50 / 5 | 有待发布结果时按数量或等待时间触发提交 |
| `text_task_reserve_bytes` / `ocr_task_reserve_bytes` | 16777216 / 314572800 | 每个文本/OCR工作位的磁盘预留；并发乘以各自预留之和不得超过分析预留 |
| `raw_capacity_bytes` / `raw_analysis_reserve_bytes` | 2147483648 / 536870912 | 总缓存2GiB，其中分析预留512MiB |
| `temporary_text_capacity_bytes` / `temporary_disk_reserve_bytes` | 268435456 / 536870912 | 待发布压缩文字上限256MiB / 文件系统最低剩余512MiB |
| `document_download_timeout_seconds` / `document_parse_timeout_seconds` | 120 / 10 | 单次PDF传输 / 原生文字提取时限，秒 |
| `document_ocr_timeout_seconds` / `document_ocr_page_timeout_seconds` | 600 / 120 | OCR整篇 / 单页时限，秒；单页不能超过整篇 |
| `request_interval_seconds` | 1 | 同来源客户端共用的请求最小间隔，秒 |
| `document_transient_retry_seconds` | 900 | 瞬时失败冷却时间，秒 |

配置在命令启动时读取，修改后下次启动生效，不提供运行中热更新。增加OCR并发时需要同步增加分析预留及总容量，例如OCR改为2时，默认512MiB分析预留不足，必须显式调整，不能仅改线程数。调度和超时配置不属于成功输入身份；调整后保留正式凭证、完整PDF、完整分析结果及有效OCR页，仅受影响的失败重试策略重新评估。

调度优先级：已分析待发布、本地已下载待分析、可恢复OCR、到期失败、新下载。同级按等待时间推进；来源发现分页穿插运行，不能等整个一年目录下载结束才分析。文本任务转OCR后释放普通分析工作位，不占线程等待OCR。

任务可以有上万条，但存在SQLite中。每次读取至多128条任务元数据，执行器只接收与工作位和容量相匹配的有限任务，不创建上万个Future。来源请求共用明确的限速与退避时间线，不能每个客户端各自限速造成总体请求翻倍。

累计50篇分析结果、首个结果等待5秒、缓存需要释放或正常收尾时触发发布；无结果不做空发布。网络请求和OCR不占用SQLite写事务。

## 9. raw硬盘缓存与内存

raw在硬盘，不是内存队列。保存下载中`.part`、完整PDF、提取文字、OCR当前页/成功页检查点、待发布分析结果及短暂解析工作文件。

| 参数 | 默认值 |
| --- | ---: |
| raw文件总容量 | 2GiB |
| 分析、OCR、发布预留 | 512MiB |
| 下载和待分析输入可用上限 | 1.5GiB |
| 文件系统最低剩余空间 | 512MiB |
| HTTP传输分块 | 64KiB |
| 单PDF硬上限 | 64MiB |

全部配置归唯一下载配置，不分散硬编码。总量包含实际文件和未兑现预留，预留随实际写入扣减，不能重复计算。所有解析临时文件归受管raw工作目录，不能转移到系统临时目录绕过容量限制。采集SQLite及WAL单独监测，磁盘余量检查覆盖所有实际写入。

派发前预留空间；文件长度未知按上限预留。达到下载配额后停止新派发，让分析、发布和清理继续。不能删除未完成文件腾空间，不能把分析保留空间让给下载。大文件按容量减少并发；单任务无法在配置内处理时明确报容量错误，不无限等待。

下载按64KiB流式写文件并计算摘要，不累计整篇PDF。解析子进程直接读取文件路径，不通过stdin再次复制整篇PDF。内存仅保存有限任务元数据、当前文字与分析对象；OCR一次一页，不同时渲染整篇。父进程和子进程树分别测量峰值，不以2GiB磁盘上限冒充内存上限。

## 10. 下载、分析、发布如何判定完成

### 10.1 下载

HTTP正常结束、大小合法、可靠Content-Length一致、基本格式通过、摘要完成、文件持久化及原子改名、任务状态提交成功后才算已下载。先落文件再记状态，两者之间中断通过恢复器认领文件。

普通16MiB和扩限64MiB是处理界限，不得造成同一文件下载两遍。在单次流式传输中超过普通界限时切换后续处理策略，直到完整接收或达到硬上限。网络中断只有在服务端支持Range且版本验证一致时继续字节，否则仅重下这一未完成文件。

### 10.2 分析与OCR

全文提取/OCR完成、质量检查通过、字段和主体/事件校验结束、完整分析结果可靠保存后才算已分析。分析结果可以是有效事实，也可以是明确的来源未披露/待核实；半篇OCR不是已分析。

OCR默认单页120秒、整篇单次尝试600秒。每页完成后原子保存文字、质量、页摘要和策略身份，再删除当前页图像。重启校验PDF及检查点，从第一张未完成页继续。保持页数、图像边长、累计资源和文字质量限制；不降低置信度门、不发布截断结果。

### 10.3 正式发布

正式库同一事务提交当前主快照、事件/证据和输入成功凭证。凭证关联公告版本、分析身份、结果摘要及股票，是唯一的发布完成依据。采集库记录仅用于调度；正式提交后、调度状态更新前崩溃，读取凭证补齐，不重新下载或发布。两个SQLite库之间不假设天然原子事务。

相同内容重复发布不改变原有效发布时间。旧版本或旧报告期结果迟到不得覆盖新版本。

## 11. 清理和重复处理边界

仅在正式凭证匹配、全部关联股票发布完成、没有执行引用、没有未完成OCR依赖、必要关联线索已保存后清理。

顺序：登记待清理→删除PDF/文字/页面检查点/临时结果→确认删除→释放引用和容量。删除失败只重试清理，不撤销正式事实。文件删除后仍保留来源定位、摘要、成功身份和凭证，因此不会再次判定为待下载。

未关联事件保留必要的结构化候选用于本地重算。新增同股事件不能重开全部未关联正文，只处理类型、时间和案件线索可能匹配的候选。局部文本、OCR或字段规则变化只影响确实依赖该规则的任务，优先复用本地输入；禁止清空全部成功凭证或全表重置正文状态。

新规则确需原文且原文已按规则清理时可以重新获取，但必须单独记录“规则变化且原文已释放”。有限缓存不能承诺任意规则升级永不联网，但必须保证同版本、同规则已成功任务不重下。

## 12. 错误分类、重试与诊断

复用统一失败诊断组件与数量配置；公司采集库保存有界失败历史。失败记录和调度状态职责分开，成功后保留原故障并记录恢复结果。

记录运行/任务/股票或范围、来源和版本、摘要和规则身份、失败步骤、稳定错误码、因果链、耗时/阈值、尝试次数、字节或OCR页码/质量、重试条件与时间、恢复时间及结果。不写密钥、完整载荷或正文。

| 错误 | 需要的证据 | 恢复方式 |
| --- | --- | --- |
| 网络/HTTP/限流 | 连接、响应头、正文阶段，状态码、字节和耗时 | 有界重试与来源退避，完整文件不重下 |
| 目录变化/并集缺口 | 分区、父计数、子并集、游标及修订信息 | 重核变化查询、缩小范围，保留成功页 |
| PDF损坏/加密/超限 | 文件摘要、大小、页数和工具结果 | 文件校验、扩限或确定性未知 |
| OCR超时/质量不足 | 页码、总页数、渲染/识别阶段、字符数和置信度 | 本地PDF及成功页复用 |
| 字段/主体/单位歧义 | 字段名、来源证据、缺失或歧义原因 | 定向补采或核验，不无限重下 |
| 同案关联失败 | 候选身份、类型、时间与关联线索 | 本地关联分析 |
| SQLite/发布错误 | 事务步骤、锁、空间和完整性 | 从对应提交步骤恢复，保留旧快照 |
| 磁盘/清理错误 | 使用量、预留、剩余空间及文件状态 | 回压或清理重试 |

瞬时重试沿现有有界重试与15分钟冷却合同；确定性失败在同内容同策略下不做每日重试。403/429等来源暂停分别限制对应网络来源，不停止可继续的本地分析和发布。诊断区分已证实原因与待定位原因，不能将所有错误归为来源暂缓。

## 13. 终端输出和完成语义

启动先输出：初始化还是增量、本轮固定截止、官方股票数、ST/曾经ST排除数、资格未知暂缓数、合格目标数、各来源D/P、继承的已发布任务、已有PDF、已有分析结果、可恢复OCR页和真正需下载数量。公司资料完整/部分/未发布的分母只使用本轮合格目标数，资格暂缓单列，不能伪装为资料完整。

运行时分别显示：目录待补、待下载、下载中、已下载待分析、普通分析、OCR页进度、已分析待发布、待清理、冷却、确定性未知、字段缺项、raw实际/预留占用和暂停原因。

本轮与累计计数分开。累计进度从持久账本计算，不因重启归零。分母变化单列新增发现、真实修订、撤回或范围变化原因。重下必须分类显示来源修订、文件损坏、未完成下载、规则变化等原因，不能无解释地出现几万篇待下载。

- 初始化/增量发现完成：对应截止的来源分页及任务登记完整。
- 处理完成：没有未处理或可重试任务，确定性未知另列。
- 资料完整：按业务字典、覆盖与核验结果评估，不能由队列为空推导。
- 冷却任务仍存在时显示待续传及最早重试时间；不能显示全部成功。

## 14. 中断恢复矩阵

| 中断位置 | 恢复动作 |
| --- | --- |
| 初始化目录一半 | 原作业、原截止、原页游标继续，不重建全量 |
| 下载一半 | 校验版本和Range，能续则续，仅该文件必要时重下 |
| 完整文件落盘但状态未提交 | 摘要校验并重新认领 |
| 文本提取失败 | 本地PDF重试 |
| OCR到22/32页 | 成功页复用，继续未完成页 |
| 结果落盘但尚未发布 | 直接发布 |
| 正式提交后调度状态丢失 | 正式凭证补齐状态 |
| 文件删除后进程退出 | 保持完成，不回到待下载 |
| 新版本覆盖旧任务 | 旧结果不得覆盖新事实 |
| 任务失败导致P落后 | 恢复该任务；D之前其他成功正文不重下 |

正常Ctrl+C停止新派发，保存可恢复文件与检查点，停止并等待线程和子进程后释放维护锁。强制结束通过上述协议恢复，不依赖退出时一次性保存全部进度。

- 跨日续传及停用超过一年后再运行时，旧范围不伪造为完成，不重下已成功内容，也不补采过期前缀。

- 一个来源失败不能借用另一来源最新时间跳过缺口；一篇OCR失败不使其他正文重复下载。
- 解禁窗口随日期延伸，不能只更新公告而让前视覆盖过期。

### 16.2 续传与缓存

- 同版本同策略成功任务连续启动三次，正文网络下载次数均为0。
- 已有PDF只分析；已有结果只发布；已发布且原文删除仍保持完成。
- 下载落盘、登记、分析、正式提交、状态更新、清理各处故障注入后结果一致。
- OCR原14页和32页失败样本实测；中断后的成功页不重复识别。
- 重复目录和调度配置变化不增加成功任务下载数，单篇修订只影响相应版本。
- 最新完整有效快照或明确完整替代版本提交后，旧任务不再下载，并能查到替代凭证；缺项、失败、不同主体/事件及仍有证据依赖时不能跳过旧任务。替代依据失效仅重开相应依赖。
- 2GiB缓存满时分析和发布持续推进，无容量死锁；共享文件不提前删除；孤立文件可认领或安全清理。

### 16.3 字段、诊断与资源

- 按字典逐字段核对来源、单位、日期和荐股消费者，明确无法取得的字段及原因。
- 新旧报告期、正式更正、迟到结果、多起风险、风险解除、合同营收时点均正确。
- 各类失败的证据、重试步骤和最终恢复结果完整保留，未证实根因不伪装成已定位。
- 报告网络字节、真正重下次数及原因、文件/结果/页面复用、D/P差距、缓存峰值、父进程和子进程内存峰值。
- 预读与正式身份一致，评分热路径无公司SQL、raw访问或网络请求。

最终验收首先看“再次执行下载了什么、为什么下载、接上了哪个步骤”，不能只看终端是否打印完成；首次全量结束后，后续执行必须能用持久来源水位证明其增量范围。

# Tomorrow 日线收盘代理训练方案

## 1. 文档定位

本文总结此前关于历史数据训练、验证和生产利用的讨论，作为后续工程批次的设计输入。本文不是候选、
过滤、公式、风险、融合或排名策略的权威来源；这些规则仍以
[`docs/recommendation-strategy.md`](recommendation-strategy.md) 为唯一权威，产品和运行边界仍以
[`docs/software-business-design.md`](software-business-design.md) 为唯一权威。本文与权威文档冲突时，
必须以权威文档为准并停止实施冲突部分，不能把本文当作生产授权。

本文提出的 Tomorrow 训练身份固定为日线收盘代理 `daily_close_proxy`。它使用完整日线收盘数据，不能作为第
15.1.32 节要求的 Tomorrow 14:50 点时一致性证据，也不能把历史结论表述为严格的 14:50 收益
验证。全部研究工件固定 `production_authority=false`；任何生产评分变化必须另立高风险生产变更批次，
先更新权威契约和机器测试，再完成实现与发布门禁。

## 2. 已确定的训练边界

- 目标是训练 Tomorrow 的本地基础评分，提高成本后、风险约束的 T+1 净超额收益，不以推荐数量、训练
  误差或单纯涨跌命中率代替收益目标。
- 第一版采用全股票统一参数模型，不为每只股票独立拟合参数。个股差异通过自身收益、动量、波动、
  流动性和横截面位置进入统一模型，避免单股历史不足和参数过拟合。
- 被硬过滤或硬过滤证据不完整的股票不生成训练样本，不进入开发、确认、终端留出或未来生产推理；
  模型高分不能绕过一级永久资格或二级硬过滤。
- DeepSeek 完全不参与训练、验证、模型选择或历史收益门禁。离线研究不装配 DeepSeek 客户端，不读取
  历史模型文本、模型分数或风险扣分，也不执行固定 68/32 融合。
- 不实施逐股模型、大语言模型训练、贝叶斯搜索、遗传算法、无限次调参、在线学习、自动晋级、自动
  激活或自动回退，始终保持 `automatic_model_update=false`。
  > 每个策略一套统一模型 + 板块/行业/流动性/波动状态的分层修正 + 极强收缩的个股残差修正。


## 3. 为什么使用收盘代理

现有已下载历史归档是前复权日线，没有历史 14:50 快照。训练行因此只能使用交易日 `D` 的完整收盘
数据，并以 `D+1` 收盘结算结果。该口径能利用现有约 5000 只股票的历史日线，适合在个人 PC 上进行
可重复的表格模型研究，但存在明确限制：

1. `D` 日 15:00 收盘输入比生产 14:50 冻结晚约 10 分钟。
2. 当日最后 10 分钟的价格和成交量可能改变短周期特征、横截面排名与成本估计。
3. 日线研究只能回答“收盘代理模型在历史上是否稳定改善 local-only 组合”，不能证明同一增量会在
   14:50 完整复现。

因此，本文不要求获取或伪造历史 14:50 数据，也不使用 `D-1` 数据冒充 `D` 日近收盘输入。若未来要把
代理模型接入生产，必须把这 10 分钟的输入分布差异列为显式剩余风险；未修改权威策略前，本研究不得
创建 `v3`、活动配置或启动指针。

## 4. 训练人口与样本构造

每个历史交易日 `D` 生成一个完整横截面批次，股票日行必须满足以下顺序：

1. 按事实 `effective_at` 重放当时已经生效的一级永久资格；不能用当前 ST、退市、财务或违法状态反向
   删除更早样本。
2. 重放可由当日日线、上市日期、证券状态和已封存结构化风险事实证明的二级硬过滤。
3. 任一必要过滤字段或特征缺失时，记录 `filter_evidence_missing` 或明确缺失原因并排除，不能默认通过、
   填零或回退到当前事实。
4. 只有通过硬过滤且所有模型输入完整的股票才能形成训练行；过滤原因只作为审计计数保存，不进入模型
   特征，避免模型学习如何绕过硬过滤。
5. 股票池、过滤规范、日期集合、逐日人口和数据来源全部绑定内容 SHA-256；同身份同内容幂等，不同内容
   冲突失败关闭。

标签必须由独立 adapter 在特征封存后计算，特征侧不能读取未来列。主标签固定为：

```text
actual_net_excess_return =
    (close[D+1] / close[D] - 1)
    - eligible_universe_equal_weight_return[D+1]
    - round_trip_cost
```

基准人口与候选使用同一交易日、同一硬过滤资格和同一有效价格。`D+1` 尚未成熟、停牌、价格异常或基准
不完整时保持 `label_pending` 或按预注册规则排除，禁止用 0 代替未知。往返成本同时结算 20bp、50bp、
100bp：20bp 是主口径，50bp 是必须通过的保守口径，100bp 只作压力测试。

## 5. 特征和模型

首版保持少量、可解释、日线可重建的特征：

- 前复权 1、3、5 日收益；
- 20、40、60 日且跳过最近 5 日的残差动量；
- 同日市场、板块和板内对数成交额暴露的确定性残差化；
- 20 日平均成交额、Amihud、实现波动率和下行半方差，用于成本估计、样本分层与稳健性诊断，不在结果
  出现后随意扩充模型维度。

模型家族在读取确认段前固定为三个候选：

1. 正则化 Ridge 统一线性模型，作为稳定、可解释的控制模型；
2. 固定深度和叶子数的浅层 LightGBM，用于捕捉有限非线性；
3. Ridge 与 LightGBM 各 50% 的固定集成。

股票代码不得作为可记忆的类别特征。所有标准化、截尾、残差化统计和模型参数都只能由当前折训练段
拟合。默认资源上限为 2 个 CPU 线程和 4096MB 内存，按交易日流式读取，工件支持内容寻址和断点续跑；
相同输入、种子和版本必须产生相同模型及报告 hash。

## 6. 时序训练和验证

全部股票日行按完整交易日分区，禁止随机拆分：

- 最旧 60% 为开发段；
- 随后 20% 为一次性确认段；
- 最新 20% 为一次性终端留出；
- 两个边界各保留 5 个交易日 embargo，最终留出不足 200 个完整交易日时返回
  `historical_data_insufficient`。

开发段执行 5 折 expanding walk-forward。每折只使用预测日前已经成熟的标签拟合，对检验期同日全部
合格股票生成样本外预测，并保存入选与未入选记录。不能只保存 Top6、盈利股票或正式推荐，也不能用
股票日行数冒充独立交易日数。

开发段只允许在预注册的三个模型中选出唯一候选。随后 20% 确认段只评价一次，不得修改特征、参数、
成本、阈值或候选家族。只有确认段通过，才能通过单独命令一次性开启最新 20% 终端留出；看到终端结果
后不得继续调参并重新测试同一留出。

## 7. 离线评分和通过门禁

模型不能只按均方误差或涨跌准确率评价。每个样本外交易日都要形成完整的 local-only 模拟链：

```text
预测毛超额收益
→ 扣除该股估算成本
→ 正净效用在当日合格横截面映射为 0–100 base_score
→ 扣一次现有本地风险
→ 执行现有本地动作门、TopK 和集中度约束
→ 形成 local-only 等权模拟组合
```

当前活动 profile 的可重建 local-only 结果是配对控制组。模型必须同时满足：

- 5 个开发折的收益方向一致；
- 确认段和终端留出的 20bp、50bp 平均日组合净超额及其移动区块 bootstrap 95% 下界严格大于 0；
- 相对控制组的逐日配对净增量及其区块下界严格大于 0；
- 严重亏损率不高于控制组，平均换手增量不超过 5 个百分点；
- Rank IC 和 Q5-Q1 严格为正，容量与板块、行业集中度不劣化；
- 正收益不能主要集中于单股、少数股票、单板块、单行业或少数交易日。

任一主要门禁失败即封存为 `historical_rejected`；数据或过滤证据不足则封存为
`historical_data_insufficient`。否定结论是合法研究结果，不能通过增加模型、反复开启留出或降低成本
门槛制造通过。

## 8. DeepSeek 隔离与未来生产利用

训练、确认和终端留出到 local-only 模拟组合即结束。DeepSeek 不进入特征、标签、损失函数、候选选择、
收益归因或通过条件，研究命令不得消耗每日 168 次物理请求预算。

只有未来另立高风险生产变更批次、修改两份权威文档并通过完整发布门禁后，历史验证模型才可能按以下
方式接入：

1. 生产继续先执行一级永久资格和二级硬过滤；
2. 仅对硬过滤允许且特征完整的 Tomorrow 股票执行不可变模型推理；
3. 模型输出只替换 Tomorrow 本地 `base_score`，不与旧基础分再次混合；
4. 本地风险仍只扣一次，动作门、TopK、集中度、14:50 冻结和失败降级保持不变；
5. 最后才由现有生产链执行固定 68/32 融合，DeepSeek 仍只是独立实时复核层。

生产模型必须使用 wheel 内置、hash 校验的不可变 profile，不接纳任意外部模型路径。工件缺失、hash 不符
或特征契约不匹配时失败关闭；单股特征缺失时该股票不获得模型分，不使用隐藏启发式 fallback。历史通过
不得自动修改生产配置、覆盖 current/frozen 记录或激活模型。

## 9. 后续实施接口与工件

后续研究批次可在更新权威契约后增加以下显式离线命令；这些名称是本文的建议接口，不代表当前已经
存在：

- `research-tomorrow-train`：只读取开发段，执行 walk-forward 并封存唯一候选；
- `research-tomorrow-confirm --run-id ...`：只对封存候选执行一次确认；
- `research-tomorrow-holdout --run-id ...`：确认通过后一次性开启终端留出。

训练工件保存数据 manifest、日期与股票池 hash、过滤规范、特征顺序、预处理统计、模型文本、成本版本、
各阶段报告 hash 和最终内容 hash。不保存 pickle、DeepSeek 文本或分数、生产配置、注册表或活动指针。

推荐实施顺序为：先修改权威契约与文档契约测试，再建立日线训练人口和防泄漏标签，随后实现三阶段
离线命令及不可变工件；只有历史终端留出通过且用户再次明确授权，才单独规划生产接入。当前本文只完成
方案归纳，不表示训练能力、收益改进或生产模型已经实现。

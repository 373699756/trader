# 荐股评分逻辑

本文是候选、过滤、因子、评分、风险、排名及收益准入的唯一权威。
架构和Web见[工程设计](2_工程设计.md)，数据维护及训练见[下载训练](4_下载训练.md)，交付状态见[工程实施](3_工程实施.md)。

## 1. 目标、范围与当前结论

程序回答两个研究问题：哪些股票值得研究，以及支持这个判断的数据是否可信。分数不是上涨概率，也不是收益保证。

| 名称 | 研究目标 | 模型是否改变最终分 |
| --- | --- | --- |
| Tomorrow | 下一交易日T+1的机会与风险 | V1用模型排序分；V2/V3仅预测诊断和成本净效用门 |
| D25 | 未来第 2 至第 5 个交易日区间内具备上涨能力的股票 | 同上；使用自己的单一2–5日模型头 |
| Long | 固定研究池的当前行情 | 不评分、不排名、不冻结 |

V2/V3是两套模型档位，不是两种持有期。每档都有Tomorrow和D25两个独立模型头。
默认启动全部档位并展示V2来自用户选择，不表示其收益已通过验证；V3也没有自动晋级权限。

全新V1已获用户明确授权正式接入，与退役V1无关；它用模型排序分确定六席，动作仍通过本地评分、可靠度、时效和风险门，接入独立正式冻结和推荐业绩。

V1同时使用模型排序分和本地分local_score：模型排序分决定谁进入六席以及席位顺序，本地分决定入选后是否达到动作门槛。Tomorrow本地分达到78、D25达到76，且净效用、可靠度、时效、下行保护及风险门全部通过，才可形成可执行推荐；分别达到72、70但未达推荐线时为关注，低于关注线时为回避。其他门仍可进一步收紧动作。本地分不改变V1模型名次，回避席位也不从第七名补位；具体合同见第6.4、8.2节。

例如Tomorrow三只股票的模型排序分依次为98、95、92，本地分分别为70、75、82。在其他门全部通过的假设下，动作依次为回避、关注、可执行，但仍保持原模型顺序。模型第一名不等于无条件推荐，这只是说明性例子，不是真实荐股结果。

旧工程Shadow记录仍按原身份只读。下文local_score最终分合同适用于V2/V3；V1的独立分数与动作语义见第6.4节，V5保持工程Shadow。

第2–8节默认描述收盘前常规新决策；已有正式记录只读恢复及收盘补建的明确例外集中在第9节。local表示尚未经过DeepSeek升级，不代表常规链可以绕过模型门。

全文用以下标签区分事实：

| 标签 | 含义 |
| --- | --- |
| 当前 | 现有代码、配置实际采用的规则 |
| 目标，待实现 | 用户已确认方向，但仍须后续代码切换和验证 |
| 研究，未生效 | 需要样本外证据，不能直接修改生产参数 |

### 1.1 为什么这些信息可以用来选股

这里的“荐股”是：在同一时点可研究的股票中，用明确规则筛选出值得进一步观察的少量对象，并给出理由与风险。算法能够生成这份名单；名单是否比简单基准更有效，则必须用之后没有参与训练的数据检验。不能从“程序能算出分数”直接推导出“买入就能赚钱”。

程序尝试利用以下关系。它们是选股假设及设计理由，不是本项目已经证实的收益规律：

| 观察什么 | 为什么可能有选股价值 | 为什么仍可能判断错误 |
| --- | --- | --- |
| 多个期限的涨跌、均线和突破 | 检查价格变化是否具有持续性，而不只看一天涨幅 | 趋势可能反转，近期上涨也可能已透支预期 |
| 成交量、成交额、换手和尾盘位置 | 检查价格变化是否伴随交易活跃度变化，以及成交条件是否支持研究机会 | 放量也可能来自集中卖出；这些字段不能证明“主力买入” |
| 波动、回撤、下行空间与已核验风险 | 在机会相近时控制不稳定性，并排除已知不合格对象 | 过去低波动不能阻止突发事件，风险过滤也不能消除亏损 |
| 财务质量、价值和成长 | 为D25本地规则提供公司层面的辅助证据 | 基本面改善未必在未来2–5日反映到股价，便宜也可能长期便宜 |

这些信息分别进入硬过滤、本地评分、模型输入或风险门，并不是全部塞进同一个模型。例如V2/V3模型主要学习历史价格特征及共同暴露处理后的信号；新V1模型首发只读取完整历史日线的价格和成交额特征。财务、盘中行情和尾盘分钟行情的具体用途仍按第3–7节及附录区分。

### 1.2 V1、V2、V3、V5各自怎样工作

四个档位代表不同算法，不是“初级、中级、高级”，也不代表收益优劣。每档都分别处理Tomorrow与D25；Long不参与评分。

| 档位 | 模型学习什么 | 模型在选择中的作用 | 谁决定最终名次 |
| --- | --- | --- | --- |
| 全新V1 | 全市场共享的LightGBM排序器学习同日股票的相对优劣；独立Ridge估计毛超额收益 | 排序器提供排名依据，Ridge与成本门决定能否继续参与选择 | 模型排序分；已获人工授权正式接入 |
| V2 | 按行业拟合的LightGBM回归模型学习特征与未来毛超额收益的非线性关系 | 提供预测诊断，过滤预测净效用不大于0的对象 | 扣一次本地风险后的local_score |
| V3 | 按行业拟合的Ridge回归模型学习特征与未来毛超额收益的线性关系 | 同V2，但使用自己的模型、特征窗口和预测结果 | 与V2相同的local_score规则 |
| V5 | 按行业拟合TCN，读取60步OHLCV/成交额序列及辅助特征 | 预测毛超额收益，经校准和成本门过滤 | local_score规则；当前仅工程Shadow观察 |

#### V2：用一组决策树学习不同条件下的收益关系

LightGBM逐轮增加决策树，让新树修正已有预测的误差；本项目使用平方误差回归目标。树可以学习“某个特征达到什么范围时，另一个特征才有不同作用”这类条件组合，不要求所有股票始终遵循同一条直线。具体分裂条件由历史样本学习，不是人工写死的买卖口诀。[算法目标说明](https://lightgbm.readthedocs.io/en/stable/Parameters.html#objective)

本项目V2使用251个市场交易日的在线历史范围，包含短期收益、剔除最近5日后的中长期趋势、处理共同暴露后的趋势及长期市场状态。按行业拟合是为了允许不同行业存在不同关系；独立校准用于调整预测数值的尺度。更灵活的模型有能力拟合复杂关系，也更容易拟合历史噪声，不能据此认定V2比V3更准。

**V2模型不直接给最终推荐分加分。** 收盘前常规链先检查模型预测扣除成本后的净效用，合格对象再按本地规则评分和选席。因此，预测收益更高的股票，未必排在本地证据更完整、风险更低的股票之前。特征与实现见[模型合同](../src/trader/training/infra/profile/v2/contracts.py)、[拟合与校准](../src/trader/training/infra/model_fitting.py)及第6.3节。

#### V3：用受约束的线性关系估计收益

Ridge的基本形式是`预测值 = 截距 + 各项标准化特征 × 对应系数之和`。训练既要减小预测误差，也对过大的系数施加惩罚，避免相关特征使系数过度放大。这里的“惩罚”约束的是模型系数，不是股票风险扣分。[Ridge原理](https://scikit-learn.org/stable/modules/linear_model.html#ridge-regression-and-classification)

本项目V3使用61个市场交易日的在线历史范围，侧重短期收益及20/40/60日趋势相关输入，不使用V2的120/250日长期市场状态特征。它表达的关系较简单，便于检查特征的方向和影响，但可能遗漏复杂的条件组合。短窗口和线性模型都不自动意味着更安全或更适合短线。

V3仍然只用模型做预测诊断和成本过滤，再按与V2相同的本地规则排序。两档若让相近的股票通过模型门，就可能产生相似名单；这与代码是否真正使用模型是两个问题。实现见[模型合同](../src/trader/training/infra/profile/v3/contracts.py)及第6.3节。

#### 全新V1：直接学习“同一天谁更值得排在前面”

V1把同一天的股票作为一个比较组，将之后实现的毛超额收益减去训练约定的固定往返成本，再构造0–4五档相对标签，由LightGBM的LambdaRank目标学习排序。训练关注前六名的排序质量，而不是要求排序器准确报出每只股票将涨多少；具体使用`NDCG@6`评价，含义是优先检查较好对象是否被放在靠前位置。[排序目标说明](https://lightgbm.readthedocs.io/en/stable/Parameters.html#objective)

排序靠前仍可能不值得参与：例如整组机会都很弱，或者优势不足以覆盖费用。因此V1另用Ridge估计毛超额收益，经独立日期校准后扣一次成本，作为准入门。排序器和收益回归器各司其职，不把没有收益单位的排序分直接拿来减交易费用。

首发模型只用信号日前251个完整交易日形成的10项价格、波动、回撤及成交额特征。同轮完整合格总体先固定，排序器原始输出再转为0–100的相对位置；这个分数表示当轮排序位置，不是上涨概率，也不能与V2/V3的80分直接比较。本地分继续约束动作，但不覆盖V1模型名次。实现见[V1拟合](../src/trader/training/infra/profile/v1/fitting.py)、[在线排序](../src/trader/recommendation/application/pipeline/local_score/v1/scoring.py)及第6.4节。

当前V1正式参与荐股、冻结和推荐业绩，按配置进入DeepSeek结构化风险复核。此次启用依据是用户明确授权，运行状态记录manual_user_override；训练报告及历史验证证据保持原事实，不代表已经通过历史收益验证或合格Shadow验收。

### 1.3 从历史学习到今天选股：一个数字例子

训练使用“当时已知的特征”和“之后实际发生的结果”组成样本。Tomorrow看T+1，D25分别看T+2至T+5后取平均，不使用四天中最好的那一天。训练与检验必须按日期分开，今天推断时不能读取今天之后的结果；详细日期、标签和成本合同见第6、12节及[下载训练第5节](4_下载训练.md#5-训练输入样本与拟合)。

四档工程训练按日期、期限分别对真实可知的估值收益等权计算基准；个股某期限收益缺失只排除该股票该期限标签。Tomorrow须有T+1，D25须有完整T+2至T+5；不使用推定停牌或缺行估算生成标签。特征横截面仍由信号时合格人口固定，日期切分和最低样本门不降低。这是已观测收益样本的工程训练目标，可能受缺失选择影响，不替代第12节完整总体收益研究及正式结算基准，也不授予收益准入。

下列均为假设数值，只解释计算和选择，不是真实预测或回测：

1. 某个历史训练样本的股票收益为1.20%，同日该期限已观测收益样本的等权基准为0.40%，其毛超额收益为`1.20%−0.40%=0.80%`。模型学习的是这种相对结果，而不是看到上涨就认定选股有效。
2. 今天某股模型预测毛超额收益为0.80%，假设完整往返成本为0.30%，则预测净效用为`0.80%−0.30%=0.50%`，通过大于0的成本门。若预测只有0.20%，净效用为−0.10%，收盘前常规链就不能让它继续参与选择；不能再给毛预测重复扣第二次同一成本。
3. 假设甲乙均满足其它资格、板限和成本门，甲local_score为82，乙为79。V2/V3把甲排在乙前面，即使乙的预测净效用更高；若V1两位模型排序分是乙高于甲，V1则把乙排在甲前面，动作仍由本地分及其它门约束。

正超额不等于绝对上涨。例如股票跌1%、基准跌2%，毛超额仍为正1%；它只表示相对少跌。六席也不是六个无条件买入信号：还须满足动作、时效、可靠度、下行和风险限制，允许不足六席或出现关注、回避项，具体规则见第8节。

### 1.4 哪些证据才能说明算法有用

本地规则提供可解释的筛选标准，模型提供从历史样本学习的关系，成本与风险门限制不值得执行的机会。它们共同构成生成研究名单的方法；有效性的前提是这些关系在后续市场中仍有一定延续，并且优势能覆盖交易成本和预测误差。

验证时应在相同日期、总体、费用及选席约束下比较“只用规则”“规则加V2/V3模型门”和“V1模型排序”，分别确认模型过滤和模型排序是否带来额外价值。不能仅看训练误差小、名单看起来合理、某次涨幅高或模型更复杂，就宣称可以稳定荐股获利。

第12节的样本外净收益、排序质量、严重亏损、回撤、换手、容量和不同市场状态检验仍是判断依据。V2作为默认档位不代表优于V3，V1直接学习排序也不代表优于规则排序；未经对应验证，三者都不能宣称已证明持续盈利。

## 2. 端到端荐股链路

### 2.1 十一层业务流程：启动、循环与发布

第1、2层启动时执行一次，固定资料身份和静态合格集合；在线轮次从第3层开始。十一层审计保留完整输入来源，层号不代表独立定时器。图中实线是本地选择，虚线是可选异步复核；V5只作Shadow观察，不获正式发布权限。

```mermaid
flowchart TD
    Boot["正常启动：读取已发布资料和模型"] --> A["1 本地资料加载"]
    A --> B["2 静态资格过滤"]
    B --> C["3 实时行情"]
    C --> D["4 动态过滤"]
    D --> E["5 固定总体与特征"]
    E --> F{"6 模型及成本门"}
    F -->|通过| G["7 本地评分"]
    F -->|拒绝或待补| Reasons["按原因记录淘汰、待补或失败"]
    G --> H["8 一次本地风险扣分"]
    H --> I["9 按档位分数固定前六"]
    I --> Publish["11 动作与发布：先交付local"]
    Publish -.->|V1/V2/V3| Review["10 可选DeepSeek结构化复核"]
    Review -.->|"证据核验、父身份有效且未到15:00"| Hybrid["11 发布hybrid：仅收紧动作"]
```

| 层 | 职责与输出 |
| --- | --- |
| 1 本地资料加载 | 启动读取本地资料并标准化；后续复用，来源年龄继续增长 |
| 2 静态资格过滤 | 按永久事实和配置黑名单固定合格总体及计数 |
| 3 实时行情 | 获取同轮报价，校验来源、时点及字段 |
| 4 动态过滤 | 按行情ST、停牌、流动性、当前价格及公司事实有效性过滤 |
| 5 市场总体与特征 | 在模型门之前固定市场、板块、行业及成本参考，形成特征 |
| 6 模型过滤 | 检查预测及成本净效用；V1另产生模型排序分，V2/V3/V5模型不改变最终分 |
| 7 本地评分 | 对通过模型门且输入合格者计算证据分，应用质量缺失扣分 |
| 8 风险扣分 | 独立计算并扣除一次本地风险，得到local_score |
| 9 固定评分前六 | V1按模型排序分、V2/V3/V5按local_score及板限固定六席；同分按代码升序 |
| 10 可选DeepSeek复核 | 仅生产档位复核固定六席，经证据核验可作结构化风险否决；V5不发起复核 |
| 11 动作与发布 | 按本地动作资格交付local；合法复核可升级hybrid，不能改分、重排或补位 |

运行时继续检查未来生效事实、公司风险窗口、证据年龄和覆盖截止。新资料手动维护后正常重启加载；静态集合复用不代表风险永久有效。数据不足与业务淘汰分别计数，不因缺资料声称股票不合格。

**10秒是调度间隔，不是一轮完成保证。** 全市场、合格总体、六席报价、Long及尾盘分钟检查按各自窗口调度；一分钟行情描述数据粒度，不保证每次检查都有新K线。合法内容或资格变化才触发评分，无变化不重复计算。

同策略最多一个在途任务和一个最新pending：A计算中收到B、C，只保留C等待；A完成后，C若已到处理时刻就立即执行，不补跑B。已经开始的本地计算可先交付合法local；旧任务是否继续复核及新结果替换规则见工程设计第4.2节。

15:00独立封口，不等待慢评分或复核，迟到结果不能覆盖正式记录；非交易日仅运行独立测试预览。精确时段、间隔和调度规则见[工程设计第5节](2_工程设计.md#5-交易日与时间线)及[第6.2节](2_工程设计.md#62-当前刷新节奏)，冻结和收盘补建例外见本文第9节。

### 2.2 活动实现边界

活动类型、逐层审计、GET/SSE、Web和诊断使用同一十一层事实。完整合格人口先过模型门，再完成本地评分及一次风险扣分，按档位合同固定六席；没有候选分、50分线、每板120只或360只业务上限。旧14阶段/16诊断的冻结记录仍按原协议和规范字节只读。

完整人口扩大后的特征覆盖、I/O及整轮耗时须独立验收，不能靠无界请求或降低数据质量实现覆盖。执行证据和未验收项只查工程实施台账。

## 3. 数据采集、点时归一化与数据就绪

## 4. 两级硬过滤

硬过滤只依据确定性规则。DeepSeek不能放宽资格或用自由文本新增阻断。

| 当前步骤 | 检查内容 | 主要结果 |
| --- | --- | --- |
| ST预过滤 | 官方名称ST/*ST/退、已确认历史ST或退市警示 | 排除；未知资格待核 |
| 一级市场条件 | 当前停牌、上市日龄、流动性、一字板、过热边界 | 已确认违反规则才reject |
| 二级公司风险 | 人工黑名单、最新财报、已核实公司风险 | 依据事实排除或只观察 |

1. 上市第0–5个交易日、重新上市首日、退市整理首日按当前规则排除，第6日起使用普通规则。
2. 主板当前过热线为8%，创业板/科创板16%；8.00%/16.00%通过，超过边界剔除。它是策略阈值，不是交易所涨停幅度，也没有最优收益结论。
3. 最新正式财报按报告期及披露时间确定；归母净利润或扣非/核心净利润任一小于0即排除。旧报告亏损不永久排除当前股票。
4. 一年公告风险窗口为评估前365天；主要股东减持按公告至完成/终止后90天处理，正式调查和强退按同案状态处理。
5. 造假、违法、资金占用、担保等须核对官方正文及主体；标题只筛文件，结案必须关联同一案件或原公告。
   不同主体的否定或结案不能清除已确认风险。年度公告窗口不证明上市初始持续风险已核实，缺少连续历史覆盖时单独标记未知并限制动作；解禁须独立覆盖决策日之后完整180天。
6. unlock_risk或pledge_risk大于0、financial_deterioration大于0.5按当前硬门处理；来源未知则保守标记覆盖不足。
7. 人工永久黑名单必须有代码、原因、生效时间及证据。公司公告不再创建永久违法排除事实。

目标把已经落库的公司事实判断前移，但实际改造必须保留同一批输入、时点和首个拒绝原因。

## 5. 板内总体、评分资格与全局排名

### 5.1 板内总体

总体是同一交易日、阶段和板块的完整合格参考集合，用来回答“这只股票在同类股票中处于什么位置”。

1. 当前至少100个有效样本；这不是只取100只股票。
2. 不足时最多复用最近5个有效交易日的同板同阶段总体，不借用其它板块。
3. 连续变量按固定参考的2.5%/97.5%边界同时截尾参考值和待评分值，再以并列平均秩计算0–100相对位置；单样本或全相等取50。参考字段无有效样本时保持缺失，不用请求子集另建参考。
4. 总体身份绑定trade_date、phase、board、data_version、merge_epoch及参考内容摘要；预选和正式评分复用同一总体。固定参考投影不随候选人数、请求分批或重排重建百分位；缺失计数描述本次请求，样本数和边界描述参考总体。
5. 行业直接评分权重为0。行业用于模型暴露控制、当前展示和集中风险提示，不等于正向加分。

例如同板100只有效参考值依次为1至100，截尾边界为3.475与97.525。值80在固定参考中为第80名，分数为`100×(80−1)/(100−1)=79.80`；只请求其中值50和80的两只，仍分别得到49.49、79.80，不能把两只重新排名成0、100。值1、2、3截尾后并列，零起始平均秩为1，得到1.01；顶端三只同理为98.99。低波动取`100−P`，同一值的方向不能混用。

这里100是最少参考样本数，实际有3000只合格主板股票时应使用完整3000只。当天不足100只，只能按上述同板同阶段的最近5个有效交易日规则寻找合法参考；没有合法参考就保留不足状态，不能以两只请求样本“补足总体”。同为0–100只是规则分的共同刻度，不证明各板同分股票具有相同未来收益。

### 5.2 评分输入资格

报价、证券身份和策略历史窗先通过明确的输入检查，模型manifest规定模型必需字段；缺失者记待补，不计业务淘汰。通过模型门后才计算本地评分。其余本地组件按第6节计质量缺失，纯展示/研究字段不因缺失阻断评分；下行保护不足仅观察。

旧候选核心字段30%缺失门已删除。board_data_reliability >= 0.85仍是复核和可执行链的要求，不替代模型必需字段及本地输入检查。固定总体和成本参考不因请求批次或模型结果重建。

| 缺失或不合格的内容 | 当前处理 | 不能用什么替代 |
| --- | --- | --- |
| 报价、身份、策略历史窗或模型必需字段 | 记输入待补；收盘补建按第9节的独立资格 | “缺失不足30%”不能放行一个必需字段缺失 |
| 一般评分子因子 | 中性填值后扣除对应质量贡献，见第6节 | 缺失不等于有50分证据，也不重复记业务淘汰 |
| 板内数据可靠度低于0.85 | 限制复核及可执行链 | 高总分不能覆盖低可靠度 |
| 下行保护、来源新鲜度或风险覆盖不足 | 按各自合同只观察或待补，保留已知硬风险 | 删去30%门不意味着删除时效、风险或成本门 |

### 5.3 完整总体输入准备

两策略分别保留完整合格集合，物理报价请求取去重并集，并按供应商有界分批执行。每轮每股只请求一次，不维护按候选分排序的储备或失败补位；原config/candidate.json及其权重已退役。

行情缺失、过期或结构非法时保留该股待补原因，不能从后续缓存读取绕过本轮缺失。deadline到达保留最近完整有效批次；新结果不得冒充旧批次更新。完整总体不等于强制等待全部来源，合法本地降级及最近有效发布仍可读。

### 5.4 全局排名

1. Tomorrow、D25分别对通过模型门且输入合格的股票完成本地评分、质量缺失扣分和一次风险扣分。
2. 使用ROUND_HALF_UP保留两位后的local_score，按分数降序、代码升序合并三板排名；不按板块先填名额，不经过每板120只中间池。
3. 按既定板块约束固定前六；不足不降低门槛。DeepSeek不改分，复核后不以第七名补位，六席可以包含关注或回避项。
4. 不再使用candidate_score及其50分线提前排除评分对象，也不按未扣风险的base_score确定最终名次；字段、时点及模型输入资格仍须满足。

| 检查例子 | 目标结果 |
| --- | --- |
| 旧候选分排第121，但local_score排全局第3，且其它资格和约束满足 | 应参与总前六选择，不能在完整评分前被截断 |

## 6. 本地评分与模型过滤

### 6.1 本地评分怎么计算

V2/V3及显式V5当前最终分是扣除本地风险后的“证据质量分”，0表示明显不利、50中性、100明显有利，不是上涨概率。V1沿用本节本地分作为动作依据，最终排序分另见第6.4节。

~~~text
signal_score = sum(component_score * component_weight)
quality_penalty = sum(missing_component_weight * missing_subcomponent_weight * 50)
base_score = clamp(signal_score - quality_penalty, 0, 100)
local_score = clamp(base_score - local_risk_penalty, 0, 100)
~~~

1. 子因子先转换为0–100，再按子权重形成组件，最后按板块权重加总。
2. P(x)表示同板平均秩百分位；较低更好的因子使用100-P(x)。
3. B(x;l,o1,o2,u)为带通评分：适中区间[o1,o2]得100，区间外侧线性下降，在l/u之外为0。
4. 一般缺失项即使填了中性50，也要扣去对应中性贡献，不能因缺失反而受益。
5. 报价、历史和模型必需字段的缺失已在前面阻断，不在此重复计淘汰。
6. base_score已扣质量缺失，尚未扣本地风险；local_score才是扣风险后的分数。

#### 三板公式与可复算示例

令Tomorrow的组件`T/L/R/S/M/E`分别为尾盘、换手流动、趋势、稳定、市场、入场；D25的`R/Q/S/L/E`分别为趋势、质量价值、稳定、量价、入场。以下分数表达与配置浮点数等价的权重比例，用于阅读，程序仍以配置为准：

| 策略 / 板块 | signal_score |
| --- | --- |
| Tomorrow主板 | `(3T+L+4R+5S+2M+3E)/18` |
| Tomorrow创业板 | `(4T+3L+3R+2S+M+3E)/16` |
| Tomorrow科创板 | `(3T+L+5R+5S+M+3E)/18` |
| D25主板 | `(5R+5Q+3S+2L+2E)/17` |
| D25创业板 | `(2R+Q+S+2L+E)/7` |
| D25科创板 | `(6R+5Q+3S+2L+E)/17` |

**Tomorrow主板示例。** 这是说明算术的假设输入，非真实股票或回测。尾盘涨幅1.20%转换为`50+1.2×25=80`，尾盘分钟均量相对此前有效分钟基线为2倍，转换为`50+(2−1)×50=100`；日内收盘位置75。因此`T=80×0.35+100×0.30+75×0.35=84.25`。

当日换手3.00%、历史20日中位数2.00%，冲击为1.5；当日成交额2亿元、历史中位数1亿元，冲击为2。两者落在各自带通最优区间，均为100；5日收益为正，价量确认`50+min(50,2×25)=100`，故`L=100`。均线位置100、斜率80、突破90，得到`R=100×0.375+80×0.375+90×0.25=90`；低波动与低回撤各80，`S=80`；risk_on得到`M=60`；已确认入场形态得到`E=100`。

完整输入无缺失，质量扣分为0，`signal_score=base_score=(3×84.25+100+4×90+5×80+2×60+3×100)/18=85.152777…`。假设风险owner已按有效证据去重合并得5分，则仅扣一次：`local_score=clamp(85.152777…−5)=80.152777…`，`ROUND_HALF_UP`发布80.15，超过推荐线78。只有同时通过输入、成本、可靠度、时效、下行及veto等门才可推荐；排名还需比较同轮其它股票，例子不保证进入六席。

**D25主板示例。** 沿用趋势字段100/80/90、稳定80、入场100；D25趋势子权重不同，`R=(7×100+6×80+4×90)/17=90.588235…`。质量80、价值60、成长缺失：先以50形成`Q=80×0.5+60×0.3+50×0.2=68`。成交额固定总体分位80，两个冲击分均100，得到`L=80×0.5+100×0.25+100×0.25=90`。

`signal_score=(5×90.588235…+5×68+3×80+2×90+2×100)/17=83.114186…`。成长缺失的质量扣分为`(5/17)×0.2×50=2.941176…`，`base_score=80.173010…`；假设同样存在有效本地风险5分，`local_score=75.173010…`，发布75.17，处于70至76之间的关注区。该成长缺失对数据可靠度按组件内已知字段比例计入，支持权重为`1−(5/17)/3≈0.90196`；可靠度不是用2.941176分直接从1中扣除，最终仍须检查总体及其它资格。

两例均在0–100内，截断不改变结果；若质量扣分后剩2分、风险5分，则截断为0。`RoundScore(72.005)=72.01`，不使用Python默认的二进制浮点round解释半入规则。例中80、90等派生分已是完成各自变换的输入：例如均线斜率采用`clamp(50+(MA5/MA20−1)×1000)`，MA5/MA20=1.03得80；突破采用`clamp((当前价/历史20日最高价−0.90)×1000)`，比值0.99得90。它们不是原始价格直接乘权重。新V1的模型排序分另有合同，动作仍依据local_score及既有质量和风险门。

### 6.3 模型做什么

| 档位 | 算法 | 拟合日 | 在线历史范围 | 独立目标 |
| --- | --- | --- | --- | --- |
| V2 | LightGBM | 1000 | 251个市场交易日 | Tomorrow T+1；D25 T+2～T+5平均 |
| V3 | Ridge | 750 | 61个市场交易日 | 同上，但读取本档自己的双头 |
| V5 | 因果膨胀卷积TCN | training.json配置，至少250；候选采用门见下载训练第5.5节 | 信号日前61个完整市场交易日；读取62日范围以排除当天 | 独立Tomorrow/D25行业模型；预测与成本过滤 |

V2/V3 启动时，D25读取所选档位双头中自己的单一 2–5 日模型头；它是一个完整且唯一的 2–5 日生产策略头，不拆成四种生产策略。
模型预测的是扣成本前超额收益；收盘前在线成本门扣一次成本，净效用不大于0不能进入正式或观察动作池。收盘补建不调用模型头，适用第9节的单独资格，不声明通过该门。
相对模型信号分仅用于诊断，不覆盖local_score，也不能理解为上涨概率。
行业残差化用于剔除共同暴露，不是行业加分。两个档位可能因为同一套本地分和相近成本门而出现相似六席，需要分步归因，不能直接认定模型无效。

当前在第6层执行模型计算和成本门，再对合格对象进行第7层本地评分；两者由同一本地决策用例编排，不能把用例名称误解为业务顺序。算法、窗口和新增概率头均先研究，不能运行时自动择优。
成本参考按同轮、同板固定：在模型门前，取通过硬过滤且满足该档该策略模型输入资格的完整人口及其有效Amihud，不受旧候选30%缺失门、候选分、120只截断、预测结果或请求批次影响。沿用未截尾的并列平均秩0–1尺度；单样本或全相等取0.5，成本公式和阈值不变。显式参考为空或该板无合格参考时记模型输入待补，不回退到请求名单。
成本身份绑定档位、策略、模型、交易日/阶段/配置、总体merge_epoch及合格人口的代码/板块/Amihud内容，与板内评分总体身份一起进入决策input_versions，并用于缓存失效、复核及冻结。仅展示报价变化不重建成本身份；参考事实或资格改变必须更新身份。同一参考、预测和自身流动性下，仅请求拆分或更换同伴不得改变净效用准入。

历史对齐后，金额均值与中位数按市场交易日保留零成交日；Amihud在最近20个市场交易日内仅对成交额为正的有效观测求均值，避免零成交日除零。没有有效成交观测时仍缺失；当前行情成交资格及成本门不因历史估值补齐而放宽。

### 6.4 全新V1模型排序与正式接入

每个持有期分别训练共享全市场LightGBM lambdarank排序器和独立Ridge毛超额回归器。输入使用信号日前251个已完成市场交易日的qfq收盘价和成交额；首发固定10项：1/3/5/20/60/120/250日收益、20日波动、60日当前回撤、20日平均成交额的自然对数。历史停牌和缺行按下载训练第5.2节保留日期，用此前同源估值与零成交量额对齐并保留估算标记；不回填上市前、缺少前值或异常价格。20日平均成交额必须为正，实时行情仍只参与既有过滤、本地解释与动作规则。

同轮、同头完整模型输入合格人口在净效用门之前固定。rank_raw无收益单位，其并列平均秩映射为0–100的final_score，单样本或全相等取50，空人口不造分；ROUND_HALF_UP保留两位。score_scale固定为learned_rank_percentile_0_100，score_model_id固定为learned_rank；排序人口、特征内容、模型及成本合同均进入决策身份。请求拆分或重排不改变同股分数。

Ridge预测扣费前超额收益，经过去独立日期校准后只扣一次完整往返成本；净效用不大于0不能进入选择链。本地风险只从证据质量base_score扣一次形成local_score，不再从模型排序分扣风险；78/76及其关注线仍比较local_score。按模型排序分降序、代码升序固定六席，板块最多四席，回避席位不补位。

用户明确授权后，新决策绑定execution_mode=production及production_authority=true，保留既有可靠度、时效、下行保护和风险限制，合格者可显示“可执行”。DeepSeek按配置使用既有全局预算，只提供经证据核验的结构化风险veto，不改变模型排序分或本地分。Tomorrow/D25分别在15:00 first-wins冻结，支持合法checkpoint恢复及同日正式缺失时的close_fallback；V1补建仍须通过自己的模型与成本门。正式结果在learned_rank职责空间保存并供结算、GET/SSE/Web只读展示“模型排序分”。缺模型、组件损坏、发布占用或缺必需特征时关闭新决策，不借V2/V3生成V1分数。

旧execution_mode=shadow且production_authority=false的决策仍不得创建正式checkpoint、scheduled/close_fallback冻结或正式业绩；不按档位名称升级或改写旧记录。非交易日预览仍不持久化或冻结。

当前历史标签仍是信号日收盘入场代理，不证明盘中可成交，也不构成第12节要求的收益准入或正式Shadow验收。此次生产启用为用户人工授权例外，运行状态明确manual_user_override及historical_unavailable；独立确认、终端留出、至少60交易日合格Shadow等证据并未因此通过，训练报告仍保留production_authority=false和原验证标记。

### 6.5 V5量价TCN与前六排序的区别

V5按行业分别训练Tomorrow和D25的TCN，输出扣费前毛超额收益，经独立过去分区校准后减一次完整往返成本。净效用不大于零的股票不能继续选席；通过者仍按两位local_score、代码顺序及既有板块约束固定前六，风险复核或动作拒绝不补位。TCN预测值及相对位置是诊断，不覆盖本地最终分。

当前V5只用于工程Shadow，按证据质量分展示，动作最高为关注；execution_mode=shadow且production_authority=false，不发起DeepSeek复核，不创建正式checkpoint、scheduled/close_fallback冻结或正式业绩。模型缺失、空批及收盘补建均不能提升权限，默认全档或显式启动也不构成生产授权。已冻结的旧记录仍按原身份只读，不按V5档位名称重新解释。

输入为信号日前61个已完成市场交易日构成的60步序列：qfq开高低收相对前收收益、实际成交量及成交额的log1p；同时读取既有短期收益及共同暴露处理后的20/40/60日动量辅助特征。当天未完成日线不进入序列，在线辅助字段仍按当前时点更新。历史停牌和缺行使用与V1/V2/V3一致的日历对齐规则，零成交日保留序列位置；缺字段、异常价格或来源冲突不能用估算修复。

TCN也能用于直接产生前六排序，例如按预测净收益排序，或另外训练排序目标；这与本批的预测过滤是不同的业务合同。模型、总体、输入及约束相同时，采用明确的代码升序破同分规则，结果是确定的；实时输入变化时名单仍可能变化，并非从启动开始永远固定。正式结果只在既有冻结时点固定且不可被迟到结果覆盖。

若以后采用模型排序，必须另行定义排序目标、分数单位、成本及风险门执行顺序、完整总体、固定六席与不补位规则，并同步身份、解释、冻结、HTTP/Web和同约束样本外收益验收；不能通过把预测值写入final_score完成替换。本批不增加该排序模式或隐藏切换开关。

#### 公司利好及统一账本

标题只选择待核验正文，不能直接加减分。只有已实际实施、主体和数值可核验的事件才可奖励：用于注销的回购、重要股东增持达到总股本0.1%/0.3%/0.5%对应1/2/3分；已生效约束性合同占当时已知年度营收5%/10%/20%对应1/2/3分。意向、计划、用途或口径不明不加分。

实际比例不能跨到计划或拟实施语句取值。合同额与年度营收分别要求唯一金额、明确人民币及各自不含税口径，并核对年度报告在合同披露前已经披露；不能以全文任一“不含税”或合同披露日补齐缺失依据。

同一利好组只取最高分。各级有效期从首次达到该级的披露日计算，Tomorrow至随后第5个交易日15:00，D25至随后第20个交易日15:00；普通进展不刷新期限，缺日历不虚构期限。更正待核实或取消停止奖励。正式持续案件无可靠解除证据时不因跨365天自动消失；减持完成或终止后保留90天风险尾窗。

Tomorrow财务综合分F=质量×0.5+价值×0.3+成长×0.2，必要输入完整时，规则奖励为2×clamp((F−50)/50,0,1)。D25财务及成长已计入基础组件，不重复奖励。有效公司风险或风险覆盖不足暂停额外公司奖励。Tomorrow财务与利好合计上限2，D25利好合计上限5。先分配财务奖励，再按事件分数及稳定身份分配。

```text
weighted_base_score = 原策略基础分（已扣质量缺失）
requested_bonus = 合格财务奖励 + 各有效利好组奖励
capped_bonus = min(requested_bonus, 策略奖励上限)
applied_bonus = min(capped_bonus, 100 − weighted_base_score)
base_score = weighted_base_score + applied_bonus
raw_risk_penalty = 去重及风险组归并后的总扣分
local_risk_penalty = min(raw_risk_penalty, 25)
applied_risk_penalty = min(local_risk_penalty, base_score)
local_score = ROUND_HALF_UP(base_score − applied_risk_penalty, 2)
```

25是最高扣分，不是最低扣分。中间计算不提前舍入，输入拒绝负扣分和非有限值。账本保存规则值、上限值、实际变化、组件已含财务/成长贡献、公司风险级别及证据和未奖励原因。99基础+5规则奖励−8风险，实际只加1、扣8，最终92；2基础−8规则风险，实际扣2，最终0。

V2/V3最终分仍为local_score；V1最终分仍为独立模型排名百分位，本地账本只参与原动作门；V5保持工程Shadow，Long不评分。账本与当轮决策共同冻结，GET/SSE只读同一对象。旧记录无账本时不补造明细，不重算、不改写旧身份。事件字段及发布身份见[下载训练第2.3节](4_下载训练.md#23-公司资料)。

### 7.3 DeepSeek结构化风险复核

只从已经固定的六席中选择输入合格、非本地veto且有高风险、动作线附近、席位边界或证据冲突的对象，最多六只。只有primary结构化复核路径，challenger已删除。失败保留本地分和席位；核验后的veto只改动作为回避，不改分、不重排、不补位。

每日全局168次物理HTTP上限保持，失败、重试及schema修复均计数；预热与emergency保持独立原子桶。

1. 每只股票最多12条点时证据，回包必须引用本地证据ID、来源和发布时间。
2. 自由文本、评级和置信度不能直接扣分；合法事实只能映射为经过证据核验的结构化风险veto。
3. 至少2个协议维度已知且confidence_coverage >= 0.50才接纳；正向事实需官方来源或至少两个独立可信来源，相反证据保留。新决策deepseek_score=null、deepseek_risk_penalty=0。
4. 单次网络 timeout 为 20 秒；密钥缺失、超时、预算耗尽、无效回包或迟到均保留local。
5. 当前预算桶、截止、熔断和缓存行为归工程设计，不因为本文写入目标就视为已删除。
6. 目标中六席先固定，veto只收紧状态，不从第七名补位。

## 8. 最终分、动作、稳定排名与 TopK

### 8.1 最终分

以下是V2/V3生产公式；V1使用第6.4节的独立模型排序分，本地动作门仍使用local_score。

~~~text
final_score = ROUND_HALF_UP(clamp(base_score - local_risk_penalty, 0, 100), 2)
final_score = 已扣一次风险的local_score，按两位小数发布
~~~

例如base_score为82.345，风险扣5，则最终分为77.35。不能再从77.35重复扣5。
显示顺序直接保留固定席位的selection_rank；选席按两位local_score降序、代码升序，复核和冻结不重新排序。

### 8.2 动作门

| 策略 | 推荐线 | 关注线 | 低于关注线 |
| --- | ---: | ---: | --- |
| Tomorrow | 78 | 72 | 回避 |
| D25 | 76 | 70 | 回避 |

观察区间由config/selection.json的推荐线减observation_margin=6得到，即72/70；配置校验固定为6。新阈值只影响新决策，旧正式记录的分数和动作不重新解释。
分数达标还须通过净效用、可靠度、新鲜度、下行保护及veto；因此高分也可能关注或回避。
本地先发布，合法复核只能基于仍有效的父决策收紧动作，数值分不变。失败、冻结后或迟到的复核不得覆盖新结果或正式记录；发布对象及并发保护归工程设计。

### 8.3 六席与集中度

1. 三板合并后按统一最终分固定前六，不按板先填名额。
2. 六席逐股展示推荐、关注或回避；不是六只推荐再加六只关注。
3. 单一板块最多 `ceil(6 * 60%) = 4`，没有行业名额限制；同行业集中风险按事实展示。
4. 固定席位保留原selection_rank；复核veto、动作变化或封口不从第七名以后递补，合法空仓不降门槛。

## 9. 冻结、恢复与不可变历史

Tomorrow/D25 15:00 后已有同日正式记录不得被任何迟到结果覆盖。Long：不冻结、不写推荐历史。

| 情况 | 处理 |
| --- | --- |
| 15:00前 | 展示同日最新合法滚动决策 |
| 已有同日正式记录 | first-wins，任何迟到结果均不得覆盖 |
| 15:00后缺正式记录 | 先尝试恢复合法同日current；确需重新计算时，仅按合法同日输入及本档合同创建一次close_fallback |
| 冻结后新报价 | 仅更新报价overlay，不改六席、分数或动作 |

冻结保存同一决策的六席、动作、输入身份、阶段审计、来源时点和内容摘要。
持久化失败只能重试已经固定的对象，不能重新评分。旧数据不重算、不补当前模型身份，也不改称当前规则的结果。

**收盘恢复与收盘补建不是同一计算路径。** 以下local-only补建对照适用于V2/V3，不放宽收盘前模型门。V1按第6.4节保留自身模型、成本及251日输入资格，补建也不能跳过；V5保持工程Shadow，不能创建正式冻结或业绩。旧Shadow记录不随当前权限升级。本节不授予收益或生产验证资格。

| 项目 | 收盘前常规新决策 | 15:00后缺正式记录的恢复 |
| --- | --- | --- |
| 已有合法同日current | 按最新合法输入滚动发布 | 先尝试固定该current，不重新评分；保留其原local/hybrid身份 |
| 必须重新计算时 | 完整合格总体先过模型及净效用门 | close_rebuild只生成local，phase为close_fallback，不调用模型头或模型成本门 |
| 历史资格 | 按所选档位及策略模型窗口校验 | 本地基础历史要求20日，不套用模型251/61日门；其余必需字段仍须合格 |
| Tomorrow可靠度 | 按常规适用组件计算 | tail_structure不纳入可靠度的适用权重和必需字段；不是补造尾盘数据，也不改写评分权重 |

| 冻结资格 | 15:00正常封口取合法已发布同日决策 | 校验同策略、当日、运行身份、观察时间和收盘输入身份；已有正式记录或正常封口待提交时不能覆盖 |

[本地投影](../src/trader/recommendation/application/pipeline/final_selection/decision_projection.py)、[可靠度字段](../src/trader/recommendation/domain/scoring/scoring_calculations.py)及[冻结协调](../src/trader/recommendation/application/pipeline/freeze_publish/freeze_coordinator.py)分别拥有计算、字段资格和恢复准入。新补建记录保留close_fallback、official_close及local_only标记；复用已有hybrid时不伪装为新local。具体调度、持久化重试与Web只读路径见工程设计第8节。

**非交易日测试预览。** `./run.sh`及所选V1/V2/V3/V5或组合采用同一运行模式，与档位无关。可靠日历确认非交易日后，以最近交易日D的真实收盘报价重新执行候选、特征、该档模型、成本净效用门、评分、风险、可选结构化复核与六席选择；不使用旧历史名单，也不进入跳过模型的close_fallback。各档原算法及Shadow权限保持独立，测试模式不授予生产资格。

## 11. 逐环节优化空间与优先级

所有收益优化均为研究建议，不能宣称提高收益；明确的目标工程调整见工程设计。

| 问题 | 比较方法 | 判定依据 |
| --- | --- | --- |
| 旧候选分提前截断漏掉多少机会 | 对照完整评分后直接选六的目标，跟踪首次淘汰位置 | Top6召回、成本后收益、完整评分范围与耗时 |
| 权重和过热线是否合理 | 一次只改变一个参数族 | 样本外净收益、回撤、严重亏损 |
| 风险扣分是否过重 | 原规则与单项消融，保留已知硬风险 | 收益与尾部风险同时比较 |
| 动作分数如何划分 | 当前按用户要求采用78/72、76/70；与旧78/73、76/71配对比较 | 样本外收益、误拒绝、回撤；阈值切换本身不证明收益提升 |
| 模型过滤是否有效 | 规则、规则+本档模型门、不同门位置 | 覆盖、过滤贡献、净效用、名单差异 |
| V2/V3或持有期名单相似 | 同日同股拆分模型预测、成本门、本地分和选择影响 | 逐环节归因，不只比较六席重合率 |
| 是否需要其它算法 | Ridge、LightGBM及独立Logistic门的预定义对照 | 校准、净收益、资源、稳定性 |
| 预读及更大缓存能否提速 | 相同输入、交替多轮测量 | 命中、淘汰、读库、P50/P95、RSS与换页 |
| 同轮到Web是否完整 | 追踪一个输入身份经过所有层 | 无混轮、无旧结果回写、明确耗时 |
| 同样80分在各板是否可比 | 分板、分市场状态比较分数与未来净收益、尾部风险 | 统一0–100标尺不等于收益已校准，不直接改权重 |
| 相近风险是否被多条规则反复抑制 | 分别移除相似因子、风险项和动作门作配对比较 | 数值只扣一次；经济含义重叠是否有益仍需证据 |
| 新增信息是否只偏向覆盖充分的股票 | 按板块、规模及资料完整度拆分待补、误拒和收益 | 数据不足单独计数，不把缺资料等同于公司差 |
| 移除行业限额后的集中度 | 统计六席行业占比及共同因子暴露 | 展示集中风险，不另造未经确认的行业硬门 |
| 复核是否有增量价值 | 同一父决策比较不复核和结构化veto | 漏报、误否决、机会成本、延迟和请求成本一起报告 |

算法复杂不代表收益更好；Logistic若作为“上涨概率”门，必须先定义目标并校准，不能把回归预测直接改名为概率。
所有参数变更先走第12节，再获得生产变更授权。

## 12. 收益验证与变更门禁

### 12.1 收益与风险口径

| 项目 | 唯一口径 |
| --- | --- |
| 进场锚点 | 研究采用D日15:00；价格有限且正，具有当时已生效资格及交易状态，不表示实际能够按该价成交 |
| Tomorrow退出 | T+1前复权收盘 |
| D25退出 | 分别计算T+2、T+3、T+4、T+5，再取均值 |
| 复权 | 进出场使用同一基准；raw用于实际可交易判断，不混用raw进场和qfq退出 |
| 成本 | 每个持有期扣一次完整买卖成本，20bp主评价、50bp稳健性、100bp压力 |
| 基准 | 同日同策略、当时已合格可交易人口的等权收益 |
| 空仓 | 空仓日保留在日期分母；未用槽及全资金口径分别解释如下 |

~~~text
gross_return_h = exit_price_h / entry_price - 1
net_excess_h = gross_return_h - benchmark_return_h - round_trip_cost
d25_aggregate = (net_excess_T2 + net_excess_T3 + net_excess_T4 + net_excess_T5) / 4
MAE = min(0, min(low[t] / entry_price - 1))
MAE/ATR20 = MAE / (ATR20_at_entry / entry_price)
~~~

1. D25不能使用未来四日最高价作为标签，必须分别报告四个期限。
2. 停牌、一字板等不可交易事实不能删除；退出不可卖时保留当日可信收盘估值，无有效收盘才沿用前有效价，并报告延迟退出压力结果。
3. MAE为收益比例，MAE/ATR20为ATR20倍数，二者均不大于0。严重亏损判断针对MAE/ATR20：Tomorrow<=−1.5倍、D25<=−2.5倍，不是收益−1.5%/−2.5%。本节公式使用小数收益；`_pct`字段使用百分点，MAE/ATR20为无量纲倍数，按字段合同显式转换。
4. 盘中进场当日不能使用进场前的最低价；15:00进场当日区间只有锚点。
5. ATR20缺失时保留可核实收益，但不得伪造风险标签；风险准入仍要求标签完整。
6. 基准人口先于候选阈值和板内上限确定，不让模型选择改变基准。
7. 保留15:00研究锚点及冻结合同；另报可交易价格、滑点和不可成交情景，不把完整收盘数据的事后可得性当作截止前可得证据。

#### 标签、选股贡献与资金收益分别解释

| 指标 | 含义和限制 |
| --- | --- |
| D25四期限均值 | T+2～T+5机会标签，逐期限另报；尚未定义分仓、重叠持仓、资金占用和退出时，不能当资金曲线或直接年化 |
| 六槽选股指标 | 当前部分研究把已扣基准和成本的选中收益求和除以6，未用槽贡献0；是固定槽位指标，不能直接称全资金组合超额 |

5. 有限参数族确认按既有策略合同取移动区块：Tomorrow默认5日，D25默认且至少10日；与前述至少5日的数据隔离不同。使用10000次bootstrap、Holm 0.05校正及95%置信区间，不得看完结果后换参数。其它已注册研究保留自身区块设置；新研究预先固定依赖处理和敏感性检查。
6. 20bp与50bp相对基准的净收益置信下界须为正，收益排序改善，严重亏损、回撤、换手和容量不得劣化；100bp只报告压力。
7. 终端留出至少200日，开发及确认完成、完整链固定后只原子开启一次；重复开启返回terminal_holdout_already_opened。
8. 报告Rank IC、NDCG@6、Q1–Q5单调性、Top10/20/50及Top6净超额、胜率、回撤、严重亏损、换手、容量、不可交易率和分年/市场状态表现。
9. 历史通过仍为production_authority=false；Shadow和人工生产授权独立完成，不自动调参、启用或回退。

### 12.4 研究比较与约束身份

oracle在这里指“事后最优对照”：回溯时已知道未来收益，在固定同一人口、成本、席位及板块限制下求出的最好可行选择，可保留现金。它是测量错失机会的上界，不是数据库、线上预测器，也不是投资者当时可以实现的收益。比如候选事后净收益为3%、2%、−1%，只允许选两只且可留现金，最优对照选择前两只；加入板块约束后可能不能同时选它们，必须重新求解同一约束，不能直接贪心取最高。生产每板最多4且无行业限额，旧独立研究每板3、每行业2的oracle不可混称同一个对照。

研究方法和收益准入仍由本文定义；类型对象、分区、父身份、精确覆盖及报告拒绝协议唯一见[下载训练第6.3节](4_下载训练.md#63-研究对象与报告绑定)。

| 研究检查 | 固定要求 |
| --- | --- |
| 召回人口 | 在模型和旧候选分截断之前固定，每股只记首个拒绝边界；目标覆盖完整合格总体，后续追踪不重算双写 |
| 旧容量研究 | 既有60/120/180/240/完整人口试验保留原身份及已固定选择；仅解释旧预选损失，不再为新目标选择生产中间池 |
| 排序四臂 | 纯规则；规则+行业模型净效用门；行业门+预测净效用排序；共享/部分池化模型排序 |
| 共享模型 | Ridge和LightGBM为同一臂预注册子项；控制市场、板块、行业和流动性暴露 |
| 选择顺序 | 固定前六后执行门且不递补，与先执行门再约束选六严格配对；空槽按现金0 |
| 召回准入 | 全体/逐板有效覆盖>=95%；Oracle Top20召回95%置信下界>=95%，Top50下界>=90% |
| 收益准入 | 20/50bp相对基准bootstrap下界均为正，通过Holm 0.05，风险、容量、换手不恶化 |
| 不确定性 | 亏损概率报告Brier和ECE；预测区间报告覆盖率；模型/训练窗口分歧、OOD与缺失不确定性分桶核验 |
| DeepSeek增量 | 同一父人口比较local-only与结构化 facts veto；本地最终分及可选结构化风险否决保持现行边界 |
| 机会成本 | 精确求解同约束oracle，可保留现金；不能用事后收益贪心排序冒充最优 |
| 既有独立复核研究约束 | oracle Top6、每板最多3、每行业最多2，属于该研究身份；不能直接外推为生产或新目标的同约束收益证明 |
| 统计口径 | 既有六槽研究未用槽位贡献0、父日期等权，入选均值另报；指标含义按第12.1节，不等同全资金组合超额 |
| 压力场景 | 原选择固定后报20/50/100bp，不重排、不恢复veto、不丢弃转亏样本，成本只扣一次 |

生产目前板块上限为ceil(6×60%)=4，独立复核研究每板最多3；部分成本选择研究还使用floor取整。它们是不同研究身份和可行集合，不能互相替代。
目标生产一致验收必须使用与目标相同的资格、评分、动作和集中度约束，另立研究身份；旧报告、旧约束和已开启留出均不改写。

当前完整总体配对研究身份为`eleven_layer_full_population`，不再运行候选容量网格或行业限额。生产对照为模型门后按两位local_score及板限固定六席，再执行结构化风险veto与动作资格，不递补；模型净效用排序臂只是隔离研究比较，不改变V2/V3最终分。旧独立研究的原约束和报告仍只解释自身身份，不能作为该目标的通过证据。

## 附录：完整字段与因子表

本附录逐字段说明程序使用什么数据、怎样计算、在哪一层发挥作用。每个字段只占一行，来源直接写中文；字段分组用于查阅，不表示每组都是独立评分组件。权重、风险和动作规则仍分别以第6、7、8节为准；本次整理不改算法。

读表时先区分以下概念：

- 实时行情：服务运行时取得的当前报价；分钟行情：按分钟记录的价格和成交量，不能由日线猜测。
- 公共参考：证券清单、上市信息、ST、交易日历、板块和行业；公司事实：已核验财报、公告、质押和解禁。
- 历史日线：已发布的完整历史数据，按信号日与各档窗口在启动时有界读取；独立sync market短窗不替代模型长窗。
- 本轮计算：用上述输入计算出来的因子，不是另一个行情供应商，也没有单独的下载命令。两个输入共同出现时必须同时满足，不表示任选一个补齐。
- 百分点与小数收益率：上涨3%在百分点字段中写3，在小数收益字段中写0.03；“倍”是分子/分母，例如2倍。“分”是0–100规则分或相对位置，不是上涨概率。
- 均线MA：一段交易日收盘价的平均值，例如MA5为5日均价。PE为市盈率，比较股价与年化每股收益；PB为市净率，比较股价与每股净资产；ROE为净资产收益率，用来描述盈利质量。
- 自然对数ln：把跨度较大的数值压缩到较平缓的尺度，ln(x)与ln(1+x)不是同一个变换。TCN为时间卷积网络，在V5中读取按交易日排列的量价序列，不能据名称认定收益更好。
- 同板百分位：在已固定、资格有效的同板股票总体中比较位置；并列取平均秩。越小越好的原始因子才反向计分。具体总体和质量规则见第5、6节。
- 缺失：没有足够依据；0：有依据算出零值。一般本地评分项缺失即使内部暂用中性50，也要扣除缺失贡献；模型必需输入缺失则待补，不制造中性预测。

本地资料仍校验原披露/交易时点、有效期、覆盖和发布身份，重新读取不刷新年龄。来源与维护入口见[下载训练第2节](4_下载训练.md#2-数据资格与资源所有权)；数据库物理列见其[数据库字典](4_下载训练.md#附录数据库文件与字段字典)。

计算依据：[历史与实时因子](../src/trader/recommendation/infra/normalization/features.py)、[本地评分](../src/trader/recommendation/domain/scoring/scoring_calculations.py)、[尾盘分钟](../src/trader/recommendation/domain/market/tail.py)、[下行保护](../src/trader/recommendation/domain/risk/downside.py)、[风险派生](../src/trader/recommendation/infra/normalization/feature_risks.py)、[模型字段合同](../src/trader/recommendation/domain/market/feature_contracts.py)、[V1特征](../src/trader/recommendation/domain/market/v1/features.py)、[V5序列](../src/trader/recommendation/domain/market/v5/features.py)。当前参数以相应配置为准，本表写出的具体计算用于解释现行实现。

### 历史与本地评分因子

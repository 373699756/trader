# V2/V3 荐股链条精简与数据、训练、配置重构计划

本文保留历史方案及尚需收益证据的研究设想，不是活动业务合同或第二份进度台账；阶段122实际交付及未验证项以工程实施记录为准。候选、过滤、评分、风险与融合的现行权威是 [01_评分逻辑.md](01_评分逻辑.md)；架构和发布边界以 [02_工程设计.md](02_工程设计.md) 为准；每批实际进度和验证证据只登记在 [03_工程实施.md](03_工程实施.md)。行为切换时，在同一批次更新权威文档、代码、消费者和验收证据。Git历史中的V3研究草案 中与本方案冲突的模型或融合设想不叠加执行，最终以届时更新的权威合同和实测为准。

目标是提高 Tomorrow 和 D25 相对同日可投资基准、扣除实际交易成本后的可重复净超额收益，同时控制严重亏损、换手、容量和集中度。任何简化或比例调整都要先与原链条做同口径对照；本文件的参数是研究起点，不是收益承诺或生产授权。产品只运行在个人 PC 上，不下真实订单。

## 1. 目标链条及必须保留的合同

| 档位 | 目标单模型 | 在线前复权特征窗口 | 离线拟合研究起点 | 工件 |
| --- | --- | ---: | ---: | --- |
| V2 | LightGBM | 至少 251 个有效交易日 | 最近 1000 个有效拟合日期 | Tomorrow、D25 独立双头 |
| V3 | Ridge | 至少 61 个有效交易日 | 最近 750 个有效拟合日期 | Tomorrow、D25 独立双头 |

1000/750 是拟合锚点数，不是总下载天数，也不包括特征预热、标签未来区间、时间隔离、校准、确认和最终留出。模型算法由档位身份固定；训练超参数、特征清单和窗口从配置读取并固化到工件。在线短窗口与离线长历史分开；LightGBM 同样使用前复权价格构造 V2 动量等特征，前复权不是 Ridge 专属输入。

目标决策链：

```text
点时合格的候选与特征
  -> 本地证据质量组件 -> base_score
  -> 本地风险只扣一次 -> local_score -> final_score
  -> 对应档位和策略头的模型预测 - 一次往返成本估计 -> 行动资格
  -> DeepSeek 解释及已校验的结构化风险复核
  -> 下行保护、动作门、TopK 与集中度 -> 发布和 15:00 冻结
```

目标 `final_score = local_score`，模型预测不换算成分数，也不覆盖本地证据分。DeepSeek 不参与数值评分：删除固定 68/32 融合、由自由文本推导的扣分以及独立的 DeepSeek 分数惩罚。仅允许通过来源、时间、字段和稳定证据身份校验的结构化风险事实影响否决或观察资格；同一风险不能与本地风险重复扣减。无 DeepSeek、失败或超时时继续合法本地降级，并显式记录原因和来源年龄。保留每日物理 HTTP 请求全局 168 次上限、失败和重试计数及独立预算桶。

Tomorrow/D25 各有自己的模型、标签、动作和同档位身份；Long 只展示当前快照，不评分、不排名、不进 TopK、不冻结、不写推荐历史。15:00 先到先得冻结、同日正式记录不可覆盖、合法 `close_fallback`、点时有效性、Asia/Shanghai 可注入时钟和失败时最近有效快照均须维持。目标融合变化要一次性改完计算、发布投影、历史 codec、API/Web 读取和权威说明；旧正式记录按旧身份只读，不重新计算或改写。现行 68/32 合同在该批行为切换完成前继续有效。

## 2. 配置职责与参考数据

### 2.1 按功能拆分静态配置

所有活动配置统一置于 `config/`，只保留单一配置入口和有类型解析。以下为目标所有权；实际文件名可沿现有约定，但一个参数只能有一个 owner，不能通过覆盖顺序形成第二真相源。

| 文件 | 唯一职责 |
| --- | --- |
| `runtime.json` | 启动档位、资源路径、运行开关 |
| `delivery.json` | HTTP、SSE 与只读交付限制 |
| `scheduler.json` | 周期、截止时间和后台调度上限 |
| `market_data.json` | 行情供应商、超时、重试、覆盖与年龄 |
| `cache.json` | 技术缓存的容量、寿命与失效策略 |
| `download.json` | 完整历史、短窗口、批量、并发和发布门禁 |
| `training.json` | V2/V3 算法超参数、拟合日期、校准及工件策略 |
| `features.json` | 档位和策略头有序特征 ID、最大回看与数据依赖 |
| `filter.json` | 资格、ST、停牌、上市年龄、交易状态等硬过滤规则 |
| `candidate.json` | 候选预选与板内限额 |
| `scoring.json` | Tomorrow/D25 本地组件权重及分数标尺 |
| `risk.json` | 本地风险、否决、观察与下行保护 |
| `cost.json` | 决策使用的单次往返成本模型及单位 |
| `deepseek.json` | 复核字段、超时、预算、降级与证据校验 |
| `selection.json` | 动作资格、TopK 与集中度 |
| `research.json` | 离线回放、时间切分和实验候选；不进在线评分 |
| `performance.json` | 离线评价指标、成本敏感性及门禁；不进在线评分 |

Tomorrow/D25 的同类参数作为对应文件内的明确子项，避免按策略复制整套文件。经常变化或参数量大的数值进入配置，并保留原精度和单位；公式、schema、业务身份以及安全不变量保留在代码和权威合同。密钥仍走凭据边界。删掉无消费者或无效开关、竞争性覆盖和重复默认值前，先列出所有读取者，验证等价解析，再原子移除旧字段、旧配置和旧消费者。每条命令仅加载其所需职责配置，但启动时仍校验该命令的完整必需项；缺失或非法参数明确失败，不使用隐藏 fallback。零参数 CLI 路径、包内资源和隔离测试须保持可用。

### 2.2 `config_filter` 与生成参考数据

静态规则移入 `config/filter.json`；下载产生的资格与行业事实仍是带来源、时间和版本的数据，不作为手工配置下载或纳入代码包：

```text
config/filter.json                     # 静态筛选规则
data/reference/historical_st.json      # 下载所得曾 ST 证据
data/reference/industry_queries.sqlite3 # 行业查询事实/必要缓存
data/reference/eligibility-*/          # 由旧资格库显式转换的版本化资格快照及清单
data/history/references/             # 已发布历史快照绑定的不可变参考
```

先盘点 `data/filter_config`、`data/reference` 的实际文件、写入者、读取者、锁和恢复路径，不根据文件名猜用途。`historical_st.json` 为现有资格链需要的生成证据，不能因为扩展名是 JSON 就迁入 `config/`。`industry_mapping.json` 若仅是最新行业投影，确认所有消费者可读有版本的行业事实后，连同写入和回滚路径一起删除；已经绑定历史快照的不可变行业参考仍保留。迁移工具的 `build-references` 同时接收仓库外的参考源副本与旧资格数据库副本，把资格事实转换成版本化快照，再在仓库外完成冲突、损坏、重启和回滚演练，保留活动数据；不在正常启动时隐式迁移，也不建立永久双读或双写。路径由组合根注入。

## 3. 下载、字段与训练合同

### 3.1 长历史、短窗口和样本日期

首次完整历史请求最近约 2000 个交易日；后续按新增交易日与已知缺口增量补齐并保留更老的有效数据，不因在线短窗口而裁剪完整历史。已有共享完整历史最低覆盖门禁先维持，只有分档位真实回放证明可安全调整才原子更改。下载就绪必须按日期、证券、字段、停牌事实和来源完整性判定，不能只检查“2000 行”或“251/61 行”。

V2 在线前复权特征最长回看 250 日，因此至少需要 251 个有效交易日；V3 最长回看 60 日，因此至少需要 61 日。两档都从在线短窗口读取，不在荐股请求中补下载。训练读取完整已发布历史、资格和行业点时事实，在分别扣除特征预热、未来标签、embargo、校准、确认和最终留出后，再选最近 1000/750 个有效拟合日期。若不足，明确拒绝本次训练或保留旧有效工件，不能缩短窗口并声称同等结果。窗口研究同时比较相邻候选长度，并在独立确认集选定，终端留出只看一次。

### 3.2 下载字段及归属

| 数据 | 必需内容 | 用途和点时约束 |
| --- | --- | --- |
| 证券与日历 | 代码、交易日、板块、上市日、来源和生效时间 | 总体、交易资格、分板与时间切分 |
| 完整日线 | 未复权及前复权 OHLC、成交量、成交额、复权身份 | 原始成交与收益标签、前复权特征；同日价量必须可配对 |
| 状态事实 | 停复牌、交易状态、涨跌停及有效时间 | 缺日判定、可交易性与执行门 |
| 历史资格 | 官方曾用名、曾 ST/现 ST、证据时间 | 永久与动态资格，不得用当前状态倒填历史 |
| 行业区间 | 行业代码、来源、起止生效时间 | 点时行业、板内基准和模型支持范围 |
| 可选行情 | 官方前收、涨跌幅、换手率等 | 仅在声明消费者需要且来源可核验时获取 |
| 增强事实 | 财务披露、公告、结构化风险及披露时间 | 各自业务 owner 消费，不混入日线必需字段 |

配置声明 V2/V3、Tomorrow/D25 的字段组和派生依赖，下载任务取所启用档位的并集；资格、风险、标签和价格配对等必需组不可通过开关关闭。可选字段缺失保留缺失状态，不伪造 0 或未来值。单一原始事实可被多档位读取，但数据源身份、质量判断和发布只保留一个所有者。

### 3.3 特征、标签和模型

下表是当前拟研究的有序价格特征合同；最终以现有代码、工件 manifest 和定向测试核对后固化，不能仅据表格改生产加载器。

| 档位与头 | 有序特征组 | 数量 |
| --- | --- | ---: |
| V2 Tomorrow | 收益 1/3/5 日；跳过最近 5 日的残差动量 20/40/60/120/250 日；市场动量 120/250 日 | 10 |
| V2 D25 | 收益 3/5 日；同一组 5 个残差动量；市场动量 120/250 日 | 9 |
| V3 Tomorrow | 收益 1/3/5 日；跳过最近 5 日的残差动量 20/40/60 日 | 6 |
| V3 D25 | 收益 3/5 日；同一组 3 个残差动量 | 5 |

市场、板块、行业及近 20 日平均成交额等暴露/流动性字段可供对应风险、路由和成本 owner 使用，不能不经实验再次计入本地质量分。Tomorrow 标签使用 T+1 对同日可投资总体的超额，D25 使用 T+2 至 T+5 综合目标并保留逐日观察；标签在拟合层保持成本前口径，成本只在行动和真实评价边界扣除。任一特征的名字、顺序、单位、回看、缺失规则以及标签日期均写入工件 manifest，在线逐项核验。

V2 LightGBM 保留自己的树参数、早停及校准；V3 Ridge 保留标准化、正则强度及独立校准，删除其无用的树早停、双模型融合和分歧字段。两档各训练并原子接纳 Tomorrow/D25 双头，不能跨档位加载或只换一个头。训练配置、输入快照、特征/标签合同、算法和校准合同共同形成工件身份；任一相关变化只使下一次显式训练到期，不在线热改旧工件。缓存按依赖精准失效，旧发布与历史工件按原身份只读。V2 仍需要 LightGBM 依赖，V3 沿用现有 Ridge 实现和工具链。

## 4. 评分删减、交易成本和收益验证

### 4.1 有限候选消融

先固定当前链条为对照，逐项只改一个因素；同一数据、模型工件、股票池、时间切分、交易假设和门槛下比较。研究候选限定为下表，避免试到“看起来最好”的偶然结果：

| 候选 | 研究动作 | 保留边界 |
| --- | --- | --- |
| 输入完整度 | 取消正向加分，保留入池和缺失资格门 | 不能用缺字段得到高分 |
| D25 价格可执行分 | 删除重复的正向分 | 涨跌停和交易资格硬门保留 |
| Tomorrow 资金流确认分 | 删除正向评分 | 仅保留有独立证据的资格或诊断 |
| 稳定性预选加分 | 删除预选中的重复计算 | 最终风险保护保留 |
| D25 质量/估值正向分 | 检验删除后重排 | 必需财务风险和 Long 展示保留 |
| 本地权重 | 比较现行比例与剩余组件等权基线 | 标尺、阈值和集中度固定 |
| 成本估计 | 比较现行流动性估计与固定 0.2% 往返成本 | 两者都只扣一次 |

以上加现行对照最多 8 组预注册组合；必要的全链目标重跑单独报告，不能把各单因素收益直接相加。删除组件时只在剩余本地组件中归一化权重，保持 0–100 标尺；候选、动作阈值、风险和集中度不同时调参。相同原始量在候选、模型、评分、风险、成本中的多次使用须列出职责图：资格与估计可复用事实，重复的正向加分须有单独增益证据；删除正向分不意味着删除其他消费者需要的原始字段。

### 4.2 DeepSeek 退出评分的合同切换

单独做“原完整链条”与“DeepSeek 只解释和风险复核”的端到端比较，记录最终排序、合法本地降级、请求量及净收益。切换时删去 68/32 融合、DeepSeek 数值分、置信扣分与仅为融合服务的状态和缓存；结构化风险证据、解释、请求预算、可观测性仍保留。Web/API 展示本地最终分和独立复核状态，不以 0 伪装缺失 DeepSeek 分。读取历史时按记录原有合同展示，不复写历史 hybrid 分。评分唯一权威和蓝图须同批更新，保证现行冻结记录和读接口能够区分旧、新身份。

### 4.3 成本只在正确边界扣除

训练标签采用成本前收益；在线模型净效用/行动资格减去一次预计买卖往返成本；落地收益评价用观察到的成交与费用减一次实现成本。Tomorrow 与 D25 都只按一笔完整往返估算，不因 D25 有多个观察日逐日重复扣。既有在线流动性估计、研究固定 0.2% 和离线 20/50/100 bp 敏感性是不同用途，不能彼此累计；成交税费、滑点与冲击必须同单位、同金额基准并在 `cost.json` 明确。比较收益时同时给出成本前与成本后、可执行率和换手；不能以未扣成本的原始涨幅宣称改进。

### 4.4 评估设计与接受门

使用按时间前滚的拟合、校准、确认和至少 200 个交易日的终端留出；未来标签与相邻折之间设置与持有期匹配的隔离。所有特征、行业、ST、公告和动作价格按当时可得时间读取，幸存者偏差、停牌、涨跌停和无法成交都计入。先按确认集选择单模型、长度与简化候选；终端留出只检验已锁定版本，失败后不能在同一留出反复选择。

每档 Tomorrow/D25 分别报告同日合格总体基准上的净超额、最差分位和严重亏损、回撤/不利变动、换手、成本敏感性、样本数与时间分段稳定性；同时报告延迟、缺失、降级、请求量、配置项与代码复杂度变化。对现有双模型与目标单模型做相同输入的对照；研究证据不足时保留现行参数和工件，不因“更简单”直接上线。现阶段不能声称 1000/750 日、任一新权重或删减项更优。

方法依据：[时间序列交叉验证](https://otexts.com/fpp3/tscv.html) 支持按时间前滚检验；[预测组合综述](https://arxiv.org/abs/2205.04216) 说明组合可能有价值，因此单模型需实证比较；[中国市场日度动量研究](https://www.nber.org/papers/w31839) 可作为本地特征研究背景。这些资料不能代替本项目的点时回放和成本后留出证据。

## 5. 双档运行、验证与交付顺序

### 5.1 运行目标

`run.sh` 支持单独 V2、单独 V3 和同时启动 V2/V3，保留既有单档命令；组合根将档位解析为去重且稳定排序的有类型身份，启动时对两个档位共四个头的工件和输入合同整体预检，不允许跨档位静默回退。行情与不可变原始事实可共享，特征、模型、成本门、选择、冻结和发布身份按档位隔离。后台下载、训练及数据库写入有单一 owner、限流和锁，不靠同时启动两套进程争写；Long 固定由 V2 lane 单一采集和发布，V3 页面只读该投影。单档失败可保留对应最近有效快照并显式降级，不能借用另一档分数。现有 Web 的双档界面接入各自已发布的只读结果，切换展示不重算、不抓数；GET、SSE 与历史身份一致。

### 5.2 每批最小充分验收

| 边界 | 必核证据 |
| --- | --- |
| 配置 | 旧值逐项等价、非法/缺项失败、职责无重叠、零参数 CLI 与打包资源 |
| 下载 | 点时来源、字段依赖、2000 日长历史及 251/61 短窗口、缺日/停牌/资格发布 |
| 训练 | 有效拟合日期计数、标签隔离、1000/750 候选、缓存身份、校准、双头原子接纳 |
| 在线决策 | 有序特征、成本单位及单次扣除、本地风险一次、DeepSeek 退出数值分 |
| 发布与页面 | 双档并行、15:00 first-wins、重启与旧记录只读、GET/SSE/桌面显示 |
| 数据迁移 | 仓库外隔离副本冲突与回滚，活动数据和冻结记录未改写 |

按改动风险运行定向 pytest、受影响 Python 范围 Ruff，公共类型或复杂边界再运行 mypy；完整阶段或发布门按仓库规定执行。每批 Review 自上一已推送提交以来的完整 diff，核对所有消费者、旧路径、隐藏 fallback、生成物和文档，并运行 `git diff --check`。fixture、mock、HTTP 200 与旧进程输出只作为对应证据，不能冒充真实全市场下载、训练或收益验收。

### 5.3 可执行批次

1. **保存方案**：本文件独立 Review、提交和推送；不修改生产合同或活动数据。
2. **配置拆分**：盘点所有参数、读取者和包资源；按职责原子切换消费者与旧配置路径，保持行为等价。
3. **参考数据归位**：静态规则入 `config/filter.json`，生成资格/行业事实保留版本化数据 owner；隔离副本演练后清理无消费者的最新行业投影。
4. **成本收敛**：梳理训练、在线和评价每个扣费点，消除重复扣除，保留明确的成本单位及回归证据。
5. **下载与训练**：建立字段依赖和有效日期预检；V2 只训 LightGBM、V3 只训 Ridge，双头工件和缓存一次切换，做离线窗口研究。
6. **双档运行**：`run.sh`、组合根、发布身份和只读 Web 一次接通 V2/V3，并核对冻结与降级。
7. **评分研究与切换**：预注册消融、确认集选型和一次终端留出；只有通过收益及风险门，才同批更新评分权威、蓝图、代码、投影与历史兼容读取。
8. **真实验收与发布准备**：在明确授权的真实数据边界完成下载、训练、桌面及回放证据；PR、合并、标签、真实数据切换和发布按仓库规则另行授权。

每批仅维护 [工程实施台账](03_工程实施.md) 中对应的原记录；独立低风险文档批次不新建阶段。当前批次完成后按仓库单批交付规则提交并推送，然后停在批次边界。后续批次以实际 owner、消费者和现行权威为起点，不在未完成批次之间另建进度表，不隐式触碰活动数据库、工件或已冻结推荐。

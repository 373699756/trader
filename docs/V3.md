# V2/V3 独立实现，以完整荐股链的净收益验证新 V3

本文保存已确认的设计计划，不代表代码已实施、收益验证已通过或生产启用已获授权。实施时先同步评分与架构权威合同；活动进度及验证证据仅维护在 `docs/03_工程实施.md`，不在本文建立第二份进度台账。

## 1. 目标和边界

**V2 保留现有方法作为稳定基线；V3 独立实现模型评分，以扣除交易成本后的选股收益为改进目标。**

采用已确认的边界：

- 允许新增目录，分别容纳 V2、V3 的训练、预测和评分实现。
- 公共部分保留数据准备、风险控制、成本门、DeepSeek 融合、动作判定、TopK、集中度及冻结发布规则。
- 允许调整必要的接口、装配和评分身份传递。
- V3 可以生成不同于 V2 的基础分，不再局限于修改现有因子权重。
- 不预设新方法必然更赚钱；未通过收益门禁时保留 V2，不强行启用 V3。

新 V3 仍通过基础分参与原有链条：

```text
公共数据和候选
    ├─ V2：现有规则基础分
    └─ V3：独立模型 → 校准后的基础分
                 ↓
公共风险扣分 → 固定融合 → 动作判定
                 ↓
现有最终评分排序 → TopK/集中度 → 冻结发布
```

## 2. 目录与职责隔离

按现有业务分层分别建立 V2/V3 目录，不把训练、网络加载和纯评分混进同一个模块。

下表路径均相对于 `src/trader/`。

| 所在位置 | V2/V3 各自拥有的内容 |
| --- | --- |
| `training/infra/profile/{v2,v3}/` | 训练目标、样本适配、拟合、校准及专属工件 |
| `recommendation/domain/scoring/{v2,v3}/` | 纯评分转换、分数含义和输入校验 |
| `recommendation/infra/scoring/{v2,v3}/` | 工件加载、批量预测和评分适配 |

实施要求：

- 将现有 V2 专属算法与全部消费者原子迁入 V2 目录，保持结果一致。
- 删除 V3 对公共拟合实现的转发导出，让 V3 拥有自己的实际实现。
- 公共部分只保留确实共用的数据读取、时间切分、资源控制及技术计算；不复制两份相同工具。
- 由组合根选择档位并注入实现，公共链条不散布 V2/V3 算法分支。
- 不保留旧路径兼容转发，不进行与本次职责迁移无关的命名整理。

`train-v2`、`train-v3` 和现有档位选择入口保留。V2 旧工件保持可用，不因目录迁移强制重训。

## 3. 新 V3 的评分方法

### 模型与训练

首轮采用 **LightGBM 学习排序＋独立概率校准＋现有收益预测成本门**。学习排序直接训练同一天股票之间的收益顺序，是区别于当前回归模型的重要变化；LightGBM 原生支持该目标。[官方说明](https://lightgbm.readthedocs.io/en/stable/Parameters.html)

- Tomorrow、D25 分别训练，不混合持有期。
- Tomorrow 使用次日毛超额收益；D25 使用 T+2 至 T+5 毛超额收益均值。
- 每个交易日构成一个排序组，在重放现有候选条件后按收益生成五档相关性标签；同收益同档。
- 每个策略训练一个跨板块排序模型，使用 `lambdarank`、浅树和 NDCG@6 早停。
- 首轮沿用 V3 的 61 日特征合同及现有可验证特征，暂不同时扩大特征和模型搜索范围。
- 按交易日切分训练、早停、校准、开发、确认和最终留出，清除标签区间跨分区泄漏。

### 基础分的明确含义

排序输出不能直接作为概率，也不能按当天名次强行拉伸成 0–100。

在独立校准分区，用单调 Logistic 校准，将排序输出转换为“毛超额收益大于零”的估计概率：

```text
V3 base_score = 100 × 校准后的跑赢基准概率
```

其中：

- “跑赢基准”不等于绝对赚钱，也不等于扣费后赚钱。
- D25 概率对应其四个持有期平均超额收益为正，不表示每天均为正。
- 校准参数随模型冻结，线上不按当天候选数量重新拉伸分数。
- 校准样本不足、缺少正负类别或校准无效时，训练失败，不采用默认映射。

保留独立的毛超额收益回归输出，供现有成本门判断是否覆盖交易成本。风险和成本不提前扣进基础分，继续由原有所有者处理。

**固定融合后的 `final_score` 是综合决策分，不是概率。** 必须在合同和展示中区分 V2 证据分、V3 模型基础分及最终综合分。

### 工件和接口

- 每档完整工件绑定特征、模型、校准器、训练数据、分区及 hash。
- 公共评分结果承载基础分、评分含义、模型身份和解释；收益预测继续使用独立字段。
- V3 缺少排序模型或校准器时明确要求重训，不静默使用 V2 或旧 V3。
- 新 V3 工件完整校验后原子发布，训练失败保留最近完整工件。

## 4. 公共链条接入与回归

公共业务规则保持现状，新 V3 必须在这些条件下证明有效：

- 原有本地风险只扣一次。
- DeepSeek 继续使用固定 68/32 融合及原预算。
- 推荐阈值、动作池、最终分排序、TopK 和集中度规则保持。
- 如果新分数在现有阈值下长期无法产生合格推荐，记录为候选方案不适配，不通过抬高分数或放宽公共阈值掩盖。
- DeepSeek 失败继续执行合法本地降级；V3 模型失败不能伪造成正常评分。
- Long 保持不评分。

必须调整现有硬编码评分身份的地方：按档位传递真实分数含义，贯穿决策 hash、冻结、历史、GET、SSE 和页面。旧历史保留原始身份和分数，不重新解释成新 V3。

回归重点：

- V2 迁移前后，同输入、同工件得到相同预测、分数和推荐结果。
- V3 训练与线上特征及评分转换一致。
- 高基础分仍会被成本门、风险 veto 或动作阈值拦截。
- 同分顺序、空仓、集中度、固定融合黄金用例保持正确。
- 15:00 first-wins、迟到结果、热冷启动和历史恢复不回归。
- 工件损坏、缺失、错档位与错策略明确失败。
- 在线批量推理无网络调用，满足现有性能门禁。

运行定向测试、受影响 Ruff、公共接口 mypy、完整 diff Review；正式启用前执行完整发布门禁和桌面展示验收。

## 5. 收益门禁与交付顺序

### 收益成功条件

固定比较 V2、原 V3、新 V3，使用相同日期、候选人口、可执行成交假设及成本口径。

新 V3 晋级需同时满足：

- 20bp 下 Top6 净超额为正，并优于 V2 和原 V3。
- 50bp 下仍有正净超额，并优于原 V3。
- 最大回撤和严重亏损率不劣于同口径生产基准。
- 报告换手、空仓、集中度、年度与市场状态表现，D25 各期限单独列出。
- 校准报告包含 Brier score、可靠性分组及分数覆盖情况。
- 开发和确认结束后冻结完整链条，再一次性打开至少 200 个交易日的最终留出；失败后不重复使用该留出选模型。

当前日线收盘代理不足以证明真实 15:00 可执行收益。点时特征、成交或 DeepSeek 历史证据缺失时，分别标明验证范围；本地链通过不能冒充完整融合链通过。

### 实施顺序

1. 修改两份权威合同，登记现有所有者、目标所有者、消费者和删除路径。
2. 隔离 V2/V3 实现，先证明 V2 行为一致。
3. 完成 V3 排序训练、校准、完整工件及独立评分。
4. 接入公共链条，完成身份、展示、失败处理和全链路回归。
5. 提交并推送工程批次，明确真实训练与收益证据状态。
6. 完成历史门禁后进行至少 20 个交易日的隔离 Shadow，检查延迟、缺失、评分和冻结一致性；不自动调参、不额外消耗 DeepSeek 预算。
7. 证据通过后由用户明确授权正式启用。

进度只维护在现有工程台账。工程完成、收益验证通过和生产启用分别记录；数据不足时交付已完成的工程能力和准确阻塞项，不宣称任务已经证明收益提升。

 
# 全工程数据、命令与读写性能优化实施计划

## 一、目标与最终入口

统一数据归属，减少重复文件、重复解析和跨文件提交，精简日常命令。删除 check，其有效检查能力合并进现有 scripts/ 诊断体系。

### 日常命令

./run.sh                 # 启动看板
./run.sh sync            # 同步在线行情窗口和公司资料
./run.sh sync market     # 单独同步、续传行情
./run.sh sync company    # 单独同步、续传公司资料
./run.sh train           # 更新完整历史，联合训练或复用 V2/V3
./run.sh help

- sync 顺序执行 market、company，各自提交、各自报告；一项失败继续另一项。取消、配置无效或公共准备失败则停止。
- 同一波次复用合法的官方总体与 ST 证据，各任务保留自己的证券范围、截止日和完整性判断。
- train 自动完成历史维护与训练准备，有效数据和模型直接复用。
- 删除三个旧 download_* 人工命令及 check，不保留别名；同步 Bash、PowerShell、Python CLI 和帮助。
- 定时历史任务统一使用 trader-cli sync history，只维护历史；更新各平台任务模板。
- stdout 仅输出最终汇总 JSON，stderr 输出进度。退出码：成功 0、失败或待补 1、参数错误 2、取消 130。
- 启动保持既有后台维护机制，不自动执行全量下载或训练。

### 开发与运维检测

继续使用唯一入口：

.venv/bin/python3 scripts/diagnose_runtime.py --profile local --output -

新增 local 组合，承接原 check 的四项能力：

| 原检查 | 合并方式 |
|---|---|
| 配置校验 | 新增配置诊断 adapter，复用配置加载和校验实现 |
| 历史维护状态 | 新增只读状态诊断，调用现有状态用例 |
| 研究状态 | 复用现有 research 诊断及其业务状态来源 |
| 离线性能 | 复用现有 performance 诊断及性能实现 |

- 不新增 check.py、第二个检测总入口或重复校验逻辑。
- local 不联网、不启动服务、不下载、不训练、不写活动业务库。
- 配置无效时，依赖该配置的检查明确标记未执行；其余独立检查继续。
- 研究证据不足在本地汇总中标记为降级，保留原因；不得将“状态可读取”写成“研究通过”。专门的研究诊断继续保留严格判断。
- 支持配置默认档位及显式 V2/V3/双档检查；性能结果分别报告。
- 汇总沿用既有诊断状态与脱敏报告规则，输出到 stdout 或明确的仓库外路径。
- 删除 trader-cli check、命令组递归包装及其汇总 schema；保留有实际消费者的配置校验、研究状态和性能底层入口，共用唯一实现。
- Makefile 门禁继续使用现有实现；同步 README、工程文档、脚本说明和测试。

### 从全工程归入 data 的内容

| 功能 | 保存内容 | 写入所有者 |
|---|---|---|
| 行情历史 | 价格修订、观察序号、日历、任务、缺口、断点、快照和绑定参考 | download |
| 在线窗口 | raw/qfq 价格、来源、档位窗口身份及完成断点 | download |
| 市场参考 | ST 证据、行业查询、在线交易日历缓存 | 保留各现有业务所有者和表边界 |
| 公司资料 | 公告、正文、财务、新闻、质押、解禁和增量断点 | download |
| 公司资格 | 永久资格、人工黑名单、事实摘要及发布身份 | recommendation |
| 训练 | 双头模型、元数据、样本和完整性标记 | training |
| 推荐状态 | 正式冻结、恢复检查点、证券总体、来源游标、日历恢复证据和发布序号 | recommendation |
| 请求预算 | DeepSeek 全局预算、调用审计及终态 | recommendation |
| 研究 | 收益结算、市场基准、提交轨迹、内部筛选和点时数据、预注册、研究检查点及报告 | training |

边界规定：

- 配置、参数、固定观察名单继续位于 config；凭据继续使用现有受保护位置。
- .runtime 保留服务进程锁、日志和临时运行产物。
- 数据维护锁紧邻被保护数据；模型发布锁位于被替换目录之外。
- 内存行情、评分输入和特征缓存保持有界，不新增落盘副本。
- 明确要求仓库外输出的研究工件、诊断报告、迁移副本和验收证据继续使用外部目录。
- 旧证据缓存、旧运行库和退役实验登记为清理候选，不整体搬入新布局。
- WAL、SHM、journal 和必要锁文件按数据库生命周期管理，不计作可随意删除的重复文件。

## 三、存储与性能改造

### 历史行情

- 当前 100 个月库收敛为约 9 个年库，另保留一个控制库。
- raw/qfq 价格、量额、交易状态和缺失状态改为结构化列，取消第二份价格 JSON；公共代码和日期只保存一次。
- 明确保留“该侧数据不存在”和“该侧某字段为空”的区别。
- 保留价格修订、观察序号和快照隔离，未发布追加不改变旧快照结果。
- 日期截面与单股时间序列使用匹配索引；训练按日期流式读取所需列。
- 年度物理库内部按月份维护逻辑摘要、行数和序号；日常增量只校验变化月份。
- 快照绑定参考按内容摘要存入控制库，与快照指针同事务发布，取消独立参考 JSON。
- 延续有界流水线、批量 FULL 事务和线程内连接复用；正常更新不复制、压实整库或删除旧修订。

### 在线行情窗口

- 八个数据库合并为一个 daily_window.sqlite3，全部板块共享结构化价格表。
- 每股保存最近 251 个市场交易日范围内的真实价格对；V3 读取最近 61 个市场交易日范围。
- 保留两档独立窗口身份和资格，不能用最后若干根成交记录替代市场日历窗口。
- 价格、两档身份和完成断点同事务提交，取消跨库 ATTACH 和独立断点 JSON。
- 使用 WAL/FULL；短读事务取完所需数据即释放，解码与特征构建在事务外执行。
- 冷启动完整校验；后续按发布身份复用未变化投影，并在接纳前后复核身份。
- 并发变化、损坏或读取失败保留最近有效投影。
- 完整历史和在线窗口保留独立维护锁、供应商流程和发布状态。

### 参考与公司资料

- ST JSON 改为 SQLite 按股票增量更新，保留 ever-ST 优先、同日 clear 和并发保守合并。
- 多类资格库与外部 manifest 合并为一个资格库，事实和发布身份同事务提交。
- 行业历史与当前查询继续分表，在线日历跨档位共享；历史快照仍绑定自身日历。
- 公司资料保持单库、页级续传、批量读写和原子发布，不新增逐股缓存文件。
- 公告、新闻、财务、质押和解禁分别保留各自有效窗口与完整度语义。

### 推荐、训练与研究

- 正式冻结的规范载荷原字节、摘要、索引和恢复检查点存入 decisions.sqlite3，取消新增逐日载荷文件。
- 策略与交易日唯一约束保证 first-wins；相同内容幂等，不同内容冲突。
- 发布序号并入对应档位快照库，保留区间预留和重启不复用规则。
- DeepSeek 使用唯一共享预算库，所有启动方式共用，每日 168 次物理请求上限不重置。
- 模型沿用每头双文件及整档双头发布，不重新引入活动指针或代次目录。
- 样本缓存与模型分离，保留用于完整性和字节摘要校验的 complete.json。
- 研究轨迹继续按交易日分区；结算和不同研究身份的数据独立，保留容量、回收及不可变证据关系。

## 四、模块、接口与兼容切换

- 配置统一为 data_dir、runtime_dir，移除独立 freeze_dir/reference_dir。
- 配置边界解析不可变 DataPaths，由唯一组合根显式注入；路径解析不创建目录或打开数据库。
- 清除业务、诊断和脚本中基于项目根目录、__file__ 的数据路径硬编码。
- 默认、显式单档、双档启动使用一致的 V2/V3 命名空间与共享预算位置。
- download/application 拥有同步编排，使用类型化请求、任务结果和进度；供应商、持久化、时钟和执行器经端口注入。
- training/application 消费发布历史，负责样本、模型、研究和结算；历史维护后训练的跨业务接线留在组合根。
- recommendation/application 拥有推荐、冻结和只读查询；HTTP/Web 继续只调用推荐只读用例。
- 技术 infra 只承载连接、事务、锁、原子文件和执行资源；业务 SQL、格式和身份校验留在所属 adapter。
- 配置诊断、研究状态、历史维护状态和性能检查共用业务实现，scripts 仅负责选择、执行和报告。
- 文件使用职责明确的 snake_case；公开 Python 类型和函数遵守 PascalCase。涉及的禁用名称与所有消费者一次切换。
- 调整历史分区引用、短窗发布端口和同步结果类型，不用无类型字典传递内部状态。
- 旧命令、旧配置和旧磁盘格式明确拒绝，不保留别名、双读或隐式迁移。
- 删除仅服务旧 qfq 布局的转换工具；历史压实工具适配年度布局，继续显式离线执行。
- CreateApp() 保持无线程、无网络、无数据库和文件写入副作用。

## 五、实施顺序、验证与交付

### 单阶段实施顺序

1. 基线与清单：记录分支、上游和已有修改；登记每项数据当前所有者、目标所有者、全部消费者和必删路径；取得稳定的仓库外副本。
2. 基础数据切换：完成统一路径、年度历史、共享短窗、参考和公司资料，并同步所有读取与发布消费者。
3. 持久状态切换：完成冻结、资格、预算、发布序号、模型缓存和研究归置，扩展既有隔离迁移工具。
4. 入口与诊断收敛：接入 sync/train，删除 check，完成 local 诊断、脚本、CLI、定时模板、帮助及退出码切换。
5. 集中验收交付：更新权威文档，Review 完整 diff，完成门禁，原阶段记录真实证据，创建一个提交并推送核对上游。

整个任务使用工程台账下一个可用阶段号；内部步骤不另建阶段或第二份进度文件。

### 正确性与回归

- 历史跨年查询、修订可见性、变更月摘要、发布失败和断点恢复。
- 两档交易日窗口、停牌、缺价、来源冲突、并发读取、原子断点及取消。
- ST 合并、永久资格、人工黑名单、行业点时和公司资料失败保留。
- 模型双头配对、缓存复用与失效、缺失降级、三种启动方式路径一致。
- 热运行、冷启动、15:00 冻结、正式记录命中、合法补算、迟到结果和重启恢复。
- 迁移前后正式载荷及摘要一致，预算不重置、序号不回退、结算和研究父身份不丢失。
- sync 部分失败、单项续传、公共准备失败、取消和退出码。
- local 离线执行、缺服务可运行、配置失败标记未执行、研究不足正确降级、双档结果独立。
- Bash、PowerShell、Python CLI 拒绝 check 和旧人工命令；帮助、文档及打包消费者无残留。
- 检测脚本只读活动业务数据，不触发初始化、迁移、下载或训练。

### 性能验收

在仓库外使用同数据、同硬件和同资源限制，交替运行新旧实现，每组至少五轮：

- 比较启动加载、热读取、训练窄字段扫描、在线投影、增量写入和无变化复用。
- 记录中位耗时、连接及事务次数、正式文件数、磁盘实际占用、WAL 峰值和峰值内存。
- 当前范围历史正式数据库从 101 个降至约 10 个，在线窗口从 8 个降至 1 个；辅助文件单独统计。
- 主要读取和增量写入中位耗时须改善，任一负载超过 10% 的退化须解决。
- 保持推荐进程 RSS 384 MiB、规范缓存 248 MiB及现有训练资源上限。
- 运行受影响 Ruff/mypy、定向测试、完整回归、打包入口和差异检查；性能测试与全量回归分开执行。
- 隔离验证、真实供应商、真实服务和发布验收分别报告。

### 默认约定与授权边界

- 沿用已确认选择：下载数据、在线窗口和模型可按新布局重新生成。
- 冻结、永久资格、人工黑名单、预算、发布序号、结算及有效研究证据必须保留；身份冲突时停止相关切换并报告。
- 保留现有训练工件删除和风险数据，生成运行数据不混入代码提交；模型 Git 白名单适配新双文件路径。
- 活动数据切换、遗留数据删除、系统任务重新安装及真实批量重下载另行明确授权；代码、迁移候选和隔离验证先完成。
- 评分、风险、成本门、数据源优先级、调度时间和发布授权不在本次变更范围内。

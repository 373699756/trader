# V1/V2 合并与 V2/V3 独立三头训练计划

## 1. 最终决策

本计划把 V1 的有效因子能力并入 V2，并按用户新确认的训练边界把 V2 与 V3 拆成两组三头 bundle：

- V2：`data/train/v2/{today,tomorrow,d25}/`
- V3：`data/train/v3/{today,tomorrow,d25}/`

V2 同样加载 Today、Tomorrow 和 D25 三个模型头，不再只拥有 Tomorrow 模型。V2 与 V3 分别训练、分别发布、分别加载，
两档只共用 `data/history/baostock` 的 2000 日历史事实源，不共用拟合结果。V2 的目标合同增加 120/250 日长期趋势和
市场状态并将在线有界读取提升为 251 日；V3 保持当前 1/3/5/20/40/60 日模型合同，作为独立基线和研究档位。

每个档位目录内部都只允许 `today/`、`tomorrow/`、`d25/` 三个策略头；训练入口必须显式绑定目标档位并对三头
顺序拟合、原子发布，禁止把 V3 文件复制进 V2 冒充扩展模型，也禁止按当前默认档位隐式决定输出目录。

目录迁移分两步闭合：现有 V3 三头工件逐字节同步到 `data/train/v3/{today,tomorrow,d25}/`；V2 三个目标目录只建立
未训练占位。V2 新工件未完整生成前不切换 loader，当前 `run.sh` 继续读取旧扁平目录。旧扁平目录只读保留，待档位感知
loader、训练器、due 状态和 CLI 一次切换并验证后删除，不能长期形成第二真相源。

## 2. 目标与不承诺事项

优化目标是在各策略自己的持有期内，提高相对同日可投资 A 股基准、扣除完整往返交易成本后的可重复净超额收益，
同时控制严重亏损、最大回撤、换手、容量不足和集中度。增加历史长度、因子数量或模型复杂度都不是收益证据。

本计划不承诺未来收益。收盘日线训练是用户确认的统一离线训练口径，但它不能被描述成历史 11:20 或 14:50
point-in-time 精确复现。训练、工件生成、历史验证、Shadow 和生产启用是相互独立的状态；训练完成、工件可加载和生产启用仍是三个不同状态。

固定业务边界保持不变：

- Today 在 11:20 冻结，Tomorrow 与 D25 在 14:50 冻结，first-wins 与收盘 fallback 语义不变。
- 模型只输出扣成本前预测超额、模型相对排名和分支分歧，不覆盖统一的 0–100 `base_score`。
- `local_score = clamp(base_score - local_risk_penalty, 0, 100)`，本地风险只扣一次。
- 融合继续使用
  `clamp(local_score * 0.68 + deepseek_score * 0.32 - deepseek_risk_penalty, 0, 100)`，并按
  `ROUND_HALF_UP` 保留两位；固定向量保持 `83.40`。
- ExecutionCost 独占完整往返成本；训练标签不预扣成本，在线选择与评价只扣一次。
- Long 不使用三个模型头，不进入 DeepSeek、TopK 或冻结。
- `automatic_model_update=false`；下载、启动、Web 请求和定时任务不得触发训练或热加载。

## 3. 档位目录与工件所有权

两个档位都拥有三个独立策略头：

| 档位 | Today | Tomorrow | D25 | 当前状态 |
| --- | --- | --- | --- | --- |
| V2 | `data/train/v2/today/` | `data/train/v2/tomorrow/` | `data/train/v2/d25/` | 空目录；等待 251 日扩展合同训练 |
| V3 | `data/train/v3/today/` | `data/train/v3/tomorrow/` | `data/train/v3/d25/` | 已从现有 `*-v3` 工件逐字节同步 |

每个目录继续只保存固定的四件配对工件：

~~~text
model.json
report.json
training-input.json
active-bundle.json
~~~

`training-input.json` 保存来源 snapshot、日历、证券集合、日期切分、特征合同和输入 hash，不保存 2000 日逐行行情；
`model.json` 保存拟合结果；`report.json` 保存训练与验证证据；`active-bundle.json` 只绑定前三者的 hash。
V2 与 V3 可以绑定同一历史 snapshot，但必须拥有不同的训练合同、feature manifest、model hash 和发布指针。

V2/V3 loader 复用同一套三头 repository 与完整性校验框架，但必须把 profile 作为目录选择和 codec 合同的一部分。
每个头必须分别校验：

- model ID、model hash 与当前档位一致；
- feature manifest 与档位合同一致，V2 明确包含 120/250 日特征；
- training-input hash、source snapshot hash、训练锚点和标签合同完整；
- V2 在线输入身份明确绑定 251 日有界读取，V3 继续绑定现有 61 日合同。

任一档位的任一 head 缺失、损坏或身份不一致，只使所选档位启动失败关闭；不得跨档回退、拼接另一档 head，
也不得在运行期临时重训。

现有 JSON 中的 `profile_id=v3`/`v3_head_*` 字符串是已发布 V3 工件的跨进程身份，为保持 hash 不变必须原样同步；
V2 新工件必须使用 V2 自己的 schema/manifest/hash，不得修改现有 V3 JSON 后重新签名。

## 4. V1 因子怎样合并

V1 的 20/40/60 日 skip-5 残差动量是当前 Tomorrow 六特征集合的子集。V1 的 20/40/60 日因子直接进入 V2 Tomorrow
模型的统一特征矩阵，不把旧 V1 模型输出作为额外分支，也不把 V1 分数与 V2 模型预测再次加权。

V2 Tomorrow 模型仍以一个可审计模型组输出一个预测：

~~~text
统一特征矩阵
  ├─ Ridge
  ├─ 浅层 LightGBM
  └─ 独立严重亏损概率头
       ↓
时间前推 OOF 学习 Ridge/LightGBM 非负组合权重
       ↓
扣成本前预测超额 + 分歧 + 严重亏损概率
~~~

旧 V1、旧 V2 和旧共享三头工件只作为有时间有效性证据的只读控制组。控制组预测必须来自决策日当时已经发布的模型工件或正式冻结记录；
禁止用训练截止日晚于或等于评价日的当前全量模型回算旧日期并冒充样本外收益。

V2 重训时，V1 因子、长周期因子、Ridge、LightGBM、OOF 权重、校准和风险头必须在同一 V2 训练合同下整体生成。
V3 继续按自身合同独立训练和发布；两档不得共享拟合参数或把一档预测作为另一档输入。

## 5. 2000 日训练跨度与 250 日特征窗口

V2 与 V3 共同读取 `data/history/baostock` 的同一个滚动 2000 个交易日 active snapshot。三个
`data/train/*-v3` 目录不是历史行情源，训练命令也不从这些目录反向读取 2000 日日线。

两个数字含义不同：

- 2000 日是共享训练事实空间，用于特征预热、开发段、滚动前推 OOF、早停、校准、embargo、确认和终端留出。
- 250 日是单个扩展特征的最长回看；计算一个锚点最多需要 251 个连续交易日位置。
- 1/3/5 日捕捉即时变化，20/40/60 日捕捉中短期趋势，120/250 日用于长期趋势和市场状态。
- 风险特征用于限制严重亏损与不可交易风险，不能转化为正向 alpha。

不得要求每只股票都拥有 2000 行。全市场交易日历是唯一日期主轴，个股只在自己的上市日至退市生效日前贡献
事实；上市前不造行，停牌不当作缺失，新股不足最长窗口时不得补零、均值填充或跨股票借值。

历史需求必须由有类型 manifest 派生，不得由 reader、训练器和在线评分分别硬编码：

- `minimum_history_sessions=61`：现有核心特征的最低完整窗口；
- `extended_history_sessions=251`：120/250 日扩展特征的完整窗口；
- `maximum_history_sessions=251`：单股在线与回放读取上限；
- 2000：离线归档与训练切分上限，不进入单股在线热路径。

开发阶段比较严格 251 日资格与显式双窗口专家。61–250 日股票若使用核心窗口专家，必须有独立路由身份与
`short_history` 不确定性；若证据不足，就维持 61 日既有资格，不得隐藏 fallback。

## 6. 统一收盘日线训练口径

三头全部使用日交易结束后的数据训练，来源仍是同一个 `data/history/baostock` active snapshot：

| 模型头 | 训练锚点 | 运行冻结锚点 | 标签 |
| --- | --- | --- | --- |
| Today | D 日 15:00 收盘代理 | D 日 11:20 | D 收盘至 T+1 收盘的扣成本前相对超额 |
| Tomorrow | D 日 15:00 收盘代理 | D 日 14:50 | D 收盘至 T+1 收盘的扣成本前相对超额 |
| D25 | D 日 15:00 收盘代理 | D 日 14:50 | D 收盘至 T+2/T+3/T+4/T+5 相对超额的平均 |

因此本计划不下载历史分钟线，不要求回填真实历史 11:20/14:50 快照，也不因为缺少分钟数据删除任何 V3 日线、
ST、行业、证券身份或标签事实。报告必须继续明确 `training_anchor=15:00_close_proxy`、
`point_in_time_parity=false` 和 `production_authority=false`，除非未来另有真实点时证据和独立授权。

D25 仍是一个模型头，T+2 至 T+5 是四列标签与验证指标；四个未来交易日缺少任一必要事实时不生成该样本。成本
只在最终执行与评价中扣一次，不按四个 horizon 重复扣除。

## 7. 下载、缺口补齐与 SQLite 边界

`download_history` 仍是唯一历史维护入口。V2/V3 不建立第二套历史库，也不因两个评分档位重复下载。初次下载
建立最近 2000 个已完整发布交易日；日常更新只补到最新完整收盘日并重读最近 5 个交易日捕获供应商修订。

缺口按事实族审计：

1. 先核对交易日历、证券上市/退市区间与支持板块。
2. 再核对 raw OHLCV/amount、qfq、交易状态、历史 ST 和带生效时间的行业。
3. 供应商明确停牌的日期保存停牌事实；不得用前收盘伪造可交易 K 线。
4. qfq 缺口只允许重新请求同一供应商，或使用已经证明的同源 raw、qfq 锚点和官方复权算法修复；不得混入另一
   来源的复权因子。
5. ST 缺失保持未知并阻止相关样本；行业缺失保留未知诊断，不得用当前行业回填过去。
6. 缺失或不可信事实只影响相应样本资格，不删除数据库中 V3 仍需使用的事实。

月分片继续使用 `data/history/baostock/partitions/YYYY/MM.sqlite3`，按交易日/代码顺序流式读取；只保存 raw、
qfq、交易状态、ST、行业与 revision 等基础事实，不把派生特征、训练样本、模型预测或报告复制进历史库。新写入
使用单批事务、WAL checkpoint、`quick_check`、行数和 SHA-256 后旁路原子发布。既有 8 KiB 页、月分片、
必要索引和 revision/observation 语义保持；本计划不新增巨型单库，不用删除历史事实换体积，也不原地 VACUUM
活动库。

## 8. 分档训练流程

两档训练必须显式分开：

~~~bash
./run.sh train-v2
./run.sh train-v3
~~~

`train-v2` 使用 251 日特征输入生成 `data/train/v2/{today,tomorrow,d25}/`；`train-v3` 使用现有 61 日合同生成
`data/train/v3/{today,tomorrow,d25}/`。两个命令都固定执行：

~~~text
资源预检
  -> 固定一个 active history snapshot
  -> 月分片 hash / quick_check / 行数只验证一次
  -> 历史按日期与代码顺序只扫描一次
  -> 按所选档位构造特征与 T+1..T+5 标签
  -> 写一个临时多目标 SQLite
  -> 顺序拟合 Today、Tomorrow、D25
  -> 逐头释放数组与 LightGBM dataset
  -> 校验三组固定工件
  -> 各目录原子发布
~~~

同一输入和同一档位训练合同已有完整 bundle 时返回 `already_current`；未到训练节奏返回 `not_due`；历史、磁盘、
内存或合同不完整时失败关闭并保留该档旧三头。三头不并行训练，计算线程最多 2，峰值 RSS 不超过 2048 MiB。

`train-tomorrow` 不再拥有隐式目标档位；后续实现必须要求显式 V2 或 V3，分别写入对应 `tomorrow/`，不能根据
当前运行配置猜测输出目录。完整训练优先使用对应档位的三头命令，保证三个 head 绑定同一父 snapshot 和训练批次证据。

训练命令只由用户显式执行，不自动改 `config/strategy.json`，不重启服务，不热加载模型，也不删除前一组完整
bundle。

## 9. V2 与 V3 的训练和运行差异

V2 与 V3 从特征 manifest 和模型工件开始分离，但继续共用历史事实、标签口径、成本所有权、风险、融合和冻结规则。

边界如下：

- V2 是 V1/V2 合并后的目标默认档位，三头加入经合同登记的 120/250 日长期特征，在线最多读取 251 日。
- V3 是显式研究/对照档位，三头保持当前 1/3/5/20/40/60 日合同和 61 日在线窗口。
- 两档必须分别拥有 model、manifest、training-input 和 active-bundle hash，不能要求预测逐位相同。
- 后模型策略仍必须拥有独立 policy hash，不能用模型差异掩盖未登记的 TopK、风险或成本变化。
- 两档都加载 Today、Tomorrow、D25，不得退化成 Tomorrow-only。

V2 的长窗口若未通过成本后收益和严重亏损门禁，就不替换当前活动 V2 release；V3 继续作为稳定基线。

## 10. 收益与风险准入

V2 扩展候选必须在同日、同股、同人口、同标签和同成本下比较旧 V1、当前 V3 基线与新 V2。
至少报告：

- Rank IC、NDCG@20/50、Q1–Q5 单调性和 Q5-Q1；
- Top6/10/20/50 在 20/50/100bp 下的成本后净超额、胜率和覆盖；
- 严重亏损率、Brier score、ECE、最大回撤和退出不可交易率；
- 换手、容量不足、成交额参与率及板块/行业/单股集中度；
- 年份、市场状态、波动、流动性、板块和上市年龄分层；
- 训练、加载、特征、预测、完整评分的 P50/P95 与峰值内存。

至少满足以下条件才可进入终端留出：

1. 全体及逐板有效覆盖率不低于 95%。
2. Q5-Q1 为正，Rank IC、NDCG 和 TopK 不低于基线。
3. 相对当前生产基准的 20bp 与 50bp 日级配对净增量置信下界为正。
4. 严重亏损率、最大回撤、换手和容量不足不恶化。
5. 主要市场状态、板块、上市年龄和流动性分层无显著反向。
6. 运行热路径零网络，并满足冻结 deadline、内存和资源上限。

任一门失败则候选封存为 `historical_rejected`，继续使用切换前 release。不得以平均分提高、推荐变多、0bp
毛收益或单一阶段结果代替准入证据。

## 11. 当前运行与目录迁移边界

确认集通过后，冻结 V2 三头工件、后模型 policy、风险、成本、动作、TopK、集中度和全部父 hash，再原子打开一次
至少 200 个交易日的终端留出。终端失败后不能在同一留出上调参数重开。

终端通过只产生历史候选资格，不自动启用。随后 Shadow 同时运行 V2 与 V3，分别读取各自三头预测，在相同事实、
候选、标签和成本下比较长窗口带来的收益、风险、换手和 deadline 差异。

当前用户已明确要求先用已有共享三头工件完成正常评分，因此默认启动边界为：

- `config/strategy.json` 的默认 `scoring_profile` 切换为 `v2`；
- 无参数启动、默认 `check`、server 和 performance 入口使用 V2；
- `--profile v3` 保持显式可用；目录切换完成后加载 `data/train/v3/*`；
- `--profile v1` 仍作显式历史对照，历史冻结记录保持原模型身份只读；
- 任一所选档位工件缺失或 hash 不一致时启动失败，不跨档回退。

这一默认切换只是用户授权的运行选择，不把 `historical_data_insufficient`、
`point_in_time_parity=false` 或 `production_authority=false` 改写为收益验证通过。以后的候选改进仍需要确认集、一次性终端留出和 Shadow。

## 12. 实施章节

实施时作为一个高风险大任务按下列顺序完成，每节先更新契约与失败测试，再修改实现；最后统一执行完整门禁。

### 12.1 三头共用合同（已被本计划的独立目录决策替代）

实施状态：已交付。

- 修改 V2 profile 能力为 Today、Tomorrow、D25 三头。
- 抽出 V2/V3 共用的三头 bundle loader、codec 与 repository。
- 删除 V2 专属 Tomorrow 训练目录和独立训练入口计划。
- 契约断言同一策略头在 V2/V3 的模型、manifest、输入和 snapshot hash 完全一致。

该历史完成状态只说明三头通用端口已经存在；模型工件共用结论不再作为目标架构。

### 12.2 现有三头工件的默认 V2 运行

- 将 `config/strategy.json` 的默认 `scoring_profile` 设为 `v2`。
- `run.sh` 与 `run.ps1` 无参数时尊重配置，不再用脚本内的隐藏 V1 参数覆盖；显式 `--profile` 只覆盖当前进程。
- 默认 V2 启动原子加载 `today-v3`、`tomorrow-v3`、`d25-v3` 现有 bundle，不执行训练、不改件、不复制。
- 用真实三头 predictor 对现有 61 日六特征输入执行 Today/Tomorrow/D25 评分，确认有限预测、诊断和成本后净超额都可产生。
- 任一 bundle 缺失、hash 或 manifest 错配都同时使 V2/V3 失败关闭，不使用 V1 fallback。

完成条件：无参数 `run.sh` 选中 V2，现有三头工件逐件通过完整性校验，三个策略都能正常评分。

120/250 日特征、251 日在线读取、OOF 权重和严重亏损头统一归入下一节的重训候选；它们没有存在于当前工件 manifest 中，
本节不实施、不预热、不计算，避免出现“代码声称有新特征，现有模型却从未训过”的错配。

### 12.3 两档独立训练与目录切换

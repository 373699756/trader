# Tomorrow V1/V2 合并为扩展 V2 的收益优化计划

## 1. 目标、范围与当前结论

本计划将 Tomorrow V1 与 V2 收敛为一个扩展后的 V2 评分档位。优化目标不是增加因子数量、提高平均分或增加
推荐数量，而是在 Tomorrow 的 14:50 至下一交易日收盘持有期内，提高相对同日可投资 A 股基准、扣除完整
往返交易成本后的可重复净超额收益，同时约束严重亏损、最大不利变动、最大回撤、换手、容量和集中度。

本计划不承诺未来收益。任何“提高收益”的结论只允许由真实 14:50 point-in-time 数据、时间隔离的确认集、
一次性终端留出和 Shadow 共同证明；日线收盘代理、fixture、平均分提高或推荐变多都不能授予生产权限。

用户可见的目标状态如下：

- V2 吸收 V1 的稳定线性残差动量因子，并扩展到最多 250 个已完成交易日及真实 14:50 日内路径；这里的
  “吸收”是把因子放入统一特征矩阵重新学习，不是把旧 V1 模型输出叠加到新模型。
- 新 V2 必须独立重新训练扩展 Ridge、浅层 LightGBM、严重亏损概率头和 OOF 组合权重并生成候选工件；日常
  启动、盘中评分、历史同步和 Web 请求都不得现场训练。
- 收益、风险、资源和运行门禁通过后，`config/strategy.json` 与无参数启动统一默认选择新 V2。
- V1 不再作为新的生产策略继续演进；生产切换完成后，配置和 CLI 不再接受 V1 启动。
- V1 历史冻结记录保持原模型身份只读，不迁移、不重算、不套用新 V2 语义。
- V3 工件和研究链保持独立；现有 `train-tomorrow` 继续维护过渡期的 V3 Tomorrow 工件，新 V2 使用新增的
  `train-tomorrow-v2`，完整三头 V3 使用独立 `train-v3`；V3 模型只作只读对照，不作为 V2 的模型参数、
  预测或融合输入，任何训练命令都不得自动启用模型。
- V2 与 V3 统一读取同一个滚动 2000 个交易日的 active history snapshot，不按评分档位重复下载或维护历史库；
  二者主要按策略范围、决策锚点、收益标签、模型结构和风险目标区分。
- 不新增 V4，也不为数据集、缓存、报告、schema、运行目录或 Web 资源创建新的项目版本号。

## 2. Review 结论与根因

### 2.1 已确认事实

当前 V1 是一个只消费 20/40/60 日 skip-5 残差动量的固定线性模型。当前 V2 已经消费 V1 的全部三项输入，
并额外消费 1/3/5 日收益，通过 Ridge 与浅层 LightGBM 各 50% 形成预测。因此 V1 的因子集合是 V2 的严格
子集；把这六项重新等权相加不构成真正的 V1/V2 合并，也没有引入新的信息。

当前 V2 的主要已知问题不是缺少正平均结果，而是现有证据中严重亏损率为 15.9472%，高于历史代理的
8.2734%；换手增加 56.2350 个百分点，且 Q5-Q1 为负。V1 同口径平均净增量为负。两档都没有通过现行收益、
风险和排序门禁，也都没有经过验证的逐股严重亏损概率。

当前在线评分和历史训练窗口把 61 根输入作为固定值，最长特征只到 60 日。这会限制中长期趋势、趋势稳定性、
波动状态和流动性周期的表达，但单纯扩大窗口仍不能自动提高收益，必须通过有限参数族研究证明增量价值。

### 2.2 被替代方案的问题

此前“六因子统一评分”方案整体废止，原因如下：

1. 六项因子就是当前 V2 已有输入，没有真正扩展 V2。
2. 用固定分位带通和两个 50% 因子组替换模型，没有样本外收益依据。
3. 把模型因子直接改写为 `base_score`，混淆了证据质量分和预测超额收益两个不同所有者。
4. 删除 Ridge、LightGBM、`model_prediction_rank` 和模型分歧，会丢失预测与不确定性诊断，不能解决已知尾部风险。
5. 继续使用最多 60 日历史，没有满足扩展历史信息的目标。
6. 没有用当前 V2 的严重亏损、换手和负 Q5-Q1 作为明确修复对象。

### 2.3 方案选择

局部方案是在现有六项输入上调整权重或直接加几个技术指标。该方案不能解除固定 61 根历史、训练/在线特征
所有权分散、V1 信号重复计权和尾部风险缺少独立模型的问题，且容易在同一份数据上反复调参。

本计划选择系统性方案：由共享特征 catalog 和 manifest 统一拥有公式、窗口、单位、可见时间和缺失语义；
V1 的 20/40/60 日因子直接进入新 V2 的统一特征矩阵，由新 Ridge 与浅层 LightGBM 在无泄漏训练样本上重新
学习系数、非线性和交互。旧 V1、旧 V2 与 V3 工件只作为只读控制组，不进入新 V2 的训练向量或组合器；通过
有限参数族、时间前推 OOF、确认集、终端留出和 Shadow 决定哪些因子和新分支可以进入唯一生产 V2。

## 3. 不可改变的评分链边界

本计划只改变 Tomorrow V2 的模型输入、模型结构、模型工件和模型风险诊断，不用模型预测覆盖统一证据质量分。
完整链继续保持：

```text
point-in-time 人口与候选资格
  -> 六组件证据质量 base_score
  -> local_risk_penalty 只扣一次得到 local_score
  -> V2 扣成本前预测超额与 model_prediction_rank 诊断
  -> model_net_utility_non_positive 成本执行门
  -> 可选结构化 DeepSeek 复核与固定融合
  -> 动作池、稳定排名、Top6 与集中度
  -> 决策身份、冻结、持久化、GET/SSE/Web
```

以下生产不变量保持不变：

- Today、Tomorrow、D25 的 `score_scale` 继续为 `weighted_evidence_quality_0_100`。
- `model_prediction_rank` 只作模型相对诊断，不进入 `base_score`、`local_score` 或 `final_score`。
- `local_score = clamp(base_score - local_risk_penalty, 0, 100)`，本地风险只扣一次。
- 融合继续使用
  `clamp(local_score * 0.68 + deepseek_score * 0.32 - deepseek_risk_penalty, 0, 100)`，并以
  `ROUND_HALF_UP` 保留两位小数；固定黄金向量保持 `83.40`。
- ExecutionCost 独占完整往返成本；成本可以阻止动作，但不能改写模型信号分或统一证据质量分。
- 正式/观察动作线、Top6、单板最多 60%、同一行业最多 2 只、14:50 冻结和 first-wins 不变。
- Long 继续不评分、不调用 DeepSeek、不进入 TopK 和冻结。

若将来要让模型预测直接改变最终分、动作线或排序，必须另立评分契约和收益研究批次，不属于本计划。

## 4. 目标模型架构

合并后的 V2 仍是一个 Tomorrow profile、一个模型身份和一个生产预测结果。它不是旧模型 stacking，而是使用
统一样本重新训练的可审计模型组：

```text
同一 2000 日 active snapshot
  -> V2 point-in-time 统一特征矩阵
       ├─ alpha 特征（含 V1 的 20/40/60 日因子及通过验证的扩展因子）
       │    ├─ 重新训练的扩展 Ridge
       │    └─ 重新训练的浅层 LightGBM
       │              ↓
       │       时间前推 OOF 非负组合
       │              ↓
       │       扣成本前预测超额收益
       └─ 风险特征 -> 重新训练并单独校准的严重亏损概率头
                              ↓
                       风险、观察或 veto
  -> 独立 ExecutionCost 成本门
```

模型约束如下：

- 旧 V2 六特征 Ridge/LightGBM 50/50 是首要控制组，旧 V1 与 V3 Tomorrow 是次级只读控制组；三者现有
  model、系数、树、校准和预测都不得复制为新 V2 的模型输入或初始化参数。
- V1 的模型能力只通过 20/40/60 日残差动量因子进入新 V2；这些因子和新增因子同时进入扩展 Ridge 与浅层
  LightGBM，由新模型重新学习，禁止额外叠加旧 V1 预测造成重复计权。
- 扩展 Ridge 负责稳定、可解释的广义信号；浅层 LightGBM 只捕捉有限非线性和交互。二者的结构、超参数
  候选和停止条件必须预注册，不能读取确认集后继续搜索。
- Ridge/LightGBM 权重必须由训练段时间前推 OOF 预测上的非负 simplex 组合选择并封存，不能继续无证据固定
  50/50，也不能用任何旧 V1/V2/V3 的样本内或最终模型预测训练组合器。
- 严重亏损概率头与 alpha 预测分开训练、校准和保存。其结果只能收缩风险、进入观察、触发 veto 或稳定同分
  排序，不能成为正向 alpha。
- 工件绑定 feature manifest、单位、窗口、缺失掩码、训练/早停/校准/确认日期、active snapshot、模型载荷、
  OOF 组合权重和内容 hash；任何错配或篡改均失败关闭。
- `automatic_model_update=false` 保持不变；训练完成、工件可加载和生产启用仍是三个不同状态。

| 资产 | 新 V2 的处理 | 原因 |

## 5. 历史窗口扩展

### 5.1 目标窗口

V2 的最大历史依赖从 60 个有效交易日扩展到 250 个已完成交易日。运行输入最多读取 251 个时间锚点，以覆盖
当前或 14:50 锚点与此前 250 个有效交易日；具体锚点排列必须由统一 FeatureSpec 声明，训练和在线只能有一种
口径。

历史需求不得继续由在线评分、历史 reader、训练窗口和测试分别硬编码。新增不可变有类型的历史需求对象，至少
表达：

- `minimum_history_sessions=61`：现有核心信号的最低完整窗口。
- `extended_history_sessions=251`：120/250 日扩展信号的完整窗口。
- `maximum_history_sessions=251`：在线单股历史读取和内存上限。
- manifest 派生的最长依赖、窗口身份和缺失策略。

2000 个交易日仍是离线归档、训练跨度、确认、embargo 和终端留出的总体资源边界，不得让盘中评分为每只股票
读取 2000 日历史。

### 5.2 为什么需要离线训练以及数据规模

250 日是单个样本的最长特征回看窗口，不是完整训练区间。旧 V2/V3 工件只绑定各自已有特征、标签、系数、
树结构和固定顺序；新增 120/250 日特征、日内路径、缺失掩码或风险头后，旧工件既没有对应参数，也无法通过
新 V2 feature manifest 校验。因此新 V2 必须至少完整离线训练一次，不能只把 reader 从 61 改为 251，也不能
把任一 V3 `model.json` 复制、改名或包进 V2 bundle 后继续使用。

“必须重新训练”不表示每次启动或每日自动重训。首次生成新 V2 候选必须完整训练；以后只有 initial、cadence、
history revision 或 training-contract due 且输入完整时，才允许用户显式执行 `train-tomorrow-v2`。未到期返回
`not_due`，相同输入与训练合同已有完整 bundle 时返回 `already_current`；服务启动、Web 请求、历史同步和定时
任务都不得触发训练。

V2 与 V3 的离线训练统一使用同一个滚动 2000 个全市场交易日的 active snapshot，为特征预热、训练段 OOF、
早停、校准、embargo、确认和至少 200 日终端留出共同提供空间；共同完整交易日少于 1250 日时返回
`historical_data_insufficient`，不得缩短切分后强行拟合。按约 5500 只股票估算，251 锚点的全市场运行输入
约 138 万条日线记录，2000 日归档的理论上界约 1100 万条；上市、退市和停牌语义会使实际有效记录更少。
这些数据由离线归档流式读取，不进入盘中同步下载。

实施前先审计当前 active snapshot 的日期、证券、raw/qfq、行业、资格和 14:50 点时证据覆盖。已有且 hash
有效的月份直接复用，只通过 `download_history` 补缺口或供应商修订，不为 V2 训练重新下载完整 2000 日。
250 日日线因子不要求新增分钟级全市场下载，但第二族日内路径必须取得真实历史 14:50 及分段分钟证据；该证据
缺失时可以完成训练工程和日线特征验证，不能读取评价收益、发布工件或取得生产权限。

日常运行只加载已经发布的 V2 工件并计算最多 251 锚点的特征，不执行拟合。历史同步、训练、工件验证和生产
切换保持四个独立动作，`automatic_model_update=false` 不变。

### 5.3 统一 2000 日来源与 `data/train` 工件边界

统一来源只表示 V2 与 V3 从同一个 `data/history/baostock` active snapshot 读取交易日历、证券身份、raw/qfq、
历史行业和资格事实，并绑定相同的父 snapshot hash；`download_history` 仍是唯一历史维护入口。训练命令不下载
数据，也不为不同评分档位复制月分片、建立第二套历史库或维护不同截止日。

必须区分训练事实、临时样本和训练结果三个物理层次：

```text
data/history/baostock/                         唯一 2000 日训练事实源
  -> manifest 约束的流式特征与标签构造       可复算的临时样本
  -> data/train/today-v3/                     V3 Today 训练结果
  -> data/train/tomorrow-v3/                  V3 Tomorrow 训练结果
  -> data/train/d25-v3/                       V3 D25 训练结果
  -> data/train/tomorrow-v2/                  新 V2 Tomorrow 训练结果
```

`data/train/{today-v3,tomorrow-v3,d25-v3}/` 不是 2000 日训练数据源。每个目录只保存四件配对工件：
`training-input.json` 保存来源、日期、代码集合、切分和训练合同的身份与 hash，不保存逐日行情或训练样本；
`model.json` 保存模型载荷；`report.json` 保存训练与验证结论；`active-bundle.json` 保存三件工件的配对 hash。
本批只读核对时，三个目录合计只有约 4.4 MB，而 `data/history/baostock` 约 13 GB；该时点证据进一步验证了
前者不承载 2000 日日线，后续大小变化不改变目录职责。

新 V2 必须从与 V3 相同的 active history snapshot 重新按 V2 feature manifest 和 Tomorrow 标签构造样本，并
重新训练扩展 Ridge、浅层 LightGBM、严重亏损概率头以及 Ridge/LightGBM 的 OOF 组合权重。旧 V1、旧 V2 与
V3 工件只作为只读控制组：其 model、report、`training-input.json` 和预测不得作为 V2 的模型参数、预测或融合
输入。换言之，任何旧评分工件不得作为 V2 的模型参数、预测或融合输入。若要减少重复计算，只能复用由同一
snapshot hash、事实 revision 和 FeatureSpec 标识的确定性基础事实或特征缓存，不能复用另一 profile 的最终
模型输入、标签、预测、权重或校准结果。

2000 日是全局归档和研究切分上限，不表示每只股票必须拥有 2000 行，也不表示 2000 日全部进入最终拟合：

```text
同一 active snapshot（滚动 2000 日）
  ├─ 特征预热：新 V2 单样本最多回看此前 250 日
  ├─ 开发段：滚动前推训练、早停、校准和 OOF
  ├─ embargo：隔离相邻区间
  ├─ 确认段：只评价冻结候选
  └─ 终端留出：完整链冻结后仅打开一次
```

因此“新 V2 使用 250 日”准确表示每个样本的最长特征依赖；“V2/V3 使用 2000 日”表示它们共用的历史事实
空间，不表示 V2 复用 V3 的已训练模型。V2 和 V3 可以复用相同基础事实和确定性特征计算，但必须分别拥有与
策略匹配的样本、标签、切分、feature manifest、模型、报告和内容 hash；任何 head 都不得读取另一策略的预测
作为隐藏输入。

### 5.4 上市时间较短股票

不得为了使用长周期因子把少于 251 日的股票填 0、均值填充或冒充完整输入。开发阶段预注册并比较两个方案：

1. 严格扩展方案：不足 251 个有效交易日的股票不进入扩展 V2 模型。
2. 显式双窗口专家：61–250 日股票只进入核心窗口专家，达到 251 日才进入扩展专家；路由规则、模型身份和
   `short_history` 不确定性必须显式保存，不得作为隐藏 fallback。

两个方案使用同一人口和 outcome 比较候选召回、成本后收益、严重亏损、上市年龄分层和机会成本，只允许一个
方案进入确认集。若二者都失败，保持原有 61 日生产资格。

### 5.5 历史读取与失效

- 归档 reader、盘中历史预热和训练缓存按 manifest 的最大依赖读取，不在评分线程同步联网。
- history revision 只失效真正受修订影响的标签日和最长 250 日特征依赖范围。
- 相同 facts revision 和相同模型向量复用同一批量预测；普通报价 overlay 不重算历史特征。
- 保持单股有界缓冲、每次只打开一个月分片、训练临时样本库和 2048 MiB 峰值 RSS 约束。
- 14:50 前无法完成的新批次放弃并保留最近有效决策，不允许扩大窗口后破坏 deadline。

## 6. 因子研究目录与优先级

新增参数不能一次全部进入模型。每次只预注册一个有限参数族，先固定公式、单位、方向、点时可见性、最长依赖、
缺失语义、候选数量和停止条件，再读取开发或确认收益。

| 阶段 | 参数族 | 候选信息 | 唯一职责 |
| --- | --- | --- | --- |
| 控制组 | 现有六项 alpha | 1/3/5 日收益，20/40/60 日 skip-5 残差动量 | 旧 V2 基准，不调整 |
| 第一族 | 长周期价量 alpha | 10/20 日收益，120/250 日 skip-5 残差动量，趋势斜率、突破距离、趋势一致性、波动标准化动量 | 判断超过 60 日的信息是否提高 T+1 排序和净超额 |
| 第二族 | 14:50 日内路径 | 隔夜跳空、开盘至锚点、上午/下午收益、尾盘 5/15/30 分钟收益与加速度、收盘位置、VWAP 偏离、尾盘成交额占比 | 提高生产锚点一致性和次日信号稳定性 |
| 第三族 | 市场与板块状态 | 上涨/涨跌停广度、横截面离散度、成交额扩张、板块相对强弱、波动状态、残差动量稳定性 | 默认只用于中性化、稳定性分层和预注册交互 |
| 第四族 | 流动性、容量与尾部风险 | Amihud 5/20/60 日、低成交/停牌频率、容量、下行半方差、20/60 日回撤、ATR、beta、残差波动、退出不可交易概率 | 进入 ExecutionCost、RiskDecision 和严重亏损头，不直接正向加分 |
| 后置族 | 财务质量与事件事实 | ROE/ROA、现金流、应计、成长稳定性、杠杆、减持、解禁、质押、回购、分红及事件衰减 | 仅在 `published_at/effective_at` 点时证据完整后研究 |

以下内容不进入候选：无法点时验证的主力资金、社交热度、成组堆叠的 MACD/KDJ/RSI 变体、当前行业回填
历史、无可靠归档的 L2 字段、DeepSeek 自由文本以及任何未来 outcome 或 oracle 排名。

市场、板块、行业、市值和流动性默认是暴露控制或分层条件。若要把其中任何一项作为正向 alpha，必须作为
独立候选重新预注册，不能在残差化后又重复加分。

## 7. 研究、训练与选择流程

### 7.1 基线冻结

实施前冻结并校验：

- 当前 V1/V2/V3 模型载荷、feature manifest、预测器、数据身份和内容 hash；它们只作为不可变控制组，不成为
  新 V2 的初始化、特征列或组合分支。
- 同一日期、同一股票、同一人口上的旧 V1 和旧 V2 预测。
- 控制组预测必须来自决策日当时已经发布的模型工件或正式冻结记录，并证明模型训练截止日早于被评价日期；用
  当前全量模型回算其训练期内的旧日期属于未来泄漏，只能作描述，不能进入收益准入统计。
- 旧 V2 的严重亏损率、换手、Q5-Q1、Rank IC、TopK、成本和覆盖基线。
- 当前候选、风险、成本、DeepSeek、动作、Top6 和集中度策略 hash。

旧 V2 是新方案必须战胜的首要控制组；旧 V1 只用于证明合并分支是否提供独立价值。不能因为新 V2 优于 V1
但仍劣于旧 V2 就判定通过。

### 7.2 数据与标签

- 所有收益研究使用真实 14:50 `anchor_price`，退出使用下一交易日前复权收盘。
- 标签固定为扣成本前 T+1 超额收益；训练目标不预扣成本，ExecutionCost 在选择和评价中只扣一次。
- 基准继续使用同日、同锚点、同资格和可交易人口的等权收益，候选模型不能改变基准人口。
- 停牌、一字涨跌停、不可买卖和 qfq/raw 转换继续由 CanonicalOutcomeEvaluator 唯一处理。
- 20bp 是主评价成本，50bp 是稳健性准入门，100bp 只作压力测试。
- 缺少真实 14:50 分钟、历史行业、资格、硬过滤或风险事实的点时证据时，必须在读取评价收益前返回
  `historical_data_insufficient`。

### 7.3 时间切分

数据按交易日排序，禁止随机拆分。同一交易日的全部股票必须进入同一切分：

```text
训练 -> 早停 -> 校准 -> embargo -> 确认 -> embargo -> 至少 200 日终端留出
```

- 开发段使用滚动前推 OOF 构造 Ridge/LightGBM 组合训练输入，不能用同一行的拟合内预测训练组合器。
- OOF 的每一折只用更早的训练日分别拟合扩展 Ridge 和浅层 LightGBM，再预测隔离后的下一段日期；
  同一交易日的全部股票必须同进同出，禁止随机拆股或随机打乱日期。
- 各折未见样本的预测按 `(trade_date, code)` 汇总后，使用预注册的非负 simplex 约束回归学习分支权重；权重
  非负且总和为 1，拟合目标仍是扣成本前 T+1 超额标签，ExecutionCost 只在选择和评价时扣一次。
- OOF 权重封存后，扩展 Ridge、浅层 LightGBM 和严重亏损概率头才允许按各自合同使用完整开发段重新拟合或
  校准；确认集、终端留出和 Shadow 均不得反向改权重或模型参数。
- 每个有限参数族先在开发集只选择一个候选；确认集只能比较控制组和该唯一候选。
- 读取确认结果后不得更换特征、窗口、模型、权重、阈值或成本假设。
- 终端留出在完整链冻结前只封存日期和 date-set hash，不读取任何收益；满足前置后只允许原子打开一次。

### 7.4 离线训练入口与工件职责

- 现有 `./run.sh train-tomorrow` 保持零参数并继续维护过渡期的 V3 Tomorrow 工件，不改变其既有工件、节奏或
  loader 语义；完整 V3 三头训练由对应实施章节中的 `./run.sh train-v3` 统一完成。
- 新增零参数 `./run.sh train-tomorrow-v2`，专门执行扩展 V2 的数据就绪检查、样本构造、滚动前推 OOF、
  Ridge/LightGBM 完整重拟合、风险头训练与校准和候选 bundle 封存；Linux 与 PowerShell 入口必须具有相同
  命令和拒参语义。
- `train-tomorrow-v2` 使用固定项目数据根和 active history snapshot，不接受 `--profile`、`--runtime-dir`、
  `--sessions`、阶段跳转、checkpoint 或 `run_id`。相同训练合同与输入 hash 已有完整 bundle 时返回
  `already_current`，数据或点时证据不足时失败关闭。
- V2 候选固定写入 `data/train/tomorrow-v2/`，整组绑定 input、report、model、feature manifest、日期集合、
  OOF 权重、校准证据、父 snapshot 与内容 hash；它不直接覆盖包内生产工件或 `config/strategy.json`。
- `data/train/{today-v3,tomorrow-v3,d25-v3}/` 继续只属于 V3 三个 head 的输出 bundle；V2 可以核对它们绑定的
  source snapshot 以建立公平对照，但训练 reader 不得从这些目录读取行情、特征行、标签或模型预测。
- 所有训练命令只能由用户显式执行，历史自动化不得调用任一命令，也不得切换 profile、重启服务或热加载工件。

### 7.5 模型候选顺序

候选按以下顺序逐级进入研究，前一层失败则停止后续组合，不滚动搜索：

1. 冻结旧 V1、旧 V2 和 V3 Tomorrow，只使用满足第 7.1 节时间有效性条件的同日同股只读基线预测，不把
   它们输入新模型。
2. 用现有六项因子重新训练新 V2 Ridge 与浅层 LightGBM，并用时间前推 OOF 学习二者权重，验证训练管线本身
   相对旧 V2 固定 50/50 是否有增量。
3. 按第 6 节的预注册顺序逐族增加因子；每个候选都从训练段重新拟合 Ridge/LightGBM，不继承上一候选参数。
4. 对 20/40/60 日 V1 因子做保留/剔除消融，只有其成本后边际贡献通过才保留；不得改为叠加旧 V1 预测。
5. alpha 候选确认通过后，再训练并校准独立严重亏损概率头和不确定性动作。
6. 完整模型通过后，才与候选容量、成本门、风险、DeepSeek、动作和集中度形成完整选择链验证。

### 7.6 新 V2 与 V3 的策略边界

V2 与 V3 的区别不由历史归档长度定义。二者共用同一 2000 日数据源和点时资格合同，但形成不同的评分策略：

| 维度 | 新 V2 | 完整 V3 |
| --- | --- | --- |
| 训练事实输入 | `data/history/baostock` 的同一 2000 日 active snapshot | `data/history/baostock` 的同一 2000 日 active snapshot |
| 训练结果输出 | `data/train/tomorrow-v2/` 的独立 V2 bundle | `data/train/{today-v3,tomorrow-v3,d25-v3}/` 的三个独立 V3 bundle |
| 策略范围 | 只拥有 Tomorrow 模型头 | 同时拥有相互独立的 Today、Tomorrow、D25 三个模型头 |
| 决策与标签 | 14:50 决策，预测至下一交易日收盘的扣成本前相对超额 | Today 对应 11:20 的 T+1；Tomorrow 对应 14:50 的 T+1；D25 对应 14:50 的 T+2 至 T+5 聚合目标 |
| 特征窗口 | 单样本保留 1/3/5、20/40/60，并允许最长 120/250 日扩展特征 | 每个 head 按自己的冻结 manifest 取数；V3 不是“读取 2000 日进行一次在线预测” |
| 模型结构 | V1 因子直接进入重新训练的扩展 Ridge/浅层 LightGBM，两者使用 OOF 非负组合，并单独训练严重亏损概率头；不包含旧模型 stacking | 三个策略分别拥有 Ridge/浅层 LightGBM、标签、校准、模型 ID/hash 和运行状态，预测不得跨策略复用 |
| 产品定位 | 收益验证通过后成为专注 Tomorrow 的默认档位 | 作为显式选择的多策略档位，价值来自 Today/Tomorrow/D25 的完整覆盖而非版本数字或更长历史 |

V3 的数字更大不代表其 Tomorrow head 天然优于新 V2。二者的 Tomorrow 结果必须在相同日期、股票、人口、成本
和选择约束下直接比较；未战胜新 V2 的 V3 Tomorrow 不得仅凭档位名称取得默认或生产优势。共享数据源只消除
重复下载和口径分叉，不合并不同策略的模型身份、收益标签、冻结时间或生产授权。

## 8. 收益、风险与排序准入门

所有候选必须在同日同股、同人口、同选择约束下比较旧 V1、旧 V2、V3 Tomorrow 和新 V2；旧模型只提供
基线结果，不作为新 V2 输入。至少报告：

- Rank IC、NDCG@20/50、Q1–Q5 单调性与 Q5-Q1。
- Top6、Top10、Top20、Top50 的 20/50/100bp 成本后净超额、胜率和覆盖。
- 严重亏损率、MAE/ATR20、最大回撤和退出不可交易率。
- 换手、容量不足、成交额参与率、板块/行业/单股集中度。
- 不同年份、牛市、熊市、震荡、高低波动、高低流动性和三板分层稳定性。
- 候选生成、报价、特征、预测和完整评分的 P50/P95，14:50 决策年龄、deadline 放弃率和峰值内存。
- 严重亏损概率的 Brier score、ECE、分桶覆盖和收益机会成本。

准入条件全部满足才算通过：

1. 全体及逐板有效覆盖率不低于 95%。
2. Oracle Top20 recall 的 95% 置信下界不低于 95%，Top50 recall 的 95% 置信下界不低于 90%。
3. 相对旧 V2 的 20bp 和 50bp 日级配对净增量 bootstrap 置信下界均为正，并通过 Holm 0.05。
4. Rank IC、NDCG@20/50、Top6/10/20/50 和 Q5-Q1 均改善，且 Q5-Q1 必须转为正值。
5. 严重亏损率不得高于同口径当前生产基准；最大回撤、换手和容量不足不得恶化。
6. 任一板块、主要市场状态、上市年龄或流动性分层不得出现显著反向。
7. 生产热路径保持零网络调用，并满足冻结时延、内存和 deadline 预算。

任一条件失败即封存为 `historical_rejected`。不得用更高毛收益、0bp 结果、平均分、推荐数量或单一市场阶段
覆盖失败门禁。

## 9. 终端留出、Shadow 与生产资格

确认集通过后，冻结完整资格、候选、特征、模型、组合权重、风险、成本、不确定性、DeepSeek、动作、TopK、
集中度和全部父 hash，才允许打开一次至少 200 个交易日的终端留出。

终端留出继续使用第 8 节全部指标和准入门。失败后不得在同一留出上更换候选或重新开启；通过只产生
`historical_validated`，仍固定 `production_authority=false`。

终端通过后运行统一 ShadowMonitor，只读比较当前生产和候选 V2 的：

- 候选重合、首次漏失边界和排名变化。
- 预测超额、成本、净效用、模型分歧和严重亏损概率。
- 成熟 T+1 收益、严重亏损、最大回撤、换手和合法空仓。
- 数据/特征/模型 hash、OOD、缺失、延迟和 deadline 放弃。

Shadow 不得修改正式推荐、冻结记录、配置、模型资源或 DeepSeek 预算。用户已在本计划批次明确授权：新 V2
通过终端留出、Shadow、完整发布门禁和真实服务重启验收后，将其切换为默认档位，不再要求实施者另行取得一次
重复授权。该授权不允许绕过任何收益、风险、点时证据或运行门；任一门失败时保持切换前的生产 release。

## 10. 生产切换与历史兼容

生产切换采用一次性完整切换，不保留 V1/V2 双生产链：

- 包内只发布一个经过授权的 V2 模型工件，profile ID 保持 `v2`，模型内容由新 hash 区分。
- `config/strategy.json` 的全局 `scoring_profile` 在切换批次改为 `v2`；无参数 `./run.sh`、默认
  `check`、server 和 performance 入口都从该配置加载新 V2。
- `./run.sh --profile v3` 继续显式加载 V3；`--profile v1` 在切换批次从配置校验、CLI、server、performance
  和 profile factory 同时移除并明确报错。
- 不提供 V1 到 V2 的自动别名、静默映射、启发式回退或兼容 predictor。
- V1 的活动 loader、包内资源和专属生产测试在切换批次删除；历史 codec 只保留读取旧冻结记录所需的明确语义。
- 旧 V1/V2 冻结记录继续绑定原 `score_scale`、模型 ID 和模型 hash，不迁移、不重算、不回填新字段。
- 回退只能切换完整旧 release 和旧运行目录，禁止新 release 在运行时隐藏回退旧模型。
- V3 继续使用独立资源和显式选择，不因 V2 切换自动变化。
- `automatic_model_update=false` 保持不变，新训练结果不能热注入正在运行的服务。
- 新 V2 工件缺失、损坏或身份不匹配时启动失败关闭，不在当前 release 内隐藏回退旧 V1、旧 V2 或 V3。

若新增严重亏损概率、历史窗口层级或分支诊断需要公开展示，必须由 Web/API adapter 白名单显式投影，并同步
更新 schema、GET、SSE 完整替换、重连/resync、旧记录解释和浏览器消费者；内部状态对象不得直接序列化为 JSON。

## 11. 实施章节与完成条件

写入实施路线；V3 后续运行验收暂停但已有工件保持不变。不得把历史压实、V3 收尾和 V1/V2 合并混入同一提交。

### 11.2 章节一：契约与失败先行测试

### 11.3 章节二：历史需求与共享特征基础设施

- 新增 manifest 派生的有类型历史需求对象。
- 扩展历史 reader、预热、缓存、revision 失效和运行状态到最多 251 个锚点。

- 覆盖 60/61、249/250/251、停牌、新股、退市、复权修订、缺失和非有限值。

完成条件：相同输入在训练、回放、Shadow 和在线得到逐位相同向量；61 日现有路径不退化，251 日资源有界。

### 11.4 章节三：有限参数族与合并模型研究

- 依次研究长周期、14:50 日内路径、状态交互和独立风险头。
- 建立旧 V1、旧 V2、V3 Tomorrow、新 V2 的同日同股控制组；只对新 V2 Ridge/LightGBM 生成时间前推 OOF
  并学习组合权重。
- 新增 `train-tomorrow-v2` 及其拒参、资源、幂等、完整工件和失败关闭契约，保持 `train-tomorrow` 的 V3
  语义不变。
- 工件 codec/hash 覆盖特征、分支、权重、模型、切分和数据身份。
- 父点时证据不足时调用评价收益次数必须为 0。

完成条件：每个家族都有唯一终态；只留下一个确认通过的新 V2 候选，或以 `historical_rejected` 关闭。

### 11.5 章节四：确认、终端留出与 Shadow

- 按第 8 节门禁完成开发和确认。
- 冻结完整选择链，原子打开一次终端留出。
- 终端通过后运行真实 Shadow，并记录漂移、收益、风险、换手、延迟和空仓。

完成条件：证据 hash 完整、无泄漏、无重复打开、所有收益与风险门通过；否则保持切换前的生产 release。

### 11.6 章节五：验证通过后的生产切换

- 发布唯一 V2 工件，删除 V1 新启动链，保留历史只读语义。
- 将默认配置改为 V2，同步 CLI、组合根、状态、冻结、持久化、GET、SSE、Web、包资源和权威文档。
- 真实重启验证模型身份、输入 hash、成本门、冻结 first-wins 和失败降级。

完成条件：无参数启动和默认检查使用唯一 V2，显式 V3 保持可用，V1 启动被拒绝；旧记录解释正确，不存在
双生产链、自动更新或隐藏 fallback。

## 12. 影响范围与验证矩阵

本计划不是只修改 `profiles/v2`。按评分链影响关系，实施必须覆盖以下边界：

| 边界 | 主要修改或 Review 范围 | 必须证明 |
| --- | --- | --- |
| 历史与参考数据 | 历史 reader、窗口对象、预热、revision、缓存 | 251 日有界读取、修订失效、资源上限、立即可见性 |
| 特征与研究 | FeatureSpecCatalog、calculator、manifest、point-in-time 数据集、有限参数族 | 点时可见、单位一致、缺失真实、训练/在线等价、无未来数据 |
| 模型与成本门 | model scoring port/service、V1/V2/V3 predictor、各训练入口、codec、artifact | history 输入与 `data/train` 输出隔离、旧模型只读、新 V2 独立重训、统一 source snapshot、入口隔离、批次身份、OOF 权重、预测确定性、成本一次、失败关闭 |
| 风险与选择 | RiskDecision、严重亏损头、动作池、TopK、集中度 | 风险不产生正 alpha、不重复扣罚、稳定排序、合法空仓 |
| 决策与冻结 | 输入身份、local/hybrid 父子关系、codec、current/history | 新旧模型 hash、14:50 五时期、first-wins、恢复与冲突 |

| 入口与打包 | 配置、CLI、profile factory、bootstrap、Linux/PowerShell、wheel 资源 | V1 启动被拒绝、无参数默认 V2、显式 V3、训练命令职责隔离、`create_app()` 无副作用、仓库外安装 |
| 文档与交付 | 四份文档、CHANGELOG、独立交付记录 | 需求、原因、改动、验证和剩余风险可追踪 |

每个实现子任务只运行直接相关定向门禁；大任务最后一个子任务完成后，对完整合并 diff 统一运行一次：

make package

- 从仓库外安装 wheel 后导入、CLI、模板、CSS、JavaScript 和图标资源验收。

## 13. 当前阻塞与退出条件

当前真实收益验证仍受外部 point-in-time 证据阻塞：历史行业缺少可证明查询时间，现有免费来源不能提供合格的
历史 14:50 分钟点时数据，历史资格、硬过滤和风险事实也缺少完整 `effective_at/published_at`。在这些证据
闭合前，可以完成 250 日日线特征、模型训练工程、确定性和资源验证，但结果只能标记
`historical_data_insufficient`、`point_in_time_parity=false`、`production_authority=false`。

本计划的最终退出条件是：

1. 只有一个通过确认、终端留出和 Shadow 的 V2 候选。
2. 新 V2 相对旧 V2 满足全部收益、排序、尾部、换手、容量、覆盖和性能门禁。
3. V1 的 20/40/60 日因子是否保留由保留/剔除消融的增量证据决定；新 V2 不包含旧 V1 模型组合权重。
4. `train-tomorrow-v2` 能生成完整、确定、可校验的 V2 候选工件；过渡期 `train-tomorrow` 与完整三头
   `train-v3` 保持各自 V3 职责，所有入口读取同一个 active history snapshot。
5. `data/train/today-v3`、`tomorrow-v3`、`d25-v3` 只保存 V3 配对工件，不被 V2 training reader 当作2000日
   事实源；V2 和 V3 工件分别绑定同一个父 history snapshot hash。
6. 无参数启动默认使用唯一 V2，显式 V3 保持可用，旧 V1 仅保留历史只读语义。
7. 所有适用自动门禁、运行实证、Review、Changelog、提交、推送和上游 hash 核对完成。

任何收益、风险、点时证据或运行门未满足，都不得宣称收益提高或完成生产合并；保持切换前的生产 release 和
既有冻结记录，不得为了实现默认 V2 的目标而绕过准入门。

# V1/V2 合并与 V2/V3 三头模型共用计划

## 1. 最终决策

本计划把 V1 的有效因子能力并入 V2，同时取消 V2 与 V3 重复训练同一批模型。V2 与 V3 必须加载同一组三头训练
bundle：

- `data/train/today-v3/`
- `data/train/tomorrow-v3/`
- `data/train/d25-v3/`

V2 同样加载 Today、Tomorrow 和 D25 三个模型头，不再只拥有 Tomorrow 模型。V3 也加载这三个目录；同一策略
头在 V2 与 V3 中必须绑定同一组 model hash、feature manifest hash、training-input hash 和 source snapshot hash，
不允许复制后改名、不允许各自再训练一套，也不允许一个档位静默加载旧工件。

V2 不再生成 `data/train/tomorrow-v2/`。计划中的独立 `train-tomorrow-v2` 命令整体取消；现有
`train-v3` 是三头共享 bundle 的唯一完整训练入口，`train-tomorrow` 只保留为同一共享 Tomorrow 头的定向
维护入口，不能生成另一份 V2 专属模型。

共用运行时已收敛：V2/V3 均由中立 `infra/scoring/head_bundles` 边界加载三组已有工件，旧 V2 包内
Tomorrow 模型、codec 和 predictor 已退役。本次收敛没有修改模型文件、活动历史库、默认档位或冻结记录，也没有执行训练。

## 2. 目标与不承诺事项

优化目标是在各策略自己的持有期内，提高相对同日可投资 A 股基准、扣除完整往返交易成本后的可重复净超额收益，
同时控制严重亏损、最大回撤、换手、容量不足和集中度。增加历史长度、因子数量或模型复杂度都不是收益证据。

本计划不承诺未来收益。收盘日线训练是用户确认的统一离线训练口径，但它不能被描述成历史 11:20 或 14:50
point-in-time 精确复现。训练、工件生成、历史验证、Shadow 和生产启用是相互独立的状态；训练完成、工件可加载和生产启用仍是三个不同状态。

固定业务边界保持不变：

- Today 在 11:20 冻结，Tomorrow 与 D25 在 14:50 冻结，first-wins 与收盘 fallback 语义不变。
- 模型只输出扣成本前预测超额、模型相对排名和分支分歧，不覆盖统一的 0–100 `base_score`。
- `local_score = clamp(base_score - local_risk_penalty, 0, 100)`，本地风险只扣一次。
- 融合继续使用
  `clamp(local_score * 0.68 + deepseek_score * 0.32 - deepseek_risk_penalty, 0, 100)`，并按
  `ROUND_HALF_UP` 保留两位；固定向量保持 `83.40`。
- ExecutionCost 独占完整往返成本；训练标签不预扣成本，在线选择与评价只扣一次。
- Long 不使用三个模型头，不进入 DeepSeek、TopK 或冻结。
- `automatic_model_update=false`；下载、启动、Web 请求和定时任务不得触发训练或热加载。

## 3. 共用范围：共用训练结果，不复制训练结果

三个目录都属于 V2/V3 的共享训练结果，不再被解释成“只有 V3 可以使用”：

| 共享目录 | 模型头 | V2 使用 | V3 使用 |
| --- | --- | --- | --- |
| `data/train/today-v3/` | Today | 是 | 是 |
| `data/train/tomorrow-v3/` | Tomorrow | 是 | 是 |
| `data/train/d25-v3/` | D25 | 是 | 是 |

每个目录继续只保存固定的四件配对工件：

~~~text
model.json
report.json
training-input.json
active-bundle.json
~~~

`training-input.json` 保存来源 snapshot、日历、证券集合、日期切分、特征合同和输入 hash，不保存 2000 日逐行
行情；`model.json` 保存拟合结果；`report.json` 保存训练与验证证据；`active-bundle.json` 只绑定前三者的
hash。V2 与 V3 不得各建一份同内容目录、复制文件后改模型身份，或把一方的预测再次作为另一方模型输入。

V2/V3 loader 必须复用同一套三头 bundle repository、codec 和完整性校验。相同策略头加载后，以下字段必须逐项
相等：

- model ID 与 model hash；
- feature manifest 与 manifest hash；
- transformer、Ridge、LightGBM、组合权重、校准和风险头参数；
- training-input hash、source snapshot hash、训练锚点和标签合同；
- 对相同输入产生的预测值、分歧与风险概率。

如果任一共享头缺失、损坏或身份不一致，V2 与 V3 都失败关闭；不得让 V2 回退旧 V2 模型、让 V3 继续用新模型，
也不得在运行期临时重训。

现有目录名和 JSON 中的 `profile_id=v3`/`v3_head_*` 字符串是已发布训练工件的跨进程身份，为保持 hash 不变必须原样解码；
它们不决定当前运行档位。运行 predictor 的 `profile_id` 由用户选中的 V2 或 V3 显式注入，因此不需要复制或改写工件。

## 4. V1 因子怎样合并

V1 的 20/40/60 日 skip-5 残差动量是当前 Tomorrow 六特征集合的子集。V1 的 20/40/60 日因子直接进入共享 Tomorrow
模型的统一特征矩阵，不把旧 V1 模型输出作为额外分支，也不把 V1 分数与共享模型预测再次加权。

共享 Tomorrow 模型仍以一个可审计模型组输出一个预测：

~~~text
统一特征矩阵
  ├─ Ridge
  ├─ 浅层 LightGBM
  └─ 独立严重亏损概率头
       ↓
时间前推 OOF 学习 Ridge/LightGBM 非负组合权重
       ↓
扣成本前预测超额 + 分歧 + 严重亏损概率
~~~

旧 V1、旧 V2 和旧共享三头工件只作为有时间有效性证据的只读控制组。控制组预测必须来自决策日当时已经发布的模型工件或正式冻结记录；
禁止用训练截止日晚于或等于评价日的当前全量模型回算旧日期并冒充样本外收益。

新增或调整共享模型时，V1 因子、长周期因子、Ridge、LightGBM、OOF 权重、校准和风险头必须在一次共享训练合同
下整体生成。这里的“重新训练”是将来升级这组三头共享 bundle 时只训练一次，并不表示为 V2、V3 各训练一次。

## 5. 2000 日训练跨度与 250 日特征窗口

V2 与 V3 共同读取 `data/history/baostock` 的同一个滚动 2000 个交易日 active snapshot。三个
`data/train/*-v3` 目录不是历史行情源，训练命令也不从这些目录反向读取 2000 日日线。

两个数字含义不同：

- 2000 日是共享训练事实空间，用于特征预热、开发段、滚动前推 OOF、早停、校准、embargo、确认和终端留出。
- 250 日是单个扩展特征的最长回看；计算一个锚点最多需要 251 个连续交易日位置。
- 1/3/5 日捕捉即时变化，20/40/60 日捕捉中短期趋势，120/250 日用于长期趋势和市场状态。
- 风险特征用于限制严重亏损与不可交易风险，不能转化为正向 alpha。

不得要求每只股票都拥有 2000 行。全市场交易日历是唯一日期主轴，个股只在自己的上市日至退市生效日前贡献
事实；上市前不造行，停牌不当作缺失，新股不足最长窗口时不得补零、均值填充或跨股票借值。

历史需求必须由有类型 manifest 派生，不得由 reader、训练器和在线评分分别硬编码：

- `minimum_history_sessions=61`：现有核心特征的最低完整窗口；
- `extended_history_sessions=251`：120/250 日扩展特征的完整窗口；
- `maximum_history_sessions=251`：单股在线与回放读取上限；
- 2000：离线归档与训练切分上限，不进入单股在线热路径。

开发阶段比较严格 251 日资格与显式双窗口专家。61–250 日股票若使用核心窗口专家，必须有独立路由身份与
`short_history` 不确定性；若证据不足，就维持 61 日既有资格，不得隐藏 fallback。

## 6. 统一收盘日线训练口径

三头全部使用日交易结束后的数据训练，来源仍是同一个 `data/history/baostock` active snapshot：

| 模型头 | 共享训练锚点 | 运行冻结锚点 | 标签 |
| --- | --- | --- | --- |
| Today | D 日 15:00 收盘代理 | D 日 11:20 | D 收盘至 T+1 收盘的扣成本前相对超额 |
| Tomorrow | D 日 15:00 收盘代理 | D 日 14:50 | D 收盘至 T+1 收盘的扣成本前相对超额 |
| D25 | D 日 15:00 收盘代理 | D 日 14:50 | D 收盘至 T+2/T+3/T+4/T+5 相对超额的平均 |

因此本计划不下载历史分钟线，不要求回填真实历史 11:20/14:50 快照，也不因为缺少分钟数据删除任何 V3 日线、
ST、行业、证券身份或标签事实。报告必须继续明确 `training_anchor=15:00_close_proxy`、
`point_in_time_parity=false` 和 `production_authority=false`，除非未来另有真实点时证据和独立授权。

D25 仍是一个模型头，T+2 至 T+5 是四列标签与验证指标；四个未来交易日缺少任一必要事实时不生成该样本。成本
只在最终执行与评价中扣一次，不按四个 horizon 重复扣除。

## 7. 下载、缺口补齐与 SQLite 边界

`download_history` 仍是唯一历史维护入口。V2/V3 不建立第二套历史库，也不因两个评分档位重复下载。初次下载
建立最近 2000 个已完整发布交易日；日常更新只补到最新完整收盘日并重读最近 5 个交易日捕获供应商修订。

缺口按事实族审计：

1. 先核对交易日历、证券上市/退市区间与支持板块。
2. 再核对 raw OHLCV/amount、qfq、交易状态、历史 ST 和带生效时间的行业。
3. 供应商明确停牌的日期保存停牌事实；不得用前收盘伪造可交易 K 线。
4. qfq 缺口只允许重新请求同一供应商，或使用已经证明的同源 raw、qfq 锚点和官方复权算法修复；不得混入另一
   来源的复权因子。
5. ST 缺失保持未知并阻止相关样本；行业缺失保留未知诊断，不得用当前行业回填过去。
6. 缺失或不可信事实只影响相应样本资格，不删除数据库中 V3 仍需使用的事实。

月分片继续使用 `data/history/baostock/partitions/YYYY/MM.sqlite3`，按交易日/代码顺序流式读取；只保存 raw、
qfq、交易状态、ST、行业与 revision 等基础事实，不把派生特征、训练样本、模型预测或报告复制进历史库。新写入
使用单批事务、WAL checkpoint、`quick_check`、行数和 SHA-256 后旁路原子发布。既有 8 KiB 页、月分片、
必要索引和 revision/observation 语义保持；本计划不新增巨型单库，不用删除历史事实换体积，也不原地 VACUUM
活动库。

## 8. 唯一训练流程

完整共享训练只执行：

~~~bash
./run.sh train-v3
~~~

`train-v3` 是三头共享 bundle 的唯一完整训练入口，流程固定为：

~~~text
资源预检
  -> 固定一个 active history snapshot
  -> 月分片 hash / quick_check / 行数只验证一次
  -> 历史按日期与代码顺序只扫描一次
  -> 构造共享特征与 T+1..T+5 标签
  -> 写一个临时多目标 SQLite
  -> 顺序拟合 Today、Tomorrow、D25
  -> 逐头释放数组与 LightGBM dataset
  -> 校验三组固定工件
  -> 各目录原子发布
~~~

同一输入和训练合同已有完整 bundle 时返回 `already_current`；未到训练节奏返回 `not_due`；历史、磁盘、
内存或合同不完整时失败关闭并保留旧三头。三头不并行训练，计算线程最多 2，峰值 RSS 不超过 2048 MiB。

`train-tomorrow` 只允许复用同一个训练实现定向更新 `data/train/tomorrow-v3/`，其输出随即同时属于 V2 与
V3；它不能创建 V2 专属工件。正常完整升级优先使用 `train-v3`，以保证三个共享头绑定同一父 snapshot 和同一
训练批次证据。

训练命令只由用户显式执行，不自动改 `config/strategy.json`，不重启服务，不热加载模型，也不删除前一组完整
bundle。

## 9. V2 与 V3 还剩什么区别

V2 与 V3 的差异从模型输出之后才开始。两个档位的 Today、Tomorrow、D25 原始模型预测必须相同；差异只能来自
明确登记并经过验证的后模型策略，例如风险收缩、观察/veto、执行成本门、动作池、稳定排序与集中度约束。

边界如下：

- V2 是 V1/V2 合并后的目标默认档位，使用共享三头模型并承载通过收益门后的生产策略。
- V3 是显式研究/对照档位，使用完全相同的共享三头模型，用于验证其它后模型策略。
- 若某一阶段尚未定义不同的后模型策略，V2 与 V3 对相同输入必须给出相同预测和动作；不得为了制造差异复制模型、
  修改训练数据或偷偷调整特征。
- 后模型策略必须拥有独立 policy hash；model hash 不因策略差异而变化。
- V3 只比 V2 额外加载 Today 与 D25 的旧方案取消；两者现在都加载三头。

如果最终没有任何经验证的后模型差异，V3 只保留历史身份和只读对照意义，不继续制造重复运行链。

## 10. 收益与风险准入

共享模型候选必须在同日、同股、同人口、同标签和同成本下比较旧 V1、旧 V2、当前共享模型与扩展共享模型。
至少报告：

- Rank IC、NDCG@20/50、Q1–Q5 单调性和 Q5-Q1；
- Top6/10/20/50 在 20/50/100bp 下的成本后净超额、胜率和覆盖；
- 严重亏损率、Brier score、ECE、最大回撤和退出不可交易率；
- 换手、容量不足、成交额参与率及板块/行业/单股集中度；
- 年份、市场状态、波动、流动性、板块和上市年龄分层；
- 训练、加载、特征、预测、完整评分的 P50/P95 与峰值内存。

至少满足以下条件才可进入终端留出：

1. 全体及逐板有效覆盖率不低于 95%。
2. Q5-Q1 为正，Rank IC、NDCG 和 TopK 不低于基线。
3. 相对当前生产基准的 20bp 与 50bp 日级配对净增量置信下界为正。
4. 严重亏损率、最大回撤、换手和容量不足不恶化。
5. 主要市场状态、板块、上市年龄和流动性分层无显著反向。
6. 运行热路径零网络，并满足冻结 deadline、内存和资源上限。

任一门失败则候选封存为 `historical_rejected`，继续使用切换前 release。不得以平均分提高、推荐变多、0bp
毛收益或单一阶段结果代替准入证据。

## 11. 终端留出、Shadow 与默认 V2

确认集通过后，冻结共享三头工件、后模型 policy、风险、成本、动作、TopK、集中度和全部父 hash，再原子打开一次
至少 200 个交易日的终端留出。终端失败后不能在同一留出上调参数重开。

终端通过只产生历史候选资格，不自动启用。随后 Shadow 同时运行 V2 与 V3，但复用同一组三头预测；Shadow
重点比较后模型 policy 造成的候选、风险、换手、收益和 deadline 差异，不能重复计算相同模型预测冒充两份独立
证据。

全部收益、风险、冻结、API/SSE、安装和桌面门禁通过后：

- `config/strategy.json` 的默认 `scoring_profile` 切换为 `v2`；
- 无参数启动、默认 `check`、server 和 performance 入口使用 V2；
- `--profile v3` 保持显式可用并加载同一组三头 bundle；
- V1 不再接受新启动，但历史冻结记录保持原模型身份只读；
- 任一共享工件缺失或 hash 不一致时启动失败，不回退旧 V1/V2 或另一套模型。

## 12. 实施章节

实施时作为一个高风险大任务按下列顺序完成，每节先更新契约与失败测试，再修改实现；最后统一执行完整门禁。

### 12.1 三头共用合同

实施状态：已交付。

- 修改 V2 profile 能力为 Today、Tomorrow、D25 三头。
- 抽出 V2/V3 共用的三头 bundle loader、codec 与 repository。
- 删除 V2 专属 Tomorrow 训练目录和独立训练入口计划。
- 契约断言同一策略头在 V2/V3 的模型、manifest、输入和 snapshot hash 完全一致。

完成条件：V2 与 V3 必须加载同一组三头训练 bundle，且任何身份漂移都同时失败关闭。

### 12.2 共享历史需求与长窗口

- 用有类型 history requirement 从 manifest 派生 61/251 日边界。
- reader、训练扫描、预热、缓存与 revision 失效支持最长 251 日。
- 增加 120/250 日长周期候选及风险特征，保持训练/回放/Shadow/在线同源公式。
- 覆盖 60/61、249/250/251、停牌、新股、退市、复权修订、缺失和非有限值。

完成条件：相同 snapshot 与 manifest 产生逐位相同向量；61 日现有路径不退化，251 日读取有界。

### 12.3 一次训练、两档加载

实施状态：两档直接加载同一组现有三头工件已交付；OOF 权重、严重亏损头与 120/250 日特征需在 12.2 后通过一次共享重训闭合。

- 扩展 `train-v3` 的共享三头训练合同；一次扫描、顺序训练、原子发布。
- Ridge/LightGBM 的 OOF 权重、校准和严重亏损头随各共享策略头保存。
- `train-tomorrow` 继续只维护同一 Tomorrow 目录，不产生档位副本。
- V2/V3 对相同输入的模型预测逐位一致，后模型 policy 从预测之后分离。

完成条件：一次训练生成唯一三头结果，两个档位直接加载同一文件与同一 hash。

### 12.4 收益验证与切换

- 在相同人口、标签和成本下完成控制组、确认集、终端留出与 Shadow。

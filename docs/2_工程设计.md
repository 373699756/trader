## 1. 产品定位与范围

产品是在个人 PC 上运行的只读 A 股研究看板，面向单一使用者，不是多租户 SaaS，
不连接券商，也不提供真实下单。结果只用于研究，不构成投资建议，不承诺收益。

三类视图为：

- `tomorrow`：交易日上午开始形成本地草稿并复用跨策略结构化 facts，13:00 后增加
  尾盘数据和增量模型复核，面向 T+1，15:00 收盘价冻结。
- `d25`：交易日上午开始形成本地草稿并复用跨策略结构化 facts，13:00 后增加增量模型
  复核，面向 T+2 至 T+5，15:00 收盘价冻结。
- `long`：固定长期潜力龙头研究池，只展示当前行情状态；只要统一行情已有固定池代码，
  warmup、上午和下午都生成当前观察快照，不运行荐股策略、不冻结、不生成交易动作、
  不写推荐历史。

系统允许返回 0 只推荐。产品不包含策略验证工作台、自动调参、机器学习训练、股票价格
预测和模拟交易页面；后台可以对正式冻结推荐进行只读收益与最大不利波动结算，作为发布
质量门禁和复盘数据，但不通过普通 Web 提供交易模拟或自动改变生产策略。

### 1.1 tomorrow 优先的目标契约

最终产品以“更快得到可信的明日研究结论，并用点时样本外证据持续提高净超额收益”为
第一目标。tomorrow 是唯一最高优先级生产决策链；d25 作为资源隔离的次级视图，
不得占用 tomorrow 的行情采集、计算、DeepSeek 或发布保留容量。tomorrow 在交易日内
提供滚动预览，15:00 固化正式结果，允许返回 0 到 6 只正式推荐和 0 到 6 只观察项，不为补满数量降低过滤、风险或
数据质量门槛。

活动产品不得包含旧冷启动预热编排、编号缓存阶段、旧执行模式开关或旧缓存分池，
也不把它们作为产品目标或兼容要求。当前链必须保留点时数据、过滤可审计、
只读 Web、冻结不可覆盖、latest-wins 有界背压和失败时不伪造数据等业务不变量。

只使用现有公开来源时，系统只能承诺内部处理时延和真实降级，不能虚构供应商响应 SLA。“提高收益”不是
收益保证。评分档位只允许 V2/V3；其模型身份、历史结论、人工授权和禁止自动更新边界分别以
[评分逻辑第 12.3 节](1_评分逻辑.md#123-当前证据与可复用研究候选)和[工程实施](3_工程实施.md)为准，
不得把日线代理或人工授权描述成历史门禁通过。

运行范围固定为 Python 3.10-3.14，以及当前稳定版 Chrome、Edge 或 Firefox 桌面版。
验收分辨率为 1280x720、1440x900 和 1920x1080。手机和平板不属于产品范围，不得为
移动端增加业务分支或运行依赖。默认仅监听 `127.0.0.1`，不提供远程身份认证。

### 1.2 current-only 最终 release 边界

当前易失运行目录固定为 `.runtime/trader`，只接受当前配置、运行数据库和事件 schema；
Tomorrow/D25 的正式记录唯一写入 `data/freeze/<v2|v3>/<tomorrow|d25>/YYYY-MM-DD.json`，
每档以 `data/freeze/<v2|v3>/freeze.sqlite3` 保存唯一性、提交状态和恢复索引。
不再创建 `decisions/records` 包装层或每日单文件目录；`checkpoints/` 仅实际保存检查点时创建，
`quarantine/` 仅发现损坏或孤儿文件时创建，二者保留恢复职责，不能作为无用数据整体删除。
新 release 不读取旧运行目录、旧数据库、旧快照或旧 schema，活动服务和公开命令也不提供兼容导入。历史下载
同样不兼容旧历史格式和旧参数；新链只读取`data/history/control.sqlite3`与正式年月分片，旧历史需清空重建，转换器已退役。
统一数据平面、正式决策与 DeepSeek 预算使用独立持久化文件；预算固定写入
`.runtime/trader/deepseek-budget.sqlite3`，不得探测或复用旧名 `runtime.sqlite3`。

整个工程（业务、运维脚本、诊断和测试）的SQLite连接统一通过`infra/sqlite_connection.py`的
`OpenSqliteConnection`创建；只有该primitive调用驱动连接接口。只读URI、有限锁超时（含显式零等待）、
FULL同步、外键、受控跨线程和事务模式由类型化选项统一，调用方必须关闭连接，事务上下文不代替关闭。
`immutable`只适用于已停止且不会改变的隔离副本；活动历史诊断使用普通只读连接以包含WAL中的已提交数据。
压缩复制显式允许目标库写入，但源库仍以`mode=ro`打开；普通只读查询继续启用`query_only`防止SQL写入。
业务SQL与表合同仍归各adapter，训练可重建临时样本保留既有OFF策略，持久数据不降低同步级别。

唯一只读产品接口及公开线格式只由第 9 节表 A 定义。

不得提供旧 API 别名、重定向、弃用窗口、双读或双写。旧 release 只能与其对应旧运行目录整体回退，
不得与当前代码、配置或 `.runtime/trader` 混用。旧运行数据可在仓库外离线保留，
但不进入新 release 的启动、恢复、查询、回放、打包或测试路径。

## 2. 系统能力与业务流程

系统从官方总体先执行ST预过滤，再从公开行情和研究数据构建点时快照，经一级市场过滤、二级公司资格与风险过滤、候选预选、本地评分、
可选 DeepSeek 结构化复核、风险合并和稳定 TopK 后发布到 Web；冻结策略按时间点保存
不可变历史锚点，当前报价只作为 overlay 展示。

```text
官方总体与历史ST资格
        |
        v
ST预过滤 -> 行情不可变观测 -> 一级市场过滤 -> 风险快照 -> 二级公司风险过滤与特征
                                  |
                    +-------------+-------------+
                    v                           v
                 tomorrow                     d25
                    +-------------+-------------+
                                  v
                     DeepSeek结构化复核（可降级）
                                  v
                        本地最终分、TopK、发布与冻结
                                  v
                        当前决策索引 -> Web/SSE
                                  |
                     检查点/正式冻结/收盘overlay
                                  |
                       后台结果结算（只写审计）
```

任何数据源或 DeepSeek 失败都不得阻塞本地推荐和只读 Web。系统保留最近有效发布，
明确标记 stale、degraded、not_ready 或冻结 fallback，不用空结果覆盖有效结果。

### 2.1 tomorrow 目标链路

目标链路按业务时限拆分为独立数据平面和不可变决策平面：

```text
公开来源持续采集 -> 规范化观测日志 -> 全市场最新报价索引
                                      |
                 DailyFeaturePack ----+---- CandidateQuoteEpoch
                                      |
                                  MarketEpoch
                                      |
         ST预过滤 -> 一级市场过滤 -> 二级公司风险过滤 -> 候选预选 -> 本地评分 -> local ScoredDecision
                                                    |
                     ResearchEpoch -> DeepSeek 复核-+
                                                    |
                                      hybrid ScoredDecision
                                                    |
                                      UnifiedDecisionIndex
                                                    |
                                      只读 API -> SSE -> Web
```

`DailyFeaturePack` 在开盘前构建并按新完成的历史、主数据和研究事实增量换版，不阻塞实时
行情；`MarketEpoch` 是一次可审计的全市场决策输入；`CandidateQuoteEpoch` 只更新候选和
已发布股票的高频报价；`ResearchEpoch` 保存经过 schema 和证据校验的结构化研究事实；
`ScoredDecision` 保存 local 或 hybrid 的完整决策身份。每个 epoch 都绑定交易日、上海
时区观察点、上游版本、接纳序号，以及按其职责适用的配置、规则、策略和 schema
版本，已发布对象不可原地修改。

ST预过滤、一级市场过滤、二级公司风险过滤、候选预选、本地评分和稳定选择必须是一次确定性管道。过滤结果使用
`pass`、`observe_only`、`reject` 三态并保留逐股原因；输入准备另有 `ready`、`data_pending`、
`refresh_pending`、`degraded`、`not_ready` 状态。缺失关键行情、证券身份或点时证据不得静默降级为通过，
也不得冒充业务 `reject`：应进入后台获取/刷新队列，或在没有可信快照时保持 `not_ready`。`UnifiedDecisionIndex` 按策略保存最后一个已提交的不可变
决策引用，并通过单提交者 compare-and-set 保证旧行情、迟到 DeepSeek 和失败批次不能
覆盖更新结果。Web 只读取该索引和报价 overlay，不参与采集、过滤、评分或持久化。

非法价格、成交额、涨跌幅和 OHLC 始终使用过滤注册表的 `DEFERRED`，不得因候选定向刷新完成改成业务拒绝；同股可信业务拒绝优先，否则陈旧/未来报价优先进入 `refresh_pending`，其余非法输入进入 `data_pending`，终态计数互斥。全空且有瞬态非法输入时生产发布门拒绝返回正式决策，只保留易失诊断草稿和既有有效投影；真实业务空集仍可发布。第 5–9 层现在传递真实不可变输出及测得耗时/接纳来源健康，活动服务和全部尝试来源审计仍待验收。

### 2.2 统一数据平面契约

`SQLiteIssuerEligibilityIndex` 保存历史资格事实；其中 ST/退市警示是逐股外部 I/O 前置预过滤的唯一事实源，人工永久事实只供二级过滤读取，旧公司违法永久事实仅作原身份审计。组合根显式装配该端口；
分类文件属于同一个不可变活动快照，不得形成多个名单 owner；
历史ST资格快照按既有qfq发布观察更新；近一年公司风险由download单库的固定点增量更新，失败保留旧事实并标记刷新失败，不由 HTTP 请求触发刷新；
资格投影保留 `eligible_unverified`、`qualification_pending` 与 `permanently_excluded` 三态，但只有当前/历史 ST 与退市警示可触发前置裁剪；
事实包含代码、原因、事实生效时间、稳定证据 ID 和来源。只有越过持久化边界的规范载荷才保存内容哈希，
同身份同内容幂等、不同内容冲突。
ST/退市警示代码必须在历史投影消费、候选定向行情、逐股公司研究、参考数据、Long 定向行情和
分钟行情提交前裁剪；其他永久事实与动态公司风险在二级过滤一次处理。供应商全市场批量接口不能按代码裁剪时允许物理返回整批，但发布人口和
全部逐股下游必须剔除 ST 代码。冻结 TopK 报价 overlay 与既有 outcome 结算按原正式身份继续，
不得用新名单覆盖历史正式记录。历史回放按事实 `effective_at` 判断，不得以当前名单回填过去。

二级永久事实只来自人工永久名单；公司公告风险只按最近365天窗口动态判断；财务亏损改由评估时刻前
最新正式披露的季报、半年报或年报动态派生，归母净利润或扣非/核心净利润任一小于0即拒绝，
新报告替换旧报告判断。旧 `historical_audited_loss` 事实只保留审计，不参与当前资格或运行状态活动计数；
普通新闻、亏损预告、未有正式结论的调查和 DeepSeek 自由文本不能创建永久排除事实。已有活动历史归档不做
破坏性删除。一级市场过滤处理停牌、价格/流动性/上市日龄和板块热度；二级过滤处理永久事实、
存续调查、减持、解禁、质押、财务恶化和其它点时风险，具体公式与原因码以荐股策略文档第 4 节为准。

统一数据平面由 `DailyFeaturePack`、
`MarketEpoch`、`CandidateQuoteEpoch` 和 `ResearchEpoch` 都是深层不可变对象：代码有序
且唯一，业务时间为 `Asia/Shanghai`，实时身份由接纳 owner 分配修订号，来源版本、上游版本、
缺失和降级原因属于身份的一部分。非有限核心数值、未来事实、无时区时间和同 sequence
不同内容必须在发布前拒绝。

进程内实时数据平面按交易日和单调 sequence 原子接纳 epoch。`MarketEpoch` 必须引用当前
`DailyFeaturePack`，`CandidateQuoteEpoch` 必须引用当前 `MarketEpoch`；新 feature pack
尚未形成匹配 market epoch 时，读取方继续获得上一组完整一致视图，不能看到新旧拼接。
每个通道只保留有界数量的最近 epoch，旧 epoch、父版本不匹配和迟到结果不得覆盖当前
指针。来源失败只更新结构化失败状态并保留最近有效 epoch；后续成功发布原子清除对应失败。

应用层唯一读取边界名为 `DataPlaneReadPort`，一次返回上述四类 epoch 的一致快照；读取方
不得持有具体缓存、SQLite、供应商客户端或旧 Pipeline 对象。每个业务字段同时携带字段值、
来源、源时间、接收时间、`valid/degraded/stale/missing/conflicting` 质量状态和内容版本。只有外部供应商
持久工件进入系统、持久化恢复或不可变证据交接时才要求载荷哈希；实时供应商载荷不做内容 hash，已经接纳的进程内类型对象只复用该身份，epoch
发布前校验字段值与血缘关系，不逐层重算载荷哈希。价格-only 或空响应没有权利删除证券
身份、交易日历、历史摘要、研究事实或既有更完整字段。

`DailyFeaturePack` 额外绑定交易日历版本和覆盖清单。潜在可执行代码必须 100% 具备证券
主数据。候选历史覆盖率是加法健康指标，不是 pack 或整批评分的发布开关；pack 可以携带历史不足的
候选，但必须保留逐股历史 session、字段缺失和版本事实，由评分输入适配器按活动策略/profile 判定资格。
不得用无效空 pack、空全市场行情或父版本不匹配的子 epoch 清空最近有效数据。

生产输入适配器在构建 local 前还必须复核请求代码、候选定向特征、证券身份和历史摘要覆盖：
候选定向特征覆盖请求代码 100%，受支持板块且无身份缺失限制的证券身份覆盖 100%。历史资格按策略和
评分 profile 逐股复核：V2/V3 的 Tomorrow/D25 双头在线推理需要各自 manifest 规定的完整 qfq 历史和字段；
V2 在线推理最多读取 251 个有效 qfq 交易日以支持 120/250 日长期趋势和市场状态，V3 在线推理仍至少需要
61 个有效 qfq 交易日。覆盖计数和比例是批次内存事实并以加法状态公开，但不再因低于统一百分比而否决已有
合法分数；活动模型字段资格必须先于板内候选限额，不合格股票不得占用名额、评分、DeepSeek 或执行。
完全没有合法评分人口时返回受控未就绪并保留最近
有效 current。状态 API 同时公开当前策略/profile 的 `history_required_sessions`，使覆盖分母与资格口径
可审计。该复核不读取网络、文件或数据库，也不进入 HTTP 查询。V2/V3 启动时只加载
所选档位的已发布 bundle，不现场训练。两档离线训练都最多消费 2000 个交易所开市日且完整训练至少要求 1250
个共同完整交易日，不能把
这个离线窗口误写成盘中评分窗口。

推荐历史缺口由download后台短窗口维护负责，`PublishedHistoryCache`只读取所选档位data/qfq派生日线；新鲜度和完整窗口资格失败保持pending，HTTP/API只投影已有健康状态，不派发历史网络请求。完整history继续服务训练、研究与结算。

生产候选计划使用不可变、按 `strategy + board` 分区的有序储备。领域候选规划器是动态硬过滤、策略历史/
模型字段资格、核心缺失率、候选分、最低分和稳定排序的唯一所有者；应用适配器只保存规划结果、取每板活动
窗口并协调共享 I/O，不得保留通用 25% 候选分、配置中的第二套通用候选权重或其它先截断路径。
候选定向行情只请求两策略活动窗口的稳定去重并集；返回后用同一领域规划器在原板内总体上复核，失效项沿
原策略同板储备顺序补位。补位共享原任务 deadline，逐次只请求填补缺口所需代码，已经完成的有效结果不因
其它分片失败从行情缓存撤销；但 deadline 到达时不得把部分补位结果发布成新的候选批次，必须保留最近完整
批次，冷启动尚无完整批次时返回明确未就绪。最终 `ScoredNativeInput.requested_codes` 与候选特征按策略隔离，
不能把 I/O 并集直接当作任一策略的候选人口；只有储备耗尽或剩余股票均不合格时才正常发布不足 120 只，
deadline 中断属于回退或未就绪而不是半批成功。

非负且不超过 0.50% 并标记已复核时才可进入 epoch；实时特征行、报价和父
`MarketEpoch` 绑定同一接纳版本；只有持久化或不可变研究边界才生成规范完整性摘要。

Hash 校验只属于信任边界：外部或仓库模型工件加载、不可变研究工件/归档加载、SQLite staged/committed
恢复、正式冻结文件提交与恢复，以及需要内容寻址的跨进程身份。一次校验成功后必须返回有类型的可信对象和

父版本、单调 sequence 或 CAS 证明的关系，使用对应语义校验。Hash 不能替代点时、字段、单位、覆盖率或
可交易性验证。实时缓存直接使用规范类型请求元组，GET/SSE 的 `content_hash` 为 null，ETag 绑定决策/overlay

### 2.5 统一决策索引与冻结契约

统一决策核心以 `ScoredDecision` 表示 tomorrow 和 d25 的评分结果，以不含任何
评分字段的 `LongProjection` 表示 long 当前观察投影。两类身份都绑定策略、交易日、上海
时区观察点、单调 sequence、上游版本与规范 SHA-256；评分身份另绑定配置、策略、融合、
local/hybrid 阶段、结构化过滤聚合和逐项分数、风险、动作、板块身份与排名。long 不生成正式记录，
也不发布评分提交事件。

每个 scored `DecisionItem` 还必须从形成该项的同批 `FeatureSnapshot.quote` 固化股票名称、板块、行业和
不可变报价锚点；锚点至少包含价格、涨跌幅、成交额、换手率、总市值、来源、来源时间和报价版本。
current、冻结历史和 HTTP 只读投影都复用该身份内元数据及类型化推荐管线审计，不得在查询时现场抓取、按代码
补算或从非互斥原因反推阶段数。
活动正式记录必须包含显示元数据和报价锚点，投影阶段不得丢弃同批已有名称或行情事实。
报价锚点参与 `ScoredDecision` 规范哈希，但只用于展示和冻结审计，
不得反向改变候选、过滤、评分、风险、动作或排名。
评分原生输入的 `evaluated_at` 取调度请求时刻与同批本地 `observed_at`/`received_time` 的最晚值，
以反映网络刷新真实完成时间；供应商 `source_time` 和公告 `published_at` 仍必须不晚于该时刻，
不得用外部声明时间推进决策时钟或绕过未来数据校验。

应用层 `UnifiedDecisionIndex` 按策略隔离当前身份和报价 overlay。每次发布必须携带调用方
实际读取的 `expected_version` 并执行内存 compare-and-set；旧交易日、旧 sequence、同
sequence 不同内容均拒绝。hybrid 必须引用同策略、同交易日且仍为当前版本的 local 父身份。
overlay 必须匹配当前 decision/projection version、策略和交易日，只能包含当前身份范围内
的代码，并完整携带价格、涨跌幅、成交额、换手率、总市值、来源、来源时间和报价版本；未来报价、
迟到 overlay 和错误 expected version 不得覆盖当前视图。评分身份与其同批初始 overlay 必须在
同一个索引临界区内通过一次 CAS 原子发布，禁止暴露“新决策已可见但行情尚未挂接”的中间状态；
local 升级 hybrid 时同样必须把匹配新父版本的初始 overlay 一起换版。成功提交评分身份时生成
应用层通用 `DecisionCommitted`；事件携带完整决策身份和逐项结果，不导入或依赖 research 类型，
observer 失败也无权反向修改决策。

研究 observer 只消费成功提交后的 `DecisionCommitted` 与评分投影同批生成的不可变研究审计。

幂等冲突检测、按需校验和损坏隔离；单分区上限必须覆盖全天滚动决策，研究归档同时公开 120 个

载荷，不删除不可变证据。审计写入失败不回滚或阻塞正式决策。
完整人口审计在带固定魔数的 zlib 表示更小时使用该表示写入既有 payload 列；内容
SHA-256、幂等比较和业务解析始终针对解压后的规范 JSON。读取器继续接受既有未压缩记录，并在解压前后
分别执行 4 MiB 持久化载荷和 64 MiB 规范载荷上限，损坏、尾随字节或解压膨胀均失败关闭；该表示变化
不新增 schema 版本、不迁移历史记录，也不改变研究事件语义。

observer 的队列、接纳、完成、拒绝、消费者失败计数和最后错误代码必须进入 `/api/status`；只要
消费者失败未在当前进程内由后续成功写入恢复，系统健康至少为 `degraded`，不得只在内存对象中保留
而让 Web 显示正常。observer 不写统一决策索引、正式记录库、API、SSE 或活动配置；它
不重新读取行情、重新评分或重新调用模型。初始化失败同样 fail open；
历史数据不从旧 snapshot 或 shadow 运行库回填，
部署后只积累新的 committed observation。新外层记录使用 `research_committed_event`；既有外层
和旧审计载荷只按原始形状校验哈希并只读解析，不迁移、不补写。研究库按策略和交易日提供
15:00 截止读取，只接受事件时间与输入时间均不晚于截止点且含完整人口的 local 观察；迟到记录保留审计
但不能恢复计划日。
决策 CAS 成功后必须由提交线程直接写入内存事件流，再异步组装并投递研究审计；研究审计构造失败、
observer 队列满或消费者失败都不得吞掉已经提交的 Web decision 事件。事件流写入失败必须显式降级，
但同样不得回滚已接纳决策。

tomorrow 和 d25 的正式记录仓储按策略和交易日唯一提交。仓储先把规范载荷及其
SHA-256 写入 SQLite staged manifest，再原子创建不可变 JSON，最后提交 manifest；同键同
内容重放幂等，不同内容冲突失败。启动恢复使用 manifest 内有界恢复载荷补齐半提交；已提交
文件缺失、损坏、哈希或身份不一致时移入隔离目录并 fail closed，绝不向当前索引返回不可信
记录。活动组合根必须接入 tomorrow、d25 的统一核心、原生 worker、正式记录仓储、
observer 和冻结时线，并接入 long 无评分 current projection。

#### 统一调度引用

`SchedulerRuntime` 拥有生命周期、lane 和调度观测；`RecommendationCycleExecutor` 拥有本地/复核周期执行，
`CloseControlCoordinator` 拥有检查点、冻结、收盘恢复和结算控制预留，依赖经 `RuntimeDependencies` 注入。
三者只协调组合根显式注入的端口；资源所有权、latest-wins、
模型预算和关闭顺序统一引用第 4 节表 R，交易日调度引用第 5 节表 T，
失败和降级引用第 6.3 节表 F。HTTP 与只读 Web 不参与调度，也不产生外部 I/O。

冻结、检查点、重试和收盘恢复统一见第5、8节，不为Tomorrow建立第二套定义。

### 2.6 统一查询与发布

活动读取链固定为 `UnifiedDecisionIndex -> application queries -> /api -> SSE -> Web`。
应用层查询一次读取完整不可变决策，并只叠加父版本、策略和交易日匹配的报价 overlay；历史查询
只精确读取请求日期的正式记录。HTTP 不得抓行情、评分、调用 DeepSeek、触发冻结或现场重放旧规则。

统一事件流使用单调序列、有界历史、有界客户端队列和最多 32 个订阅者。无游标连接从打开时的
当前序列开始；显式 `Last-Event-ID` 或 `cursor` 才回放。游标超前、过期、不连续，schema、
base 或 identity 不匹配，以及慢客户端统一发送 `resync_required`，浏览器随后以 ETag 重新读取
current。每个 committed decision 的 `decision_version` 同时是 Web 的 `publication_id`；阶段状态
只能作为随该发布身份提交的诊断聚合，不能在决策提交前逐股改写推荐内容。事件发布不等待客户端消费；
客户端按策略、交易日和事件类型过滤，正常 decision 事件直接应用完整 TopK replacement patch；仅 schema、基础身份、TopK 校验失败或事件丢失时按 ETag 条件读取 current。overlay 事件携带行级报价
patch 并只修改匹配父决策的展示报价。无关策略或日期事件不得触发 GET。status 与 current 共同公开由决策
版本和有效 overlay 版本形成的 `projection_version`；事件丢失时客户端按该身份对账恢复。SSE 正常时
不持续轮询完整决策；游标重同步完成前保留上一份完整快照。

`DecisionView` 必须对 tomorrow、d25 和 long 使用同一 envelope；评分策略
公开决策身份、阶段、冻结、覆盖、过滤、分数、风险和匹配父版本的报价 overlay，long 固定
`score_status=not_applicable` 且 history/dates 不适用。current 与 history 支持 ETag/304，dates
只列按交易日倒序的正式记录。status 汇总 Tomorrow、D25、Long 三个视图的数据年龄、覆盖、冻结、降级、DeepSeek 预算和
事件流健康；根页面只消费这些统一接口。旧 URL 和独立 tomorrow 页面不再注册，相关源文件已
物理删除，不构成兼容期或保留承诺。

### 2.9 long 运行契约

活动组合根按 `long_watchlist.json` 的唯一版本、项目顺序和全局唯一分组构造
`LongRuntime`。调度 cadence 只提交带上海时区观察点、phase、deadline 和 force 标志的
`LongRefreshRequest`；独立 `trader-long` 单 worker、单 latest-wins 待处理槽直接调用固定池
定向行情端口并向 `UnifiedDecisionIndex[strategy=long]` 发布 `LongProjection`。Long current
的 `score_status=not_applicable` 由无评分投影类型和运行状态共同保证。
投影观察点使用组合根注入的处理完成时钟，不得把请求发出后、网络完成前的正常接收时间误判为
未来数据；来源时间或接收时间晚于处理完成时刻时仍必须拒绝。

每个 `LongProjectionItem` 直接携带代码、配置名称、行业、唯一分组身份、价格、涨跌幅、成交额、
换手率、总市值、来源、来源时间和 quote version，不存在候选分、本地分、融合分、风险扣分、
动作阈值或排名字段。投影严格保留配置项目顺序和完整固定名单；同轮有效报价标记 `live`，部分
代码失败时优先使用该代码同交易日最近有效报价并标记 `retained`，仍无报价则保留显式
`missing` 占位。未来报价、未知代码、非正价格和错误时区输入不得进入 current，也不得自动换股。

Long runtime 不注入 reviewer、observer、冻结协调器、正式记录仓储或结算端口，不创建正式记录、
历史日期或结算事件，不读写旧 snapshot。定向行情整体失败时仍以完整固定名单发布或保持最近
有效 current，并在状态中公开 `long_quote_unavailable` 与覆盖计数；同交易日最近有效报价只在
进程内由该 runtime 持有，交易日切换立即清空。Long 慢请求只占用 `trader-long`，不得阻塞
tomorrow、d25 的评分、DeepSeek、冻结、overlay 或结算资源。

## 3. 架构与模块边界

活动产品代码只有`src/trader`。按业务划分，而非按供应商、模型或页面再建一套流程。

| owner | 负责与输出 | 允许的消费者 | 不负责 |
| --- | --- | --- | --- |
| `download/` | 获取与标准化历史、参考资格、逻辑快照、qfq短窗口 | training及recommendation的有类型只读边界 | 拟合、评分、HTTP |
| `training/` | 特征样本、拟合、双头工件、研究/回溯/留出/评价 | 推荐工件加载及离线报告 | 实时采集、生产排名、自动启用模型 |
| `recommendation/` | 实时输入、14层编排、评分、冻结、发布和查询 | HTTP/Web及诊断 | 完整历史下载、离线拟合 |
| `http_api/` | 请求校验、路由、白名单序列化、SSE | 浏览器 | 抓行情、评分、读业务库或写状态 |
| `web/` | 无副作用app factory、模板和静态资源 | HTTP页面边界 | 后台业务、训练或数据同步 |
| 顶层`infra/` | 配置、时钟、SQLite/HTTP primitive、锁、执行资源、原子文件 | 各业务基础设施与组合根 | 业务schema、评分规则、预算决策 |
| `bootstrap.py` | 唯一组合根，创建并注入客户端、池、端口与运行时 | CLI/server薄入口 | 第二套业务流程、全局服务定位器 |

三个业务统一采用`entrypoints/infra -> application -> domain`：领域保持纯函数和不可变类型，
应用拥有用例与端口，基础设施实现外部I/O。业务间只传有类型不可变对象，不共享可变缓存，不跨层读全局状态。
应用层只可使用已裁决的窄执行协议`WorkerExecutor/ManagedWorkerExecutor`、`SubmitOrReject`及关停值，
不能因此导入具体执行器或业务infra；架构守卫按符号检查，不整体豁免模块。

`CreateApp()`无线程、无网络、无数据库、无文件写入；资源构造属于组合根，启动/停止顺序属于应用运行时。

服务进程先解析配置并取得`server.lock`，再由组合根构造资源、加载模型与当前行业缓存；重复启动在这些重操作之前拒绝。完整history不在启动时全量载入，按窗口只读访问；qfq由后台观察器加载，保留未就绪/降级状态。公司资料在首次需求时读取已发布投影，同一后台观察器每30秒检查公司发布版本，接纳手工下载的新结果；不调用供应商，不修改已有冻结记录。读取失败保留最近有效缓存并公开失败类别。下载命令不构造Web、运行时荐股管线或加载在线模型。
同一底层客户端不隐式重复创建，业务适配器不自建隐藏线程池。
每项迁移必须同时切换新owner、全部消费者并删除旧路径；不保留转发、兼容导出、双读或双写。
活动源码单文件最多1200行，按职责拆分，不为行数制造聚合空壳。

### 3.2 共享primitive与状态约束

外部HTTP仅由`infra/http_transport.py`访问Requests/urllib3，业务与诊断只使用`HttpTransport`、不可变`HttpRequest/HttpResponse`和项目错误类型；原始响应在driver内关闭，不向消费者暴露会话、socket或可变供应商响应。`bootstrap.OpenExternalHttp`是创建入口，连接惰性建立、句柄排他使用，下载会话池继续跨股复用keep-alive。默认不读取环境代理，不自动重试或跟随重定向；每次调用对应一次物理尝试，重试、来源选择及DeepSeek预算仍归业务owner。

连接/读取使用有限超时，每个原始分块检查单调deadline、取消和容量；普通响应上限16MiB，官方文件及WebDriver为32MiB，PDF和研究能力抽样为4MiB，Web健康检查为1MiB。压缩数据同时限制传输字节和解压字节；使用urllib3的`read1`避免等满大块才检查缓慢响应，依赖最低版本在pyproject声明。可观测事件只含host、方法、耗时、字节数、状态和错误类别，不含完整URL、凭据或载荷。

download拥有Tencent日线协议、交易所证券身份、BaoStock行业、Tushare显式能力和AkShare日历SDK边界；recommendation拥有实时行情归一化和DeepSeek业务，training通过下载侧的类型化历史能力接口获取日期元数据。Tencent日线请求、JSON/JSONP及量额换算只有一个owner；研究和诊断复用该实现。SDK不通过`getattr`或通用方法名透传；BaoStock登录、退出和分页限流复用同一session边界。AkShare日历和当前行业的阻塞SDK查询由组合根注入一次性进程执行器，超时或取消后终止并等待回收，不留下超时后台线程；日历缓存策略与行业120秒上限不变。

- 数据库schema、幂等键、损坏恢复各由业务infra拥有；连接、游标、事务有界关闭，Web不直接访问业务库。
- 时区wall clock处理业务日期；单调时钟处理deadline。source_time、as_of、generated_at、frozen_at和published_at各有独立语义，不互相代替。
- 调度器比较注入的上海墙上时钟与单调时钟：跨日、墙上时钟回退、单调时钟回退、两者增量偏差超过 5 秒或采样间隔超过 300 秒时递增会话代次。任务排队时绑定代次，写入当前快照、overlay、Long 或冻结前重新校验；旧代次结果丢弃，保留最近有效快照。状态公开会话代次与跳变原因，新代次排序优先于旧时间戳。没有本会话有效输入的普通冻结点标记错过，由合法 `close_fallback` 重建；已有正式记录保持 first-wins。
- 下载、训练和推荐的内容身份使用唯一纯技术 `infra/serialization/canonical_codec.py` 编码边界；业务模块决定身份字段和历史排除规则，JSON 编码、字段遍历与字节排序由 codec 负责，持久化投影留在业务 infra。迁移保持既有内容哈希，不改写旧记录。
- 内部状态不使用dict、Any或反射fallback；JSON只在供应商解析、配置、持久化codec、HTTP/事件投影边界。内部对象不定义as_dict/to_json决定公开schema。
- canonical UTF-8、排序键、稳定Decimal/时间/空值和SHA-256用于不可变工件与持久化；实时cache/ETag/SSE使用版本元组或单调序号，不反复hash全市场。
- 发布序号先耐久预留块，热路径只分配内存序号；崩溃可跳号不可复用。hash一致只证明身份，不授予生产或发布权限。
- 可替换文件同目录临时写、flush/fsync、replace及目录fsync；正式冻结和证据采用create-or-conflict，同键异内容不覆盖。
- 缓存绑定完整请求/来源/合同/配置/时点身份并有条目与字节上限；负缓存只记录实际尝试失败，取消/superseded不写负缓存。source_age与entry_age分开。
- single-flight所有终态释放等待者；失败不刷新旧成功时间。队列满立即报告resource_rejected，不能偷偷同步执行。
- 可关停资源提供幂等关闭、在途状态和有界等待，统一deadline见表R；所有失败span闭合，观测不阻塞业务。
- 配置由单一settings入口严格解析同目录职责文件，不递归包含或隐式覆盖。runtime保存路径，strategy保存档位，其余按delivery/scheduler/market/cache/download/training/cost等职责分开；凭证不进入配置hash、数据、日志或API，不隐式热重载。

事件至少包含事件 ID、主体、交易日、阶段、策略、优先级、数据版本、配置版本、创建

```text
trade_date + phase + strategy + event_type + subject_key + data_version
```

事件在跨线程前转换为深层不可变有类型对象，JSON仅存在于边界投影。状态固定按
`pending -> running -> success/failed/expired` 在有界进程内账本中进行 compare-and-set；
相同幂等键只有一个有效执行者。冻结、风险变化和 DeepSeek 补审高于普通行情，拥有独立

交易 session generation 和交易日，跨日、系统时钟回拨、wall/monotonic 偏差或明显休眠
跳跃会轮换 generation，迟到的旧 generation 结果不得发布、冻结或更新当前状态。

最终当前运行只接受当前 runtime schema，不对旧 schema 补默认值，也不保留旧执行模式开关；
回退只能切换完整 release、配置与运行目录。

`ScoringInputEpoch`；读取期间又有更新输入时，只禁止把该元组写入新版本缓存，不得作废已经形成的评分输入。

规则。两条板块评分通道各保持一个 worker，待处理

tomorrow 或 d25 的其他策略请求。多个策略同时等待时优先执行 tomorrow，再执行
d25；完成一个策略后从下一个策略继续轮转，持续输入不得饿死其他策略。候选和
评分事件的排队过期时间分别包含上游

## 7. 当前运行内存、缓存与性能契约

### 7.1 固定资源上限

内存验收同时约束规范缓存逻辑载荷和整个进程峰值 RSS，二者不得互相替代：

| 指标 | 上限 | 约束 |
| --- | ---: | --- |
| `cache_logical_bytes` | 248 MiB（260,046,848 字节） | 所有有界缓存的规范载荷、身份和计费内容 |
| `process_peak_rss_bytes` | 384 MiB（402,653,184 字节） | Python、原生缓冲、线程栈、队列、临时副本和全部活动 活动对象 |

384 MiB 是进程硬上限，不是缓存容量；不得把 136 MiB 差额分给缓存、扩大候选、延长 TTL
或保留额外历史。验收必须同时记录逻辑缓存、RSS 峰值和可用时的 USS、Python traced、
Polars 估算及瞬时峰值原因；不得用 Python 分配量或逻辑缓存估算代替 RSS 峰值。配置必须
分别使用 `cache_logical_bytes` 与 `process_peak_rss_bytes`，旧单字段配置启动前拒绝。

缓存身份固定包含数据集、来源、主体、请求指纹、交易日、阶段、来源契约、配置和 schema
版本。TTL 条目具有动作年龄、负缓存和容量；epoch 只命中完整身份；任一分区满只拒绝本区
新写入，不能清空其它分区。当前决策、正式记录和 overlay 的驻留容量必须以 当前类型和查询
需求核算，不得用旧 Pipeline 阶段编号定义所有权。

### 7.2 性能与背压门禁

每条异步 lane 都必须有固定并发、单 latest-wins 待处理槽、deadline、替换计数和有界停止；
旧输入可以完成审计，但 compare-and-set 不得覆盖更新的索引或正式记录。依赖范围无法证明时
扩大重算范围，不能用近似桶跳过真实变化。

实时生产链必须以不可变数据版本而不是调度时间驱动重算。每个刷新任务返回有类型的变化结果，
至少记录任务、是否改变评分输入、数据版本、变化代码、完成时间和是否使用最近有效回退；无变化、
超时后回退旧快照或相同研究版本只能更新健康状态，不得触发新评分。
刷新完成时间必须先按绝对时刻选取调度请求、本地特征观察和报价接收中的最晚值，再显式投影为
`Asia/Shanghai`；供应商或基础设施返回 UTC 不得使已经成功发布的行情刷新在结果对象构造阶段失败，
也不得通过放宽应用层上海时区类型契约规避该边界。
候选报价刷新产生的完整基础候选特征必须作为共享 `ScoringInputEpoch` 直接复用，D25 使用
基础 epoch，Tomorrow 只按同一基础 epoch 追加尾盘分钟差量；禁止刷新后丢弃特征再从缓存重复构建，
也禁止以 `observed_at` 制造相同数据的新缓存身份。运行中评分在数据准备完成、纯本地评分开始和发布前
都必须检查是否已有更新输入，并仅按表 R 处理替换、发布和复核。冻结仍只接纳边界前已发布且 CAS 合法的最新 current。

两策略窗口的腾讯候选报价先形成稳定去重并集，完全不重合时最多 720 只；允许按供应商批次上限形成有界

## 8. 发布、冻结与持久化

盘中 current 只存在于 `UnifiedDecisionIndex`：tomorrow、d25 保存最新已接纳的

未冻结的六席榜单随已接纳 current 驻留；评分已经完成但输入质量
门禁尚未通过时，最新同日 local 决策只写入独立、单调更新的 `UnifiedDecisionDraftIndex`，不得写入
正式 `UnifiedDecisionIndex`。草稿查询只投影同轮评分前六，只在对应盘中窗口展示，

只使用已提交的六席身份，不以草稿补位。

Tomorrow 与 D25 在 14:59:20（含）至 15:00（不含）由调度器自动尝试保存同运行身份、距边界不超过 30 秒、
哈希有效的检查点，暂时失败只在该窗口内重试；15:00 收盘价原子封口各自索引。正式提交失败只允许以 1/2/5/10/30 秒退避重试
同一 sealed object，不得重新评分、重新选择或让收盘恢复抢占。15:00 前
冷启动只可恢复符合上述窗口、尚未消费且身份匹配的同日检查点。

15:00 后，已有正式记录不可覆盖。Tomorrow/D25 同日正式记录缺失且没有待重试封口时，运行中
优先固化本进程已有 当前决策；冷启动才以完整同日 official-close 输入执行一次纯本地补算。

可审计的不可变空记录，不得降低门槛或用观察项补数。
Long 不冻结、不写正式记录、不进入历史或结果结算。

独立收盘点在行情采集成功后保留同日 `RefreshOutcome` 回执，复用数据适配器中的不可变输入，

身份，不得把正常冻结封口作为补算提交。两策略正式记录齐备后，后续 tick 才派发结算；
结算失败可续接，在途和成功键去重。收盘点仅在正式记录齐备且结算成功后 completed。
成功采集回执仅在同一交易日、同一时钟会话有效；时钟跳变或跨日后重新采集，Long 快照刷新仍独立执行。

overlay 只能改变价格、涨跌、成交额、换手率、总市值、来源和报价时间，不能改变名单、分数、
风险、动作或排名。记录按
策略和交易日唯一，规范 JSON、manifest 与 SHA-256 通过临时文件、flush、fsync 和原子提交

`CanonicalOutcomeEvaluator` 是上述收益、等权基准、成本、MAE 和 D25 聚合的唯一纯计算所有者；允许用

`Asia/Shanghai`，SQLite 锁定或暂时不可用不得使 status 失败。

默认仅监听本机，不承担公网认证、授权和 TLS。扩大网络边界必须另立产品与安全契约。

### 11.1 统一阶段快照

14 层统一输出 `PipelineStageSnapshot`，不能把评分、风险、融合、动作或发布错误表示成“过滤掉”。字段必须使用真实类型：

阶段快照必须有类型地携带stage、order、as_of、state、输入/输出/拒绝/待补充/失败计数、原因聚合、来源健康、单调耗时和降级标志。具体字段以对应不可变类型及HTTP白名单为准，不在文档复制类声明。

只有ST预过滤及合并承载一级市场/二级公司风险的动态过滤阶段附带 `BusinessRejectionSummary`，其 `rejection_rate` 使用 `Decimal`，原因使用 `RejectionReasonCode` 与 `Severity` 枚举。其它阶段分别通过 `pending_count`、`failed_count` 和有类型原因表达数据未就绪、模型推理失败、风险限制、动作阻断、集中度跳过、冻结冲突或发布失败。

第 14 层 I/O 的 `PublicationIoSnapshot` 使用独立计数单位 `operation`：每次尝试输入为 1，完成后输出、待补充或失败互斥为 1，业务拒绝为 0；进行中待补充为 1、耗时未知。回执携带操作、尝试 ID、策略/日期/可空决策身份、输出身份、上海时区时间、原因和来源健康/年龄，实际耗时由单调时钟测量。来源读取成功但记录缺失或不合格时来源健康可为 ready、操作为 not_ready；索引冲突为 failed，源响应成功不等于发布成功。失败保留最近成功时间，观测时钟不可用时年龄未知，不阻断合法结果或只读状态。状态 adapter 按字段白名单投影到 `/api/status.scheduler.publication_io`，失败纳入运行降级。Web 第 14 层详情按同日同策略显示各操作最近回执及其独立身份，不混入股票人口、不计算拒绝率、不与股票阶段耗时累加。回执不写入决策哈希或正式记录，冷恢复不能伪造前十三层，历史页不能借用当前进程回执。

`StageReasonAggregate` 只包含：

- `code: StageReasonCode`
- `label: str`
- `count: int`
- `severity: Severity`

#### 11.1.1 评分子阶段观测词汇（状态与决策投影的 16 个 key）

状态合同存在两套固定词汇，二者不得混用、互相替换或用其中一套反推另一套：

- 第3节的14层链路是唯一的领域流水线编号，统一输出 `PipelineStageSnapshot`，Web 监控展示层只能直接读取这 14 层快照；
- `GET /api/status` 中每个短线策略 `input_quality` 的类型化 `pipeline` 使用另一套固定的 16 个评分子阶段 key，由 `recommendation/domain/evidence/pipeline.py` 的 `PIPELINE_STAGE_ORDER` 唯一定义，固定顺序为：`input_readiness`、`dynamic_filter`、`board_cross_section`、`strategy_history`、`model_input`、`candidate_score`、`board_limit`、`candidate_refresh`、`input_coverage`、`evidence_score`、`model_cost_gate`、`local_score`、`deepseek_review`、`fusion`、`action_gate`、`concentration`。同一 `RecommendationPipelineStatus` 也可作为短线决策身份的 `pipeline` 字段，并由 `decision_view`、SSE 和冻结记录只读投影；这些消费者不得另定义阶段顺序。

该投影是阶段可观测性 API 合同，不是第二套流水线编号：它描述评分子阶段的输入质量与分面，不拥有业务流水线的层数、批号或所有权。每个阶段显式携带 `pending/running/completed/degraded/not_applicable` 状态、可空输入/输出数、适用门槛、指标最小/最大值、互斥或覆盖分面与主要原因计数。语义边界固定为：

- 首个 `input_readiness` 阶段只报告发行人资格后人口中具备完整可信输入的就绪人口及其 `data_pending`/`refresh_pending` 原因，输出数不得计入业务 `rejected_count` 或占用每板名额；待下载/待更新与业务拒绝必须分档，页面和 API 先展示输入准备再展示 `dynamic_filter`；
- 行情、证券主数据和有效历史是 `input_coverage` 的并行分面，不得伪装成先后过滤节点；该阶段不替代候选层 `input_coverage` 的并行分面；
- 观察/正式门槛与动作分类是 `action_gate` 分面，正式/观察最终入池是 `concentration` 分面；
- `fusion` 是既有第 12 层键，现投影本地最终分和风险复核合并结果，不做数值融合；`local_score` 对应第 10 层已扣本地风险的评分，`deepseek_review` 对应第 11 层结构化风险复核。14 层快照与 16 key 投影之间没有一一映射义务，不得把 16 个评分子阶段重新拼成展示层。

两套词汇变更必须同步类型owner、adapter及schema/API契约测试。

### 11.2 身份与审计边界

公开 Web/API 只能展示：

- 每层输入、输出、业务拒绝、待补充、失败和耗时；
- 原因聚合、规则范围、门槛、来源健康与降级状态；
- 各档位、策略、板块组的汇总状态。

公开投影、冻结记录和历史记录不得保存或返回未入选股票身份。当前运行内存仍可用时，统一只读诊断脚本可以通过受限探测端口按单个 `code` 查询首个阻断原因；探测结果不得写入冻结记录、历史快照、普通日志或 Web 响应，也不得输出完整行情、模型特征或外部载荷。


## 12. 安装、运行与运维

源码更新不会替换已经运行的常驻进程；活动 Web 把模板与静态资源固定为启动时 release 快照，
不会从工作树热加载。部署新提交时必须正常停止旧 `run.sh`/`trader-server`，再依次执行
`./run.sh check` 与 `./run.sh`；启动后应核对 `/api/status` 的 `runtime_version`、
`release`、`scheduler.strategy_errors` 和各策略状态，不能只以 HTTP 200 判断更新生效。浏览器出现
“服务版本不一致”时不得继续等待或重复刷新，必须先完成上述正常重启；同一运行目录的进程锁会
正确拒绝第二个 `./run.sh`，这不表示新代码已经替换旧进程。

一键启动使用 `run.sh`、`run.ps1` 或 `run.bat`。手动流程为创建虚拟环境、从
`pyproject.toml` 安装、用绝对配置路径执行 `trader-cli validate-config`，再启动
`trader-server`。任何环境都不得依赖仓库当前工作目录才能读取资源。启动脚本的无参数行为固定为
启动看板；帮助必须把日常命令与显式离线研究命令
分组展示并逐项说明，不得再把所有名称压缩成一行伪装成必填启动参数。未知命令必须在创建虚拟环境、
安装依赖或启动入口之前失败，并只给出日常无参数启动与帮助命令指引。Linux/macOS 与 PowerShell
入口必须保持相同分类和默认语义；`run.bat` 继续委托 PowerShell 入口。当前公开脚本命令固定为
`check`、`download_train`、`download_qfq` 和 `download_risk`。历史自动化安装/卸载不再提供公开脚本入口；已有任务仍可调用组合内的
`download_scheduled`，只读状态由 `history-automation-status` 提供。旧 H0 历史归档、回测和筛选命令已经退役。组合内的
底层 `trader-cli` 阶段继续保留用于测试、自动化和故障定位，但不再逐项暴露为 `run.sh` 命令。

`model_industry_reference_unavailable`，报告引用行数、错误/超时计数和脱敏错误类别；诊断本身仍保持只读。

统一诊断的 `runtime/web` profile 只读取运行中 Web，`research` profile 复用只读
`trader-cli research-status` 权威投影并只保留活动研究窗口摘要，`sources` profile 才执行真实供应商请求并消耗适用配额，
其 `research_readiness` 根投影固定 `production_authority=false`，不得因子研究状态缺失而默认获得生产权限。
`history-daily-capability` profile 是阶段 A 固化的只读来源门：它用有硬超时的独立进程抽样 BaoStock raw/qfq，
结合配置权限审计 Tushare 与逐股腾讯/东财适配器，并只输出行数、时延下限、能力布尔值和稳定错误类别；不得输出
价格、token 或供应商原载荷，也不得写 `data/history`。旧日期化探针只证明当时的样本与权限，
不得据此判定当前供应商全市场能力。当前Tencent价格单源与BaoStock历史行业边界见下载训练第3节，
实际覆盖和耗时证据只记工程实施台账。

正常停止时在服务终端按一次 Ctrl+C，并等待最多 30 秒；第二次 Ctrl+C 是立即强制退出，
只用于确认不再等待。浏览器关闭不会停止后台服务。正常重启后，观察池、候选、历史派生内存视图、
研究/review 临时结果、退避和 session 内存状态重新构造；活动历史快照、正式推荐、合法冻结
检查点、恢复载荷、预算、证据、overlay 和结算继续按各自持久化契约恢复。任务管理器强制
结束、断电、第二次信号和期限强退属于异常终止，只依赖冻结仓储恢复保证正式记录一致。

备份只需要当前配置、`data/freeze/` 下V2/V3的正式记录、恢复证据与SQLite，以及已验证归档；缓存、构建物和临时
文件不备份。普通 Web 不直接读取历史归档；只读状态使用推荐侧已经聚合的内存投影。回退必须切换完整旧 release 及其对应运行目录，
禁止只替换单个模块；当前数据不得写回旧运行库，非独立清理任务不得破坏性删除正式历史。

离线命令为`./run.sh download_train`、`./run.sh download_qfq`、`./run.sh download_risk`；数据布局、增量、锁、恢复、工件复用及训练due唯一见[下载训练](4_下载训练.md)。
不从Web启动完整历史或训练；正常重启不构成模型生产授权。参考数据迁移只在仓库外构建并验证副本，真实切换与删除另需明确授权。

## 13. 测试与发布验收

日常 `make test` / `make test-fast` 仍运行非slow集合；`make test-history`、`make test-train`、`make test-recommendation`按唯一业务归属选取，包含本业务慢用例。发布使用`make test-full`，不得把快测冒充全量。
默认4个pytest-xdist worker，可通过`PYTEST_WORKERS`调整。提速优先减少重复建库、拟合、源码扫描和真实等待，不以skip或改slow标签替代优化。
只读测试复用关闭后的不可变种子，每个写入/损坏测试复制独立文件，禁止共享可变SQLite连接或硬链接；同步/事务/续传测试仍走真实持久化边界。


每次发布必须运行：

```bash
make format-check
make lint
make type-check
make test-full
make package
```

还必须验证架构 AST、`CreateApp()` 无副作用、本地最终分与复核 veto 分离、预算并发上限、
single-flight、latest-wins、来源乱序、SSE 游标恢复和慢客户端、冻结恢复与哈希一致性。
从仓库外安装 wheel 后验证 `trader` 导入、`trader-cli`、`validate-config`、Web 模板、CSS、
JavaScript、图标、三平台历史自动化模板和 `pip check`。桌面三档需要实际渲染证据；若宿主图形栈阻断，必须把
错误和未完成门禁列为剩余外部风险，不能宣称通过。
测试目录由 pytest 自动标记为 `unit`、`component`、`contract`、`integration`、`performance` 或 `js`，
其中性能测试同时标记 `slow`。`make test-*` 提供分层入口；`make test-release` 构建 wheel，并在仓库外
临时环境执行安装、CLI 配置校验、`pip check` 和包资源读取。

质量门禁`make lint` 还必须执行严格复杂度与命名债务的单调收敛门禁：活动树中
`C901`、`PLR0911/0912/0913/0915` 和适用的 `N` 系列问题数量不得高于已登记基线；公开顶层函数大驼峰
由 AST 专项校验，`N802/N813` 不用于判定公开函数及私有导入别名。每个重构批次
必须同步下调已经消除的问题额度，禁止新增同类债务。最终目录切换时这些临时额度必须
全部归零。活动源码单文件仍以第 3 节规定的 1200 行为上限，不另设任意的 500 或 800 行限制。

性能 fixture 必须固定数据、策略和配置哈希，并记录提交、工作树、源码树 SHA-256、
Python、系统、内核、架构和 CPU。runner 禁止外网，DeepSeek 用固定响应，SQLite 使用
临时库。延迟轮次关闭 tracemalloc，内存轮次单独开启；内存报告必须同时覆盖
`cache_logical_bytes <= 260046848` 和 `process_peak_rss_bytes <= 402653184`。
固定性能配置直接使用稳定的 `performance_budgets` 字段合同，不设置独立编号版本，并分别执行生产函数性能 CLI
与真实浏览器 runner；任一绝对预算红项必须保留在报告中并阻断发布，不能用其他阶段的
余量抵消。

### 13.1 荐股可用性防回归矩阵

永久验收同时覆盖热运行与冷启动，并贯穿“统一行情 -> 历史就绪 -> 候选 -> 评分 ->
`UnifiedDecisionIndex` -> 正式记录 -> 查询 -> Web current”整条链：

| 上海交易时段 | 热运行必须保持 | 冷启动/缺稿恢复 | 禁止行为 |
| --- | --- | --- | --- |
| 09:30-13:00 | 三策略同日 current；tomorrow/d25 为本地草稿，long 为当前观察 | 输入满足门槛后生成三类 current | 因只路由单一短策略而延迟其它策略 |
| 13:00-15:00 | tomorrow/d25 增量复核；long 更新 current | 缺失策略可从同日输入恢复草稿 | 用审核加严解释午前无数据 |
| 15:00 前后冻结边界 | 15:00 前继续生成滚动结果；15:00 后两类荐股使用同日正式记录，long 仍为当前观察 | tomorrow/d25 只可恢复合法同日检查点 | 把迟到结果写成正式记录 |
| 15:00 后 | 正式记录继续可查且只更新 overlay；long 当前可见 | tomorrow/d25 先读正式记录/当前决策，均缺失才创建一次 `close_fallback` | 用上一交易日冒充当前 |

合法空集合必须返回 ready 与 `selection_diagnostics`，上游未就绪才返回 `not_ready`。
任一来源、评分、索引、持久化或 Web 环节失败时保留最近同日有效投影并报告明确降级，
不得用空或旧日结果覆盖。Long 单独验证完整固定名单、同日 current、行情时间和价格，
不按荐股评分或冻结语义验收。

所有调度、队列、缓存、评分、冻结、查询或前端 current 变更都必须覆盖上午热运行、午间
冷启动、15:00 冻结边界、15:00 后热运行及正式记录命中/收盘恢复。每次相关发布仍须
启动真实 `trader-server`，核对 `/api/status` 和三策略 current；只验证 fixture 不算发布证据。

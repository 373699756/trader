# 项目重构规划
| 策略 | 决策目标 | 生产锚点 | 正式结果 |
| --- | --- | --- | --- |
| `tomorrow` | 15:00 至下一交易日收盘的净超额 | 15:00 冻结 | 0–6 只正式推荐，盘中另有最多 6 只观察项 |
| `d25` | 筛选未来第 2 至第 5 个交易日区间内具备上涨能力的股票 | 15:00 冻结 | 一个 D25 决策，0–6 只正式推荐，盘中另有最多 6 只观察项 |
| `long` | 固定长期研究池的当前行情观察 | 不冻结 | 无评分、无动作、无推荐历史 |

模块化需求：
业务放线：下载，训练，荐股，三条业务线模块功能彼此独立，互不干扰，避免修改一个业务线影响另外的正常使用
功能方向：在为业务线服务的同时，各功能模块也要独立，避免互相干扰，
infra:公共部分提取到infra模块，进行封装，接口统一

D25 是一个完整且唯一的 2–5 日生产策略头，不得拆成 T+2、T+3、T+4、T+5 四个生产头；
四个观察点只用于 D25 的标签、终端留出、风险和稳定性评价。“具备上涨能力”是对该区间综合收益信号的
研究判断，不表示四天必须逐日上涨，也不构成收益保证。V1 下 D25 使用规则评分；V2/V3 启动时，D25 只读取

## 1. 命名规划
命名需要专业简洁明了，避免出现 Store、Lifecycle 这类不专业命名

Python 命名类别固定为：
类和异常使用 `PascalCase`，
函数、方法、参数和普通变量使用`snake_case`，
常量使用 `UPPER_SNAKE_CASE`，
模块和 Python 文件使用小写 `snake_case`；
导入别名必须保持被导入对象的命名类别。严格质量检查对 `src/trader`、`scripts` 和 `tests` 统一执行 Ruff `N` 命名规则。

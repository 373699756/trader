## 数据源耗时与评分字段覆盖测试命令

在仓库根目录执行。统一入口为 `scripts/diagnose_runtime.py --profile market-factor-compare`，只读采集外部数据和本地 qfq、模型，不写生产快照或触发 DeepSeek。需要本机已有相应档位的 qfq、训练工件及运行配置。

### 测试组合与输出范围

`--market-mode all` 测试五组：腾讯单源、东方财富单源、新浪单源、腾讯后接新浪补缺、腾讯后接东方财富补缺。组合为串行补缺失行情数值字段，不包含三源同时合并或并发对冲；新浪和东方财富使用全市场接口后筛选目标股票，因此小样本的物理请求量与腾讯不同，可查看 `attempts[].physical_rows`。

报告包含逐字段有效数、缺失数、覆盖率、来源与合并冲突，以及准备、采集、合并、特征构建、输入封存、评分、总耗时。V2/V3复用同批行情，分别使用各自历史和模型；行业另行获取，财务、公告和分钟数据只探测三个板块样本，不代表全市场研究信息完整。

### 小样本：120只、V3、每组一次

```bash
.venv/bin/python3 scripts/diagnose_runtime.py \
  --profile market-factor-compare \
  --market-sources tencent eastmoney sina \
  --market-mode all \
  --market-profiles v3 \
  --market-sizes 120 \
  --source-samples 1 \
  --source-timeout-seconds 4.5 \
  --command-timeout-seconds 600 \
  --output /tmp/trader-market-factor-120.json
```

结束后打印：

```bash
cat /tmp/trader-market-factor-120.json
```

### 全市场：V2/V3、每组三次

`--market-sizes 0` 表示官方全市场股票池；若同时比较规模影响，改为 `--market-sizes 120 720 0`。多规模、多轮测试可能需要十几分钟，建议先跑上面的小样本。

```bash
.venv/bin/python3 scripts/diagnose_runtime.py \
  --profile market-factor-compare \
  --market-sources tencent eastmoney sina \
  --market-mode all \
  --market-profiles v2 v3 \
  --market-sizes 0 \
  --source-samples 3 \
  --source-timeout-seconds 4.5 \
  --source-interval-seconds 2 \
  --command-timeout-seconds 1800 \
  --output /tmp/trader-market-factor-full.json
```

结束后打印：

```bash
cat /tmp/trader-market-factor-full.json
```

### 参数与结果解读

- 改为 `--market-mode single` 只测单源；改为 `combined` 只测腾讯加辅助源。
- `--source-timeout-seconds 4.5` 是单次请求超时，不是整波5秒保证；采集批次预算默认30秒。如需探测5秒预算，追加 `--market-batch-seconds 5`，并查看超时和完整度，不能把被丢弃或缺字段的结果当作成功。
- 报告在整次命令结束后输出，目前没有逐组实时进度；改为 `--output -` 可直接输出JSON。启动时还需读取和校验本地qfq、加载模型、获取参考资料，整条命令的运行时间不等于行情采集时间。
- 状态 `degraded` 表示存在覆盖或验证限制，应检查具体字段；`failed` 或命令总超时不能当作快速成功。三轮P95只是小样本统计，不是时延保证。

以下路径均位于JSON的 `checks[0].summary` 内：

| 路径 | 用途 |
| --- | --- |
| `preparation`、`reference_setup_ms`、`model_industry_probe` | qfq校验、模型加载与参考资料准备耗时 |
| `comparisons` | 各规模、档位、路线的P50、P95、最大耗时及完整轮数 |
| `samples[].attempts` | 单源请求耗时、异常、物理返回数和原始字段覆盖 |
| `samples[].quotes.fields` | 合并后行情字段的有效数、缺失数和覆盖率 |
| `samples[].factors.fields` | 评分因子缺口、来源类别及消费者 |
| `samples[].factors.models` | 模型输入资格、历史长度要求及特征合同 |
| `samples[].factors.qfq_length_distribution` | qfq实际历史长度分布 |
| `samples[].factors.qfq_one_session_short_rows` | 相对模型要求仅缺一天的数量 |
| `samples[].scoring` | 候选数、诊断模型输入/输出数及本地投影结果 |
| `samples[].input_qualified`、`input_seal_ms`、`deadline_exceeded` | 输入完整条件、采集至封存耗时及是否超预算 |
| `auxiliary_samples` | 三只样本的财务、公告、风险和分钟数据探测 |

判断“5秒合格输入”至少需要 `input_qualified=true` 且 `input_seal_ms <= 5000`；还需单独检查研究证据覆盖。盘后测试不能证明盘中实时性，供应商缺字段或预算内未返回也不等于其接口永远不支持该字段。

`total_ms` 包含诊断审计及额外模型吞吐探测，不能直接当作生产更新周期。当前命令不测14条链路到Web的原子发布，也不验证“第二波完整发布前保持第一波不变”；这些需要真实交易时段的生产链路验收。

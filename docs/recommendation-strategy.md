版本：v2（活动 Tomorrow 模型由 `tomorrow_scoring_profile=v1|v2` 选择，默认 `v1`，运行身份由有效配置 SHA-256 生成）

引擎：`engine_review28_2026_07`

融合：`fusion_local68_deepseek32`

状态：活动策略契约；V2-only 工程与发布门禁已验收，正式 0.2.0 release 尚未声明

本文是候选、过滤、因子、评分、风险、DeepSeek、融合、动作、排名和策略验收的唯一
权威。产品、架构、时间线、发布、API、运维和工程路线以
[软件业务设计文档](software-business-design.md) 为准。策略用于研究，不构成投资建议，
不保证收益，不触发真实交易。

### 0.1 评分目标与证据原则

Today、Tomorrow、D25 及其后续所有评分计划的唯一业务目标，是提高对应持有周期内可重复、扣除交易成本、
相对同日可投资 A 股基准的风险约束净超额收益。推荐数量、命中率、平均原始涨幅、页面非空和模型分数
本身都不是优化目标，不能为了避免 0 只结果降低风险、动作或收益门槛。研究晋级必须同时检查净超额、
严重亏损、最大不利变动、换手、容量、集中度、Rank IC 和分组单调性；收益改善若以不可接受的尾部风险
或交易成本为代价，不得宣称评分更优。

每个新评分计划必须在读取评价区间收益前登记策略、持有期、预测锚点、成本后基准、主要收益指标、
尾部风险、换手/容量、样本外切分、统计功效、停止条件和生产权限。缺少任一项的工作只能标记为数据或
因子诊断，不能进入调权、模型选择、阈值修改或生产晋级。历史回放、前向影子和工程实现都必须服务于
这个收益目标，但工程完成本身不构成收益改善证据。

生产数据就绪与收益证据必须分离。过去行情窗口只服务于明确登记的因子或模型输入；未来结算标签只
服务于事后评价，不得反向参与当天评分或阻塞启动。V1/V2 比较必须覆盖同日、同股、同一冻结输入下全部
共同可评分候选，而不是只观察最终 Top6；即使正式推荐为 0，也必须继续形成无生产写权限的配对预测和
后续标签，避免用已入选样本评价选股器造成选择偏差。没有足够样本外证据时必须写“未证明”，不得用
工程完成、推荐数量或人工授权代替收益证明。

最终 V2 评分口径只产生 `ScoredDecision`，Long 只产生无评分 `LongProjection`；新 release
不得构造或读取旧 `RecommendationSnapshot`，也不回放旧策略、旧引擎或旧 schema。当前
V2-only 工程与发布门禁验收已闭合；当前版本仍在 `Unreleased`，尚未声明正式
`0.2.0` release。旧链已从活动树物理删除，不定义候选、公式、
风险、融合、动作或排名。历史问题与实施过程只进入 `CHANGELOG.md` 和报告。

## 1. 策略目标与共同纪律

- `today`：盘中短线，面向 T+1；11:20 冻结。
- `tomorrow`：上午生成滚动本地草稿并复用跨策略模型 facts，13:00 后增加尾盘量价和
  增量模型复核，面向 T+1；14:50 冻结。
- `d25`：上午生成滚动本地草稿并复用跨策略模型 facts，13:00 后增加增量模型复核，
  面向 T+2 至 T+5；14:50 冻结。
- `long`：固定长期潜力龙头研究池，只展示当前行情快照；warmup、上午和下午都可随统一
  行情生成当前观察快照，不运行荐股策略、不冻结、不产生交易动作、不写推荐历史。

允许 0 只推荐。所有计算只使用观察时点已经生效的数据；实时价格、涨跌停和冻结锚点
使用未复权价格，历史收益、均线、波动和回撤使用点时可得的前复权序列。行业、证券
状态、财务和规则按实际生效时间进入特征。每次输入绑定交易日、阶段、数据、规则、
行业、配置、因子 schema、策略和引擎版本。

缺失原始值保持 `null` 并记录 `missing_fields` 与 `missing_reasons`。允许用于确定性评分
的中性占位为 50，但不得把占位序列化成真实观测，也不得通过缺失字段获得额外优势。
非有限数值、未来数据、无时区数据、截止后结果和无法验证的证券状态不得用于可执行
推荐。

### 1.1 tomorrow v2 收益与选择目标

tomorrow 是目标架构唯一最高优先级的生产选择任务，在交易时段滚动发布本地预览并于
14:50 冻结。每个决策允许 0 到 6 只正式推荐和 0 到 6 只观察项；候选不足或全部未通过数据、风险、动作和集中度
门槛时必须返回真实空结果，禁止为凑数降阈值。

首要收益标签固定为 14:50 锚点至下一交易日收盘的相对全市场等权净超额收益，并同时
报告下一交易日最低价对应的 MAE/ATR20、换手和行业集中度。成本敏感性统一使用
20bp、50bp、100bp 三档往返成本，不得只展示最有利口径。

DeepSeek 继续参与融合分，但只能复核候选池内股票、返回经 schema 与证据校验的 facts，
不能放宽硬过滤、引入池外股票或用自由文本直接扣分。正式融合在新挑战者通过样本外和
前向影子门禁前继续使用当前固定 68/32 公式。普通阶段全策略合计目标 36、硬上限 66，
其中 tomorrow 独占目标 21、硬上限 38；失败、超时和重试同样计数，耗尽后保留 local
决策，不阻塞发布或冻结。独立 emergency 桶和全局 168 次灾难保护线以第 11 节为准。

## 2. 板块身份与交易规则

板块固定为 `main`、`chinext`、`star` 和 `unsupported`。识别顺序为带生效时间的证券
主数据、交易所清单、行情源市场字段、六位代码前缀降级。前缀降级记录
`board_source=code_prefix_fallback` 和 `board_reliability=degraded`；来源冲突记录
`board_classification_conflict`，只能观察。

每个观察点保存：板块、来源、可靠度、交易所、上市日期、上市交易日龄、是否有价格
限制、交易所限制比例、策略热度上限、规则版本和生效日期。

首次上市第 0-5 个交易日、重新上市首日、退市整理首日直接排除，第 6 个交易日起才用
普通规则。上市日期或交易日龄不可验证时只能观察。普通热度边界：主板 8.00% 通过、
8.01% 剔除；创业板和科创板 16.00% 通过、16.01% 剔除。无价格限制状态不计算普通
`limit_proximity`。

## 3. 统一行情与点时合并

策略只消费不可变统一行情，不直接读取供应商对象。相同有效输入无论来源完成顺序都
产生相同字段归属、来源版本、冲突集合、缺失集合、合并 epoch 和规范 JSON 哈希。
合并 epoch 绑定排序后的已接受观测身份、点时、版本、载荷哈希、缺失原因和定向范围；
最终规范 JSON 哈希继续覆盖完整统一快照，两者不得用不稳定对象地址或输入完成顺序生成。

同来源先按来源时间、接收时间选择较新字段；跨来源同时点按既定优先级。新鲜腾讯
候选价只能在与东方财富或新浪至少一个全市场观测偏差不超过 0.50% 时完成冲突复核，
不得自证。慢数据不得覆盖更新的实时价格。全源失败时沿用最近有效统一快照并降级，
不能生成空快照清除推荐。
未准入影子来源不得写入统一行情字段，也不能参与候选、过滤、评分、DeepSeek 证据、
冻结或收益结算；通达信/mootdx 在权威准入前只可作为独立影子观测，不构成候选 fallback。

## 4. 硬过滤

候选依次执行带严重级别的确定性过滤。当前 `FilterSeverity.REQUIRED` 必需阻断包括：

- 非六位受支持 A 股代码或 `unsupported` 板块，ST/`*ST`/名称含“退”、停牌；
- 价格或成交额非有限、非正，行情时间无时区、来自未来或超过本阶段动作年龄；
- 跨源偏差字段本身非法，开高低收结构非法或当日涨跌幅缺失/非有限；
- 上市第 0-5 个交易日、重新上市首日、退市整理首日；
- 20 日成交额中位数缺失、非有限或低于 5000 万元；
- 一字涨跌停、配置黑名单或行情已标记重大监管风险；
- 超过板块热度上限；
- 经点时 schema 和官方证据验证的 `major_shareholder_reduction`、
  `financial_fraud_history`、`official_investigation_history`、
  `major_illegal_history`、`fund_occupation_history`、`illegal_guarantee_history` 或
  `forced_delisting_risk` 命中；
- `unlock_risk > 0`、`pledge_risk > 0` 或 `financial_deterioration > 0.5`。

当前可选告警/观察限制包括：未复核的跨源价格偏差超过 0.50%、
`board_classification_conflict`、`board_identity_degraded`、`missing_listing_date`、
`missing_listing_age_sessions`、`structured_risk_unavailable` 和
`corporate_risk_history_unavailable`。这些事实写入 `optional_flags`；统一行情同时写入
`execution_restrictions` 时，最终动作即使达到阈值也会改为 `observe`。候选必需字段缺失
比例超过 30% 属于板内预选剔除，不冒充硬过滤；
板块数据可靠度低于 0.85 属于动作门和 DeepSeek 资格限制，同样保留本地候选但只能观察。

硬过滤是结构化规则，不能由 DeepSeek 放宽、删除或新增池外股票。可选告警进入
`optional_flags`，不冒充阻断原因；必需阻断保存在 `filter_reasons`。原因码必须细分到
具体板块和事实，例如 `chinext_board_too_hot`、`star_board_too_hot`，不能用模糊成长
板标签替代。

严重公司风险只接受发行人、交易所、监管或司法结构化披露及其稳定证据 ID；新闻标题、
DeepSeek 自由文本和普通风险提示、问询函、一般诉讼、亏损预告不能创建或解除硬事实。
规则固定为：

- 大股东指控股股东、实际控制人和持股不低于 5% 的股东；减持计划从公告起阻断，至官方
  完成或终止后 90 天解除，无终态则持续阻断；
- 官方决定确认的财务造假、虚假记载、重大遗漏、重大违法、资金占用和违规担保永久阻断；
- 正式立案调查和强制退市程序在存续期及官方结案、撤回或终止后三个自然年阻断，满三个
  自然年当日解除。

风险事实随研究缓存持久化合并，旧命中不能因本轮来源失败消失。来源失败或覆盖状态不可
确认时不能猜成 0：已确认事实继续阻断，其余候选保留本地快照但动作降为观察，并记录
`corporate_risk_history_unavailable`。减持、解禁、质押必须保持独立字段。
财务、公告/公司风险历史、质押和解禁是四个独立覆盖分项；程序运行时按分项 TTL 复用缓存，
并非每次评分都重新请求，也不是进程一生只请求一次。批次超时只延后未完成股票，已经完成
股票和分项立即形成新研究版本。上述采集与覆盖状态独立于 DeepSeek 模型复核。一般负面新闻、
普通问询、一般诉讼和未经正式财报确认的亏损预告仍只作研究提示，不能新增硬过滤；正式财务
报告触发 `financial_deterioration > 0.5` 或官方结构化风险事实命中时才按本节既有阈值阻断。
CNInfo 公告增量链只保存带稳定公告 ID 的结构化披露、公告组件状态和来源游标；重复页按公告
ID 去重，空增量只更新游标和审计，不能把既有 `known_risk` 覆盖为 `known_clear`。交易所公告
交叉校验未形成正式来源前，CNInfo 证据的 `exchange_cross_check_status` 固定为 `pending`，
可进入本地风险事实注册表和观察降级判断，但不得宣称已完成交易所级复核。
东方财富发行人公告必须按实际 100 条单页上限有界遍历并以稳定公告 ID 去重；缓存已有完整历史时
允许用新首页与旧基线做增量合并。只有不晚于评估时刻的有效公告数量覆盖供应商 `total_hits` 时，
`announcement` 分项才能成为 `known_clear` 或 `known_risk`；分页不完整继续
`corporate_risk_history_unavailable`，不能通过减少回看窗口或只读首页解除观察门。

## 5. 板内总体与成交因子

横截面总体固定为：

```text
trade_date + phase + board + data_version
```

流动性、换手、波动、回撤、趋势和相对强度均在板内按
2.5%/97.5% 截尾、归一化和稳定排序。有效板内横截面至少 100 只；不足时最多回退最近
5 个有效交易日的同板同阶段总体，不能借用其他板块。

板内总体与本轮候选是两个不同集合：全市场特征只用于按
`trade_date + phase + board + population data_version/merge_epoch` 构建和缓存总体、
分位与归一化基准；候选定向报价完成后，只把每板最多 120 只的新鲜候选投影到该基准并
计算候选分和本地分。不得再次对约 5500 只全市场股票逐只执行九组候选选择和本地评分，
也不得先从全市场选出另一批股票再与本轮候选代码求交集。候选报价版本变化只失效相应
候选批次和逐股本地分，不得无条件失效未变化的板内总体。候选预选与正式评分必须沿用
同一份全市场特征自带的 `merge_epoch`；缓存只保留总体参数和参考分布，命中后不得为
每个策略重复序列化全市场，正式评分只投影有界候选并直接执行纯本地评分函数。
全市场总体与候选定向批次必须分别使用自己的点时水位和年龄上限：总体在其完整发现批次的
`observed_at/source_time/received_time` 最大值上执行预选新鲜度审计，候选在最终
`evaluated_at` 上执行评分新鲜度审计。候选历史、研究或分钟增强较慢，不能把此前已完整接纳的同一
`merge_epoch` 总体倒算为 `stale_quote` 并清空横截面；候选原始 `source_time` 过期时仍必须拒绝，
不得借总体水位恢复候选执行资格。原生输入边界必须先把总体与候选的全部业务时间规范为
`Asia/Shanghai`，再计算最大水位，不能让 `max()` 保留胜出 UTC 对象的时区身份。

行业只用于展示、审计、DeepSeek 行业政策零权重标签和最终集中度标识，不进入候选分、
本地分、DeepSeek 总分、动作门或活动下行保护。特征服务仍计算并保存
`industry_strength`、`industry_breadth`、`industry_trend` 和
`industry_policy_score`，通用 DeepSeek ground-truth 也可携带这些已存在字段；活动板内
评分不读取它们，`industry_policy` 维度权重固定为 0，活动下行保护调用固定
`require_industry_breadth=false`。`peer_gap`、`leader_gap` 不属于活动评分输入。修改同一
股票的行业数值不能改变其候选分、本地分、DeepSeek 总分、动作或下行保护；行业名称本身
只可能改变最终每行业最多 2 只的集中度选择。

换手和成交冲击：

```text
turnover_shock_20 = current_turnover / median(turnover, 20)
amount_shock_20 = current_amount / median(amount, 20)
volume_price_confirmation = sign(return) * normalized_amount_shock
```

分母缺失、非正或非有限时保持缺失。换手使用带通函数
`B(x;0.8,1.1,2.0,4.0)`，成交额使用 `B(x;0.8,1.2,3.0,6.0)`。所有成交量、成交额和
换手指标统称 `flow_proxy`，不得解释为主力、机构或散户资金。

## 7. 本地评分

定义带通函数 `B(x;l,o1,o2,u)`，其中 `l < o1 <= o2 < u`：`x <= l` 或 `x >= u`
得 0，`o1 <= x <= o2` 得 100，两侧区间线性变化。参数非法时配置拒绝启动，缺失或
非有限输入按缺失规则处理。`P(x)` 是 0-100 横截面平均秩，反向因子必须登记并计算
`100-P(x)`。

统一计算边界：

```text
base_score = sum(component_score * component_weight)
local_score = clamp(base_score - local_risk_penalty, 0, 100)
```

### 7.1 确定性入场质量

tomorrow 和 d25 的 `entry_quality` 取缩量回踩与放量突破两类确定性形态的
较高值。热度本身不阻止入选；只有形态、下行保护和既有硬过滤共同决定是否可执行。

- 缩量回踩：`MA5 >= MA10 >= MA20`、MA20 斜率向上，价格距离 MA5 不超过 1% 或距离
  MA10 不超过 2%，点时 `volume_to_5d_average` 不高于 0.70，且价格不低于 MA20。
- 放量突破：价格不低于前 20 个完整交易日最高价，点时 `volume_to_5d_average` 不低于 2.0，
  收盘位置不低于 70，突破偏离不超过 5%。
- `volume_to_5d_average` 优先使用供应商点时 `volume_ratio`；供应商未提供时，使用同日
  点时成交额除以最近 5 个已完成交易日平均成交额派生，不使用同日历史 bar。
- 完整形态为 100，趋势前提成立但入场确认不完整为 50，趋势破坏为 0；必要输入缺失
  保持 `null`，不能以中性值冒充确认。

行业组件移除后，其权重按各策略剩余组件原比例归一化；`entry_quality` 保持上述确定性
形态定义。过热事实继续审计和软扣分，不再作为 d25 独立正向组件。

### 7.2 tomorrow v2 确定性本地选择

tomorrow v2 旁路选择只消费同一数据平面快照：昨日及更早历史、证券主数据和结构化风险来自
`DailyFeaturePack`；全市场当前报价来自其父版本匹配的 `MarketEpoch`；当日尾盘、入场、
执行质量和日内结构风险只能由 `CandidateQuoteEpoch.CandidateFeatureRow` 覆盖。实时特征
白名单不得包含财务、公司风险或证券身份字段。候选价格必须携带本轮跨源偏差并满足
`cross_source_verified=true`、偏差有限且 `<= 0.50%`；不得沿用旧全市场价格的复核状态。
候选单股来源时间早于父市场同股报价时，候选价格及同批实时特征都不得覆盖更新值。

该快照只通过应用层 `DataPlaneReadPort` 读取。`DailyFeaturePack` 发布前必须证明潜在可执行
代码的证券主数据覆盖为 100%；候选历史覆盖率作为健康和容量指标公开，不再拥有整批发布否决权。
每只候选按活动策略/profile 的类型化数据需求独立判定评分资格，缺失只排除该股票并记录稳定原因；
仍有合法评分人口时必须继续评分，完全无合法评分人口才报告未就绪，禁止把数据不足解释成策略真实空集。

活动生产适配器必须在本地决策发布前复核逐股资格。候选定向特征须覆盖全部请求代码；证券身份完整表示受支持板块且
不存在 `board_identity_degraded`、`missing_listing_date` 或 `missing_listing_age_sessions`；
历史资格不是统一的 20 日布尔值：Today 与当前启发式 D25 至少登记 20 日流动性/风险摘要；Tomorrow
V1/V2 因使用 20/40/60 日 skip-5 动量，必须具备至少 61 个有效 qfq 交易日及所选模型全部字段。
证券身份仍必须 100%；历史资格逐股执行，覆盖率只作诊断。部分股票不合格时发布其余合法评分，
活动模型字段资格必须在板内候选限额前执行，禁止不合格股票占用名额并挤掉可评分股票；全部候选均
不合格时返回 `transient_invalid_empty/not_ready`，不得发布 `business_empty`。

逐股过滤状态固定为：

- `reject`：任一必需硬过滤失败，不进入板内候选分；
- `observe_only`：硬过滤通过但存在可选告警，或板块数据可靠度低于 0.85；保留本地分和
  审计，不进入 DeepSeek 或正式 TopK；
- `pass`：必需过滤通过、无可选告警且板块可靠度达标，可继续参加正式本地选择。

每板先按可靠度是否达标、候选分降序、代码升序稳定截取最多 120 只，再计算本地六组件和
本地风险。本地风险只从 `base_score` 扣一次，输出 `local_score`；DeepSeek 后续融合不得
再次扣 `local_risk_penalty`。全局按本地分降序、候选分降序、代码升序稳定排序，只从
`pass` 且达到 `tomorrow 阈值 - observation_margin` 的候选中选最多 6 只，每行业最多
2 只。允许真实空结果；`observe_only` 候选在独立观察集合中展示和审计，不占正式 TopK。

候选核心缺失超过 30%、候选分低于 50、每板 120 上限、本地风险 veto、本地门槛、行业上限
和 TopK 上限分别记录稳定原因码，不得合并成“本轮没有可评分候选”。相同 epoch、配置、
fallback 和评估时间无论输入顺序如何都必须产生相同逐股状态、分数和选择顺序。

### 7.3 long 固定研究池

## 8. 执行质量、可靠度与容量

### 9.1 活动下行保护

`observe`，高分和高热度不能覆盖 `observe`。下列任一条件将可执行候选降为观察：

- 从当日最高价回落至少 1 个 ATR20，且收盘位置不高于 35；
- `trend_breakdown` 命中；
- 板内 `low_volatility_score <= 20` 且 `low_drawdown_score <= 20`；
- `market_regime=risk_off`、市场上涨宽度不高于 30，且 tomorrow/d25 尾盘收益为负或
  收盘位置不高于 50；today 使用 5 分钟收益为负或收盘位置不高于 50；
- ATR20、20 日波动、20 日最大回撤、低波动分或低回撤分缺失、非有限或过期。

`short_term_overheat`、高波动或临近涨停单独出现时仍只按既有风险表软扣分，不构成

七项理论合计和截断上限均为 25；无事实时扣 0。普通连续弱势只由基础组件反映，不能
重复触发离散扣分。缺失、非有限或样本不足不触发扣分，只记录缺失。long 不使用这组
短线结构扣分。风险事实保存实际值、阈值、方向、严重度、证据、生效时间、互斥/叠加
组和本地规则版本。

完成之后、动作判定和正式池/观察池集中度选择之前；保护只把原本达到执行门槛的候选降为
`observe`，原因使用 `downside_guard:<受控原因>`，不得修改 `local_score`、`final_score` 或融合
组成，也不得把低于观察门槛、硬拒绝或 veto 候选提升为观察。观察池原本就不可执行时保持既有
动作语义，避免把保护器误用成补数或新的排名加分。

## 10. DeepSeek 结构化复核

DeepSeek 是可选复核器，不是候选生成器。默认使用受控双模型：V4-Flash 非思考主审，
V4-Pro 思考挑战者仅处理预注册的不确定、高风险或边界案例。供应商不可用、密钥缺失、
超时、预算耗尽或 schema 失败时回退本地推荐，并明确 `local_degraded` 或相应终态。
若硬过滤、板块样本或可靠度门槛使本轮没有可复核候选，必须标记
`deepseek_skipped_no_eligible_candidates`；未发生物理请求时不得标记
`deepseek_incomplete`。后者只表示已有可复核候选但请求、预算、响应或校验未完整完成；
long 永久不进入复核，因此不得附加任一 DeepSeek 降级原因。

活动结构化事实接缝固定为 `deepseek_v4_review_facts_v1`。该接缝只允许模型返回可校验
事实，不允许自由文本、评级或置信度直接决定分数、风险、动作或排名。事实
集合固定包含：催化方向、重要度、确认状态、周期和引用；价格反映桶；基本面状态；行业
政策状态；监管、减持、解禁、质押、诉讼和业绩风险；事实冲突；证据覆盖；以及
`abstain`。每条事实必须引用本地 manifest 中的证据 ID、来源等级、发布时间和摘要哈希；
无法用 schema 与证据核对的字段必须拒绝或转为 abstain。

每只候选最多使用 12 条点时证据，首轮槽位仍按结构化行情 1、尾盘分钟 1、财务与研究
3、监管/质押/解禁等风险 4、新闻与公告 7 的顺序依次填充，达到 12 条即停止。空槽按
监管风险、财务研究、分钟量价、新闻公告的顺序补给；补位后监管最多 6、财务最多 5、
新闻公告最多 8，行情和分钟仍各最多 1，总数仍不得超过 12。跨来源同主体、事件 key
和证据分类的记录只保留质量更高且更早接收的一条；存在有效相反材料时至少保留一条
反证。证据 manifest 必须携带 `source_tier` 和 `event_key`，正向加分只接受官方来源或
两个独立可信来源支持。

V4 事实只由本地纯函数映射，原始维度从 50 分开始并限制在 30-70；模型不能直接返回
维度分、生产扣分或 veto：

| 结构化事实 | 本地原始变化 | 投影维度 |
| --- | --- | --- |
| 催化方向与重要度 | 高/中/低按方向记 `±15/±8/±3` | `value_quality` |
| 价格反映状态 | 未反映/部分反映/充分反映按方向记 `±12/±5/0` | `market_flow` |
| 基本面 | 改善 `+15`、稳定 `+3`、恶化 `-18` | `financial_health` |
| 行业政策 | 仅形成审计标签，不进入分数、覆盖率或已知维度数 | `industry_policy` |
| 风险事实 | 维度保持 50，只经本地风险规则形成 penalty/veto | `risk_quality` 与独立风险通道 |

V4 六类风险事实进入通用风险规则前必须由同一个领域纯函数按事实类型和 schema 严重度归一化，
映射固定如下；不存在映射、映射目标未注册、证据类型不符、证据过期或置信度不足时失败关闭，
不得在 schema 解析成功后静默丢弃：

| V4 风险事实 | 本地规则映射 |
| --- | --- |
| `regulatory_risk` | 三档严重度均映射 `regulatory_risk` |
| `shareholder_reduction`、`unlock_risk` | 按 low/medium/high 映射 `reduction_or_unlock_low/medium/high` |
| `pledge_risk` | 按 low/medium/high 映射 `pledge_risk_low/medium/high` |
| `litigation_risk`、`earnings_risk` | 三档严重度均映射 `negative_announcement` |

该映射只选择本地已登记规则；实际严重度、penalty、互斥组、TTL、证据类型和 veto 资格仍完全取自
映射后的本地规则，模型不得自定。启动配置校验必须枚举六类事实的 low/medium/high 组合并确认每个
目标规则存在，schema 风险集合与领域映射集合也必须由模块加载契约保持一致。活动映射版本固定为
`deepseek_v4_local_rules_2026_08`，该字段参与策略内容哈希；改变映射必须同时提升版本，避免旧缓存或
旧决策身份与新语义混用。

证据质量同时作为维度 confidence，使变化值在融合前向 50 收缩：官方来源 `1.00`、两个
独立可信来源 `0.85`、单一可信来源 `0.65`、软信息 `0.40`，事实冲突时最高 `0.25`。
正向催化必须已确认且质量至少 `0.85`；正向基本面和政策同样要求质量至少 `0.85`，
否则不得加分。负向事实不因来源质量不足被反向提升，但仍必须引用合法点时证据。

五维固定为价值质量、财务健康、资金量价、行业政策和风险质量。每维输出 0-100 的
`score`、0-1 的 `raw_confidence`、flags、evidence_ids 和 assessment。有效分与总分为：

```text
effective_i = 50 + (score_i - 50) * raw_confidence_i
deepseek_score = sum(effective_i * w_i)
confidence_coverage = sum(raw_confidence_i * w_i)
```

未知维度固定为 `score=50, raw_confidence=0, effective=50`，其余权重不重归一化：

| 策略 | 价值质量 | 财务健康 | 资金量价 | 行业政策 | 风险质量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| today | 11.7647% | 11.7647% | 47.0588% | 0% | 29.4118% |
| tomorrow | 18.75% | 25% | 31.25% | 0% | 25% |
| d25 | 25% | 31.25% | 25% | 0% | 18.75% |

仅当 schema 和证据有效、结果未迟到、非 abstain、至少两个维度已知且
`confidence_coverage >= 0.50` 时应用模型分。高风险证据有效且置信度不低于 0.7，且
本地风险表登记了证据类型、有效期和 veto 资格时，才允许本地映射 veto。
任何提高或降低该门禁都必须提升策略、prompt/schema 和缓存版本并重新执行第 15 节验证。

输出必须通过严格 schema，包含代码、维度分、结构化风险事实、证据引用、主审/挑战者
状态、请求/实际模型、thinking 模式、原始与校准置信度、证据 manifest 哈希、校准版本
和受控评级。缺失、越界、代码错配、证据错配或未知字段按规则拒绝或修复；修复重试也
计入物理请求。

## 12. 融合、动作与稳定排名

固定公式：

```text
final_score = clamp(
    local_score * 0.68
    + deepseek_score * 0.32
    - deepseek_risk_penalty,
    0,
    100,
)
```

`local_score` 已扣本地风险，融合时禁止再次扣 `local_risk_penalty`。所有输入使用十进制
确定性计算，最终以 `ROUND_HALF_UP` 保留两位小数。固定验收向量结果必须为 `83.40`。
未应用有效 hybrid 时（无复核、复核拒绝/弃权/迟到、覆盖率或已知维度不足，或当前模式
不是 hybrid），`final_score = local_score`，模型风险 penalty 不从分数扣除；已通过
schema、证据与本地规则映射的独立 veto 仍可保持更保守动作。
本地事实已经形成的 veto 与模型事实映射形成的 veto 使用逻辑 OR 合并；有无模型复核都不得覆盖、
清除或降级本地 veto。领域融合结果自身必须满足该不变量，调用方不得依赖二次补救。

生产排序固定为：`final_score` 降序、`local_score` 降序、股票代码升序。模型评级、
置信度、挑战状态和自由文本不得改变同分顺序。

本地评分完成后必须立即生成 local `ScoredDecision` 并尝试提交 `UnifiedDecisionIndex`，不能
等待 DeepSeek。复核结果随后只对未冻结、仍为 current 的同日 local 父版本生成 hybrid
`ScoredDecision`；两阶段必须有不同决策版本和 ETag，迟到结果不得覆盖冻结或更新版本。
失败、超时、预算耗尽或空响应保留已经发布的 local。`LongProjection` 不含评分阶段且不调用
DeepSeek。

活动动作阈值：

- today 09:36-10:30：`final_score >= 70` 可执行；
- today 10:30-11:20：`final_score >= 76` 可执行；
- tomorrow：`final_score >= 78` 可执行；
- d25：`final_score >= 76` 可执行；
- 距对应门槛 5 分以内为观察，其余不可执行。

可执行项还必须通过硬过滤、时间窗口、新鲜度、周期匹配且无 veto。Tomorrow/D25 的
`close_fallback` 使用各自正常门槛；Today 不允许 `close_fallback`。已有正式记录冻结后动作
不可改变。
旧动作和旧阈值只供带旧策略/引擎/schema 身份的冻结回放，不得成为活动默认值。

#### 15.1.1 研究身份、状态与生产隔离

Score-R0 研究身份固定为 `score_p0_v1`。一次研究决策必须同时绑定研究 spec、交易日、观察点、
`input_version`、生产 `decision_version`，以及数据、日历、规则、配置、策略、融合、schema、
引擎和统计版本；规范载荷生成 SHA-256，写入时钟、文件路径和执行顺序不得参与内容哈希。
研究状态固定为：

```text
draft -> extracted -> historical_rejected
                   -> historical_passed -> forward_collecting
                                        -> forward_rejected
                                        -> promotion_eligible
```

状态可以因证据不完整或门禁失败单向终止，不得把失败批次删除后重跑成成功。`promotion_eligible`
只表示满足研究门禁，不表示已上线；研究状态变化不得直接写活动策略配置、规则注册表、融合配置、
冻结记录或统一决策索引。

上述 `score_p0_v1` 状态机保留为首轮不可变档案；替代评价 `score_p0_v2` 使用相同单向状态机但独立
spec hash、日期、随机流、报告和前向仓储。两者之间禁止复制成功状态、父报告或前向日记录。

研究轨迹迁移到 V2 后只允许由已经提交的 `V2DecisionCommitted` 及其同批不可变研究审计投影形成，
observer 不得重新读取行情、重新评分或重新调用模型。研究审计至少包含完整点时股票池的有界身份、
资格和来源时间、硬拒绝聚合、硬过滤通过候选的板块和行业键、候选组件、缺失掩码、覆盖率、板块可靠度、生产候选分/排名/Top120 身份，
以及已进入完整评分集合股票的本地组件、风险、动作与跳过原因。研究审计使用独立哈希，不得改变
活动 `decision_hash`；身份变化必须显式升级研究 schema。

Score-R1-Migrate 新写入审计 schema 固定为 `v2_committed_research_audit_v2`，外层持久化 schema 为
`v2_research_committed_event_v2`；既有两个 v1 schema 只允许按原始载荷形状验证哈希并只读解析，不迁移、
不补写人口证据。每次成功提交分别保存 `production_local` 与 `research_shadow`：local 提交使用完全相同的
control copy 并保存一次完整点时人口，hybrid 提交只投影本批已存在且通过校验的结构化 facts 并引用相同
人口哈希；两者都不得重新执行评分。14:50 点时读取只接受同交易日、事件时间和 `input_observed_at` 均不晚于
截止点且含完整人口的 local 观察，迟到事件不能恢复计划日。外层规范载荷和内层审计各自计算独立 SHA-256，正式冻结重放缺少同批审计时
只保存通用事件，不伪造候选字段，也不得覆盖同 identity 已存在审计。研究链的 DeepSeek 物理 HTTP
请求增量必须为 0。

同输入的 hybrid 只允许引用当时已经存在且通过 schema/证据校验的结构化 facts；没有可复用
facts 时必须保存 local control 副本。研究链和所有挑战者的 DeepSeek 物理 HTTP 请求增量必须为 0。

#### 15.1.2 历史点时覆盖与两阶段裁剪

Score-R2 开始提取前必须先形成历史证据覆盖审计，逐日验证实际交易日历、三板点时总体、候选
摘要、日线、分钟线、共享前置因子窗口、公司行为处理、标签日后结算和全部来源时间。不得从当前
供应商响应反推历史时点，不得把标签日后形成的事实写回决策输入。主窗口缺失只能按第 15.1 节
已预注册的日期向前扩展；达到 2026-05-18 仍不足 40 个有效日时状态只能停在探索报告。

第一阶段读取完整点时股票池的有界身份/资格事实、硬拒绝聚合和硬过滤通过总体的紧凑组件；不得把
硬拒绝身份扩展为评分、收益或完整供应商载荷。第二阶段只为明确且排序唯一的保护集合读取完整字段；保护集合从活动每板 Top120 起步，
再加入任何仍可能进入研究 TopK 的上界候选。相同代码/交易日/分钟或共享窗口出现同身份不同内容
时整日失败，禁止按到达顺序选择。

一般评分组件的已知覆盖率和统一收缩分固定为：

```text
coverage = sum(known_weight)
known_weighted_mean = sum(known_weight * known_score) / coverage  # coverage > 0
coverage_shrunk_score = 50 + coverage * (known_weighted_mean - 50)
```

`coverage == 0` 时 `coverage_shrunk_score = 50`，但所有原始字段仍保持缺失；该公式等价于
`sum(known_weight * known_score) + (1 - coverage) * 50`。关键交易、可执行性、风险或下行保护
字段缺失仍按现有规则转观察或拒绝，不得用收缩公式绕过。该统一公式只属于
`coverage_shrink` 研究影子；通过完整晋级与生产发布前，`production_local` 继续使用当前活动
缺失策略。

组件值域固定为 `[0, 100]`，因此单个评分族的乐观组件上界固定为：

```text
optimistic_component_score = sum(known_weight * known_score) + sum(missing_weight * 100)
mandatory_known_local_risk_penalty = sum(confirmed_non_disappearing_local_risk_penalties)
local_upper_bound = clamp(optimistic_component_score
                          - mandatory_known_local_risk_penalty, 0, 100)
hybrid_upper_bound = clamp(local_upper_bound * 0.68
                           + recorded_deepseek_score * 0.32
                           - recorded_deepseek_risk_penalty, 0, 100)
```

上界假定未知一般组件取允许最大值，但不得假定已确认风险消失。`mandatory_known_local_risk_penalty`
只汇总在该点时身份下即使未知组件取最优值也仍然成立、且不会被字段补齐撤销的本地风险扣分；
可被后续合法证据解除的风险必须以状态分支分别计算上界，不能直接归零。硬过滤、关键缺失、veto、
`observe_only`、动作资格和集中度约束始终生效，不能通过分数上界绕过。有合法可复用 DeepSeek
facts 时，hybrid 上界使用既有 `deepseek_score` 和已验证模型风险扣分代入固定 68/32 公式；没有
facts 时 `hybrid_upper_bound = local_upper_bound`，不得假设一次新的模型满分。

候选召回保护使用约束感知 `active-set`，不得采用事后分差或固定多取若干只：

1. 先完整评分活动每板 Top120，并用正式池、观察池分离的生产选择器形成当前边界；
2. 按乐观最终分降序、代码升序检查未加载候选，判断其在最佳允许状态下能否穿过分数、板块
   60%、每行业最多 2 只、`unknown` 行业上限和 TopK 排序约束；
3. 仍可能进入任一池的最高上界候选加入完整字段集合，重新评分和选择；
4. 重复直到每个未加载候选都有 `upper_bound < constrained_selection_frontier` 的不可进入证明。

证明只保存候选研究身份、上界、边界、规则版本和哈希。任一上界无法复算、组件范围不成立或选择
约束无法证明时，该日召回审计无效，不得用估算值补齐。最终候选召回率按所有有效日的研究 oracle
TopK 微平均计算；证明排除项属于 oracle 已证实不可能入选的部分，而不是未观察样本。

Score-R2 的实现身份固定为 `score_r2_historical_v1`，分区 schema 固定为
`score_r2_partition_v1`。日期选择先按主窗口升序验证，主窗口无效日只允许从最近的前序实际
交易日向 `2026-05-18` 倒序补足，接纳达到 40 日即停止。每个未接纳日期必须保留结构化覆盖原因；
不足 40 日的顶层状态固定为 `exploratory`，不得删除失败日后把结果标记为 `extracted`。

active-set 以紧凑证据携带的每板生产 Top120 身份作为起始集，完整评分由后续回放注入的同一纯领域
评估器完成，提取器本身不得复制生产评分公式。未加载候选以其允许进入的正式池/观察池最佳状态
逐一代入 Top6、板块 60% 和每行业最多 2 只约束；能进入任一池者必须加入下一轮完整字段读取，
直到不再扩展。其余候选保存 `upper_bound < constrained_selection_frontier` 或约束阻止入选的
证明，证明绑定候选、池、上界、边界、规则版本和规范哈希。一般组件的缺失值只用于上界取 100，
不改写原始缺失；已有模型 facts 才应用固定 68/32 上界，没有 facts 时使用本地上界。

每个有效日写入独立不可变 Parquet 分区，至少分离日身份/覆盖、紧凑候选、完整候选、日线、
分钟线、共享复权窗口、结算和裁剪证明；同代码复权窗口只保存一份。manifest 按文件相对路径排序
保存字节数和 SHA-256，并再对规范 manifest 计算顶层 SHA-256。相同身份同内容重放幂等，不同内容冲突；
写入时钟、临时路径和执行顺序不得进入哈希。

Score-R3 的实现身份固定为 `score_r3_baseline_report_v1`。回放器不得复制活动过滤、评分、风险或
选择公式，只能通过 `HistoricalBaselineReplayEvaluator` 调用相同生产纯领域函数；该端口必须为
R2 完整评估集合逐股返回 production baseline 与 active-set oracle 两套排名。两套正式池分别校验
连续 Top6、单板最多 `ceil(6 * 60%)` 和每行业/`unknown` 最多 2 只；production 入选还必须属于
当日生产 Top120，oracle 用于衡量生产候选池是否召回同一纯领域评估器在受保护 active-set 上的
潜在 TopK，不修改生产名单或活动每板 120 上限。

日级 production baseline 组合在有正式选择时等权，合法 `no_decision` 固定为零暴露。报告必须直接
复用同一 `CostSettlementBasis`，分别计算 20bp、50bp、100bp 日组合净超额，同时报告平均
MAE/ATR20、`MAE/ATR20 <= -1.5` 的严重回撤率、候选召回率、一般最终组件已知权重的字段覆盖率、
板块/行业集中度、平均日内 Spearman Rank IC，以及五分组 20bp 净超额。候选召回率分母是 oracle
正式 TopK，分子是其中属于生产 Top120 的代码；oracle 为空时保持 `null`，不能伪造 100%。Rank IC
和五分组使用同一日全部有效评估候选及结算依据；有效配对少于 5 条时保持 `null`，不得补 0。

日级与汇总对象绑定 R2 extraction/day/input 哈希、production replay 版本、三档成本和报告 schema；
规范 JSON 生成 SHA-256，不包含写入时间、临时路径或执行顺序。冻结文件相同内容重放幂等，不同内容
冲突，文件或报告哈希篡改必须拒绝。只有 R2 恰好包含 40 个有效日时报告状态才可为 `replayed`；
不足 40 日只能生成 `exploratory` 报告并保留真实覆盖，不得宣称已经取得历史门禁或收益晋级证据。

#### 15.1.3 五个挑战者的唯一行为

五个挑战者都以 `production_local` 为唯一基线，使用相同硬过滤通过总体、点时输入、结算标签和
确定性平局键；每个变体拥有独立 `variant_version`，不得共享可变权重、阈值或缓存状态。

1. `continuous_entry`：只改变 tomorrow/d25 缩量回踩和放量突破的研究形态值。两种形态分别
   使用自己的必需字段；每个布尔边界改为以当前生产阈值为中心的预注册分段线性 `[0,100]`
   隶属分，单个形态取其必需条件子分的最小值，两种形态取最大值。各字段过渡宽度和端点必须
   在读取任何收益前以表格签入本文及机器契约；关键字段缺失仍转观察。
2. `coverage_shrink`：所有允许中性缺失的一般组件统一使用第 15.1.2 节的向 50 分收缩公式；
   不改变硬过滤、关键字段缺失、风险 veto 或下行保护。
3. `candidate_upper_bound`：只在研究影子中使用 active-set 扩展完整评分保护集合；活动 50 分、

#### 15.1.4 同日同股收益与每日组合口径

主评价策略固定为 tomorrow，主标签继续使用 14:50 决策锚点至下一有效交易日收盘相对全市场
等权基准的收益。每个基线/挑战者以硬过滤通过候选并集形成同日同股贡献配对；挑战者和基线
未选中股票的组合权重为 0，不能因为两边名单不同而删除股票。全部输入、决策和结算有效但组合
没有正式选择时，记录合法 `no_decision` 和零暴露，该交易日仍作为有效日保留在日序列中。

若生产策略没有其它已签入的仓位权重，正式选择在各自组合内等权。每只股票在成本 `c` 下的贡献为：

```text
stock_net_contribution(c) = selected_weight * gross_excess_return
                            - selected_weight * turnover * c
daily_portfolio_difference(c) = sum(challenger_contribution(c) - baseline_contribution(c))
```

其中 `c` 分别为 `0.0020`、`0.0050`、`0.0100`，`gross_excess_return` 和 `turnover` 必须直接复用
同一 `CostSettlementBasis`，不得在报告层重新选择价格或换手定义。停牌、价格不连续、公司行为
无法可靠排除或标签不完整时保持 `insufficient_data`；历史阶段按预注册日期扩展规则决定整日是否
有效，前向阶段保留失败日期且不得替换。

严重回撤、个股贡献、板块贡献、集中度和 Rank IC 都从同一同日同股表派生。分数组固定为每个
有效交易日按最终分平均秩切成五个尽量等大的组，代码升序处理剩余和完全并列；少于 5 个有效
评分股票的日期不进入分组与 Rank IC，但仍进入组合收益。Spearman 使用平均秩，日内有效配对少于
5 条时该日 Rank IC 缺失且不得补 0。

#### 15.1.5 配对移动区块 bootstrap 与多重检验

统计输入是按交易日升序排列的 `daily_portfolio_difference(20bp)`。区块长度为 `b` 时，从原序列
枚举所有长度为 `b` 的非循环连续区块；使用该变体和 `b` 的独立种子有放回抽取区块，按抽取顺序
拼接并截断到原交易日数。样本日数小于 `b` 时该敏感性结果无效，不得改用循环区块或缩短区块。

每个变体/区块固定生成 10,000 个配对重采样均值。95% 区间采用未中心化配对分布的 2.5% 和
97.5% 最近秩分位；主要单侧 p 值在保持日序和区块结构的前提下先将日差减去原样本均值，再对
零假设分布重采样，固定为：

```text
p_value = (extreme_count + 1) / (10000 + 1)
```

其中 `extreme_count` 为零假设重采样均值不小于原观察均值的次数。五个挑战者的 20bp、5 日主
区块 p 值构成固定家族，按 p 值升序、`variant_id` 升序稳定执行 Holm step-down，家族大小始终
为 5。第 `i` 个有序 p 值只在 `p_i <= 0.05 / (5 - i + 1)` 时拒绝原假设，首个不满足项及其后
全部停止拒绝；历史失败或未进入前向的变体不能通过缩小家族获得优势。晋级同时要求 Holm 校正
通过且未中心化 95% 置信下界大于 0。3/10 日区块、50/100bp、其它指标和消融只报告，不新建
检验族。

严重回撤率差使用相同交易日区块和配对索引报告区间，门禁点估计不得高于基线。删除最佳月份
时先按上海交易日月份汇总挑战者相对基线贡献，再删除正贡献最大的月份；删除最佳板块时按股票
活动板块汇总贡献并删除正贡献最大的板块。没有正贡献组时仍执行并明确记录 `no_positive_group`。

集中度分母是全部正向同日同股超额贡献之和；非正贡献不进入分母。单股占比必须不高于 10%，
按占比降序、代码升序的前五只合计不高于 30%。最高分组净超额必须高于最低分组，平均有效日
Spearman Rank IC 必须大于 0；若最高分组相对最低分组的严重回撤率差在 5 日配对区块 95% 置信
下界大于 0，则视为高分区持续出现更高严重回撤并拒绝晋级。

#### 15.1.6 历史门禁、固定前向封存与完成定义

历史报告必须单独输出 40 日窗口结果和全部失败身份。只有满足全部历史门禁的冻结变体才能进入
`forward_collecting`；进入时绑定相同变体、数据 schema、规则、配置、策略、融合、统计和报告
版本，禁止回看历史收益改参数。

前向 collector 对 2026-11-02（含）至 2026-11-27（含）的每个计划交易日只允许形成一条
`valid`、`failed` 或 `no_decision` 日记录。同一日期相同内容重放幂等，不同内容冲突；服务停机、
数据失败、空选择和零收益必须保持各自真实身份。仅当输入、决策和结算均完整时，`no_decision`
才是有效零暴露日；否则必须记为 `failed`。实现可以将统计引擎、collector 和最终封存拆为独立
工程批次，但不得因实现了 collector 就宣称前向证据完成。

最终封存必须等最后计划日的 T+1 标签完成，且 20 个计划交易日均有有效日证据、总计至少 300 条
可结算同日同股配对、前向至少 100 条。任何计划日无效、身份冲突、参数变化或样本不足都转为
`forward_rejected`；不得向前后顺延、补抓后来数据、删除亏损日或以历史日替换。最终报告分别
列出历史、前向和 40+20 合并结果，并重新按固定五变体家族执行全部晋级门禁。

Score-R5 的实现身份固定为 `score_r5_statistical_gate_v1`，统计版本固定为
`score_r5_paired_mbb_holm_v1`，前向记录 schema 固定为 `score_r5_forward_day_v1`，最终报告
schema 固定为 `score_r5_final_report_v1`。历史统计器以 R3/R4 哈希和 R4 冻结参数 manifest 为
父身份；只要历史日数不是恰好 40、同日同股总数不足 300 或任一固定门禁无有效证据，该变体就以
结构化失败原因终止为 `historical_rejected`，不得进入 collector。

统计器分别保留 local-only 相对 production、hybrid 相对 production，以及 hybrid 相对 local-only
的日序列。五变体 local-only 的 20bp、5 日区块单侧 p 值构成固定 Holm 家族；结构变体的历史资格
以 local-only 全部门禁为准，hybrid 只有另行证明相对 local-only 的 20bp、5 日区块未中心化区间
下界大于 0 且单侧 p 值不高于 0.05 时才标记独立增益。50bp、100bp、3 日和 10 日结果只报告。

前向记录键固定为 `variant_id + planned_trade_date`，并绑定历史门禁哈希、R4 变体/参数、数据
schema、规则、配置、策略、融合、统计和报告版本。collector 只接受固定 20 日集合中的日期和
`historical_passed` 变体；不可变 JSON 中同键同内容重放幂等、不同内容冲突。`failed` 记录不携带
伪造日回放；`valid` 与 `no_decision` 必须携带完整同日同股结算，且 `no_decision` 的挑战者权重为
零。最终封存对历史、前向及合并序列重新计算同一固定五变体家族；真实证据尚未到齐时只能返回
`forward_collecting` 或 `forward_rejected`，不得生成伪 `promotion_eligible`。

#### 15.1.7 第二轮权重、风险与门槛研究

Score-R6 的回顾性候选搜索可在 `score_h0_v1` 固定归档覆盖门禁通过后建立，不等待 Score-R0 的未来
40 日观察。开始前必须固定候选网格、目标函数、训练/验证切分和确定性平局规则；验证集只能评价
训练集选出的冻结候选，不得回看改参。任何候选取得生产晋级资格前，仍必须创建新的前向研究身份和
日期窗口。Score-R6 不得
复用 Score-R0 的 40+20 评价窗口，也不得把前向结果重新当训练集。

候选权重必须非负且精确合计 1，并通过下式向当前生产权重收缩：

```text
weight(lambda) = (1 - lambda) * current_weight + lambda * candidate_weight
```

`candidate_weight` 位于同一组件单纯形，`lambda` 候选集合、正则强度和每组件最大偏移必须在新
窗口结果可见前预注册。板块有效样本低于预注册下限时只能回退全局候选权重，不得独立拟合小板。
78 分动作门槛和 3/4/5 分风险扣分只能从预注册有限集合联合评价，仍需同时满足净超额、严重回撤、
换手、召回、稳定性和集中度门禁。

hybrid 相对 local-only 使用同日同股和相同组合口径另做增量检验；未证明独立增益时，结构挑战者
即使通过也只能晋级 local，活动融合继续保持当前 68/32 行为而不扩大模型作用。

Score-R6 工程身份固定为 `score_r6_historical_v1`，历史代理组件固定为 H0 可可靠重建的
`momentum/stability/liquidity`，当前代理权重固定为 50%/30%/20%。候选单纯形步长为 10%，目标
固定为 50/30/20、70/20/10、30/60/10、30/20/50 和 40/40/20 五组，收缩
`lambda` 固定为 0/25%/50%，每组件相对当前代理权重的最大偏移为 15%，L1 正则强度固定为 0.15；
联合网格门槛固定为 76/78/80，风险扣分固定为 3/4/5。历史风险只允许使用 20 日收益波动率不低于
4% 的可重建高波动事实；公司风险、尾盘结构和 DeepSeek facts 继续标记 `not_reconstructed`，不得按
零风险参与筛选。训练目标同时包含 20bp 后 5 日净超额、严重损失、持仓换手、日收益稳定性、oracle
召回和权重偏移正则，固定为
`net_excess - 2.0 * severe_rate - 0.05 * turnover - 0.25 * daily_excess_stddev + 0.10 * recall - 0.15 * L1_offset`；
按目标值、权重偏移、距 78 门槛、距 4 分扣分及候选哈希确定性平局。
历史候选同时保留单纯形目标和 `lambda`，不能把 50/30/20 代理权重直接发布。冻结时把同一目标与
`lambda` 分别应用到三板当前 production 权重：momentum 对应 trend、stability 对应 stability、
liquidity 对应 turnover_flow；尾盘、市场状态和入场质量保持当前权重不变，可重建三组件的板内总
权重也保持不变。生成的三板六组件权重必须各自非负、以万分单位精确合计 10000，且任一生产组件
相对当前权重偏移仍不得超过 15%，否则该候选在结果可见前即从固定网格排除。

全局训练和验证分别至少 100 个有效日、候选至少 80 个有选择日；单板训练至少 5000 个股日且至少
100 个有效日才允许独立拟合，否则绑定全局候选。验证段只评价训练段冻结结果，并相对当前 50/30/20、
78 门槛、4 分高波动扣分基线同时检查净超额、严重损失、换手、稳定性、召回、单股正贡献集中度和
板块集中度。冻结候选相对基线允许的单侧容差依次固定为净超额/召回不得低于基线 0/2 个百分点，
严重损失率、换手、稳定性标准差、单股正贡献集中度和板块集中度不得高于基线 1/5/5/5/5 个百分点。
历史报告固定无生产晋级权限，并以 `score_r6_historical_report_v1` 封存。

只有历史门禁通过后才能创建 `score_r6_forward_*` 身份：在注册日固定恰好 20 个随后日期，且不得与

5 日非循环配对区块 bootstrap 执行 10000 次；固定 95% 区间下界必须大于 0 且单侧 p 值不高于
0.05，否则报告的生产范围固定为 `local_only`。这些资格只供 Score-R7 人工档案使用，R6 不写活动配置。

`ROUND_HALF_UP`。模型输入不足 61 个 qfq 交易日、金额无效或任一必需字段缺失时，该股票固定为
`production_model_features_missing` 且不评分，禁止暗中回退旧 Tomorrow 启发式分。

这一人工越权发布保留以下已知差异与风险：历史训练/验证使用完整 H0 日线横截面和收盘输入，在线使用
现行 Top120 候选横截面和点时价格；历史严重亏损率 15.9472% 高于代理 8.2734%，换手增加 56.2350 个
百分点，Q5-Q1 为负。它们进入状态 API 和发布剩余风险，不能改写为“历史通过”。78/73 门槛、Top6、
每行业最多 2 只、单板最多 60%、硬过滤、冻结和 DeepSeek 预算均不因本次切换降低。

上线后的 20 个未来交易日不参与当天评分，也不阻塞启动。交易日运行时，现有 15:00 后后台结算器自动
对已冻结 Tomorrow 正式项采集 T+1 收盘、20bp 后净超额、MAE/ATR20 和严重回撤并不可变写入 outcome
库；状态 API 公开 `monitoring_mode=automatic_t1_outcome_settlement`。该数据用于后续人工复核和另立研究
版本，不允许自动调权、重训、晋级、回切或覆盖冻结结果。当前 V2 不含逐股严重亏损概率头，Web 不得用
历史总体严重亏损率伪造个股“亏损概率”，状态固定 `loss_probability_status=not_modeled`；Web 可以展示
评分版本、V2 信号分、预测超额、估算成本、预测成本后净超额和模型分歧。评分版本必须读取决策绑定的
`input_versions.score_model`，不能用活动策略标签冒充模型身份。

#### 15.1.18 V1/V2 生产评分配置切换

2026-08-30 用户进一步要求把两个生产评分档位做成可配置策略，并授权按已说明方案选择残差动量作为
人工 V1。策略配置 schema 15 的 `tomorrow_scoring_profile` 只接受 `v1` 或 `v2`，默认 `v1`；旧值
`p1|p2` 必须失败关闭，不保留兼容别名。配置内容参与
`strategy_sha256_*`，切换必须重启进程；组合根只创建一个 Tomorrow 评分服务，不保留并行评分、热切换、
隐藏回退或双状态源。所选模型 ID/hash 写入 `input_versions.score_model`，因此另一 profile 不能覆盖既有
冻结记录；同日已有正式记录继续遵守 first-wins 和冻结恢复规则。

`v1` 明确映射到独立人工代理 `v1_manual_residual_momentum_v1`，不是原 P1 研究身份的晋级工件。它只读 H0
`score_h0_v1` 训练段 2024-07-01 至 2025-12-31 的 1,765,685 行，用与在线链一致的日线可重建
`h0_board_amount_residual_momentum_proxy_v1`：20/40/60 日 skip-5 动量扣除同日市场、板块及板内对数
20 日平均成交额线性暴露，再用固定 ridge `1e-3` 拟合下一日全市场等权超额。包内线性工件的规范化内容身份 SHA-256 固定为
`4291ea514c233a14ab6f9262e72ea541d1e9a794e73d02f10f8220509f6f502b`，启动时必须同时校验 profile、模型、
特征、H0 规范、manifest、schema 和完整 hash。状态固定公开 `historical_status=historical_unavailable`、
`original_five_candidate_research_artifact_unavailable` 和
`manual_daily_proxy_not_original_research_evidence`，不得误报原 P1 通过。

`v2` 继续映射 `daily_reconstructible_ensemble_v1` 及第 15.1.17 节工件、历史拒绝原因和人工越权边界。
两种 profile 共用 20bp Amihud 成本、正净效用横截面 0–100 映射、本地风险只扣一次、固定 68/32 融合、
78/73 门槛、Top6、集中度、DeepSeek 预算、14:50 冻结和 T+1 后台结算；V1 线性模型的模型分歧固定为 0，
两者都没有逐股亏损概率头。Web 统一显示“模型信号分”和决策绑定的真实模型版本，不用 V1/V2 标签代替
模型 ID/hash。任一包内资源缺失、篡改、字段宽度或 hash 不一致都拒绝启动，禁止回退旧 Tomorrow 分。

这里的 V1/V2 只表示活动生产档位，不重命名不可变的历史研究身份与封存字段。原
`score_tomorrow_shadow_p1_v1`、`score_tomorrow_historical_p2_v1`、P2 报告 schema、`p2_*` 工件输入字段
继续按原名只读，以保证既有规范、报告和模型 hash 可复核；它们不能再作为配置值或公开活动
`profile_id`。新冻结记录只写 V1/V2 及实际模型 ID/hash，既有冻结记录保持原始身份且不得回写。

#### 15.1.19 V1/V2 差异、收益证据和未完成任务

两种生产评分都在相同硬过滤后的 Tomorrow 候选上只替换本地 `base_score`；其后的本地风险、固定 68/32
融合、78/73 动作门槛、Top6、行业/板块集中度、DeepSeek 预算、14:50 冻结及 T+1 结算完全相同。
差异固定如下：

| 维度 | V1 | V2 |
|---|---|---|
| 模型 | 三因子 ridge 线性代理 | 六因子 ridge/LightGBM 各 50% 集成 |
| Alpha | 20/40/60 日 skip-5 残差动量 | 1/3/5 日收益与同组三个残差动量 |
| 成本与分数 | 扣 20bp Amihud 成本后按正净效用横截面映射 0–100 | 同左 |
| 模型分歧 | 单模型，固定为 0 | ridge 与 LightGBM 预测差绝对值 |
| 历史证据 | 只在 H0 训练段拟合，尚无该生产代理的独立留出结果 | 有 139 日、678,370 条验证配对，但被三项风险/排序门禁拒绝 |
| 主要特点 | 结构简单、输入较少、可解释，但证据最弱 | 平均收益信号证据较多，但换手和严重亏损风险明显更高 |

关于“哪个荐股更能挣钱”，当前唯一诚实结论是：尚不能认定 V1 或 V2 是可重复的未来收益胜者。V2 相对
H0 历史代理在 20/50/100bp 下的平均成本后净增量均为正，且 20bp 区块 bootstrap 下界为正，因此
V2 的平均成本后净增量证据强于 V1；但它同时出现严重亏损率 15.9472% 对 8.2734%、换手增加
56.2350 个百分点及 Q5-Q1 为负，已被预先固定的门禁拒绝。V1 没有独立样本外结果。故不能据此断言
V2 未来更能挣钱，也不能因为 V1 更简单就宣称 V1 风险调整后更优。默认 V1 仅表示用户指定的日常选择，
不表示收益保证或研究晋级。

**V1 未完成任务**：

1. 用与 V2 完全相同的 H0 验证日期、候选代理、成本和门禁补做一次只读独立留出评估；训练段不得重拟合
   或调参，结果无生产写权限；这项评估立即使用既有冻结历史证据，不等待新的未来交易日。
2. 当前人工 V1 不是原 P1 五候选研究胜者；原 `score_tomorrow_shadow_p1_v1` 的 2027 日历、40+20
   日期和唯一工件缺口只属于该历史研究身份，不是当前 V1 留出评估、配对采集或改进研究的前置条件，
   也不得借其名称替 V1 背书。
3. 单一线性头没有模型分歧，也没有逐股严重亏损概率；若要提供这两项，必须另立 V1.x 模型、校准数据、
   schema 和发布批次，不能把固定 0 或总体亏损率伪造成逐股指标。

**V2 未完成任务**：

1. 既有 P2 历史路线已经 `historical_rejected`，P2-2/P2-3 不是待办而是禁止继续的终止分支；不能放宽
   失败门槛、覆盖原报告或重新解释为通过。
2. 若要降低换手、严重亏损和分组不单调，必须另立 V2.x 挑战者和研究身份，在未读取新验证收益前冻结
   风险目标、成本、特征和停止条件，再做回顾筛选；不得在线修改现有 V2 工件。
3. V2 仍缺逐股严重亏损概率的独立标签定义、概率校准和可靠性检验；完成前 Web 保持
   `loss_probability_status=not_modeled`。

**共同未完成任务**：

1. 实现无生产写权限的配对影子比较器：每日在同日、同股、同一冻结输入上计算 V1/V2，保存两套预测、
   成本、排序和选择状态，但只让配置选中的档位进入风险、DeepSeek、动作和冻结，不增加 DeepSeek 请求。
2. 给配对结果补 T+1 标签并形成不可变 manifest。现有活动档位单边 T+1 结算存在选择偏差，因为它只看
   已入选股票，不能用于判定未活动档位或未入选样本谁更优。
3. 在首个比较标签可见前，使用冻结历史日级收益差、最小有经济意义的净超额、显著性和目标统计功效
   预注册所需独立交易日与最小配对量，同时冻结 20bp 主成本及 50/100bp 敏感性、配对区块 bootstrap、
   净超额、严重亏损、换手、集中度、Rank IC、Q5-Q1 和多重检验规则。前向采集只用于后来
   的无后见证据，不阻塞当前评分，也不参与当天分数；同日多股只能增加横截面诊断样本，不能冒充多个
   独立交易日。
4. 证据满足预注册门禁后生成 `production_authority=false` 的人工审查档案。任何默认档位、模型、API/Web
   字段或冻结行为变化都必须另立高风险发布批次；后台不得自动切换活动档位。
5. 配对影子与 T+1/对应持有期结算必须覆盖全部共同可评分候选，不能只保存活动档位最终入选项；正式
   推荐为 0 仍应产生预测、排序、成本和后续标签。报告必须同时给出全候选与最终组合两层结果，避免
   选择偏差并直接服务于提高风险约束、成本后荐股收益的目标。

推荐完成顺序固定为“V1 同口径历史留出 → 配对规范冻结 → 影子比较器与存储 → 从首个 T+1 标签起持续
结算与报告 → 达到预注册统计功效后形成人工审查档案 → 如确有胜者再独立发布”。固定 20 个未来交易日不是
开始历史留出、实现比较器、采集配对预测或研究挑战者的前置条件；正式推荐为 0 也不能停止全候选预测与
标签。最终生产切换所需独立日期数由标签可见前冻结的统计功效规范决定，不按页面非空日累计，也不能因
服务失败挑日替换。前向日期后来成为历史数据的意义，是规则在结果出现前已经锁定，从而排除看完收益再
挑日期、模型或阈值，而不是让未来数据反向影响今天的评分。

#### 15.1.20 运行档位与研究组合命令

评分档位是单进程启动参数，不是盘中热切换。`./run.sh`、`./run.sh serve` 和未指定档位的组合命令均
使用 V1；`./run.sh --profile v2`、`./run.sh serve --profile v2` 或任一公开组合命令追加
`--profile v2` 才使用 V2。启动参数形成只在本进程生效的类型化配置覆盖，不写回 `strategy.json`；覆盖后
重新计算有效策略 SHA-256，并由新决策绑定实际模型 ID/hash。进程内不得同时保留两套活动评分源，档位
改变必须正常重启，且不能覆盖既有正式/冻结记录。

公开 `run.sh` 研究入口收敛为三条固定流程：`check` 顺序执行配置校验、研究状态和所选档位性能门禁；
`research-history` 顺序执行历史归档下载/续传和固定回测；`research-screen` 顺序执行 R6 历史筛选、R6
日线筛选、R6 稳定性诊断及 Tomorrow P2 历史筛选。每个阶段仍保留独立 `trader-cli` 命令供自动测试和
故障定位，但不再作为 `run.sh` 公开入口。组合器对普通非零门禁结果继续执行剩余阶段，最终输出包含每段
退出码的 `trader_command_group_v1` 汇总并返回非零；配置无效、工件冲突引发的未处理异常等操作性故障
仍立即失败关闭。

`--profile` 对生产启动、配置校验和性能门禁生效；历史下载、回测和不可变筛选本身继续绑定各自冻结的
H0/R6/P2 研究身份，不因 V1/V2 参数改名、重算或覆盖工件。这样统一参数表面不会把活动生产档位误作
历史研究版本，也不会让离线研究结果反向改变当前分数。

### 15.2 活动发布门禁

自动验证至少覆盖：

- 三板识别、冲突、上市第 1/5/6 日和主板 8.00/8.01、成长板 16.00/16.01；
- 行业、同行和竞争组字段变更不改变候选分、本地分、DeepSeek 分、动作或下行保护；
- 2.5%/97.5% 截尾、板内至少 100、最多 5 日回退和跨板隔离；
- 九组候选权重、九组本地权重不仅精确合计 1.0，而且逐项等于本文固定向量；50 分、30%、120 只、
  0.85 边界；配置校验同时固定模型覆盖率 0.50、至少两个计分维度已知和观察余量 5；
- 换手和成交带通边界、缺失分母、d25 无双乘；
- ATR、缩量回踩、放量突破、单纯过热可执行和五类下行保护边界；
- 本地风险去重、上限、六类 V4 模型风险对全部严重度的本地规则映射、模型事实校验和禁止自由文本扣分；
- 168 物理请求、并发原子预留、失败/重试计数、14:48 截止和跨策略共享；
- 固定融合 `83.40`、ROUND_HALF_UP、排序键、TopK 60%、单行业/`unknown` 最多 2；
- 正式/观察分池分别执行行业上限，观察不挤占正式 TopK；
- local 先发布、hybrid 通过按策略隔离的 latest-wins 复核 lane 异步升级、慢复核不阻塞更新的 local，
  hybrid 以不同身份重发布、复核失败保留 local、冻结或更新序列拒绝迟到 hybrid；
- 严重公司风险永久/90 日/三自然年边界、官方证据约束、注册表降级和旧命中保留；
- 结果结算幂等和无未来数据；
- 冻结前后竞态、旧版本回放、哈希一致性和 long 不持久化。

性能门禁使用固定 360 候选：单板预选 P95 不超过 250ms、单板单策略评分 250ms、单板
三策略 750ms、三板三策略墙钟 1000ms、360 只全局稳定选择 100ms。线程并行只能宣称
失败域隔离和绝对预算通过；若实际加速比未大于 1，不得宣称 CPU 计算加速。
板内评分性能样本必须传入独立全市场总体和有界候选集合，断言评分回调只接收候选代码；
用全市场集合完成评分后再按候选代码过滤不属于合格实现。

任何候选权重、评分权重、硬过滤、风险映射、动作门槛、TopK、模型路由或融合变化，
必须先更新本文、提升相应版本并通过点时样本外验证。验证需按交易日切分，计入 T+1、
停牌、涨跌停、费用和滑点，预注册指标并控制多重检验；未取得真实前瞻交易日证据时，
只能描述结构、可靠性或性能改善，不能声称收益提高。

## 16. 明确不采用的策略

- 不让 DeepSeek 自由文本、评级或置信度直接改变分数、风险、动作或排名。
- 不由 DeepSeek 新增候选、绕过硬过滤或选择方向。
- 不进行运行时自动调权、自动晋级、在线学习或看完结果后切换动量/反转。
- 不引入多智能体生产编排、第三方项目的交易结论、券商连接或真实下单。
- 不把 `flow_proxy` 解释为不可验证的主力或机构资金。
- 不把历史回测、研究审计或社区 Star 当作生产收益证据。
- 不为补满 TopK 放宽质量门，不把缺失值伪装成 0 或真实中性观测。

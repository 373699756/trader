# 下载、训练与回溯

本文是下载、历史数据、独立 qfq 短窗口、训练工件及离线回溯工程的唯一权威。
评分、过滤、收益口径和研究准入规则见[评分逻辑](1_评分逻辑.md)，全局架构、资源、API/Web和发布见[工程设计](2_工程设计.md)，实际验证与未完成项只见[工程实施](3_工程实施.md)。

## 1. 离线入口与消费者

| 入口 | 输入与职责 | 输出与消费者 |
| --- | --- | --- |
| `./run.sh sync` | 一次官方总体与ST准备，顺序同步market和company | 分项结果及最终汇总 |
| `./run.sh train` | 官方名单与ST核验；Tencent日历/价格对、BaoStock行业；历史验收后联合训练或复用工件 | 发布history与V2/V3独立双头工件 |
| `./run.sh sync market` | 独立名单与ST核验、Tencent日历和同源滚动短窗口 | `data/market/daily_window.sqlite3`；推荐只读 |
| `./run.sh sync company` | ST资格、近一年公告、财务、质押、解禁及候选新闻；页级增量续传 | `data/company/evidence.sqlite3`；推荐只读 |

日常入口为`sync [market|company]`与`train`，不接受路径或profile参数。旧人工下载命令与check删除，不保留别名；PowerShell保持一致。机器入口`trader-cli sync history`只维护历史，模板同步，真实系统任务重新安装另行授权。sync按market、company顺序各自提交并报告，单项失败继续；取消、配置无效或公共准备失败停止。同波次只准备一次官方总体和ST证据，各项仍保留各自窗口及完整性判断。stdout仅最终JSON，stderr为进度；退出码0/1/2/130分别表示完成、失败或待补、参数/配置错误、取消。

随Tushare估值/财务增强退役，同步删除`cache.json`中的`daily_valuation_financials`配置项；使用自定义配置副本时也须移除此项。历史子阶段保留`download`日志标签，该标签不代表可单独调用的CLI命令。

`train`由组合根在同一进程串联历史维护与双档训练；历史维护失败或参考数据不完整立即返回失败。已发布快照仍有价格缺口时明确报告并继续尝试训练，缺失或非正价格不进入有效样本；各档按训练切分的有效日期和样本门禁决定能否发布，不因其他股票的缺口整体阻断。V2保留1000拟合日/251日特征窗的LightGBM，V3保留750拟合日/61日特征窗的Ridge；联合扫描一次价格行，分别构建样本、拟合与原子发布。各档仍有Tomorrow/D25两个头。

```text
train -> ST资格 -> 历史维护/完整性 -> 双档工件校验 -> 复用或联合训练
                       已发布history -> 隔离研究、回溯与结算
sync market -> ST资格 -> 独立短窗口 -> 推荐内存投影
sync company -> ST资格 -> 公司资料单库 -> 推荐只读风险与财务特征
已加载模型 + 推荐内存投影 -> 本地证据质量分、模型成本门与风险动作 -> 只读API/Web
```

各业务保留独立维护锁和发布状态；qfq不依赖history或完整历史下载顺序。训练需要历史维护的合法发布结果，推荐模型推理需要匹配的模型和本档短窗口。
全新克隆可直接启动看板；history、qfq或所选档位模型缺失时输出警告，不自动触发历史下载或训练。
缺少双头模型时该档模型评分保持未就绪；补齐训练工件后需正常重启。qfq仍由既有后台观察器接纳。
完整 `history` 不直接进入盘中评分线程：它训练出的每策略模型头读取本档 qfq 在线特征，输出扣成本前预测超额、相对信号诊断和成本后净效用门。预测净效用不大于 0 时不能进入观察池或正式池，但预测值、训练指标和模型相对分不加进 `final_score`。独立 qfq 的真实成交日线同时供已配置的本地历史因子和在线模型特征使用；模型字段不足时逐股 `data_pending`，不以短窗口长度不足否定 Tencent 已成功返回的数据。DeepSeek 可选复核只影响证据核验后的风险 veto，最终数值分仍为扣一次本地风险的 `local_score`。评分准入和具体因子权重以评分逻辑为准。
流程接通不证明历史点时一致或收益提高；当前名单和截至下载日的ever-ST排除存在选择偏差。

## 2. 数据、资格与资源所有权

| 数据/资源 | 唯一owner | 使用边界 |
| --- | --- | --- |
| `data/market/reference/historical_st.sqlite3` | download公开曾用名适配器 | history、qfq及sync company按同一规则刷新，sync共用一次准备；训练消费发布总体，推荐消费已发布qfq总体 |
| `data/market/reference/industry.sqlite3` | 跨业务日期查询证据；download写历史锚点的`queries`表，recommendation仅在当前引用满7日时写同库`current_industry_queries`表 | 两表共用摘要校验与日期语义，互不覆盖；推荐读取最近有效查询，训练仍只读catalog中已发布快照绑定的参考记录 |
| `data/market/history/catalog.sqlite3` | download控制与发布 | 日历、证券、任务日期、缺口、尝试、序号、snapshot及active指针；bound_references按内容摘要保存绑定参考，与指针同事务发布 |
| `data/market/history/prices_YYYY.sqlite3` | download正式年库 | 结构化价格对、缺失状态及观察序号；训练/研究通过只读快照接口消费 |
| `data/market/daily_window.sqlite3` | download短窗口维护 | 推荐只读，不复制完整history或参考数据 |
| `data/training/models/{v2,v3}/` | training | 每头model.json与metadata.json，整档双头发布；推荐只读加载 |
| `data/company/evidence.sqlite3` | download公司证据 | 手工sync company与09:15/12:45后台共用写入者、事务断点和发布投影；recommendation只读 |

其余持久路径：`data/training/samples/{v2,v3}/{samples.sqlite3,complete.json}`；`data/company/eligibility.sqlite3`；`data/recommendation/{v2,v3}/{decisions.sqlite3,snapshots.sqlite3}`；`data/recommendation/shared/deepseek_budget.sqlite3`；`data/research/{v2,v3}/{outcomes.sqlite3,traces/YYYY-MM-DD.sqlite3,experiments/<研究身份>/}`。日历跨档位共享`data/market/reference/trading_calendar.json`。资格事实与发布身份同库，正式冻结保留原字节和first-wins；预算与发布序号迁移不得归零。`.runtime`只保留服务锁、日志和临时产物，数据锁紧邻数据，模型锁位于整档替换目录之外。

所有下载命令先取得官方证券总体，再查询ST资格并过滤，之后才查询日历、行业、价格、公司研究或巨潮公告。`train`与已安装history周维护复用完整下载链，后台qfq复用独立qfq链。当前官方简称带ST时直接记为ever-ST并排除，不请求该股曾用名或其它业务数据；该事实优先于同日clear缓存。曾ST永久排除；clear仅复用当前上海检查日（不使用旧批次价格截止日）；缺失、过期及未知资格通过同一公开曾用名源补查，查询失败的未知股票不进入下载，全部不合格时停止业务下载。
证据损坏不得清空永久排除后继续。ST检查按最多8只滚动在途，每64只或收尾时短锁合并并原子保存；网络请求不持文件锁。
同日并发未知证据保守合并，ever-ST优先。日志分别显示官方总数、合格数、曾ST排除及未知排除，价格下载分母使用合格数。
qfq在维护锁内移除已排除代码的旧派生窗口；history保留物理旧行，但当前快照总体不再公开这些代码。

`./run.sh sync company` 是唯一公司资料入口，先复用/更新ST资格再下载公司证据。全新数据库不兼容、不读取或迁移旧风险库；程序不删除旧数据。只保留一个 `data/company/evidence.sqlite3`，不再分成当前/历史库后合并。共享进程锁保护手工和后台写入；缺失文件可以创建，非本合同数据库失败关闭。

- 公告与风险：首次建立最近365天发行人披露基线，按市场/固定日期分页、过大片二分；默认排序与30条分页，拒绝重复/截断/总数漂移。后续仅新增日期、失败页、最近7天重叠，以及每天轮巡一个旧月修订检查。已下载正文在元数据未改变时复用，不每次重下载。
- 新闻：最近7天、每股最多50条，仅当前或最近有效候选/备选；无候选冷启动不下载全市场新闻，不阻塞必要资料发布。
- 财务：批量取得最新正式报告与对比报告期，最长550天报告期范围；以后按披露时间增量并回看7天。不是把财报套用新闻窗口或下载上市以来所有报表。
- 质押与解禁：最新完整市场质押快照、未来90天解禁；整批完成后替换，失败不清空上一有效值。

首次与增量共用入口，进程重启读取每片首个未提交页，不重下完成基线。事实和页游标同一FULL事务提交，WAL允许推荐并行只读；短事务及唯一键控制写放大。规范数值列负责更新，逐股已发布投影负责低成本读取；投影在同一事务发布，不做全库复制。疑似风险标题只作为正文筛选，不能仅靠标题确认硬风险；正文核验受大小/页数/时间限制，失败明确未知。调查不再保留结束后三年、公司违法不再永久排除；当前判断只覆盖一年，旧冻结证据不改写，详见评分逻辑4.3。

单次请求最多8秒，巨潮请求间隔至少1秒。巨潮公告页与正文下载遇到传输超时、连接失败或HTTP 408/500/502/503/504时，同一请求最多3次物理尝试，两次重试分别等待2秒、4秒；等待与每次请求均受原阶段截止和取消约束，成功后继续当前页流程，不重复提交已保存页。403/429、其它HTTP错误和内容解析/校验失败不重试；重试耗尽仍停止本轮该来源扩散并保留断点，再次运行继续。HTTP底层不自动重试，结构化资料仍沿用单次失败停止策略。手工从启动起约58分钟预算，预算包括ST准备；预留公告正文和候选新闻时间，预算到达或缺口未闭合时返回待补而不是宣称完成。首次全年基线速度受真实公告量与来源限速影响，不能承诺固定时间；“常规增量10分钟”是待实测目标，不是已通过结果。

stderr按阶段区分股、页、分片、篇，显示已完成/总数、阶段百分比、待处理数与当前日期范围/请求页；供应商尚未返回总页数时显示`?`，有效缓存明确显示本地复用。阶段终态立即输出，源站等待每5秒输出当前阶段心跳，累计耗时统一为`HH:MM:SS`。公告分片可随日期拆分增加，阶段进度不代表全市场风险覆盖；正文按来源与公告身份去重计数。各阶段只显示自身失败，结束行汇总失败并分列已发布股票投影、待补公告分片和待补正文篇数；HTTP 403/429保留`access_denied`/`rate_limited`类别，其余HTTP失败显示状态码，传输超时显示`timeout`。

stdout仅输出最终JSON；`published_codes`表示可读取的逐股投影数量，不等于完整覆盖；`pending_partitions`是待补公告分片数，`pending_documents`是待补正文篇数，`elapsed_seconds`仍为数值秒。重新运行同一数据目录的`sync company`会续传未提交的公告页、补取未完成正文，并按日期窗口和缓存有效期更新资料；成功提交的数据保留，无需删除数据库。服务仅在09:15与12:45调用相同增量用例，单次120秒且不得越过窗口末端；14条推荐链路与HTTP/Web只消费已发布结果，下载失败保留旧投影并公开来源年龄、失败与降级。

SQLite底层连接、只读模式、FULL同步、超时、取消及显式事务由infra技术接口统一，业务SQL和表合同仍由所属adapter负责。history、公司资料和共享qfq库使用WAL/FULL；qfq的原子边界为单库内价格、双档身份、日历、断点与发布标识。连接只由使用线程持有，不设置全局连接池。公司资料按最多128股批量读取关联表、批量UPSERT并原子发布；只读者在同一事务捕获所需行，关闭事务后解码和调用消费者。新闻第二次发布只重算尝试更新的代码，全库发布身份仍覆盖全部已发布代码；时间窗口和过期检查在每轮主发布中重新计算。

数据源按能力封装：Tencent日历/价格、交易所总体、Sina曾用名、BaoStock行业、CNInfo披露/PDF和Eastmoney结构化/新闻各自拥有解析、分页、超时及失败分类。删除没有评分/风险消费者的Tushare估值、财务增强请求及`tushare_*`特征注入，删除只有旧测试引用的Tushare前复权接口；公司财务唯一来自公司资料单库。Tushare当前120积分的生产参考能力不足时不提交空任务，独立daily研究审计仍保留；不因一次超时删除有消费者的来源。字段裁剪不改变评分、风险过滤或缺失语义。

这些adapter统一注入项目HTTP接口，Requests/urllib3仅存在于infra传输driver，客户端与池由bootstrap显式装配，传输由调用方按作用域关闭。Tencent的完整历史、qfq短窗、推荐历史适配器及研究抽样共用`download/infra/tencent_daily.py`的请求/JSONP协议；成交量转为股、成交额转为元只在该边界发生一次。raw/qfq等价仍须每行满足原有零复权证据，缺口和分页策略仍由下载用例判断；HTTP封装不会自行换源或增加重试。

交易所主数据、BaoStock行业与Tushare适配器已归入download，旧`infra/market_data/providers`路径删除；Tushare只暴露明确的`stock_basic/trade_cal/daily`方法，权限门禁保持原样，不保留动态SDK透传和`pro_bar`入口。研究侧只接收不可变日期/时间戳及响应字节数，不再解析供应商字段。诊断脚本同样通过bootstrap取得传输，WebDriver和本地Web健康请求也遵守传输容量、超时和关闭规则；响应大小分级及SDK进程回收合同见工程设计3.2。

行业查询锚点为首日、固定半年首个交易日和截止日。只接纳`updateDate <= 查询日`的事实，压缩连续相同区间，不能用当前分类回填历史。
推荐启动及在线评分直接只读该库`queries`与`current_industry_queries`两表中不晚于观察日、摘要与证监会分类校验通过的最近全市场查询，形成当前行业引用；旧库尚无在线表时仍可读取历史锚点。背景在最近有效查询满7日时尝试新的当前日期查询，仅写在线表，失败按后台重试间隔再试并保留最近有效引用，不因每轮行情触发行业联网。该当前引用可用于当前页面、行业热度、集中度和生产模型暴露，不用于回填历史区间或改写旧快照；download历史查询仍按原锚点和不可变证据规则执行。库不可读时推荐保持只读 Web 和行情最近有效快照可用，行业模型输入逐股待补充。
完整成功查询按日期独立FULL事务缓存，身份包含供应商/依赖、查询日、观察截止日和内容SHA。
已验证的全市场历史查询永久复用，不按年龄过期、不随滚动计划删除；每轮最多64个查询日期，缓存累计保留历史证据。仅新增查询日期、缓存缺失、摘要损坏或来源身份变化时补查，不自动吸收供应商后续历史修订。全市场查询成功与逐股行业覆盖是两种状态：目标证券缺行业不使整日查询失效，新增证券也按完整查询结果投影，缺失明确计数，不伪造分类或用当前行业回填。
完整下载先使用Tencent日历，再于Baostock登录前检查行业缓存；全部命中不启动供应商子进程，部分命中只对缺失日期查询并复用同一会话。空响应、未来事实及失败不缓存成成功，观察截止日晚于本轮截止日的证据不得回用；每轮按当前合格总体投影，股票池变化不丢弃完整查询证据。
训练仍只读快照绑定的参考JSON。参考文件缺失或损坏时可由校验通过的查询缓存重建，内容须匹配原绑定摘要；新证据以新身份发布，不覆盖旧快照。查询缓存整库不可读时明确报错并保留原文件，不自动删除或破坏性修库。

完整history维护锁与本档训练锁保护重I/O：历史维护、系统定时维护和联合训练不并发读写完整历史；联合训练从工件复用校验、样本构建到两档拟合完成一直持有history锁及两档训练锁，失败不破坏已有工件。qfq使用独立维护锁，不等待它们。
同类任务非阻塞竞争，不能删除他人锁。train的Linux入口使用独立用户scope，4608 MiB回压、5120 MiB硬限制；下载阶段仍用股票/日期单元上限限制载荷，每档仍最多两个计算线程。联合训练仅在SSD、至少4核、可用内存至少5 GiB及cgroup上限至少5 GiB，并且`TRADER_JOINT_FIT_EVIDENCE`指定的绝对路径含相同CPU数与存储类别、同输入串/并拟合实测通过证据时并行；其余串行，缺失、无效、降速或峰值超限证据不得触发并行。隔离副本基准入口为`.venv/bin/python3 scripts/check_joint_training_performance.py --history-root <仓库外历史副本绝对路径> --workspace-root <仓库外临时目录绝对路径> --output <仓库外证据JSON绝对路径>`；它按串行→并行→串行跑三次完整联合训练，使用两次串行中的较快值作保守基线，要求并行拟合快至少10%、峰值RSS不超过5 GiB，仅在外部临时目录生成并清理工件，不得对活动数据执行。
基准返回`passed`后，以`TRADER_JOINT_FIT_EVIDENCE=<证据JSON绝对路径> ./run.sh train`显式使用证据；不设置时即使SSD资源充足仍串行。证据仅决定训练拟合调度，不改变模型或推荐准入。

### 3.1 请求与增量

### 3.2 实际覆盖与价格冲突

Tencent两侧成功响应后，以实际返回的同日raw/qfq价格对作为该股历史覆盖；完成上述有限旧页查询后少于2000日不算下载失败，不查询BaoStock交易状态或价格。两侧同一日期均未返回时，记录`tencent_inferred_suspended`空价格点；这是基于Tencent结果的停牌推定，不是可成交价格。单侧缺行保留为无完整价格的待重试日期，不伪造成交或停牌；续传请求该日期，已确认非正qfq日期遵守上述有界延迟，后续请求失败不得把已保存的单侧事实降为未知。请求失败、身份冲突或响应损坏仍待重试。后续真实成对价格可替换原推定，已有真实价格不会被推定覆盖。
超时、限流、断网、响应损坏和身份冲突仍是下载失败，保留已验证价格并标记待重试，不能伪装成供应商正常少返回。旧失败断点仍先由Tencent重试。

BaoStock在完整下载中只提供历史行业参考，价格、停牌核实及交易日历不调用BaoStock。行业缓存未命中且登录超时时，使用已经取得的Tencent日历、官方证券总体和Tencent价格先发布价格快照；因为缺少历史行业，训练保持`data_incomplete`，后续下载在BaoStock恢复后补齐参考身份并复用既有价格。登录超时不连续重试三次阻断Tencent价格下载。

已有已发布或本轮已提交的完整日线先到先用，只补缺日；缺任一侧必须由同一来源整对补齐，不跨源拼一日。
raw OHLC容差0.0051元、量100股、额100元；raw、交易状态、证券身份和ST校验保留。
完整history不因后到qfq价差覆盖旧值，不猜比例、不平滑、不为该差异整股重拉。
这允许跨日期存在复权口径差异，不能宣称误差一定很小或历史收益严格连续；独立qfq仍遵守第4节的同源完整窗口合同。

确定raw/锚点/窗口冲突终止该股的无效重复尝试；身份/ST冲突及持久化错误中止同步。
有效部分可以发布；Tencent正常少返回的日期按双侧推定停牌或单侧无完整价格处理，不因数量不足进入下轮下载缺口；真正请求失败的日期才保留为下轮缺口。

### 3.3 正式年库与逻辑快照

供应商结果在内存校验后直接写正式年库，不建立Tencent价格暂存、qualified、pending或seal副本，也不执行历史价格整理。
在途下载、待写及当前写入合计最多64股和32768个请求日期单元，派发前预留容量，满载时回压；这是载荷计数上限，不是精确内存字节保证。空库首建在正式年库依靠主键拒绝重复日线并直接插入，续传和增量仍执行完整已有记录校验。未发布批次续传时，同序号未知缺日只可更新为经验证的其它状态，单侧缺失或Tencent推定停牌只可升级为完整价格对；已发布观察及完整价格对的同序号改写仍拒绝。下载启动时只读识别目标文件系统的旋转盘属性，并报告HDD、SSD或unknown；识别失败使用既有参数。HDD首建按8股或16384日期单元触发写入；SSD、unknown及续传增量按16股或8192日期单元触发，另有5秒或网络任务排空触发。写入按年度归组，每4096行一个FULL事务，正常WAL允许并发只读。单次管线在同一写线程内最多复用32个年库连接，每批仍独立FULL提交；成功、失败或取消都在释放维护锁前关闭并等待这些连接。
控制库不保存第二份价格。跨月全部提交后，同一写批次的股票在一个控制库FULL事务中确认；中断续用已经提交的完整价格，先续原截止日批次再追赶最新日历。
不同PC的供应商执行环境（SDK、Python及依赖版本）摘要差异，以及官方名称变化，均不清空续传断点：日历日期、代码集合、板块、上市/退市日期、来源类型及原截止日必须一致，当前ST资格证据须通过，名称含ST标记仍拒绝。先持久化本轮参考身份，再原子重绑未发布批次的来源、日历和总体引用，保留任务日期、确认进度、尝试和缺口。价格仍按Tencent原有资格与冲突规则校验；已发布快照及其参考不改写。真实身份冲突继续中止，错误码区分日历、截止日、代码集合、证券身份、ST及来源变化，不能仅凭代码相同放行。

年库按`(trade_date, code, revision_id)`日期主序、`WITHOUT ROWID`保存，另有单股和截面查询索引。
年度负责物理路由，月份保留逻辑摘要与查询边界，业务键仍为`(code, trade_date)`。所有月份视图显式限制日期范围，不重复扫描同年其它月份。raw/qfq保存具名数值列、交易状态、侧存在标记与缺失状态；取消价格JSON，区分整侧缺失与某字段为空，保持原数值身份。
正式库累计保留历史日期，活动训练日历最多2000日；旧快照引用的行不随滚动窗口前移删除。

每月引用绑定`logical_hash`、`row_count`与`sequence`。发布检查变更月完整性、可见键和内容摘要，未变更月复用引用。
绑定参考、控制快照与active指针同事务切换，未发布追加行对旧快照不可见；发布失败保留旧active，后续复用已提交价格。
可追加年库不能用整文件SHA或SQLite immutable连接建立信任，正常WAL不是损坏。

当前旧格式不兼容，旧转换器已退役。清空重建或真实数据切换必须由用户明确授权，下载不会替用户删除旧库或备份。

### 3.4 空间与进度

history体积包含累计历史、观察/修订、索引及WAL，不由字段数量单独决定。
诊断按inode去重，区分正式库、旧pending/seal遗留、备份、空闲页和日志；不能把硬链接逻辑大小重复相加。
写入前及批次中检查磁盘余量，正常更新不复制整月、不常规VACUUM、不自动删除旧revision或备份。
SQLite页缓存有界、禁用mmap；空间治理先只读诊断，再经独立授权实施。

准备、行业、缺口扫描、网络等待、年库提交和发布分别计时；长等待与SQL有心跳和取消点。
“股日”是股票与交易日组合数；最终摘要另给受影响股票数、日期范围与原因分组。无效qfq按逐日持久证据计数，其余按最近下载任务的失败原因分组，未分类缺口标记history_price_pending；这些分组不冒充逐日根因鉴定。推定停牌不冒充未修复价格缺口。
逐股完成必须在持久提交后显示。`download`与`sync market`共同使用“耗时、命令股票进度、累计进度、股票、处理、结果、raw、qfq、完整配对、缺日”的固定主干；history后接网络、落库、待写、下载、落库耗时、回压和总计，未知统计保留占位。原因、最多八个缺失日期及总数、超长完整名称统一放在行尾，保持一股一行。中文/全角按两显示列、英文数字按一列、组合字符不额外占列；名称区8列（四个汉字），超长用省略号并保留行尾全名，缺名显示“—”；数量预留六位并右对齐，超过宽度不截断，百分比固定两位并容纳100%。覆盖分子分母分别补位，耗时使用HH:MM:SS，超长耗时不截断。持续逐股完成时不额外输出管线汇总，超过5秒无完成才输出等待行；无真实月份和数量的月库占位心跳不显示。重试显示n/3，最终摘要分别报告成功、残留缺口、未处理及稳定失败原因。

日志状态、结果和异常字段按语义着色：正常进度/等待/复用/资格排除默认色，完整提交成功绿色，部分/缺日/待重试/取消黄色，最终失败/完整性冲突/写库或发布失败红色；同批摘要保留最高严重程度，异常提取不得误报完成。先补齐显示宽度再加ANSI，每段立即重置；字段中的控制字符、已有转义序列和分隔符先清理，单条日志一次写出。仅实际输出流为终端且TERM非dumb、NO_COLOR未设非空值时启用颜色；文件、管道和机器JSON不带颜色，颜色不替代文字、不影响数量、重试、持久化或退出码。
缺口统计是待修复的股票×交易日数，不是网络请求数量，也不是股票数。
行业日期的开始与完成由准备层唯一输出，底层仅报告等待、重试和失败。失败摘要只使用实际失败操作的位置，不将最后成功股票当成故障股票；未知位置明确显示。history失败保留有界异常类型与代码位置的因果链，不输出完整异常文本、路径、局部变量或供应商载荷。qfq末尾及JSON的`pending_reasons`分别汇总逐股待重试类别与数量；JSON另列`latest_missing_codes`，该数达到系统性阈值时终态为待核、命令返回非零并由后台重试。`failure_reason`仅表示整轮失败或取消，非空待重试仍返回非零退出码。

## 4. 独立qfq短窗口

V2最多保留最近251根、V3最多保留最近61根同源raw/qfq真实成交日线，完整窗口分别提供250/60特征日及一根前置日线。qfq下载一次请求最近251个市场交易日，逐股尾部请求按实际所需日期数传递供应商行数参数，不使用固定640；两档分别从最近251/61日内保存Tencent实际返回的成对日线，不为凑满根数向前回查。实际根数不足时由模型字段资格判为输入待补充。
全部板块与两档共用daily_window.sqlite3；251/61是市场交易日范围，不按最后成交根数补齐。
`bars`以`(code,day)`为主键，`identities`保存每档每股来源、内容hash与市场日历边界，`calendars`保存两档日历，`completions`保存完成断点，`publications`保存每档每次提交的唯一发布标识。只保存真实返回字段，不伪造昨收、涨跌幅、换手率、停牌或ST事实。

维护对共享库执行一次完整性检查，再按档位和证券校验窗口身份。
Tencent第一阶段最多8股滚动在途；同源缺1–5日只请求尾部和3日重叠，无新日且无有效断点时核对3日重叠。
工作池暂时满载时最多等待5秒；到期仍拒绝则停止整轮新派发，保留已接收任务的合法结果并完成落盘及断点确认。整轮失败原因标记`qfq_worker_unavailable`，未派发股票按`worker_unavailable_before_processing`计入待重试，不伪装为供应商请求失败或完成；取消仍拒绝迟到结果。
来源变化、旧无来源或重叠冲突时重取该股完整251日窗口，不升级为2000日全历史重拉。

Tencent成功响应中的单侧缺行和双侧缺行均不触发补页或换源；前者缺完整价格，后者按推定停牌计，短库只写真实成对日线。请求失败、内容或身份无法校验，以及整窗只有单侧价格且没有完整价格对时，保留旧有效窗口并待下轮Tencent重试；不调用BaoStock补充短窗口。推荐只读投影从真实日线构造特征；最近成交日不满足在线新鲜度时，该股仍为待更新或只观察，不沿用陈旧价格作可执行荐股。
整窗均为推定停牌且零真实日线时，逐股记“无真实日线”，不写短库、不推进该股完成断点、不计待重试；下一交易日重新检查。成功返回但只有单侧价格、没有任何完整价格对时仍计待重试，不显示“合格”。
每股raw/qfq合计180秒单调deadline，包含请求和重试；单次45秒、最多2次重试，关停宽限独立。
单股失败保留旧有效窗口并继续其它股票，不推进该股完成断点；“复用”不等于“本轮下载合格”，待重试不能靠改统计消除。实际下载、本地复用、无需下载和本地检查失败均使用与完整history相同的逐股字段顺序输出终态；等待心跳与最终汇总独立输出。

写前比较内容和来源，无变化不创建写连接；变化只写变更行、删除过期日和更新身份。
共享库使用WAL/FULL；价格、两档身份、日历、完成断点与发布标识同事务提交，失败整批回滚。移除证券时同步更新对应档位发布标识，最后一只移除后清除该档发布身份；无变化复用保持原标识。发布标识是随机唯一值，不扫描全库生成；内容摘要仍由实际身份与日历确定。先前成功批次保留并准确报告。
下载线程与单写入线程由组合根独立注入，配对落库期间继续补充请求。待写、在途和写入中合计最多32股/8192日期单元；16股、4096行、1秒或网络排空触发提交。取消停止接单，等待在途配对事务退出后释放维护锁。统计与逐股输出由协调线程消费提交回执。
完成断点与两档身份同事务，删除独立断点JSON；取消或提交失败不记完成。断点已确认但最后一个目标交易日尚无真实成对日线时，下一轮仍复核该股尾部，以接纳供应商迟到的日线；单股推定停牌不因此伪造成交或业务淘汰。

后台仅在进程已运行到上海时间15:10时每天尝试一次，不在启动时下载；15:10及以后启动不补跑当天，失败、锁占用或当日错过执行都不自动重试，由人工运行`./run.sh sync market`补齐。次日仍只在15:10尝试新一轮；短库预检、断点续传与最新交易日真实配对判定保持不变，少量推定停牌不触发同日反复下载。
推荐后台观察器每30秒检查已发布短库；加载manifest时读取全体身份与日历并计算内容摘要，在同一只读事务捕获发布标识（类型字段publication_id）。每批窗口读取前后只按档位核对发布标识，不重复扫描全体身份。逐股只在读取行与校验内容摘要时保持只读事务，取完即释放锁后再解码和构建特征，不得以整板长事务阻塞V2/V3成对发布。观察前后复核短库内容身份，并发发布造成标识变化时丢弃混合结果，下轮重建；完整验证后才原子替换有界内存投影。损坏或身份变化保留上一有效投影并明确降级。
候选、评分及HTTP/Web不现场下载、不扫描完整history。新上市或资格未核对代码为data_pending，不算业务淘汰。

短库采用包含发布标识的SQLite格式（user_version=2）；旧板块布局及缺少发布标识的共享库明确拒绝，不隐式迁移、双读或覆盖。旧数据已删除时由sync market按新格式重新生成；程序不自行删除遗留文件。

## 5. 训练输入、样本与拟合

### 5.1 预检与样本

联合训练先在锁内校验V2/V3的双头指针、模型、报告和输入文件摘要。两档均与当前历史快照、成熟标签截止日、参数、特征合同、依赖版本及训练/领域实现内容摘要匹配时返回`reused=true`，不扫描价格、不拟合；任一缺失、损坏或身份变化时重训双档，不受due提醒周期限制。旧工件没有当前实现身份会触发一次重训。缺manifest、行业覆盖不足或空样本必须有明确阻塞原因。
价格首扫前校验行业连续覆盖、训练/早停/校准/验证锚点及行业样本保守上界。
所有行业均达不到20000行门槛时快速返回`history_industry_training_rows_insufficient`，上界通过不代表实际样本合格。

交易所日历是唯一日期轴，同一日期全部股票进入同一切分；上市前不填充，未知缺日不跨越；Tencent双边成功缺行作为推定停牌跳过特征成交日，显式来源停牌保留自身真实状态。
V2/V3分别维护最长251/61日滚动特征状态，按日期计算横截面，以有界缓冲等待T+1～T+5成熟标签。
横截面暴露残差和V2市场状态必须由当日已知的完整合格模型输入人口计算，先于未来标签可得性固定；缺失未来标签只影响该行能否进入某一目标训练，不得反向改变同日其他股票特征。在线推理用对应完整市场模型输入人口计算同一暴露，预测器只消费通过候选与模型资格的股票。
特征和标签按代码、交易日连接，不按某股第N行位置对齐；V2需要250日特征历史，V3需要60日特征历史。
写入唯一最终samples表，不建raw_samples，不把完整历史或全部行业矩阵留在内存。

Tomorrow使用T+1目标；D25使用T+2～T+5的统一聚合目标，不拆四个生产头。
训练标签是扣成本前的预测超额收益；在线净效用只扣一次配置成本。研究20/50/100bp口径及MAE、可交易性、基准和终端留出规则唯一见评分逻辑第12节，不能在训练目标和在线门重复扣除。
真实点时数据与15:00日线工程代理分别标识；日线训练成功不能改写`point_in_time_parity=false`或授予`production_authority`。

### 5.2 切分、缓存与资源

V2固定1000个有效拟合日、V3固定750日；日历窗口还要容纳特征预热、标签成熟、早停、校准及验证隔离。
切分从终端留出向前倒排，预留预热和拟合→早停/校准、开发→确认、确认→代理留出、代理留出→终端留出的五日隔离；实际建样本后按策略标签核对每个切分的有效日期数。不足时在发布前阻断。V2 的250日预热与1000日有效拟合仍可在完整2000日窗口内分配，不能先按比例截出开发集再让预热占用拟合日期。
750/1000/1250候选窗口的收益比较属于隔离研究，不能描述成日常命令自动择优。
全局2000日不是所有日期都进入拟合；同日横截面不能跨切分，embargo和留出不得用于调参。
2000日指最近2000个市场交易日的共同日期窗口，不为每只股票向前凑满2000根日线。Tencent已完成双边请求仍未返回的日期投影为推定停牌空价格点，不清空该股已验证的真实成交日特征窗口；单侧缺行和失败造成的未知缺口仍清空并重新积累251/61根。T+1～T+5始终沿共同日历定位，不把下一根成交日线当作次日标签。新上市、长期无价格的股票是否提供样本由实际特征与成熟标签决定。

完整样本缓存身份绑定snapshot、切分、特征与标签语义及字节SHA，不绑定学习率等拟合参数；拟合身份另行绑定参数。
只有完整、同身份且通过验证的缓存可复用；未完成构建、输入变化或损坏重建，不做部分样本续传。
每档最多一份完整缓存，拟合失败保留；成功或明确拒绝后释放。强杀遗留的未完成工作库由下一同档任务清理。

标签统计合并扫描，按行业/切分聚合一次；拟合只读取需要的训练、早停和校准矩阵，validation只统计。
行业顺序拟合，float64原地标准化，不保留三份等价矩阵，不以float32或行业并发换速度。
SQLite样本缓存32 MiB，LightGBM列式直方图池64 MiB，计算线程和2 GiB资源门不变。
同日动量复用不可变exposure context，保持market→board→industry→liquidity顺序及黄金向量。

### 5.3 工件与消费

需要训练时按两档可读日期并集只扫描一次价格行，分别构建、校验及封存各档样本缓存，再按资源门并行或串行拟合。样本缓存身份也绑定实现摘要。每档内部仍顺序拟合Tomorrow、D25；V2只产出LightGBM字段，V3只产出Ridge字段，不生成无效双模型占位。
input、features、model、report绑定数据、同档双头训练运行hash、特征字段顺序/单位、切分、训练合同和内容hash。
新训练report把`artifact_structure_valid`与`prediction_return_validation_passed`分开：前者只证明模型结构、
行业头和validation行可加载，后者只有真实点时收益门通过才可为true。当前日线收盘工程代理固定保持后者false并
记录`daily_close_proxy_not_point_in_time`。旧report的`validation_passed`格式不再兼容或加载；合同变化后必须删除
旧双头bundle并分别完整重训V2/V3，不能迁移、补写或用旧标志作为收益验证证据。
双头全部合格后先在同级临时目录形成并校验本档完整配对，再切换到可由Git追踪的 `{v2,v3}/{tomorrow,d25}/` 固定目录；每头`metadata.json`记录训练身份、模型摘要与嵌套合同，整档校验双头共同身份；不保存活动指针或隐藏代次。拟合、校验或切换失败回滚上一完整组；切换瞬间并发读若遇目录暂不可用则失败关闭，不接纳半组。不自动切档、不用Tomorrow代替D25。
推荐只读加载所选档位工件和匹配短窗口，不热加载磁盘模型；正常重启后接纳新工件。

训练与推理复用纯特征公式和manifest；固定日期、证券及来源输入的等价性需要黄金向量和真实供应商证据。
来源复权或点时语义未验证时保持明确限制，不能用“工件存在”或mock通过替代真实配合验收。

训练进度分别报告预检、历史读取与训练样本生成、横截面样本、索引、标签/行业统计、拟合和发布；训练不再输出输入分片复核阶段。阶段开始立即输出，长阶段10秒心跳。
同时保留缺行业、缺价格、短窗口、无效特征、标签不足计数和已知磁盘峰值，失败不清零已有诊断。

## 6. 回溯、评价与生产隔离

线上冻结评分前六用于连续观察；运行结算分别统计其中实际入选的“推荐”和“关注”，
“回避”只保留历史锚点与只读涨跌展示。两档统计使用原策略目标周期，不能合并为正式推荐业绩，
线上结算仍不得用于训练、校准或生产参数准入。ATR20 缺失只排除 `MAE/ATR20` 与严重亏损风险标签，不删除可验证的收益标签；
点时研究、风险训练和生产准入仍拒绝该类风险标签不完整的样本。

收益公式、D25聚合、成本、MAE和一次性终端留出合同见评分逻辑第12节；本节只定义工程消费边界。
完整研究链为：点时数据资格→数据集与统一特征→候选召回归因→有限参数族→分档开发/确认→增量同源性→风险/成本/DeepSeek消融→冻结选择链→一次性终端留出→Shadow。
不读取终端留出收益来选择窗口、因子或参数；不足时停止并保留blocker，不用线上正式推荐结果回灌训练。

冻结选择链的离线配对实验由有类型规范一次封存四组排序臂、每板60/120/180/240/完整人口、固定前六不递补/
门后约束选六、20/50/100bp和策略目标。Tomorrow只评T+1；D25同时评T+2～T+5均值、固定T+5、预定义退出
和多期限门，不评事后最高价。共享/部分池化臂分别保留Ridge与LightGBM子身份及市场、板块、行业、流动性暴露。
同一父行和日期输出六槽位净超额、Rank IC、NDCG@6、胜率、最大回撤、换手、严重亏损、MAE/ATR20、
退出不可交易、容量和oracle Top6召回；前置点时或召回不足时零读取收益并返回`historical_data_insufficient`。

研究适配器使用仓库外隔离输出，不接入HTTP、SSE、生产调度或活动数据库。
来源能力必须分别证明历史日线、行业生效区间、15:00分钟及事件披露时间；真实点时资格不足时为`historical_data_insufficient`。
报告和manifest绑定父hash、数据行、特征、日历、证券主数据、日期切分和选择策略；身份冲突、篡改或合格基准人口outcome不完整时不发布部分结果。
历史已通过报告只证明原提交和原数据，不能证明当前代码已授权生产或收益提高。

### 6.1 点时资格和证据绑定

日线资格要求完整2000日manifest、总体完成且无失败；行业要求至少300只分层样本及代码、分类、生效起止、查询时间和来源身份证据。
分钟要求分层代码/日期覆盖至少95%，证明上海时区、15:00锚点、量额、raw/qfq及公司行动语义。默认单股诊断不是全量资格证据。
`PointInTimeDataQualificationReport`是唯一有类型三门结果；任一不足时不读取下游收益，保持terminal_holdout_opened=false和production_authority=false。

点时数据集每行绑定日线、分钟、证券、行业、事件、特征和outcome路径hash；published_at不得晚于锚点。
生产纯选择规则重建首次拒绝边界，基准资格在候选阈值/板限之前确定，不以入选人口替代基准。
训练/早停/校准/确认有独立逐日hash，至少5日embargo及至少200日终端留出写入父身份，构建期不调用终端留出来源。
同内容重放幂等，异内容或父身份篡改失败关闭，不发布不完整manifest。

候选召回账本复用上游首次边界，后续追踪只补评分/风险/动作/集中度及单调累计延迟，不重算双写。
日归因验证行hash、覆盖和延迟证据，有限因子族消费者重新校验父绑定；TopK遗漏用每日min(K,人口数)微汇总，空组均值和风险率为None。
行业审计只在effective_from <= trade_date < effective_to命中，同分类可合并来源证据，不同分类冲突拒绝。
Shadow仅输出聚合漂移、校准、成本后收益和尾部风险，不改生产配置或自动启用模型。

## 7. 维护、提醒与验收

操作系统每天15:10/20:30检查；完整history落后至少7自然日且不早于15:10才自动下载，手工download不受周门槛限制。
无库/控制库不可读等待手工初始化或修复；锁竞争返回already_running，未到期返回not_due，数据及身份无变化返回already_current。
下载只报告数据截止、标签截止、成熟日数量及训练due，不自动训练或更新模型。

due基线是活动模型的label_cutoff：无模型为initial_training_required，新增20个成熟交易日为cadence_due，逻辑修订为input_revision_due，合同变化为training_contract_due，输入不足为data_incomplete。

# Change-impact matrix

Select every row touched directly or transitively. The commands are the minimum targeted evidence; `AGENTS.md` risk classification can escalate them to the full gate.

| Boundary | Typical paths | Mandatory downstream review | Minimum targeted evidence | Live profile |
| --- | --- | --- | --- | --- |
| Market providers and normalization | `src/trader/infra/market_data/**`, `src/trader/application/market_data/**` | field units, timestamps, adjustment semantics, fallback, cache identity, source health | matching market unit/component tests | `sources`; use `live` when current recommendations depend on it |
| History warmup and reference data | market-data history services, `src/trader/infra/research/**`, security references | worker waves, queue wait, batch deadline, immediate visibility, SQLite transaction count, candidate priority, identity completeness | matching history/reference unit and component tests plus scheduler integration when publication changes | `live`; add external `--persistence-runtime-dir` only for persistence comparison |

| Diagnostics, skill, docs | `scripts/**`, `.agents/skills/**`, `AGENTS.md`, operational docs | bounded CLI, stdout/external output, no secret/raw payload aggregation, discoverability, accurate routing | direct unit/contract tests, Ruff, skill quick validation, `--help` and a safe profile smoke | use only the profile whose behavior changed |

When one row feeds another, include both. Provider/history changes normally reach scheduler status and Web summaries; scheduler/current changes normally reach API, SSE, and browser; scoring meaning or identity changes normally reach freezing, persistence, API/SSE, Web, and research interpretation; schema changes always reach serializer and consumer contracts.

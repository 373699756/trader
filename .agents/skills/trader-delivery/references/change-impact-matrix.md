# Change-impact matrix

Select every row touched directly or transitively. The commands are the minimum targeted evidence; `AGENTS.md` risk classification can escalate them to the full gate.

| Boundary | Typical paths | Mandatory downstream review | Minimum targeted evidence | Live profile |
| --- | --- | --- | --- | --- |
| Market providers and normalization | `src/trader/infra/market_data/{tencent,tushare,eastmoney,sina,history,normalize,merge}*` | field units, timestamps, adjustment semantics, fallback, cache identity, source health | matching unit tests plus `tests/component/test_market_{vendors,history,tushare}.py` as applicable | `sources`; use `live` when current recommendations depend on it |
| History warmup and reference data | `service_history*`, `service_history_warmup.py`, `history_seed.py`, `security_references.py` | worker waves, queue wait, batch deadline, immediate visibility, SQLite transaction count, candidate priority, identity completeness | warmup unit tests, market-history/reference components, scheduler integration | `live`; add external `--persistence-runtime-dir` only for persistence comparison |
| Scheduler, cadence, lanes, resource orchestration | `src/trader/application/{v2_runtime,schedule,cadence,workers,source_lanes,shutdown}*`, `bootstrap*.py` | all four strategies, latest-wins, cancellation, freeze controls, observer, shutdown, status | runtime/schedule/worker unit tests and `tests/integration/test_v2_scheduler_runtime.py`; bootstrap changes are high risk | `live`, then affected five-period real-service scenario |
| Scoring, filters, risk, fusion, ranking | `src/trader/domain/recommendation/**`, `scored_*`, policy/config | candidate population, missing facts, risk once, fixed fusion, action pools, stable TopK, version/hash | affected domain/application tests, fixed `83.40`, strategy contract; run performance when hot path changes | `full` only when runtime latency or Web delivery changes |
| DeepSeek | `src/trader/infra/deepseek/**`, review/fusion application modules | shared budget, cache/single-flight, evidence/schema, deadline, local-first fallback, late-result CAS | DeepSeek components, fusion tests, 168-request concurrency and deadline tests | `runtime`; do not spend real quota unless explicitly needed |
| Persistence and recovery | `src/trader/infra/persistence/**`, decision records, outcomes, research stores | first-wins/idempotency, conflict, corruption, restart, hash, writer ownership, fail-open/fail-closed boundary | matching unit/component tests plus restart/recovery integration | `runtime` after a normal restart when activity is affected |
| API, SSE, Web, release assets | `src/trader/web/**`, decision queries/stream, static/template resources | serializer whitelist, schema/release identity, ETag, current/history, SSE resync, browser state, four strategies | Web/architecture contracts, decision-stream and JS tests, Firefox evidence for behavior/layout | `runtime`; `full` for browser delivery or performance |
| Entrypoints, packaging, dependencies | `src/trader/entrypoints/**`, `bootstrap.py`, `pyproject.toml`, package resources | side-effect-free app factory, CLI resource control, wheel resources, install outside repository | high-risk full command group and external wheel install | affected runtime profile after install |
| Offline score research | `src/trader/{domain,application,infra}/research/**` | production isolation, immutable identities, point-in-time evidence, no Web/network/DeepSeek side effects | matching research unit/component/contract tests and mypy for public types | none unless production wiring changes |
| Diagnostics, skill, docs | `scripts/**`, `.agents/skills/**`, `AGENTS.md`, operational docs | bounded CLI, stdout/external output, no secret/raw payload aggregation, discoverability, accurate routing | direct unit/contract tests, Ruff, skill quick validation, `--help` and a safe profile smoke | use only the profile whose behavior changed |

When one row feeds another, include both. In particular, provider/history changes normally reach scheduler status and Web summaries; scheduler/current changes normally reach API, SSE, and browser; schema changes always reach serializer and consumer contracts.

# Change-impact matrix

Select every row touched directly or transitively by a behavioral or cross-boundary change. For lightweight documentation, skill, process, or metadata work, use only checks material to the edited content. `AGENTS.md` risk classification determines whether to narrow or escalate the listed evidence.

| Boundary | Typical paths | Downstream review | Targeted evidence | Live profile |
| --- | --- | --- | --- | --- |
| Market providers and normalization | `src/trader/infra/market_data/**`, `src/trader/recommendation/{application/pipeline,infra/market_data}/**` | field units, timestamps, adjustment semantics, fallback, cache identity, source health | matching market unit/component tests | `sources`; use `live` when current recommendations depend on it |
| History warmup and reference data | `src/trader/download/**`, `src/trader/infra/market_data/{history,references}/**`, `src/trader/recommendation/infra/market_data/**` | worker waves, queue wait, batch deadline, immediate visibility, SQLite transaction count, candidate priority, identity completeness | matching history/reference unit and component tests plus scheduler integration when publication changes | `live`; add external `--persistence-runtime-dir` only for persistence comparison |
| Scheduler, cadence, lanes, resource orchestration | `src/trader/recommendation/application/runtime/**`, `src/trader/bootstrap.py` | Tomorrow/D25 decision runs, Long snapshot refresh, latest-wins, cancellation, freeze controls, observer, shutdown, status | runtime/schedule/worker unit tests and `tests/integration/test_scheduler_runtime.py`; bootstrap changes are high risk | `live`, then the affected five-period real-service scenario |
| Candidate and evidence-quality scoring | `src/trader/recommendation/domain/{candidate,evidence,scoring,selection}/**`, `src/trader/recommendation/application/pipeline/{candidate_pool,quality_check,local_score}/**`, `config/strategy.json` | population and point-in-time eligibility, candidate reserves, 0/50/100 score anchors, component/weight ownership, local risk once, action pools, stable TopK | affected domain/application/config contracts, Tomorrow/D25 golden vectors, fixed `83.40`; use the scoring-chain guide | `performance` when the hot path changes; `full` when Web delivery also changes |
| Model diagnostics and execution gates | `src/trader/recommendation/application/ports/scoring.py`, `src/trader/recommendation/application/pipeline/local_score/**`, `src/trader/recommendation/infra/scoring/**`, `src/trader/training/infra/model_bundles/**` | profile eligibility, prediction identity/hash, relative signal only as diagnostics, cost exactly once, non-positive utility gate, local-first failure behavior | model profile/service, projection, selection, deadline, cache and cost-gate tests; use the scoring-chain guide | `performance` for inference-path changes; do not spend external model quota |
| Risk, fusion, action, ranking | `src/trader/recommendation/domain/{risk,selection}/**`, `src/trader/recommendation/application/pipeline/{risk_review,score_merge,downside_action,final_selection}/**` | local risk once, fixed fusion, veto, action pools, stable ranking and concentration | risk/fusion/selection tests and fixed `83.40` | `runtime` when current decisions change |
| DeepSeek | `src/trader/recommendation/infra/deepseek/**`, `src/trader/recommendation/application/pipeline/{risk_review,score_merge}/**` | shared budget, cache/single-flight, evidence/schema, deadline, local-first fallback, late-result CAS | DeepSeek components, fusion tests, 168-request concurrency and deadline tests | `runtime`; do not spend real quota unless explicitly needed |
| Decision identity, freezing, persistence and recovery | `src/trader/recommendation/application/pipeline/freeze_publish/**`, `src/trader/recommendation/infra/persistence/**`, `src/trader/training/{application,infra/research}/**` outcome consumers | score/model/input identities, first-wins/idempotency, old-record semantics, conflict, corruption, restart, hash, writer ownership | decision identity, freeze, codec, current/history and restart/recovery tests; apply the five-period matrix | `runtime` after a normal restart when activity is affected |
| API, SSE, Web, release assets | `src/trader/http_api/**`, `src/trader/web/**`, recommendation read-only queries/events | serializer whitelist, `score_scale`/model identity, ETag, Tomorrow/D25 current/history, Long current-only projection, SSE replacement/resync, browser state | HTTP/Web architecture contracts, decision-stream and JS tests, desktop browser evidence when behavior/layout changes | `runtime`; `full` for browser delivery or performance |
| Entrypoints, packaging, dependencies | `src/trader/{entrypoints,download/entrypoints,training/entrypoints}/**`, `src/trader/bootstrap.py`, `pyproject.toml`, package resources | side-effect-free app factory, CLI resource control, wheel resources, install outside repository | high-risk full command group and external wheel install | affected runtime profile after install |
| Offline score research | `src/trader/training/{domain/evaluation,application,infra/research}/**` | production isolation, immutable identities, point-in-time evidence, cost ownership, confirmation/holdout/Shadow state, no production authority | matching research unit/component/contract tests and mypy for public types; use the scoring-chain guide | `research`; no production/live claim unless wiring changes |
| Diagnostics, skill, docs | `scripts/**`, `.agents/skills/**`, `AGENTS.md`, operational docs | bounded CLI, stdout/external output, no secret/raw payload aggregation, discoverability, accurate routing | skill/doc changes: quick validation plus link/path checks; script changes: applicable unit/contract tests, Ruff, `--help`, and a safe profile smoke | use only the profile whose behavior changed |

When one row feeds another, include both. Provider/history changes normally reach scheduler status and Web summaries; scheduler/current changes normally reach API, SSE, and browser; scoring meaning or identity changes normally reach freezing, persistence, API/SSE, Web, and research interpretation; schema changes always reach serializer and consumer contracts.

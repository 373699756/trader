# Python 工程设计与编码规范

## 分工与必读资料

用户要求和仓库 AGENTS.md 优先。先读适用的 AGENTS.md、pyproject.toml，已有上下文有效时不重复读取。本 skill 只负责 Python 判断；Trader 的阶段、业务影响、诊断和提交推送交给 [trader-delivery](../trader-delivery/SKILL.md)。规划和只读审查不因加载本 skill 就获得修改授权，也不重构无关代码。

| 当前任务 | 此时必读 | 应形成的判断 |
| --- | --- | --- |
| 编写、修改或审查 Python | [编码规范](references/coding-standard.md) | 公开边界、命名、类型、错误与资源生命周期 |
| 新建工程、拆分模块或改变依赖/状态owner | 再读 [工程设计](references/engineering-design.md) | 当前owner、目标owner、消费者与原子迁移边界 |
| 核对规则出处、许可证或旧建议 | [资料来源](references/sources.md) | 历史资料与当前仓库约定的区别 |

不需要架构变化的小实现只读编码规范；不默认加载全部参考。

## 命名与消费者证据

[编码规范第3节](references/coding-standard.md#3-命名格式与可读性)是命名规则唯一维护位置。公开与内部符号按真实消费者分类；不依赖通用Python默认风格覆盖仓库规则，也不在其它文档复制规则。

修改已有公开边界或执行已授权改名时，先搜索定义、导入、导出、入口字符串、调用和mock/patch目标；完成切换后再搜索旧标识，区分活动引用与外部固定字段、不可变历史。检查结果要能说明全部消费者如何切换，不以“命名已核对”一句代替证据。保留职责与可见性未变化的既有名称。

## 代码核对与验证选择

完成实现切片及消费者切换后，逐项对照实际 diff：公开接口与数据字段、依赖方向和唯一owner、类型与异常因果、I/O超时及资源停止/等待。发现问题先修复，不因读过规范而跳过代码核对。

| 改动 | 必要验证 |
| --- | --- |
| 文档、注释、非运行元数据 | 完整diff与空白检查；skill另查元数据、引用和示例 |
| Python逻辑或公开符号改名 | 受影响Ruff；改名另核对旧引用、导出、入口及消费者 |
| 关键业务、公开合同或重要回归风险 | 实现后集中补最小充分回归并运行定向门禁 |
| 公共类型或复杂边界 | 再运行受影响mypy |
| 测试基础设施、全仓测试调整或发布 | 按 AGENTS.md 和工程设计执行相应完整门禁 |

沿用声明的工具和支持版本。Trader直接Python命令只用 python3 或 .venv/bin/python3。复用现有门禁，不新建第二套命名检查、工具配置或豁免来绕过发现。

结束时把代码结论与实际检查结果交给delivery：通过、失败、未运行及其原因分别列明；定向通过不等于全量或真实运行通过。审查发现给出位置、触发条件及修复方向。
